# 《AI 工作启动指令》使用指南（个人速查版）

> 生成于 2026-09-17。这是你个人的使用教程，**不是仓库文档**（放在 quandao/.workbuddy/ 下，不进 promotion/，避免第二入口）。
> 对应正文：`promotion/AI工作启动指令.md`（586 行，13 个场景 A~M）。模板有改动时以它为准。

---

## 一、这份文档解决什么问题

让每个新会话的 AI **不靠聊天记忆、不靠猜**，按同一套入口读仓库、按同一套纪律干活。
你只需要做一件事：**把对应场景的「📋 发给 AI」代码块整段复制，贴给 AI，末尾补一句你的具体任务**。

## 二、每次使用的三个动作

```text
① 选场景      → 问自己"我要 AI 做什么"，对着下面的决策树挑
② 复制粘贴    → 把该场景的「📋 发给 AI」整段原样复制（不要改写模板句子）
③ 末尾补定制  → 在代码块末尾加"【任务定制】"段，写清对象/范围/预授权
```

> 模板的措辞是随口径迭代定稿的（如 013/019 都调过触发口径），**照抄最稳**。

## 三、场景决策树

```text
你要 AI 做什么？
├─ 新会话接着干活（不新生任务）────────────── A
├─ 生产一条视频 ─────────────────────────── G
├─ 只要选题（不动手）─────────────────────── B
├─ 修一个已经明确的小问题 ────────────────── H
├─ 只做 Remotion 工程实现 ───────────────── I
├─ 把复杂任务拆成执行表 ─────────────────── C
├─ 只调查"为什么/是谁的"（不动手）────────── D
├─ 只评估一个想法（不动手）───────────────── K
├─ 全局审计（不动手）────────────────────── L
├─ 正式执行全局整改 ─────────────────────── E
├─ 复核"之前说完成的到底完成没"──────────── F（流程版）/ J（证据版）
└─ 大动作前先建立全局认知 ───────────────── M
```

**先过一道复杂度闸**（写在 §四）：任务命中任一条 → **先发 M，拍板后再发执行场景**：
- 涉及两个以上 Owner；
- 涉及两个以上流程或共享组件；
- 涉及全局规则、跨行业规则或规则替代；
- 跨多个产物（文档/脚本/模板/视频/事务）。

单 Owner 的连续任务 → 直接用执行场景，不用 M。

## 四、13 个场景速查表

| 场景 | 什么时候用 | 末尾定制写什么 | 真实例子 |
|---|---|---|---|
| **A 接班** | 新会话继续在产的任务（比如做到一半的片） | 无需多少——AI 自己找未完成节点；只想限定范围时补一句 | "当前只推进 g10，别开新片" |
| **B 选题** | 只出选题方向，不做片 | 时间点/节日/行业偏好；要不要限定行业 | "重点看 10 月国庆+中秋双节" |
| **C 拆任务** | 大任务先要执行表再动手 | 任务是什么；有没有不能动的部分 | "把『四张真值表全部重核』拆成节点" |
| **D 只调查** | 出了怪象要查根因（不许修） | 现象描述；你已经知道什么 | "gate-all 为什么 2/15 红，查一下" |
| **E 全局整改** | 已经拍板要动全局规则/跨对象 | 整改目标；边界（不许碰什么） | 今天的"changelog 全系退役"就是 E 类 |
| **F 流程复核** | 怀疑"之前说完成"的事没真完成 | 要复核哪笔事务/哪个结论 | "复核 CHANGE-015 是否真完成" |
| **G 生产视频** | 正式做片 | 对象片/行业/预授权/可选项 | g11-烧烤重建 |
| **H 修小问题** | 单点、明确、不动规则 | 问题一句话 + 位置；声明"发现升级就停线" | "AI工作启动指令.md 不在 ref-registry 扫描面，修一下" |
| **I Remotion** | 内容/分镜已批，只写工程 | 哪条片；有没有新增组件要求 | "g10 的 R9 视觉卡已批，做工程" |
| **J 证据复核** | 交付/关闭前的最后一道人查 | 要复核的对象；证据清单在哪 | "018 关闭前证据复核一遍" |
| **K 评估想法** | 有个念头，先看代价不动手 | 把想法写完整；别附"执行吧" | "抖音能不能也发图文？"（今天真实案例） |
| **L 全局审计** | 定期体检，找第二 Owner/口径漂移 | 关注重点（可留空全查） | "月底来一次全局审计" |
| **M 战场侦察** | 复杂任务前置：建全局认知+排兵 | 本次范围 + 预授权 + 要它重点观察什么 | 2026-09-17 上午那次 + g11 重建前 |

## 五、完整示例

### 例 1 · 最日常的一条：修一个明确问题（场景 H）

直接把下面整段发给 AI（H 模板逐字 + 末尾定制）：

```text
先读取 `promotion/AGENTS.md`（唯一 AI 入口 / Owner 地图 / 全局纪律）；再读取 `promotion/AI工作启动指令.md` 的 §〇~§四 与 §十八、§十九。本场景只是其中一个工作模式；公共协议与停线交接规则一律按上述章节执行。

现在只修一个已经明确的问题。

先确认：
1. 问题是什么；
2. 当前唯一 Owner 是谁；
3. 要修改的当前产物在哪里。

只修改解决这个问题必需的文件。
不要顺手整理其他文档。
不要修改全局规则。
不要趁机重构无关代码。

如果你发现这个问题实际上涉及流程、共享组件、跨行业规则、多个 Owner 或多个入口：
按 §十八 A 类停线并报告"这个问题已经升级为全局变更"，不要继续局部打补丁。

修复后必须运行对应验证，并报告修改了什么、验证了什么、结果是什么。

【任务定制】
问题：`AI工作启动指令.md` 没有登记进 `scripts/ref-registry.json` 的 extraDocs，
导致它整体不在文档引用闸门的扫描面（这是 2026-09-17 挂账的已知盲区）。
预期：登记后 `check-doc-references` 应能扫描到它且不新增断链红。
```

### 例 2 · 有个想法先探路（场景 K）——"抖音图文"的正确打开方式

K 模板照抄，定制段：

```text
【任务定制】
我的想法是：抖音除了短视频，也发"图文"帖子（单图+背景音乐的备忘录风教程，
竞品账号已验证）。评估：这算不算口径变更、该落在哪个 Owner、要动哪些文档。
```

AI 会回报"这是平台口径变更 → 落 SKILL → 走 R8"，**你说"执行"后它自己建契约**——不需要你再发 E。

### 例 3 · 复杂任务两步式（M → G）

见 2026-09-17 16:03 给你的 g11 重建示例（M 定制范围 → 拍板 → G 模板+任务定制块）。要点：**M 阶段把预授权写清楚**（哪些红是任务目标、哪些现场拍板），避免 AI 在"红灯禁开工"上卡死。

### 例 4 · 只想让 AI 解释文档（§〇 只读模式）

不要用场景块！只要表述是"纯阅读"，就不进执行协议：

```text
只读不执行：给我解释一下 AI工作启动指令.md 的 §十八 三类停线分别怎么应对，
读完等我下一步指示。
```

（关键词：**"只读不执行"** + "读完等指示"。AI 不会读 AGENTS、不会跑 Gate。）

## 六、AI 停下来找你时，怎么回（§十八 三类）

**一句话总纲**：AI 不会自作主张——方向/审美/发布必须你拍板；发现"事实和你给的预期相反"必须停；拿不出完成证据不许说完成。三类对应这三种情况。

| 类型 | 大白话 | 长什么样 | 真实案例（2026-09-17 你亲历的） | 你怎么回 |
|---|---|---|---|---|
| **A 停线** | **红灯**——事实和预期相反，继续改会越改越糟 | "发现结构性冲突（第二 Owner / 事实与契约相反…），停止修改" | 上午侦察发现：有人删了 changelog，但之前的契约白纸黑字写"保留"——**契约说 A、事实是 B**，AI 没继续修，停下来报告 → 你拍板"退役吧，更新引用"，才有了后面的收口 | 看它报的冲突事实，二选一：**给新方向**（"退役吧"）或**改任务范围**。**不要说"继续"** |
| **B 交接** | **等签字**——不是出问题，是走到必须你决策的点（方向/审美/发布是宪法规定 AI 不能替你定的） | "列好选项＋影响＋建议，等你拍板" | 全天十几次：① changelog"恢复 vs 永久退役"；② 图文线"定 A 还是 B"；③ 关事务前的"要不要关"——你回"退役吧 / 定 A / 都处理掉 / 关"，全是标准回应 | 一句话决策："选 1" / "按你的建议" / "改用 XX" |
| **C 证据不足** | **缺材料**——活干完了，但"完成"还差一块拿得出的证据 | "动作做了，但还证明不了完成" | 011/012 最初卡在"NOT CLOSED——缺 GitHub CI 运行记录（本地拿不到）"→ 你拍板"不用管 CI"→ 口径改成等价重现 → 证据补上才关闭 | 二选一：**"补做取证"** 或 **"接受缺口并记录"**（像放弃 fresh CI 那次，是把口径改掉，而不是硬说完成） |

**给程序员的类比**：A ≈ CI 硬失败（build 挂了必须先修，跳过 = 掩埋地雷）；B ≈ code review 等你 approve（流程规定等人，不是卡壳）；C ≈ 功能写完但验收环境跑不了（挂起，不许谎报通过）。

## 七、常见误用（2026-09-17 真实踩过/差点踩的）

1. **只说"帮我看看 promotion"** ——不选场景，AI 行为不可控（可能只读、可能自己选场景）。想要确定行为，永远发场景块。
2. **把定制写进模板中间、或顺手改模板句子** ——定制一律加在**末尾**的【任务定制】段。
3. **一条消息塞多个任务** ——一次一场景一任务；第二个任务等第一个收口。
4. **AI 停线后硬推** ——§十八 A 类停线说明结构性事实和你的预期相反（d896110 删 changelog 就是这类），硬推会放大损失。
5. **新会话忘了选工作空间** ——启动指令首句自带"读取 AGENTS.md"，但 WorkBuddy 会话要先指向 `~/Desktop/baijiang/quandao` 工作空间，记忆和文件路径才自动对上。
6. **会话工作空间会被重置** ——临时文件放这里可能丢（本指南原放会话工作空间被清掉一次）；个人长期资料放 `quandao/.workbuddy/` 下更稳。

## 八、一页速查（记这四句就够）

```text
1. 动手做 → 找执行场景（G/H/I/E）；拿不准复杂度 → 先 M
2. 只看不改 → D 调查 / K 评估 / L 审计 / F·J 复核 / B 选题
3. 复制「发给 AI」整段 + 末尾【任务定制】；模板句子不改
4. AI 停线 = 给拍板，不是催它继续
```
