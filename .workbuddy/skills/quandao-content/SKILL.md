## 一、项目定位与边界

- 面向实体店的**免费**电子券工具（制券→发券→领券→扫码核销→统计，支持企微自动发券）；运营主体：郑州百桨数字科技。
- 当前只做**宣传推广线**（获新商户）。教程线、客服线、公众号等宣传发布渠道均已移除，不在宣传线范围（此为发布渠道口径，与产品功能无关）。
- 无真实案例：正文中一律用**行业泛称**（咖啡店/火锅店/美容店等）指代，不编虚构店名、不编数据。

## 二、铁律红线（唯一真源，AI 必守）

> **分级原则（重要）**：本 §二 只列**不可突破的合规铁律**（§2.1 内容合规 + §2.2 限流红线，违者=封号/限流/虚假宣传，是底线）。**渠道策略、时长基线、画风模型不在此列**（见 §三，属设计基线而非铁律）。**纯风格/审美偏好（配色、UI 元素等）不单列规则**——既不禁止也不提倡某色/某元素，AI 在合规前提下自由发挥即可。规矩越多越束缚设计，请让风格回归 AI 的常规设计判断。

### 2.1 内容 · 品牌合规
1. **不虚构功能**：无在线支付/收款、无短信验证码领券、统计无趋势图、券包/次卡仅私密发放、无在线预约、核销=商家扫顾客、无会员积分、无第三方对接、企微群发需人工确认。
2. **不编案例与数据**；数字以 `docs/internal/00` §6 为准（随机金额券区间 = 1–99 元）；禁极限词；宣传**不提「审核」**。
3. **核销活码不在宣传中使用**（2026-08-17 决策）：核销卖点只讲「扫码核销、手动输码兜底」，不提 5 分钟刷新/防截屏等活码特性。
4. **小程序码仅限微信生态**；小红书/抖音/搜狐严禁小程序码及任何微信系二维码。
5. **画面/图片不显示平台品牌**：截图/封面/视频均不得带微信等平台品牌 logo/水印；「券到卡包」作为结尾署名可轻显示（不得做常驻水印/角标/大号 logo 式铺满），且绝不得点名微信生态。
6. **文字不凸显品牌名**：视频与文章的所有发布文案（旁白、分镜、封面文案、正文、须知）一律禁用——①「微信搜索/微信里搜」导流（含微信搜券到卡包等同义）②「微信小程序/小程序」点名微信生态；**「免费使用」可说，但不着重强调**（可作为事实卖点轻提，不堆促销意味、不承诺永久免费，见 07 §3）。合规保留：仅「置顶评论/主页简介/私信自动回复」这类平台资料位可放「微信小程序+搜索引导」；企微发放功能作为核心宣传卖点，但对外（含资料位）一律不直接提「企业微信/企微」字样，只用功能泛称描述（如「加好友自动发券」「进群自动弹券」）。视频与文章正文绝不出现微信搜索/小程序/企微类文案（「免费使用」可轻提、不乱用）。

### 2.2 三平台限流红线（核心诉求=不被限流、拿更大推荐）
7. **站外导流零容忍**：微信/小程序/搜XX/VX 等暗语，平台 AI 语义识别，一次降权、多次封号。→ **抖音/小红书/搜狐正文与视频绝口不提微信/企微/小程序**。企微发放功能可作为核心宣传卖点，但对外（**含账号资料位**）一律不直接提「企业微信/企微」字样，只用**泛称描述能力**（如「加好友/进群自动发券」「顾客扫码加你好友就收到券」），不点名微信生态。
8. **AI 内容标注**：平台要求 AI 生成内容（含 AI 配音）须标注；当前 G02 视频/封面按用户 2026-08-15 决策暂不加「AI 技术制作」角标，待浏览效果评估后再定是否恢复。
9. **软种草 >> 硬广**：带明显导流外链的视频自然推荐低约 62%。做「痛点+玩法干货+价值」，结尾不硬推关注/收藏（内容打动商家自然收藏），更绝不「去领券/去搜/下个视频」。
10. **同质化严打**：相似度 >25% 压流量池；多行业/多选题须做风格差异化（见 §六）。
11. **完播率生死线**：抖音完播 <15% 十分钟停推；前 3 秒强钩子。单条 ≤200s 均合规，以把当前设计点一次讲透为准，不强压 40s 内，更不得为凑时长硬切「下个视频」钩子；靠强钩子+高信息密度+节奏保完播，而非靠压短时长。

## 三、核心视频模型（代码驱动 UI 组件 + 三平台 + 9:16 单画幅）

> **视频模型基线（分发 / 时长 / 画风，非合规铁律，属设计基线）**：
> - **抖音唯一短视频主阵地**；视频号仅作微信生态品牌承接位，**不做宣传内容发布**（企微功能宣传统一在三大平台用泛称进行，不借视频号平台发布）。
> - 单条 **≤200s**：以把当前设计点一次讲完整为准，不强压 40s 内（完播率红线见 §二 第 11 条，靠内容节奏保完播而非压短）。
> - 画面元素自由组合（代码 UI 组件 / 项目商用字体 / SVG 内联图标 / 关键字大字标题 / 可选纹理底纹，均可增删重组），**创意不锁死**；仅遵守 §二 硬红线（不虚构功能、不编数据、禁小程序码、软种草等）。**当前制作不使用截图素材、不显产品 UI、不靠 AI 生图做主视觉**（非永久约束，未来如需用先对齐）。
> - **视觉配色/元素以设计稿为唯一真源**：AI 不得自行建议或使用设计稿未规定的颜色；设计稿须显式锁定每个画面的色值（见 `outputs/gXX-行业/设计稿.md` 的「配色/字体方案」段），未确认配色不得开渲；代码颜色用设计命名常量（如 `GREEN`），禁止 `BRAND` 类暗示品牌注入的命名（redlines 已机械守卫）。

- **推荐创作元素（非固定组合）**：① UI 组件（Remotion 代码绘制：卡片/对比面板/流程图节点/数据指标卡/列表/要点）② 项目商用字体（排版层级，已 bundle 进 `video/public/fonts/`）③ SVG 内联图标（自绘业务图标，单色描边）④ 关键字（从口播稿提取的金句/痛点词，大字标题传递核心信息）⑤ 纹理底纹（可选，来自 `图标素材/图鱼素材/`）。以上为起点工具箱，AI 可自由增删、重组、引入新元素；**主视觉由代码 UI 组件承载，AI 生图原则上不用于主视觉**（质感不可控、与代码 UI 风格不统一）。
- **三平台宣传类型**：
  | 平台 | 形式 | 画幅 |
  |---|---|---|
  | 抖音 | 短视频（唯一主阵地） | 9:16 |
  | 小红书 | 图文笔记（不发视频） | 封面 3:4 裁切中间区 |
  | 搜狐 | 图文文章（长文攻略） | 文章 16:9 头图（创客贴+素材库生成，非 Remotion 视频） |
- **Remotion 单画幅**：注册 9:16 单一 `<Composition>`（1080×1920，FPS 30）；字号/间距基于固定画幅的绝对 px（vmin = width/100 = 10.8px 可作等比换算基准），保证多行业变体比例一致。视频只发抖音。内容配音同一套。

## 五、生产 SOP（AI 做 / 人做）

### 5.0 设计稿先行（规划阶段 · 渲染前必做 · 本单元唯一真源）

> **核心原则**：任何渲染/合成前，必须先产出本单元的 `outputs/gXX-行业/设计稿.md`，它是**视频（Remotion）+ 文章（搜狐图文）+ 封面**三者的视觉与内容唯一真源。先规划、后执行，从根上杜绝「文档/代码/画面口径不同步」（曾踩坑）。

**流水线顺序（不可省，完整步骤见 12-SOP §三）：**
1. AI 产出 `设计稿.md`（按下方六段结构）
2. 人审查设计稿（封面制作包 + 验收清单打勾，含口播稿文字量是否匹配 dur）
3. 封面制作：AI 先从 `背景素材/` 索取合适模板/素材（含自行检索到可直接用的命名模板）；**库内无合适模板时，AI 须输出「详细引导」**：给出检索词/尺寸规格/风格要点/版权需可商用，手把手说明用户如何到创客贴等优秀设计网站查找制作；用户据此制作回传 PNG 后 AI 核对合规收口。
4. 视频背景图：每条视频配一张行业专属背景图（B 方案，见 13 §3.3），全片共用作为氛围底层。设计稿阶段输出「找图关键词 + 选图标准 + 放置路径」引导，人选取后复制到 `video/public/backgrounds/gXX/bg.jpg`。处理方式：模糊 30px + 30% 透明度 + 主色渐变蒙版。
5. 后续步骤（代码执行、TTS、渲染、发布）见 12-SOP 步骤 5-11

**`设计稿.md` 结构（单一统稿，6 段）：**
1. **元信息**：单元编号/名称、平台、画幅、时长上限(≤200s)、关联指针。
2. **封面图规范**：定位（未播放态缩略图，≠ 第一帧，可独立构图、更海报化）；首帧复用封面 hero 视觉（同背景/主视觉/标题，可加动效延续，不必逐像素等于封面，共用同一 hero 视觉语言）；来源流程（2026-08-17 统一）：**AI 先从 `背景素材/` 索取**合适模板/素材，库内有合适模板直接用；**库内无合适模板时，AI 输出「详细引导」**——给出检索词/尺寸/风格/版权要求，手把手指引用户到创客贴等优秀设计网站查找制作，用户回传 PNG 后 AI 核对收口；**不 AI 生成**（AI 负责找素材与出引导，不负责把封面做出来）；构图铁律（标题居中留白）；发布提醒（抖音手动设封面并关自动同步、小红书 3:4 裁切中间区）。
3. **视频分镜详规**：每屏含——时间码 / 口播逐字稿 / 画面显示什么 / 如何显示(布局·组件·字号·位置) / 配色(锁值) / 动画细节(进·出场·转场+缓动+时长) / 关键字大字 / 声画同步点；一次讲透，无「下个视频」。
4. **配色/字体方案**：显式锁定全部色值与商用字体（命名常量用 `GREEN` 等，禁 `BRAND` 类品牌色命名）。
5. **背景图引导**：视频背景图的找图关键词、选图标准、放置路径（行业专属背景图 B 方案，见 13 §3.3）。
6. **文章内容**：搜狐图文全文（绝口不提微信搜索/小程序，导流仅限账号资料位），头图用封面（搜狐 16:9 版），正文截图配图从 `截图素材/` 速查表选取（见 11 §1）。
7. **分平台适配 + 验收清单**：单帧画面确认项（布局/配色/动画/节奏/封面与首帧连贯）。**设计稿审查清单（2026-08-18 补充，必须打勾）**：
   - □ **内容深度**：视频只讲 ≤2 个核心功能，无"功能罗列"（每屏换一个功能）——如果某屏主题与上一屏无关，判定为功能罗列，须删减
   - □ **叙事递进**：场景之间有叙事推进关系，而非"换个功能再讲一遍"
   - □ **叙事结构差异**：场景类型序列与已有行业视频至少 3 个位置不同，非"换行业词照搬结构"

**四条纪律（写进规范，非待确认项）：**
- **流水线铁律**：口播逐字稿在设计稿阶段定稿，文字量按 4-5 字/秒校准 → 代码执行（dur 从设计稿取值）→ TTS 自然语速生成（禁止 atempo）→ 一次性渲染成片。设计稿是最终权威，TTS 验证语音时长匹配 dur。
- **文档边界**：设计稿规定 What（显什么/何时/配色/动画意图），不规定 How（具体代码）；实现受阻在设计稿批注可行性、不停滞。
- **事实查证纪律**：所有涉及产品功能的描述、数字、术语，必须以 `docs/internal/00-产品事实表.md` 为唯一事实依据。策划阶段选卖点/找切入点翻 `05-内容弹药库.md`，写教程/讲步骤查 `02-业务流程.md`。禁止自行脑补功能、编造数字、误用术语。
- **沉淀纪律**：每个行业单元交付完成后必须做生产回顾并回写 09 最佳实践库。交付完成 = 视频 + 文章 + 四件套 + 生产回顾笔记 + 09号库更新。**缺回顾 = 任务没做完，不得宣布"完成了"**。

### 5.1 生产步骤（按序执行）

1. **风格情报（新行业 / 新选题首做时必做）**：搜索 2–3 个源做"站在巨人肩膀上"的参考挖掘——优先抖音/小红书同赛道爆款 + 站酷/花瓣 + 创客贴/Canva 模板库（少看 Awwwards/Behance 作品集风，与短视频调性不匹配）。产出一份**风格 brief**：① 参考方向（配色/构图/转场灵感）② 明确**避开项**（已被用滥的雷同套路）③ 关键词集（喂 Remotion `theme`）。**只借鉴不搬运**：参考思路落到自有代码 UI 组件与动画，绝不盗用具体成片（版权 + 同质化双坑）；情报仅补"风格"，主素材仍来自 `商用字体/图标素材纹理/代码 UI 组件`（AI 生图仅作补充，经人确认入库）。
2. **选题**：按 12-SOP 步骤 1 动态调研定行业与角度（原 06 选题库已归档）。
3. **写脚本/口播稿**：口播逐字稿与每屏布局已在 §5.0 设计稿.md 规划（含时间码、配色、动画细节、声画同步点）；本步从设计稿提取执行。结构参考：Hook(0–3s 静音可懂) → 痛点(3–10s) → 解法软种草(10–20s) → 价值点(stagger) → CTA(末 3–5s，屏幕≥5s)。行业泛称、不编数据。
4. **提取每屏 UI 组件布局 brief + 关键字**：每屏 UI brief 已在 §5.0 设计稿.md 段3 产出；本步从设计稿提取关键字（金句/痛点词），按设计稿锁定的布局/组件/字体配置执行；AI 生图不用于主视觉（仅当代码 UI 不足以表达情境时作补充，经人确认入库）。
5. **TTS 语音合成（验证环节）**：豆包 `seed-tts-2.0`，`speech_rate=0` 常速；先出 5-10s 样片（**选信息密度最高的一屏**，含数字验证）由人确认语速，再逐屏合成全片。**数字统一写中文**（如"三天"非"3 天"）。**禁止 atempo 调速**。用 `getAudioDurationInSeconds` 获取精确时长，偏差 ±5% 内正常，超出微调 dur。**单屏音画预览**：每屏 TTS + still 帧拼 1-2s 快速预览，人耳确认节奏。**成片渲染后盲听全片一遍**（不看画面），确认无断句异常、无卡顿。
6. **成片渲染（含音频）**：`npx tsc --noEmit` → `npx remotion render`。整片时长 = 设计稿总时长，声画帧级同步。**执行渲染命令前必须前置 `NODE_OPTions=""`（见 §七硬执行约束），否则 WorkBuddy 的 safe-delete 钩子会中断渲染。**
7. **人确认成片**：确认画面质量 + 语音同步 + 整体节奏。不通过 → 分情况回退：画面/动效问题改 data；语音/节奏问题回审设计稿调整口播稿。
8. **发布（人）**：抖音发视频、小红书发图文笔记、搜狐发图文文章；发布动作由人执行。
9. **生产回顾与沉淀（强制 · 交付必要条件）**：
   - **触发**：成片人审通过、交付完成后，AI 主动发起，不等人催。
   - **回顾模板（5 项必答）**：①做得好的 ②踩坑的 ③用户反馈 ④待验证假设 ⑤可沉淀资产（详见 12-SOP 步骤 12）。
   - **三个沉淀去向**：金句/结构/踩坑 → `09-最佳实践库.md`；功能事实 → `00-产品事实表.md`；红线/CTA/SOP 变更 → 本 SKILL + 对应 docs。
   - **过程归档**：完整回顾笔记存 `outputs/archive/{日期}-gXX-生产回顾.md`。
   - **交付完成 = 视频 + 文章 + 四件套 + 生产回顾 + 09号库更新**，缺回顾 = 任务没做完。

## 九、协作分工（AI / 人）

### 9.1 AI 角色定位

**AI = 策划者 + 设计者，不是执行者。**
- 用户给方向，AI 拿方案；用户说感觉，AI 拆成落地动作
- 用户说"内容不够丰富"→ AI 要能拆解出具体改进点（深度/密度/真实感/数据感），而不是等用户说"加 X 改 Y"
- 主动全局思维：接到需求先想"这件事在整个体系里的位置是什么？会影响哪些环节？"，改一处，全量对齐

### 9.2 两步确认法（所有实质性改动必走）

**第一步：理解确认**
- AI 用自己的话总结用户的意思（3-5 句话）
- 问用户："我理解的对吗？"

**第二步：规划确认**
- AI 给出具体规划：做什么 / 怎么做 / 影响范围 / 先后顺序
- 问用户："按这个来，可以吗？"

两步都过了才执行。禁止"用户说一句我做一句"的零散式响应。

### 9.3 分工边界

- **AI 负责**：生产 + 自查 + 归档执行（按本 skill 与 docs）。
- **人负责**：前置资源（Key/缺图真截）+ 确认拍板（素材/语速/封面）+ 最终发布。
- 图像类（插画/封面）不自动入库，需人确认后才归档。
- 每个决策节点基于已确认文档依据回答，禁止凭印象拍脑袋。

### 9.4 决策必回写

用户拍板的任何决策、口径、规则，必须同步写进权威文档（`docs/internal/` 或本 skill），不能只停留在聊天里。今天的共识要让明天的 AI 也能读到。
