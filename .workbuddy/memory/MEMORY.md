> 「券到卡包」电子券工具内容运营项目。`docs/`=事实知识库+SOP；`applet/`=业务源码（不在本仓库）。效力：docs/00事实表 > 其余 docs > outputs。
> **记忆更新规范（2026-08-17 确立）**：所有决策、进展、口径变更直接更新本文件对应章节，不再依赖当日日志中转；当日日志（`.workbuddy/memory/YYYY-MM-DD.md`）仅作可选的过程流水，不是权威记忆。

## 1. 项目定位
- 面向实体店**免费**电子券工具（做券→发券→领券→扫码核销→统计，企微自动发券）；主体郑州百桨数字科技。
- 三大产品：优惠券(6型)/券包/次卡（次卡含 通卡·次卡·权益卡 三类型，2026-08-16 代码新增）。
- 仅宣传线冷启动，无真实案例，正文用行业泛称（咖啡店/火锅店等），不编具体店名/数据。

## 2. 铁律红线（完整真源=quandao-content skill §二；冲突以 skill 为准）
- 不虚构功能（以 applet/ 代码为准）、不编案例数据、数字以 00§6 为准、禁极限词。
- 分平台 CTA：三平台文章/视频绝口不提微信/小程序/搜索，导流仅限账号资料位；禁小程序码。
- 企微泛称红线：企微发放功能作为核心宣传卖点，但对外（含账号资料位）一律不直说「企业微信/企微」，只用功能泛称（加好友/进群自动发券）；视频号平台不做宣传发布（仅品牌承接位）。
- 当前**视频主视觉**不使用截图、不显真实产品 UI，主视觉=Remotion 代码 UI 组件+项目商用字体+SVG自绘图标；**文章配图**可使用截图素材（2026-08-19 恢复，用于小红书/搜狐文内功能示意，发布前裁剪微信元素）。
- 配色以分镜规划(设计稿)为准，AI 不得自定颜色；代码用设计命名常量(GREEN等)，禁 BRAND 类品牌暗示命名。
- 抗同质化(风格轮换)、保完率(≤180s，前3s强钩子，一次讲透不硬切"下个视频")。
- (2026-08-17 决策)「免费使用」可说但不着重强调，不堆促销/不承诺永久免费；收尾 CTA=自然收尾，不硬推关注/收藏，可轻署「券到卡包」；宣传文档在 quandao/promotion、业务代码在 quandao/applet（分开）。
- (2026-08-17 决策) **核销活码（5分钟刷新/防截屏）功能不在宣传内容中使用**——产品真实功能保留在 00 事实表备查，但对外文案/视频/选题/卖点一律不提；核销卖点只讲「扫码核销、手动输码兜底」。
- (2026-08-17 决策) **视频设计稿工作流确立**：AI 按 13 §5 模板产出帧级设计稿（含图片素材 8 字段规格表），人审确认后，人按规格表到设计平台找图（不用 AI 生图），AI 再写 data/gXX.ts 执行。13 为 Remotion 技术唯一源（动画硬规则/设计稿模板/风格五维状态/组件规格）。
- (2026-08-18 决策) **G02 CTA 口径拍板**：结束语统一为「券到卡包，再小的门店也可以制作电子券」，无「免费/关注/收藏/进主页」等导流或促销词，纯品牌署名收尾。此口径适用于 G02 视频 S5、攻略文章文末署名、四件套封面文案包；后续行业视频可参考此「品牌名 + 一句价值主张」的 CTA 范式。

## 3. 关键事实与缺口
- 次卡发放需平台审核通过(auditStatus)方可发放(硬阻断)；券包仅展示审核警示标签、发放不受阻断；优惠券无审核。审核属平台合规机制，宣传一律不提。(2026-08-16 校正)
- 券包/次卡仅私密发放，无公开领取；统计无趋势图表；无支付/收款/会员积分/在线预约/第三方对接；企微群发非全自动。
- 公众号/客服等真实能力曾从 docs 移除(用户决策)；如需对外提及须先回查 applet/ 代码确认。

## 6. 经验沉淀

> 从每次生产和讨论中提炼的可复用经验。更完整的内容见 `docs/internal/09-最佳实践库.md`。
> 这里放最核心、最高频的「一句话经验」，新 AI 接手快速建立感觉。

### 内容生产心法
- 做内容不是功能罗列，是**场景 + 痛点 + 解法**的叙事
- 前 3 秒必须出钩子，用具体场景比抽象提问更抓人
- 视频 30-40 秒最佳，讲透一个点比铺十个点强
- CTA 走品牌署名路线（"品牌名 + 一句价值主张"），不硬推

### 风格审美偏好
- 背景用行业专属图（B 方案）：模糊 + 低透明 + 渐变蒙版，有氛围不抢戏
- 不要任何角标编号（SLIDE xx/xx 类）
- 文字是主角，视觉是骨架，不搞花哨装饰
- 每条视频独立设计，风格五维 ≥3 维不同，避免模板感

### 协作效率
- 先出文档确认再生产，两个确认节点（文档审 + 成片审）
- 设计稿写到帧级，代码阶段只管实现
- 改任何事实/口径，全量对齐所有引用文档，不留尾巴
- 红线闸门最后统一跑，零命中才算过

- **记忆更新**：所有决策/进展/口径变更直接更新 MEMORY.md 对应章节，不依赖当日日志中转。
- **决策回写权威层**：用户拍板须同步写 docs/ 或 skill，不只留记忆(.workbuddy/ 其他 agent 读不到)。
- **产物保留 vs 规范清理**：已生成的视频/图片等产物必须留档(命名清楚供对照)，规范文档错误则删改。
- **意图落盘三原则**：原话优先；落盘前回读确认；推断标(待确认)。
- **参考图吸收精髓**(非读一下完)、**本地资源优先+向外找优秀模板**(站酷/Pixso/Dribbble等)。
- **环境/删除操作先列清单向用户确认**再执行。
