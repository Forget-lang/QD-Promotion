> 版本：1.0 验证版
> 完成日期：2026-08-19
> 架构阶段：1.0 验证片（2.0 标准为 8-10 屏 / 120-150s / 6 信息单元）

## 1. 做了什么

**基本信息**
- 业态：茶饮咖啡（咖啡店）
- 核心玩法：闲时填空档 + 转赠裂变（时间线叙事型）
- 屏数：7 屏（hook / pain / solution / flow / grid / panel / cta）
- 时长：52.6 秒（1578 帧 @30fps）
- CTA：「券到卡包，再小的门店也可以制作电子券」

**风格五维**
| 维度 | 取值 |
|---|---|
| palette | warm-orange |
| motion | snappy |
| transition | slide |
| typography | friendly |
| hookStyle | question（时钟场景型） |

**技术实现**
- 架构：Remotion 代码 UI 驱动，数据在 `data/g02.ts`，组件库在 `components/` + `scenes/`
- 场景积木：9 种（hook / pain / solution / flow / grid / panel / cta / timeline / transfer）—— 初期 7 种，后扩充 timeline 和 transfer
- 声画同步：J-cut 转场同步法（上句淡出 + 下句满音量进入），voiceOffset=0，一次出片零调试
- 特色组件：TimelineScene（客流曲线 SVG 绘制，Catmull-Rom 平滑）、TransferScene（转赠飞卡 spring 动画）、HookScene clock 型

**视觉方案**
- 背景图：B 方案（行业专属图 + 15px 高斯模糊 + 55% 透明度 + 场景背景色半透明叠加）
- 品牌记忆锚：品牌署名「券到卡包」+ 语义色体系 + 字体家族 + 底部字幕
- 移除元素：SlideTag 进度指示器（SLIDE XX/XX），用户评审后要求移除

**叙事主线**
下午 3 点咖啡店空座 → 闲时客流浪费的痛点 → 闲时券填空档 → 转赠裂变带来新客 → 数据看板看效果 → 品牌收束

## 2. 哪些地方效果好（验证了什么假设）

**验证通过的假设**

1. **时间线叙事型结构有效**：从具体场景（下午 3 点的咖啡店）带入，痛点 → 解法 → 升级玩法 → 数据 → CTA，层层递进，叙事流畅。用户认可"场景带入比空泛讲道理好"。

2. **J-cut 声画同步方案一次到位**：TTS 自然语速生成 + ffprobe 测时长 + 公式算 dur，不需要反复调试语速，首字不丢、尾音不爆、节奏自然。验证了"设计稿驱动 + J-cut = 零调试出片"的可行性。

3. **Remotion 代码 UI 能达到专业质感**：纯代码绘制的 UI 组件（卡片/流程/数据面板/客流曲线/转赠飞卡）视觉效果超出预期，不需要 AI 生图做主视觉，风格统一可控。

4. **warm-orange 暖橙色系与茶饮咖啡行业高度适配**：暖色调与咖啡/茶饮的行业氛围天然契合，用户一眼认可。

5. **行业背景图 B 方案显著提升质感**：从 A 方案（纯渐变 + 噪点）改为 B 方案（行业图 + 模糊 + 蒙版）后，画面有了行业代入感和氛围层次，不再像"模板视频"。

## 3. 哪些地方踩坑了（具体问题 + 怎么解决的）

| 编号 | 问题 | 原因 | 解决方式 |
|---|---|---|---|
| E-001 | 左上角 SlideTag 进度指示器多余 | 初期设计加了 SLIDE 01/07 角标，用户评审后觉得像 PPT，破坏沉浸感 | 直接移除 SlideTag 组件，后续视频不再加 |
| E-002 | 字幕遮挡画面内容 | 加字幕后发现底部内容太靠下，与字幕重叠 | 建立底部 160px 字幕安全区规范，内容控制在 y:120-1760 活动区内 |
| E-003 | 背景图 A 方案渐变蒙版不可见 | 纯渐变 + 噪点纹理太素，画面没层次，行业感弱 | 改为 B 方案：行业专属背景图 + 模糊 + 降透明 + 场景色半透明叠加 |
| E-004 | 初期音画不同步 | 早期用 atempo 调速 + 经验值估 dur，反复调试还是不同步 | 改用 J-cut 方案：TTS 自然语速 → ffprobe 精确测时长 → 公式算 dur → 一次出片 |
| E-005 | 功能描述容易越界 | 写文案时不自觉脑补功能细节 | 建立"写文案必查 00 号事实表"的规矩，任何功能描述找得到依据才能写 |
| E-006 | 不同文档口径不一致 | 改了一处忘了同步其他地方 | 建立"全量对齐"规则：改动前自查影响范围，改完逐一核对 |

## 5. 下次怎么做更好（可复用经验）

**内容层面**
1. **信息量升级**：G02 作为 1.0 验证片只有 7 屏 52.6s，信息量偏薄。2.0 标准提升到 8-10 屏 / 120-150s / 6 个信息单元，内容要讲深讲透，不能只提一嘴。
2. **玩法要更具体**：从"讲功能"升级为"讲一套完整玩法"，有具体场景、有步骤、有为什么有用，让老板看完想说"这招我也能用"。
3. **钩子再狠一点**：前 3 秒必须抓住人，可以用数字冲击、反常识、灵魂拷问等方式，不要慢悠悠铺垫。

**技术层面**
1. **J-cut 方案标准化**：所有新视频默认采用 J-cut 声画同步法，TTS 只生成一次，不需要先出样片确认语速。
2. **行业背景图 B 方案标准化**：每条视频配一张行业专属背景图，模糊 15px + 55% 透明度 + 场景色半透明叠加，作为氛围底层。
3. **组件库持续扩充**：G02 验证了 9 种场景积木的可用性，后续根据新行业需求按需扩充（calendar / map / before-after 等），不提前造轮子。
4. **设计稿写到帧级**：动画时序必须精确到帧（组件名 + delay + duration + easing/motion），不能模糊描述，否则代码实现时会有偏差。

**流程层面**
1. **两步确认法**：设计稿确认 + 成片确认，两个节点走到位，避免返工。
2. **本地素材优先**：做设计稿先检索本地素材库（背景/图标/插图），有合适的直接用，省找图时间。
3. **红线闸门必跑**：内容写完统一跑 `node scripts/check-redlines.mjs`，零命中才算过。
