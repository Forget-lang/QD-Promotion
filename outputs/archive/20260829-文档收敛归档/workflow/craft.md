## 1. 内容方向锚（管"好不好看"）

> 质量标准三层结构：硬边界（`spec/redlines.json` 管"会不会死"）→ 方向锚（本章管"好不好看"）→ 创作自由（pipeline.md §5 创作自由清单管"怎么达到，AI 自己说了算"）。
> 方向锚的**闸门化量化要求**（≥6 信息单元 / ≥2 层递进 / 深度 4 问 / 各内容形式深度要求）见 pipeline.md §1.6 内容深度闸门。

### 1.1 方向锚一：内容定位是「场景化功能教学片」

**定义**：视频不是"产品宣传片"，是"场景化功能教学片"。
- 不是告诉老板"我们产品好"
- 是让老板看完觉得"这个我店里也能用"

✅ **对的样子**：
- 全程用具体行业场景说话（"咖啡店上午没人坐""奶茶店下午排队"）
- 每讲一个功能，说清楚"在哪种情况下用、怎么用、用了有什么用"
- 像同行分享经验，不像广告
- 看完老板能记住一个具体的用法，而不是记住一堆功能名

❌ **不对的样子**：
- 只罗列功能名（"我们有次卡、券包、满减券..."）
- 自夸式宣传（"最好用的电子券工具""提升效率 10 倍"）
- 全程说抽象概念，不说具体怎么操作
- 看完觉得"哦，有这么个东西"，但不知道自己能不能用、怎么用

**自检问题**：如果你是一个咖啡店老板，看完这条视频，你知道怎么用这个产品解决你店里的某个具体问题吗？

### 1.2 方向锚二：内容深度 · 三重绑定

**定义**：每讲一个功能点，必须同时讲清楚三件事：
1. **场景**：这个功能在什么情况下用（哪个行业、什么问题）
2. **操作**：具体怎么用（几步、做什么动作）
3. **目的**：用了能达到什么效果（帮商家解决什么问题）

三者缺一个，就是"浅"。

✅ **对的例子**：
> "咖啡店上午没人坐（场景），做一张早鸟次卡发给老顾客（操作），顾客提前付钱，上午也有稳定收入（目的）"

> "想拉新客到店（场景），做一张满减券公开领取（操作），附近的人领了券就会想来用掉（目的）"

❌ **错的例子**：
> "我们有次卡功能"（只有功能，没有场景和操作）
> "次卡可以提升营收"（只有目的，没有场景和操作，也不知道怎么做到）
> "次卡就是可以用很多次的卡"（只有定义，没有场景和目的）

**自检问题**：我讲的每个功能，是不是都讲清了"在哪用、怎么用、用了有啥用"？

### 1.3 方向锚三：说服力 —— 讲怎么做，不是喊口号

**定义**：让商家觉得"这个靠谱"的方法，是讲清楚操作路径，不是喊口号。
- 不说"效果很好"，说"发了多少张、用了多少张，后台看得见"
- 不说"操作简单"，说"3 步做一张券，手机就能操作"

✅ **对的说法**：
- "3 步做一张券：选模板、填信息、发给顾客"
- "顾客到店出示二维码，店员扫一下就核销了"
- "不用安装、不用设备，有手机就能用"

❌ **不对的说法**：
- "操作非常简单"（口号，没说怎么简单）
- "效果非常好"（口号，没说怎么个好法）
- "功能非常强大"（口号，空的）

**自检问题**：我说的每一个"好"，有没有具体的东西支撑？还是只是形容词？

### 1.4 方向锚四：节奏 —— 信息密度要高，不能水

**定义**：每一秒都要有信息，不能为了凑时长说废话。好的视频是"全程都是干货"，不是"前面铺垫半天"。

✅ **对的样子**：
- 前 3 秒直接戳痛点或抛问题，不墨迹
- 每屏讲一个完整的点，不空泛
- 转场快，不拖沓
- 看完觉得"信息量好大"，而不是"怎么还没说完"

❌ **不对的样子**：
- 开头"大家好，今天给大家介绍..."（废话，直接说事）
- 一句话能说清的事说三句话
- 重复说同样的意思
- 为了凑时长加没用的内容

**自检问题**：如果把这条视频剪掉一半，会不会损失重要信息？如果不会，说明水了。

## 2. 视觉审美标准（V-R 红线 / V-S 建议）

> 从历次用户反馈中提炼的风格偏好，指导后续视频设计。分三层弹性标准：红线必须遵守、建议择优使用、创意自由发挥。
> 操作化检查清单（逐屏打勾版）见 pipeline.md §2.7.2 美感自查；四维评分与视觉预演闸门见 pipeline.md §2.3/§2.4。

### 2.1 风格总偏好速查

| 维度 | 偏好 | 不偏好 | 来源 |
|---|---|---|---|
| 背景 | 行业专属背景图（模板图直接显示原图，blur: 0，有氛围不抢戏。详见 pipeline.md §4.2 图片使用规范·背景图显示策略） | 纯渐变+噪点纹理（太素） | 用户拍板 B 方案 |
| 角标 | 不要进度指示器（SLIDE xx/xx） | 左上角任何数字编号 | 用户要求移除 |
| CTA 风格 | 品牌名 + 价值主张（具体文案由设计稿根据视频内容定制，不硬推关注/收藏/免费） | 硬推关注/收藏/免费 | G02 CTA 拍板 |
| 叙事方式 | 场景带入 + 问题→解法→升级 层层递进 | 功能罗列、7 屏全是痛点 | G02 v2 时间线叙事获认可 |
| 视频时长 | 60-150s（按玩法复杂度自然落位：简单 60-90s / 标准 90-120s / 复杂 120-150s），上限 200s | 过短（<60s）信息量不足，过长（>200s）掉完播 | 深度标准 |
| 钩子时机 | 前 3 秒必须出钩子 | 铺垫太长、慢悠悠 | 抗划走原则 |
| 视觉重心 | 文字是主角，视觉是骨架 | 花哨装饰、喧宾夺图 | 鱼皮风格参考 |
| 信息密度 | **高密度但不杂乱**——一屏装下尽可能多的有效信息，但视觉上井然有序 | 空荡荡没内容 / 塞太满看着累 | 用户拍板 + 创可贴封面验证 |

> 注：时长、钩子时机、叙事方式的**闸门化判断**（≥6 信息单元 / ≥2 层递进 / 深度 4 问）以 pipeline.md §1.6 内容深度闸门为准；本表只作速查。

### 2.2 高密度不杂乱 · 实现手法

> 核心目标：单位时间内让商家看到尽可能多的价值点，但视觉上不拥挤、不混乱。以下 6 个手法与 §2.3 V-S 建议一一对应，写设计稿时直接对照使用。

1. **统一视觉语言** —— 全片同色系、同圆角、同字体风格（对照 V-S06：卡片/图标风格全片统一）
2. **清晰视觉层级** —— 大标题/中标题/小字/说明，字号差拉开 2 倍以上（对照 V-S04：关键词有视觉强调）
3. **网格对齐** —— 所有元素对齐到隐形网格，等距分布（对照 V-R02：内容填满上 2/3）
4. **重复元素样式** —— 图标、标签、对勾、卡片，同款样式重复出现（对照 V-S13：色彩只用在关键点）
5. **分组明确** —— 相关信息放一起，用卡片/色块/线条区隔（对照 V-S10：纵向列表视线一条线）
6. **留白呼吸** —— 元素之间有足够间距，不是挤在一起（对照 V-S12：画面填满不留大块空白）

**反例（写了会返工）**：
- 一屏只有一句话，虽然干净但信息效率太低
- 什么都想放大，结果没有重点，看起来反而乱
- 颜色超过 3 种主色，视觉噪音大

### 2.3 三层弹性标准（红线 / 建议 / 创意）

> **定位**：本标准是视频画面的"审美底线 + 方向指引 + 创意空间"。红线必须遵守，建议择优使用，创意自由发挥。
> **依据**：从创可贴设计参考图（7 张）+ 自有视频迭代经验 + 用户历次反馈中提炼。
> **更新规则**：每次出片后根据验证结果更新红线/建议，活标准；改动记 changelog。

#### 🔴 红线（不遵守就不及格，必须返工）

| 编号 | 红线 | 说明 | 反例 |
|---|---|---|---|
| V-R01 | **标题必须醒目** | 标题是全屏最大元素之一，字号 ≥ 56px，颜色深色或主色（与背景有强对比），位置要么居中要么左上但必须有存在感，不能淡、小、飘在角落看不清 | 标题白色半透明放在左上角，和背景融为一体 |
| V-R02 | **内容填满上 2/3** | 标题 + 主体内容必须集中在画面上 2/3 区域（top: 120px 到 y: 1400px），不能 3 张小卡片只占中间 40%、上下全空 | 3 张小方块挤在画面中央一条，上下各空 1/3 |
| V-R03 | **一屏一个视觉焦点** | 每屏必须有且只有一个主焦点（大数字/大标题/大图标/大卡片），所有元素围绕焦点排布，不能所有元素一样大、没有主次 | 3 张卡片尺寸完全一样，眼睛不知道先看哪 |
| V-R04 | **文字对比度足够** | 任何文字在背景上必须清晰可读，对比度 ≥ 4.5:1。模糊/看不清的文字就是失败 | 浅绿字放在浅蓝色背景上，看不清 |
| V-R05 | **相邻屏布局不重复** | 连续两屏不能用同一种布局模式（比如不能连续两屏都是"3 张卡片纵向列表"），必须有节奏感变化 | S2 卡片列表 → S3 卡片列表 → S5 卡片列表，审美疲劳 |
| V-R06 | **安全区内排版** | 内容在安全区内：顶部 ≥ 120px，底部 ≥ 160px（字幕区），左右 ≥ 80px（G03 实测：抖音发布后左右会被遮挡，60px 不足，2026-08-25 调）。**此为视频画面内容安全区；封面图另有口径（顶160/底200/左右80），见 发布弹药库 §1.5.1，两者对象不同、勿混用** | 内容贴边、被字幕遮挡 |
| V-R07 | **禁止全屏遮罩盖住背景图** | 背景图直接作为画面基底（blur: 0，显示原图），内容直接放在上面。**禁止**铺满全屏的半透明纯色/渐变遮罩把背景图完全盖住。文字看不清时用局部处理（文字加描边/投影、卡片加白底），不用全屏遮罩 | 深色渐变 + 发光光斑 + 点阵底纹铺满全屏，背景图完全看不见 |
| V-R08 | **每屏信息点 ≥ 3 个** | 不能一屏只有一句话或一个孤零零的元素撑场面 | 结尾屏只有两行字飘在中间，像半成品 |
| V-R09 | **内容屏有干货** | 方案/流程/优势等内容屏必须展示具体、可操作的信息（如卡券参数、操作要点等），不只是抽象标题+一句话描述；具体内容从 01-券组合文案提取（提取流程见 pipeline.md 步骤 3.5），设计稿按叙事需要选取 | 内容屏退化成"标题+一句话描述"，观众看完知道有道理但不知道怎么动手 |

#### 🟡 建议（择优使用，显著提升质感）

| 编号 | 建议 | 说明 |
|---|---|---|
| V-S01 | **每屏选排版参照** | 从本文 §7 排版参照库选一个匹配的参照类型，标注"参照：#X（XXX 型），借鉴了 Y 手法"，不凭空发明布局 |
| V-S02 | **至少 3 层视觉层次** | 背景层（模板图直接显示原图）+ 主体层（卡片/图标/文字）+ 装饰/强调层（高亮底条/大数字/标签/投影），三层叠加画面才有厚度 |
| V-S03 | **颜色承担信息功能** | 主色用在最重点（标题/核心数字/CTA），辅色用在次要信息，灰色用在说明文字。颜色不只是装饰，是引导视线的工具 |
| V-S04 | **关键词有视觉强调** | 重要词汇用高亮底条、变色、放大、加粗、描边等方式强调，和普通文字拉开差距 |
| V-S05 | **装饰元素少而精** | 每屏用 1-2 个装饰元素（角标/标签/大图标/分割线/底条）增加层次和填充空间，但不堆砌（全片装饰件 ≤1-2 处，见 R3-Remotion技术参考 §四 组件生长机制） |
| V-S06 | **卡片/图标风格全片统一** | 圆角大小、阴影强度、图标风格、字体字号在全片保持一致，不混搭 |
| V-S07 | **数字/数据做放大处理** | 凡是出现数字（百分比/步骤数/统计数据），一律放大做视觉焦点，配合动效（弹入/跳动/计数）增强冲击力 |
| V-S08 | **对比屏用左右/上下分色** | 痛点对比屏（传统做法 vs 新方法）用分色/分栏做强烈对比，左边冷/暗/灰（传统痛点），右边暖/亮/鲜（解法好处） |
| V-S09 | **内容多寡决定布局形态** | 左右两栏内容量不一样时，不要硬做成一样大的卡片。内容多的占主体空间（列表/大卡片），内容少的用"强调感"补分量（大字/气泡/印章/结论条），形态不同就不会有"一边空一边满"的违和感 |
| V-S10 | **纵向列表，视线一条线** | 清单/步骤/痛点类内容优先用纵向列表布局（从上到下一条线），视线不左右横跳，读起来顺。配合图标/序号/分隔线，每一条都有存在感 |
| V-S11 | **白底卡片 + 浅背景，清爽干净** | 内容放在白色/浅色卡片上，背景是浅色系（渐变/模糊底图）。对比度足够、文字清晰、整体不花哨，信息是主角而不是设计 |
| V-S12 | **画面填满，不留大块空白** | 标题 + 主体内容要把上 2/3 区域填饱满，不能上下各空 1/3、中间挤一小块。内容不够用大字号、大图标、装饰元素来撑，不能空着 |
| V-S13 | **色彩只用在关键点** | 全片颜色控制在 2-3 个色系内（主色 + 黑白灰 + 1 个强调色）。颜色用在标题、图标、关键词高亮这些"引导视线"的地方，不用颜色堆砌装饰 |
| V-S14 | **标题有"容器感"** | 标题不是飘在画面上的一行字，而是有"容器"——底色条/便签纸/顶部栏/标签框，让标题有重量感、第一眼就看见 |

#### 🟢 创意（自由发挥，鼓励创新）

| 维度 | 空间 |
|---|---|
| 特殊屏布局 | 钩子屏、结尾屏可以跳出常规布局，用大字冲击、品牌升华等创新形式 |
| 动效设计 | 入场动画、强调动画、转场方式，在 R3-Remotion技术参考 §七 制作硬规则（动画/转场规则）范围内自由设计 |
| 装饰选择 | 具体用什么装饰元素（波浪线/手绘圈/贴纸/光效），根据内容和行业自由选择 |
| 色彩微调 | 在 palette 色系范围内，可以根据场景微调饱和度、明度，制造节奏变化 |
| 新手法尝试 | 发现新的好用设计手法，验证后沉淀回本标准 |

> 用户不是设计师，只会说感受。AI 收到以下感受时，**按表翻译成可执行指令**，禁止简单化成"放大字体/放大卡片"。

## 3. 视觉层级参数表（设计生成配方，解决"只会放大字体"）

> 字号、间距、留白、色彩**按阶梯取值，禁止凭感觉给数字**。参考图里的设计，也要按本表换算成参数，而不是照抄尺寸。

**字号阶梯**（焦点数字 > 主标题 > 副标题 > 正文 > 标注）：

| 层级 | 字号 | 用途 | 约束 |
|---|---|---|---|
| 焦点数字 | 160-200px | 大数字（百分比/金额/数据） | 全屏最大，唯一可超 150px |
| 主标题 | 96-120px | 每屏标题（≤14 字） | ≥ 副标题 1.5 倍 |
| 副标题 | 56-72px | 辅助说明（≤30 字） | ≥ 正文 1.4 倍 |
| 正文 | 36-44px | 卡片内描述 | ≥ 标注 1.3 倍 |
| 标注 | 26-30px | 脚注/提示 | 最小可读，不低于 26px |

> **本表是"应然档"，已落地组件是"实然档"——填屏时以实然为准（2026-08-28 定，教训 F11）**：共享场景组件把各屏字号写死在代码里，与本表并不吻合（例：`HookScene` story 主标 80 / `PainScene` 标题色块 64 / solution·flow·usetips·cardface·panel 标题 72 / `CtaScene` 品牌名 140）。**照本表给已落地组件的设计稿写"主标 110"，渲出来必然是 72——设计稿失真、闸门 3 才发现。**
> - 给**已落地组件**填屏：字号一律取组件实测值（读 `video/src/scenes/*.tsx` 或跑盘点），与本表不符时在分镜表「组件差异说明」登记差异，**不改共享组件迁就单片**
> - 给**新组件 / 封面 / 图文**定档：按本表取值
> - 确实需要改已落地档位：走设计稿「组件改动提案」（写清改动范围 + 对已渲视频的兼容性论证），由用户拍板后才动

**层级比例铁律**：焦点元素 ≥ 相邻元素 **2 倍**（大小）+ 至少一项额外对比（颜色/明暗/位置居中）。达不到 2 倍，就**缩小相邻元素**，不是放大焦点。

**间距网格**（8px 基准）：
- 卡片内 padding ≥ 43px ｜ 卡片间距 ≥ 卡片高度 20%（保持）
- 标题与内容间距 40-60px（保持）
- 列表行间距 ≥ 24px ｜ 图标与文字间距 16px

**留白规则**：
- 标题区顶部 y:200 起；内容区 y:200-1100 集中（保持）
- **每屏至少保留 1 个"呼吸区"**（≥画面 15% 的连续空白）——高级感的主要来源
- 底部 y:1600-1760 为留白缓冲（字幕上方）

**色彩比例（60/30/10 法则）**：
- 主色（背景/大面积）≈60% ｜ 辅色（卡片/次要）≈30% ｜ 强调色（焦点/数字/箭头）≈10%
- **强调色只用在焦点元素上**；次要元素一律降饱和/降明度
- 全屏色彩 ≤3 个色系（主/辅/强调 + 黑白灰）

## 4. 一屏一焦点规则（V-R03 的可执行版）

每屏必须回答"观众第一眼看哪"，按以下规则设计：

1. **焦点选择**：该屏最重要的信息（大数字 / 主标题 / 对比中心 / 核心券面）
2. **焦点实现**：三选二——大小对比（≥2 倍）/ 颜色对比（强调色）/ 位置居中或视觉中心
3. **降级处理**：非焦点元素必须主动弱化——字号缩小、饱和度降低、透明 0.6-0.8、移出视觉中心
4. **反例**：全屏所有元素同字号同明度 = 无焦点 = 必返工

> **组件能力核对规则（2026-08-25 加，08-26 改）**：设计稿选呈现类型前，先跑 `node scripts/list-assets.mjs` 查实时组件清单（真源=代码，本表状态列仅为快照）；未实现的类型必须走 R3-Remotion技术参考 §五 扩展指南（分镜表「组件核对」字段标 new:xxx 并附规格），**禁止假装已实现**——否则编码时必然回落成通用白卡，导致"换皮同款"。

**信息密度手段（2026-08-25 定，丰富画面的途径）**：信息密度的来源是**信息组织方式**，不是"多塞卡片"：
1. **产品真实 UI 重绘**：涉及产品界面展示的屏，参考 applet 真实样式重绘（卡面/券面/表单/统计页）——真实界面天然信息密度高（速查表与换算见 R3 §5.5 产品 UI 参考指引）
2. **多层分区排版**：一屏放下多层信息（标题 + 大数字焦点 + 字段明细 + 对比/结论条），用本文 §7 排版参照库的多层分区/括号分组/大边框手法
3. **禁止"抽象卡片列表"兜底**：内容屏不得退化成"标题 + 白卡列表"（G03 骨架；由 pipeline.md §2.2 视觉观感比对拦截换皮同款）
4. **呈现手法轮换（2026-08-25 加；08-27 口径对齐规格表；08-28 计数随 R3 §5.6 扩容）**：信息组织方式用「呈现手法库」（R3 §5.6，**手法名一律取该表「手法」列原名，共 14 种，本文件不复述清单**），每屏标注手法、相邻屏不同、行业之间轮换——防连续多期"审美疲劳"（卡片是默认容器、不算手法；判定看视觉语法不看标签，全片多数内容屏同一种语法即按卡片流判不合格）
5. **重要维度原则（2026-08-25 加）**：信息密度 = 展示**对商家决策重要的维度**（经营结果 / 顾客体验 / 操作成本 / 数据透明），**不为填密度硬塞规则/口径细节**——G04 教训：转赠规则"首位领取者得卡"、核销率公式被用户否（属次要规则细节，不是重要维度）

**口播与画面分工**：设计稿需标注每屏哪些内容画面展示（不念）、哪些口播讲。
- 画面负责：展示具体内容（卡券参数/操作要点/流程链路等可截图信息）
- 口播负责：讲"为什么这样设"和"怎么操作"的关键理由
- 例：使用须知 4 条贴在画面上，口播只讲重点（"面额 20 块，30 天有效，开启转赠"），不用逐条念

## 6. 参考图拆解模板（用户给参考图时必走）

> 用户提供优秀参考（视频页面/创可贴设计）时，AI **必须按 7 项拆解并写进设计稿**，禁止"看一眼就放大字体"。

```yaml
参考图: （用户提供，可多张）
拆解结果:
  ① 视觉焦点: 第一眼看什么？怎么突出的？（大小/颜色/位置）
  ② 区域划分: 画面分几个区？各占多少比例？
  ③ 色彩分配: 主色/辅色/强调色各是什么？各占多少？
  ④ 字号层级: 最大的字 vs 最小的字差几倍？层级几档？
  ⑤ 留白位置: 哪里是空的？空多少？为什么空？
  ⑥ 质感细节: 圆角/阴影/纹理/光效？什么让画面"不廉价"？
  ⑦ 转化到本屏: 布局模式（L-XX）+ 焦点元素 + 借鉴的具体手法（只借鉴手法，不照搬）
```

**纪律**：拆解不出 7 项 = 该参考图没被真正理解 = 设计稿不达标。每屏至少 1 张参考图（或 1 条已提炼的布局模式）。

### 9.1 可复用组件 / 手法清单

| 组件/手法 | 来源 | 可复用的用法 | 落地状态 |

| 浏览器顶栏容器（BrowserHeader） | 创可贴封面 | 橙色顶栏 + 三点 + 分类标题，适合知识类/干货类视频的场景容器 | 装饰件类，不预建，按需实现 |
| 吊牌标签（TagLabel） | 创可贴封面 | 右上角倾斜的便签纸标签，增加信任感和层次感。文案必须用事实型（"手机上就能做""小门店适用"），**禁用"亲测有效"类效果见证**（见 `spec/redlines.json` `false_claims`） | 装饰件类，不预建，按需实现 |

> **装饰件纪律（拍板原则）**：封面是静态海报语言，视频化必须节制——画面主要靠排版层级和内容动效撑，不靠堆装饰件（防「会动的 PPT」感）。装饰组件**不批量预建**，设计稿确需时按需实现，**每条视频装饰件 ≤1-2 处**（机制见 R3-Remotion技术参考 §四 组件生长机制）。

### 9.2 封面与首屏衔接手法（前 3 秒接住流量）

> 核心认知：封面是流量的第一道门，首屏（前 3 秒）是第二道门。封面决定"有没有人点"，内容决定"有没有人看完"。封面和首屏必须**连起来设计**，不能各做各的。人在刷视频时判断封面只有 **0.3 秒**，大脑只处理 3 件事：**这是什么？（行业识别）→ 有什么好处/威胁？（利益点/痛点）→ 跟别人有什么不一样？（反差/好奇）**。

**4 种承接方式**：
1. **自问自答型**：封面问"下午 3 点没人怎么办？"，首屏答"试试这 3 招"—— 接住问题，给出希望
2. **场景延续型**：封面是咖啡店空座照片，首屏接着讲"下午 3 点的咖啡店，员工比客人多"—— 延续场景，加深共鸣
3. **数字开场型**：封面有大数字，首屏开口就报数字—— 强化冲击，快速进入正题
4. **反差升级型**：封面说"不打折也能锁客"，首屏说"反而赚更多"—— 把反常识进行到底

**绝对不能做**：
- 封面问 A 问题，首屏讲 B 内容 → 用户感觉被骗，秒走
- 首屏慢悠悠铺垫（logo 转一圈 / "大家好我是 XX"）→ 等你铺垫完，人都走了
