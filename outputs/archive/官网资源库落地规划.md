## 2. 官网的四个角色（定位）

| 角色 | 用法 | 采信级别 |
|------|------|---------|
| **1. 选题素材库**（主用） | 每片开工挖候选场景，延续 08 候选清单形态 | 玩法层：可借鉴，每环功能回 `spec/facts.json` / `spec/coupon-fields.json` 溯源 |
| **2. 行业认知加速器** | 进入新行业先读 `/industries/<行业>`：一句话痛点 + 推荐券卡组合，5 分钟建立行业语感 | 话术层：只作对照，必过 `spec/redlines.json` |
| **3. 场景灵感参照** | 玩法页的行业场景区（每页 3 个行业具体场景）供发散参考；**结构骨架暂不借**（B 未解锁） | 结构层：冻结待裁 |
| **4. 对账镜（单向避雷）** | 防官网越界说法流入我方内容；发现的错误只记我方台账，**不反馈官网、不产出修改建议**（A 已裁） | 断言层：**永不采信**，只认 facts/真值表 |

**官网不是**：产品能力权威来源（那是 facts.json）；文案复制来源；一次性做成"内容地图"大文档的对象。

## 4. 每片开工的官网动作（固定机制 · 自片 2 起执行）

**触发时机**：SKILL 第 1 步"定攻略"，交候选场景清单之前。

**固定阅读清单（≤5 页，顺序固定，计入五页封顶）**：

1. `/industries/<本片行业>` —— 痛点 + 推荐券卡组合
2. `/marketing/<相关玩法>` ×2~3 页 —— 按本片候选功能链选页
3. `/solutions/<行业>-NN` ×1~2 篇 —— 行业深文，看场景细节
4. 首页仅在需要跨行业玩法灵感时补读

**固定产出**（并入该片候选场景清单，不另立文档）：

- 每条候选场景标注**官网出处 URL**（08 清单已有此列，保持）
- 三态判定照旧：已证 / 表缺 / 代码无·禁用
- 新发现的官网越界/错数 → 追加本文件 §3 台账（不反馈官网）

**两条新增纪律（2026-09-02 实测得出）**：

1. **现读现挖，不信快照**：本文件与 08 清单里的官网结构记录只作历史参考，开工时以官网现网为准。
2. **「免费」口径隔离**：见台账 W5。

**实操坑沿用**：`outputs/**/*.md` 全在红线文案层扫描面内——台账与候选清单不得逐字复述站外生态词/极限词，用「站外生态词」措辞指向 `spec/redlines.json`。
