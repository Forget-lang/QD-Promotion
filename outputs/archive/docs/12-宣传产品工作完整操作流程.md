# 12 · 宣传产品工作完整操作流程（SOP）

> 本文件是「券到卡包」**宣传与运营主流程**的总操作手册，整合 00、02、04~07、10、11、13 的执行步骤。
> 当前阶段：宣传推广线冷启动（获新商户），无真实案例，正文用行业泛称。
> 任何一步拿不准，先回 `00-产品事实表.md` 核对能力边界，或标注「待确认」交人核实。

---

## 一、目标与范围

- **目标**：通过内容（文章/视频）让实体店老板知道、心动、注册「券到卡包」，完成首次制券。
- **范围**：宣传推广线（获客）+ 素材生产（代码 UI 组件绘制 / 可选插画 / 关键字提取 / 封面）。
- **暂不做**：付费投流。

## 二、角色分工

| 角色 | 负责 |
|---|---|
| AI | 选题建议、文案、券组合设计、设计稿（含背景/封面找图需求输出）、代码执行（data/gXX.ts）、无声版渲染、豆包 TTS 调用、Remotion 最终渲染、封面文案包、合规自查、归档 |
| 人 | 确认设计稿、找背景图+封面图并放入对应目录、提供 TTS Key/音色、确认无声版画面、确认最终成片、最终发布、纠偏 |

### 二.5 AI 协作准则（贯穿全流程）

> AI 是策划者+设计者，不是执行者。以下准则适用于全流程所有环节。

**1. 主动策划，不被动执行**
- 用户给方向/感觉/建议时，先拆解成具体可落地的改进方案，再跟用户确认
- 不要等用户说"加 X""改 Y"才动手，要主动想"还能怎么更好"
- 每个环节结束时主动想：下一个环节需要我提前准备什么？

**2. 两步确认法（关键节点必走）**
- 理解确认：先复述用户的意思，确认理解对了再动手
- 规划确认：给出具体规划（做什么/怎么做/影响范围/顺序），确认了再执行
- 两个确认节点：设计稿确认（步骤 4）、无声版画面确认（步骤 8）

**3. 全局一致性**
- 改动前自查 3 问：影响事实层吗？影响流程层吗？影响经验层吗？
- 改一处，全量对齐。不能只改一份文档，相关文档都要同步
- 红线类改动必须跑闸门（`node scripts/check-redlines.mjs`），零命中才算完

**4. 决策必回写**
- 用户拍板的任何决策、口径、规则，必须同步写进权威文档
- 不能只停留在聊天记录里，要让下一个 AI 也能读到
- 生产回顾是强制动作（步骤 12），缺了不算完成

## 三、完整操作流程

### 步骤 1 · 业态选型 + 玩法匹配

> **玩法库**：05 号文档 §4 玩法库（P-01~P-07），策划时先查表。

**第一步：选定细分业态**
- 不要选大行业（如"美业""餐饮"），要选**细分业态**（如"美容院""美甲美睫""茶饮咖啡"）
- 原则：业态越具体，痛点越精准，内容越有说服力
- 参考：05 号 §4.3「业态 × 玩法 匹配矩阵」

**第二步：匹配玩法（1 主 + 1 辅）**
- 从 05 号玩法库里选 **1 个主打玩法** + **1 个辅助玩法**
- 主打玩法：视频核心内容（8-10 屏，讲深讲透）
- 辅助玩法：视频进阶部分（1-2 屏，体现深度）+ 小红书图文/搜狐长文可以展开
- 每个业态至少做 2 条视频，避免内容疲劳

**第三步：业态调研三问（验证玩法是否成立）**
1. **这个业态的老板最头疼什么？** → 搜索具体业态的经营痛点（越细越好）
2. **这个业态现在怎么做营销？** → 搜索现有做法，找到"反常识"的切入点
3. **选的玩法能不能解决这个痛点？** → 结合前两步，验证玩法是否真的适配

**产出**：业态画像（100-200 字）+ 主打玩法 + 辅助玩法 + 一句话核心理念。

**架构升级重做时的旧文档处置**：当内容架构升级（如 1.0→2.0）导致旧行业单元交付物全部作废时，旧版本整体移至 `outputs/archive/` 并加日期前缀归档，新版本从零开始写，不在旧文件上修改。避免新旧口径混杂。

### 步骤 1.5 · 场景策略设计（内容深度闸门）

> **内容质量标准权威在 `08-内容质量三层标准.md`**，本步骤是 08 号文档的落地闸门。
> **内容深度标准权威在 `08 号 §2.5`**，每条视频必须满足「6 个信息单元 + 2 层递进 + 讲清怎么做和为什么」。
>
> **核心**：在画任何一帧之前，先想清楚"这条视频到底要讲一套什么方案"。不泛泛罗列功能，而是设计一个具体的、让老板看完想说"这招我也能用"的完整方案。
>
> **三层对照**：
> - 硬边界（第一层）：功能不能说错、不能编数据 → 对照 00 号事实表检查
> - 方向锚（第二层）：要达到"老板觉得我能用"的效果 → 对照 08 号 4 个自检问题 + 内容深度闸门
> - 创作自由（第三层）：切入点、结构、句式 → 自由发挥

**怎么做：**
1. 基于步骤 1 选定的玩法，设计一个**具体的经营场景**——不是"次卡可以锁客"这种泛泛之谈，而是一个有细节、有逻辑的完整方案，含以下要素：
   - 具体业态场景（如"美容院做完疗程后的送卡时刻"）
   - 核心玩法和卡券组合（如"养护六次卡 + 核销间隔三天 + 转赠闺蜜"）
   - 预期效果和逻辑链条（如"顾客每三天来一次 → 耗卡节奏锁住 → 卡不睡死 → 转赠带新客"）
2. **内容深度自检**（必须满足）：
   - ✅ ≥ 6 个有效信息单元（钩子/痛点/思路/步骤/为什么/进阶）
   - ✅ ≥ 2 层递进（痛点有深挖、方案有层次）
   - ✅ 讲清了「怎么做」（具体步骤，不是概念）
   - ✅ 讲清了「为什么有用」（底层逻辑，不是口号）
3. **对照 08 号文档自检**：AI 自己先过一遍第二层的 4 个自检问题
4. **人确认这个场景策略**：人觉得"这个场景确实能打动老板，有真实感"→ 再进设计稿。人觉得"太浅/太假/不痛"→ 回炉。
5. 确认后，场景策略作为设计稿的"核心理念"写入设计稿元信息。

### 步骤 2 · 券组合设计 + 边界校验
- 基于步骤 1.5 确认的场景策略，设计卡券组合（优惠券/券包/次卡）。
- **边界校验**：逐字段对照 00§6（数值上限）与 00§8（能力边界）。次卡走私密发放、随机金额 1~99 整数、套餐券只写文字预约说明（不暗示在线预约）。

### 步骤 3 · 四件套文案（G 类）
> 「四件套」= ① 活动设计总览 + ② 卡券制作单（逐字段 + 边界 + 使用须知）+ ③ 发放组合与执行顺序 + ④ 攻略长文。封面文案包随四件套一同产出（含抖音/小红书/搜狐三平台封面文案），不计入「四件套」数量。
- 数值以 00§6 为准，状态文案以后端 Label 为准。

**四件套格式要求**：

| 件套 | 内容要求 | 格式 |
|---|---|---|
| ① 活动设计总览 | 活动名称、目标客群、核心玩法、活动周期、预期效果 | 表格 + 简要说明 |
| ② 卡券制作单 | 每张券的逐字段配置（名称/面额/库存/有效期/使用条件/核销方式），附边界校验结果 | 逐券列表，每券一个表格 |
| ③ 发放组合与执行顺序 | 发券顺序、发放渠道、话术要点、时间节点 | 时间轴 + 执行清单 |
| ④ 攻略长文 | 场景化功能教学（不是功能罗列），≥6 信息单元 + ≥2 层递进，遵守 08 号内容质量标准 | 长文格式，含小标题分段 |

### 步骤 4 · 视频设计稿（AI 核心产出，闸门）
- 按 **13 §5 模板**产出完整设计稿：视频元信息 / 风格配置五维 / 相似度检查（≥3 维不同 + 叙事结构差异 ≥3 位置不同）/ 逐屏分镜表（帧级动画时序，遵守内容深度铁律）/ 图片素材清单 / 口播稿 / 合规自查。
- 口播稿、关键字、每屏 UI 布局 brief 全部在设计稿中定稿，不再单独产出「脚本」。
- 动画时序写到帧级（组件名、delay、easing），禁止模糊描述（13 §1.1）。
- **内容深度**：以 `08-内容质量三层标准.md` 为准。方向锚是"让老板觉得这个我能用"，达到这个结果就行，具体怎么组织内容 AI 自由发挥。禁止"功能罗列"——每屏换一个功能、每个只提一嘴。场景序列必须与已有行业视频至少 3 个位置不同（查看 13 §7.1 已注册场景序列），不可"换行业词照搬结构"。
- **图片素材清单**：先按 13 §4.1 检索本地素材库，本地有合适的标注源路径；不足才输出外部找图规格（13 §4.3）。
- **资源检索**（写画面布局前必走）：资源分两类处理——
  - **A 类 · 背景图 + 封面图**：查 11 号 §9.1 背景模板索引，有匹配的标注编号直接使用；没有的在设计稿末尾输出「找图需求单」（11 §9.4），写明关键词、色调、构图、尺寸，人去找图
  - **B 类 · 插画 / 挂件 / 装饰**：查 11 号 §9.2 + §9.3，有匹配的直接用；**没有的 AI 用代码图标/几何/文字排版替代，不卡流程，不输出找图需求**
- **排版参照**（写画面布局时）：从 09 号 §排版参照库 选一个匹配当前屏类型的参照，在设计稿中标注"参照：#X（XXX 型），借鉴了 Y 手法"。
- **核心内容集中**：每屏核心内容（标题+卡片/图标/流程）必须集中在 y:200-1100 区域内，卡片内 padding ≥ 43px，多卡片间距 ≥ 卡片高度 20%（详见 13 §2.3）。
- **行业背景图**：设计稿必须包含视频背景图的找图引导——关键词、选图标准、放置路径（`背景素材/` 对应子目录）。每个行业一张专属背景图，全片共用作为氛围底层（模板图毛玻璃微虚化，blur: 4px，详见 13 §3.3）。
- **文章配图**：小红书图文和搜狐长文的截图配图从 `截图素材/` 速查表选取（见 11 §1），在文案对应位置标注截图文件名。
- **闸门**：人确认内容方向/风格/素材来源/内容深度/叙事结构差异后，才进步骤 5。

### 步骤 5 · 背景图准备与代码执行
- **背景图（人执行）**：按设计稿的找图需求单，人到创可贴/设计平台找背景图，放入 `背景素材/抽象模板/` 对应子目录，告诉 AI 文件名 → AI 更新 11 号 §9.1 索引 → 复制到 `video/public/backgrounds/gXX/bg.jpg`（路径引入机制见 13 §4.1）
- **代码（AI 执行）**：新建 `data/gXX.ts` 填入 scenes + style；复用 `components/` + `scenes/`；如需新积木按 13 §7.2 扩展；新图标用 Icon MCP Server 检索/生成后转内联组件（13 §8.3）；图片用 `staticFile()` 引用。插画/装饰类库中没有的，用代码图标/几何/文字排版替代。
- **技术硬规则**：全部动画用 useCurrentFrame + interpolate/spring、禁止 CSS animation、motion 透传 style.motion、非 spring 插值用 EASE_OUT、场景间 TransitionSeries 转场（13 §2）。
- **验证**：`npx tsc --noEmit` 零错误 → 每屏单帧 still 验证。
- **渲染命令必带** `NODE_OPTIONS=""` 前缀（13 号文档 §6）。

### 步骤 6 · 文章配图
- 小红书图文、搜狐长文**使用截图素材作为功能示例图**（来源：`截图素材/` 目录），讲哪个功能配哪张图，让读者直观看到产品界面。
- 截图作为功能示例图使用，不做文章头图（头图仍用封面图/设计图风格）。
- AI 负责选图、放到文章对应位置；**截图中的微信元素（导航栏、分享面板等）由人发布前裁剪处理**。
- 配图素材清单标注来源（截图素材路径）。

### 步骤 7 · 封面（文案包 + 找图需求）
- **AI 输出封面文案包**（系列条/主副标题/排版留白）+ **封面找图需求**（风格/色调/构图/尺寸），人到创可贴等设计平台找图或制作。**AI 不生成封面。**
- 封面 = 未播放态缩略图（≠ 第一帧，可独立构图、更海报化）；首帧复用封面 hero 视觉（共用同一视觉语言，13 §5.9.7/07 §3）。
- 尺寸：抖音 9:16（1080×1920）、小红书 3:4（图文笔记封面）、搜狐 16:9（1920×1080）。
- 三平台封面不得含小程序码；设计原则见 07 §3。

### 步骤 8 · 视频生产（两阶段：先无声确认画面 → 再加语音出成片）

**核心原则**：先出无声版确认画面，画面过审后再生成 TTS 做最终成片。设计稿填预估 dur 作为无声版参考，最终 dur 由 TTS 实测 + dur 公式确定。禁止 atempo 调速。

---

#### 阶段一 · 无声版（画面确认）

目标：让用户在没有语音的情况下确认**画面质量、排版节奏、内容结构**是否合格。

- **代码执行**：新建 `data/gXX.ts`，dur 从设计稿取预估值（按 4.5-5 字/秒估算）。视觉：代码 UI + 字体 + 图标，关键字层从设计稿口播稿提取；首帧复用封面 hero 视觉。
- **字幕占位**：字幕内容按口播全文拆分（语义断句，每行 10-20 字），时间轴按预估 dur 均匀分配（仅作位置参考，不追求精确）。技术实现见 13 §2.7。
- **无声版渲染**：`npx tsc --noEmit` → `npx remotion still` 关键帧验证 → `npx remotion render`（无音频、有字幕占位）。
- **闸门**：人确认画面质量（构图/排版/节奏/核心内容集中）。不合格 → 列问题 → AI 改 → 再渲染确认；合格 → 进入阶段二。

  **断句示例**（以 g02 S1 口播为例）：
  ```
  口播原文：开咖啡店的老板，别再让顾客充卡了。充一次几百块，顾客怕跑路不敢办；就算办了，充完就不见人，卡睡死半年用不完。换个思路——十杯次卡，锁客反而更牢。

  拆为 4 行字幕（按语义断句，每行 10-20 字）：
  行1：开咖啡店的老板，别再让顾客充卡了。
  行2：充一次几百块，顾客怕跑路不敢办
  行3：就算办了，充完就不见人，卡睡死半年用不完
  行4：换个思路——十杯次卡，锁客反而更牢
  ```
  无声版每行字幕大致均匀分布在该屏时长内；有声版按 TTS 实测精确定时。

---

#### 阶段二 · 有声版（最终成片）

画面确认后才启动，确保语音不浪费、不返工。

- **TTS 语音（J-cut 一次到位）**：豆包 `seed-tts-2.0`，`speech_rate=0` 常速。逐屏合成全片，输出 `public/audio/{视频ID}/s1.wav` ~ `sN.wav`（N = 屏数，按视频 ID 分子目录，避免多视频串音）。自然语速 + J-cut = 一次到位；如有问题整体重录，不做片段微调。**数字统一写中文**（如"三天"非"3 天"）。**禁止 atempo 调速**。
- **精确时长计算**：用 ffprobe / `getAudioDurationInSeconds` 获取每段语音精确时长，按 13 §2.6 J-cut 公式计算每屏 dur（语音时长 + 尾音留白），更新 `data/gXX.ts`（语音时长决定帧数，设计稿内容结构不变）。
- **字幕精确同步**：字幕内容 = 口播全文，按语义断句分行；每行字幕的显示/隐藏时间点由 TTS 实测时长精确分配（先 TTS → 量时长 → 拆字幕时间轴 → 更新 dur → 再做画面动画微调）。
- **J-cut 声画同步**：voiceOffset=0（画面一出来就说话），转场采用上句淡出 + 下句满音量进入（J-cut），首字不丢、尾音不爆、无缝衔接。详见 13 §2.6。
- **成片渲染**：`npx tsc --noEmit` → `npx remotion render`（含音频+字幕）。声画帧级同步，字幕与口播逐句对齐。
- **闸门**：成片经人确认语音同步 + 整体节奏后，才进入发布。**盲听校验**：渲染后盲听全片一遍（不看画面），确认无断句异常、无卡顿。

### 步骤 9 · 测试—纠正循环

每轮只做 1 个单元，人审 → 列问题 → AI 改 → 沉淀踩坑点。过审再扩量。

**无声版检查清单**（阶段一，AI 渲染后逐项自检，人审时参考）：

| 检查项 | 检查方法 | 通过标准 |
|---|---|---|
| 画面安全区 | 渲染关键帧，检查顶部 120px 和底部 160px 是否有内容溢出 | 无内容溢出安全区 |
| 核心内容集中 | 检查每屏核心内容是否在 y:200-1100 区域内 | 无内容分散到全屏 |
| 排版节奏 | 逐屏看卡片 padding、间距、标题与内容的关系 | 呼吸感好，不挤不散 |
| 整体节奏 | 按预估语速默读一遍，感受节奏是否拖沓/仓促 | 节奏自然，无明显拖沓或仓促 |
| 字幕位置 | 检查字幕是否在底部安全区内，不侵入内容区 | 字幕位于 y:1760-1920，底部距底 ≥60px |
| 转场流畅 | 检查屏间转场是否有黑帧/闪白/卡顿 | 转场无缝衔接 |
| 跨平台尺寸 | 检查抖音 9:16 / 小红书 3:4 / 搜狐 16:9 是否正确 | 各平台尺寸正确 |

**有声版检查清单**（阶段二追加检查）：

| 检查项 | 检查方法 | 通过标准 |
|---|---|---|
| 字幕对齐 | 播放全片，逐屏检查字幕是否与口播同步 | 字幕与口播首字同步，无提前/延迟 |
| 首字完整性 | 逐屏检查口播第一个字是否被截断 | 每屏首字完整可听 |
| 尾音不爆 | 逐屏检查尾音是否有爆音/截断 | 尾音自然衰减，无突兀截断 |
| 整体节奏 | 盲听全片一遍（不看画面），感受节奏是否自然 | 节奏自然，语速舒适 |

### 步骤 12 · 生产回顾（固定动作 · 自进化核心）

> 这是系统"越做越好"的关键一步。做完不等于完成，沉淀了才算完成。

**触发时机**：每条视频/每篇文章人审通过、最终交付后，AI 主动发起，不等人催。

**回顾模板（5 项必答）**：

1. **做得好的**：哪些地方效果超预期？为什么好？能不能提炼成可复用的模式？
2. **踩坑的**：哪些地方走了弯路、出了问题？根本原因是什么？下次怎么避免？
3. **用户反馈**：用户说了什么（夸的、骂的、改的）？背后的偏好/规律是什么？
4. **待验证假设**：这次有什么想法没来得及试？下次可以怎么验证？
5. **可沉淀的资产**：有没有新的金句、新的结构、新的组件，可以加到最佳实践库里？**固定一问：这次哪些场景级 JSX 值得提成通用 UI 组件？**（收编进 `video/src/components/ui.tsx` 并更新 13 号 §8 组件表，机制见 13 号 §8.5）

**填写示例**（以 g02 茶饮咖啡为例，帮助 AI 理解写到什么粒度）：

> 1. **做得好的**：S6 进阶玩法的"转赠裂变"叙事角度好——从"老客有次卡用不完"切入，比直接说"可以转赠"更有代入感。可复用模式：**痛点场景 → 产品功能作为解法**，不要反过来。
> 2. **踩坑的**：S5 自检表描述和实际内容不一致，原因是改了 S5 内容没更新自检表。下次改内容时必须同步更新自检表。
> 3. **用户反馈**：用户说"画面卡片排版不协调，全挤在中间"。规律：AI 默认把内容放在安全区正中央，但视觉上应该集中在 y:200-1100 区域。
> 4. **待验证假设**：字幕如果按 TTS 实测逐词级同步（而非逐句同步），观看体验会不会明显更好？下次 g03 有声版验证。
> 5. **可沉淀的资产**：新增"核心内容集中原则"（y:200-1100），写入 13 号 §2.3。新增字幕断句示例写入 12-SOP 步骤 8。

**沉淀去向（按内容分类回写）**：

| 沉淀内容 | 回写到哪里 |
|---|---|
| 高转化句式 / 验证过的结构 / 踩坑记录 / 风格偏好 / 效率技巧 | `docs/internal/09-最佳实践库.md` |
| 通用 UI 组件（第二次出现的券面/数值/步骤/对比结构） | `video/src/components/ui.tsx` + 13 号 §8 组件表 |
| 新功能事实 / 产品能力边界调整 / 术语变更 | `docs/internal/00-产品事实表.md` |
| 新红线 / 新 CTA 口径 / SOP 变更 / 新的生产规范 | 14 号文档 + 对应 docs |

**过程归档**：完整回顾笔记存 `outputs/archive/{日期}-gXX-生产回顾.md`，作为过程留档。

> 原则：**做完一个行业，系统就强一分**。不沉淀 = 白做。
