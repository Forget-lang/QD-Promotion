## 一、维度 1：避雷三大平台（抖音/小红书/搜狐）的限流规定

### 现状评估：**中（偏良）**

红线框架已搭建完整，分级清晰，有机器闸门兜底。但违禁词覆盖有盲区、闸门检测范围有限、部分限流场景未覆盖。

### 具体发现

#### 1.1 红线体系结构完整，分级合理

- **分层设计好**：SKILL §二 将红线分为「内容·品牌合规」（6 条）和「三平台限流红线」（5 条），明确区分"合规铁律"和"设计基线"，避免什么都塞进铁律导致束缚。
- **机器守卫存在**：`redlines.json` 分三层（codeBanned / outputsReview / docsInfo），每层有不同的 scope 和 exitOnHit 策略，code 层零命中硬失败，文案层人工确认，文档层仅提示——逻辑合理。
- **全量对齐流程明确**：SKILL §八 规定了"改一处、全量对齐"的扫描面（6 个位置）和强制闸门（跑脚本），并有"决策回写权威层"的硬约束。

#### 1.2 违禁词覆盖存在盲区

`redlines.json` 的 `codeBanned` 当前只有 11 个 token：
`["微信", "微信搜", "微信小程序", "小程序", "小程序码", "搜券到卡包", "搜索框", "BRAND", "企业微信", "企微", "活码"]`

**缺口**：

| 遗漏类别 | 具体漏项 | 风险等级 |
|---|---|---|
| **微信暗语变体** | VX、v信、薇信、微x、WX、weixin 等谐音/拼音/缩写 | 中高——平台 AI 语义识别能抓到，用户也可能用暗语绕过 |
| **搜索类导流词** | SKILL 明确说"绝口不提...搜索"，但 redlines 里只有"搜索框"和"搜券到卡包"，缺少"搜索""搜一下""搜一搜""找一下"等通用搜索词 | 中——通用搜索词是导流重灾区 |
| **极限词** | 08 号文档 §1.4 明确列出了"最、第一、唯一、顶级、永久、100%、绝对、全网首发、国家级"等广告法违禁极限词，但 **redlines.json 完全没有覆盖** | 高——极限词既违法又限流，是硬红线 |
| **硬推 CTA 词** | SKILL 规定 CTA 不硬推关注/收藏，但"关注""收藏""点赞""评论区""主页"等词未进入机器检查 | 中——这些词虽然不一定限流，但与"软种草"原则冲突 |
| **平台特定违禁** | 抖音"最好用""神级""绝绝子"等夸张词；小红书"种草""安利"等营销词；没有平台差异化的违禁词库 | 低——当前阶段可人工把控 |

#### 1.3 闸门检测范围有限

- **只查代码层画面，不查语音层**：`check-redlines.mjs` 只扫描 `.tsx/.ts` 文件中的文本，TTS 语音合成的口播稿如果有违禁词，脚本检测不到。视频画面和语音是两条独立的内容输出通道，语音层目前没有自动化校验。
- **outputs 层只列不拦**：`outputsReview` 层 `exitOnHit: false`，只是列出来供 AI 人工确认。如果 AI 偷懒不认真逐条确认，违禁词可能溜过去。
- **封面图/图片素材不检测**：图片中的文字（如封面标题、截图中的微信元素）脚本检测不到，只能靠人工检查。
- **小红书图文/搜狐长文的正文层**：虽然在 outputs 范围内，但只是"列出来确认"，没有强制校验。

#### 1.4 CTA 导流方式有框架但缺细节

- **抖音/小红书 CTA**：只规定"自然收尾""轻署券到卡包""副标题可用'再小的门店也可以制作电子券'"，给出了一个标准话术。但没有提供更多可选的合规 CTA 句式库，AI 发挥时可能踩线。
- **置顶评论/私信回复**：SKILL §2.1 #6 提到"仅置顶评论/主页简介/私信自动回复这类平台资料位可放'微信小程序+搜索引导'"，但没有给出**具体的合规模板话术**（置顶评论怎么写、私信自动回复怎么写），实操时容易出界。
- **搜狐导流**：只说"导流仅限账号资料位"，没有说清楚资料位具体放什么、怎么放才合规。
- **"免费使用可说但不着重强调"**：定义模糊——出现几次算"着重强调"？放在什么位置算"强调"？AI 难以准确把握尺度。

#### 1.5 限流场景覆盖有缺口

SKILL §2.2 覆盖了 5 条限流红线（站外导流零容忍 / AI 内容标注 / 软种草 / 同质化 / 完播率），但仍有缺口：

| 限流场景 | 当前状态 | 缺口 |
|---|---|---|
| **虚假宣传/夸大效果** | 有"不编案例数据"规则 | 没有针对"营销效果夸大"的专门检查（如"客流翻一倍""转化率提升 50%"等表述） |
| **小红书营销号判定** | 未覆盖 | 小红书对频繁发硬广的账号有限流，当前没有"内容比例/发布频率"的指导 |
| **平台审核敏感词** | 部分覆盖 | 缺少金融/医疗/教育等特殊行业的敏感词（产品面向实体店，可能涉及医疗口腔、教育培训等行业内容） |
| **搬运/同质化** | 有相似度检查（视觉维度） | 只检查了视觉风格五维，**没有检查文案/叙事结构的相似度**（虽然13 §5.3 补充了叙事结构差异检查，但不是闸门强制项，也没有机器校验） |

### 问题/缺口总结

1. 违禁词库覆盖不足，尤其缺少极限词和微信暗语
2. 语音层（TTS 口播）没有自动化校验通道
3. CTA 合规模板不足（置顶评论、私信回复、搜狐资料位）
4. "免费""着重强调"等模糊口径缺少量化标准
5. 行业敏感词未覆盖

### 改进建议

1. **扩充 redlines.json 违禁词库**：
   - 新增极限词组（最、第一、唯一、顶级、永久、100%、绝对、国家级等）
   - 新增微信暗语组（VX、v信、薇信、WX、weixin 等）
   - 新增通用搜索导流词组（搜索、搜一搜、找一下等）
   - 按类别分组管理，便于维护

2. **增加口播稿红线检查**：
   - 在 TTS 合成前，对口播文本跑一次红线检查
   - 可以扩展 `check-redlines.mjs` 增加纯文本输入模式

3. **补充 CTA 合规模板库**：
   - 抖音结尾署名的 3-5 种变体话术
   - 置顶评论的标准写法
   - 私信自动回复的合规模板
   - 搜狐账号资料位的文案模板

4. **明确"免费"使用规则**：
   - 给出具体的使用频次限制（如"每篇最多出现 1 次"）
   - 给出正反例（✅ 对的用法 / ❌ 错的用法）

5. **建立行业敏感词清单**：
   - 按行业分类（医疗/教育/金融等）
   - 做行业内容时额外加载对应行业的敏感词检查

## 二、维度 2：是否吸取了优秀设计

### 现状评估：**良**

竞品分析有结构化框架，设计稿自查清单能倒逼 AI 思考，组件库分层清晰。但竞品样本量少、落地跟踪弱、自查清单约束力不足。

### 具体发现

#### 2.1 竞品分析框架结构化、可落地

09 号文档 §六 的竞品分析质量较高，两个案例（实体店电子券工具 / 创可贴封面）都采用了统一的分析框架：

- 整体定位（一句话定性）
- 视觉风格拆解（多维度表格 + 可借鉴度评分）
- 叙事结构拆解（分镜序列 + 核心手法提炼）
- 可直接复用的组件/手法（列清单，命名清晰）
- 与我们当前风格的对比表（找差距、明方向）
- 行动项（checkbox 列表，下个行业验证）

**优点**：
- 不是"看看别人怎么做"的泛泛而谈，而是拆解到组件级（"黄色高亮底条""胶囊标签云""手机真机演示框"），可以直接落地到代码
- 有对比表，知道差距在哪、方向是什么
- 有行动项，不是看完就完了

#### 2.2 竞品分析样本量不足

- **只有 2 个参考样本**：1 个抖音竞品 + 1 个封面设计。对于冷启动阶段的内容运营来说，参考量偏少。
- **平台覆盖不全**：只有抖音视频的竞品分析，没有小红书图文笔记的竞品分析，也没有搜狐长文的竞品分析。
- **同赛道账号分析缺失**：没有分析 3-5 个抖音同赛道账号的整体策略（内容比例、更新频率、钩子风格、CTA 方式等）。
- **缺少"避坑"分析**：只分析了"可以学什么"，没有分析"哪些是坑、不要学"。

#### 2.3 设计稿自查清单能倒逼 AI 执行，但约束力不足

13 号文档 §5.8 的「美感 & 内容密度自查」有 14 项检查，分 5 大类（色系与统一性 / 文字层级与信息密度 / 构图与布局 / 丰富度与层次感 / 行业适配性）。

**优点**：
- 有明确的"低于 6 个 ✅ 须返工"的门槛，能倒逼 AI 在设计阶段主动思考
- 检查项具体（不是"要有美感"这种空话，而是"主色不超过 2 个""每屏文字层级 ≥ 3 层""使用了 ≥ 1 个从竞品学习的组件"）
- 最后一条要求"使用了 ≥ 1 个从参考作品/竞品学习的组件或手法"，直接把竞品分析和设计产出挂钩

**问题**：
- **自检 = AI 自己打勾自己判**，没有第三方校验。AI 可能放水，全部打勾通过。
- **标准偏主观**："有留白呼吸感""视觉井然有序"等描述，不同 AI 判断标准不同。
- **"努力达到"定位降低了约束力**：文档明确说"不是硬性红线，目的是倒逼 AI 主动思考"——这定位本身没错，但客观上降低了执行刚性。
- **没有量化工具**：信息密度、留白比例等无法用脚本检查，全靠 AI 自我评估。

#### 2.4 组件库规划清晰，但深度不足

**做得好的**：
- 分层清晰：animations（6 个动画组件）/ ui（2 个 UI 组件）/ icons（内联 SVG 图标库）
- 场景渲染器有明确的 9 种 type（hook/pain/solution/flow/grid/panel/cta/timeline/transfer）
- 新建积木有完整的 5 步流程（设计稿标注 → 人审确认 → 代码实现 → 验证 → 文档回写）
- 判断标准清晰：区分"内容不同"和"结构不同"，避免滥用新建

**问题/缺口**：
- **UI 组件太薄弱**：只有 SlideTag（进度指示器）和 SectionTitle（段落标题）2 个。卡片、按钮、标签、列表、对比面板等常用 UI 组件没有独立封装，散落在各 scene 里。
- **缺少组件设计规范**：没有统一的圆角、间距、阴影规范，各 scene 可能各自为政。
- **缺少组件使用指南**：什么时候用什么组件、组件之间如何搭配组合，没有指引。
- **版式变体标注"待实现"**：13 §7.3 列了 3 种版式变体（vertical/horizontal/split），但标注"待实现"，当前 solution 只有 vertical 一种实际可用。状态不明确——是排期中？还是已废弃？
- **竞品行动项无跟踪机制**：09 §六 的行动项是静态 checkbox 列表，没有负责人、没有 deadline、没有验证状态、没有"验证后移到已实现区"的闭环。

### 问题/缺口总结

1. 竞品样本量少，平台覆盖不全（缺小红书/搜狐）
2. 自查清单靠 AI 自审自判，约束力不足
3. UI 组件库薄弱，缺少统一的组件设计规范
4. 竞品行动项无跟踪闭环，容易石沉大海
5. 版式变体状态不明确

### 改进建议

1. **扩充竞品分析库**：
   - 新增小红书图文笔记竞品分析（2-3 个同赛道账号）
   - 新增搜狐长文竞品分析（1-2 个同类工具的搜狐号）
   - 新增 2-3 个抖音同赛道账号的整体策略分析

2. **强化自查清单的约束力**：
   - 增加"人审时核对自查清单"的环节，把自查清单作为人审的检查项之一
   - 对部分可量化的检查项（如主色数量、文字层级数），考虑加入脚本自动检测

3. **完善 UI 组件库**：
   - 梳理现有 scene 中重复出现的 UI 元素，抽取为独立组件
   - 建立组件设计规范（圆角、间距、阴影、字号层级）
   - 补充组件使用指南

4. **建立竞品行动项跟踪机制**：
   - 每个行动项加"状态"字段（待验证 / 验证中 / 已落地 / 已放弃）
   - 每次生产回顾后更新行动项状态
   - 已落地的移到"已实现组件库"专区

5. **明确版式变体状态**：
   - 确认 horizontal/split 等版式变体的优先级
   - 标注清楚哪些是"已实现"、哪些是"规划中"、哪些是"已废弃"

## 三、维度 3：是否具备自我进化机制

### 现状评估：**良（框架完整，执行靠自觉）**

自我进化的框架设计得很完整——生产回顾强制、三个沉淀去向明确、决策回写权威层有硬约束。但强制性主要靠文档约定，缺乏技术保障；质量和更新频率依赖人的监督。

### 具体发现

#### 3.1 生产回顾机制设计完整

- **强制定位明确**：12 号文档步骤 12 标题直接写"生产回顾（固定动作 · 自进化核心）"，SKILL §五 也强调"交付完成 = 视频 + 文章 + 四件套 + 生产回顾 + 09号库更新，缺回顾 = 任务没做完"。
- **回顾模板具体**：5 项必答（做得好的 / 踩坑的 / 用户反馈 / 待验证假设 / 可沉淀的资产），不是空泛的"总结一下"。
- **三个沉淀去向清晰**：按内容分类回写到 09 最佳实践库 / 00 事实表 / SKILL + 对应 docs，避免不知道往哪写的问题。
- **过程归档**：完整回顾笔记存 `outputs/archive/{日期}-gXX-生产回顾.md`，有留痕。

#### 3.2 强制性缺乏技术保障

- **纯文档约束**："必须做生产回顾"只是写在文档里的规则，没有技术手段强制执行。AI 可以偷懒跳过，或者敷衍了事。
- **没有自动化卡点**：没有"回顾文档不存在 → 不允许归档交付"的脚本检查。
- **质量无标准**：回顾模板有 5 项，但没有"什么样的回顾算合格"的标准。写一句话也算完成了？还是要有具体的提炼和沉淀？
- **回写质量无审核**：回写到 09 号库的内容，没有审核机制。写得对不对、有没有用，全靠 AI 自己判断。

#### 3.3 记忆与文档同步机制有漏洞

- **决策回写覆盖不全**：SKILL §八 第 4 条只说"用户拍板的决策/口径/红线"必须回写权威层，但生产中发现的问题、踩的坑、验证的方法，是否需要同步更新文档？机制不明确。
- **MEMORY.md 与 docs 的关系模糊**：
  - AGENTS.md 说"记忆唯一源：MEMORY.md"，同时又说"权威状态永远在 docs/ + skill"
  - 两者的关系是：MEMORY.md 记录决策过程，docs/ 是最终权威？还是 MEMORY.md 也有裁决权？
  - 如果 MEMORY.md 和 docs/ 不一致，以哪个为准？虽然 SKILL 说"以本 skill 为准""以 00 号为准"，但 MEMORY.md 被称为"记忆唯一源"，容易混淆。
- **缺少文档定期审视机制**：没有"每做 N 个行业单元，审视一次文档是否过时、是否需要更新"的机制。文档可能越积越旧。

#### 3.4 自查清单的更新机制不明确

- 13 §5.8 最后说"每次出片后，把验证过的好做法回写到 09 最佳实践库，自查清单同步更新"
- 但**自查清单在 13 号文档里，不在 09 号文档里**。"同步更新"具体怎么操作、谁来操作、触发条件是什么，都不明确。
- 09 号文档的定位是"经验沉淀层"，13 号是"技术规范"。自查清单属于技术规范的一部分，但又依赖经验沉淀的输入——两者的衔接没有明确流程。

#### 3.5 数据闭环缺失

- SKILL §六 提到"用 docs 回顾模板记'风格×表现'，让数据选赢家而非拍脑袋"
- 但当前处于冷启动阶段，没有真实发布数据，也没有**数据回收机制**（发布后的数据怎么采集、怎么记录、怎么分析、怎么反哺风格选择）
- 风格轮换的效果无法验证，只能靠主观判断
- 待验证假设（09 §八）有 4 条，但没有验证进度跟踪，也没有"验证后移到已验证区"的机制

### 问题/缺口总结

1. 生产回顾的强制性缺乏技术保障（靠自觉，不靠机制）
2. 回顾质量无标准，回写内容无审核
3. MEMORY.md 与 docs/ 的权责边界模糊
4. 自查清单的更新机制不清晰
5. 数据闭环缺失，风格效果无法验证

### 改进建议

1. **增加回顾质量标准**：
   - 每项回顾至少要有具体的例子/细节，不能只有一句话

## 四、维度 4：AI 是否能准确理解

### 现状评估：**良**

文档写作规范（08 号）执行得不错——多数规则有正反例、能用表格不用段落、检查清单多。术语表完整。但仍存在术语不一致、模糊表述、流程指引不够细等问题。

### 具体发现

#### 4.1 文档写作规范落地好

08 号文档的「写作六条」在多数文档中得到了较好执行：

- **正反例丰富**：08 号文档自身是典范，每条规则都有 ✅ 对的例子和 ❌ 错的例子
- **表格使用多**：00 号术语表、数值约束表；05 号卖点表、行业速查表；09 号金句库、踩坑清单、竞品对比表；13 号技术规则表、组件规格表——大量使用表格，信息密度高、一目了然
- **检查清单多**：08 号第三层 4 个自检问题、13 §5.7 合规自查（7 项）、13 §5.8 美感自查（14 项）、13 §九 质量检查清单（18 项）
- **13 号文档的"模糊写法 vs 精确写法"对照表**（§1.1）非常好，直接告诉 AI 什么样的描述是不合格的、什么样是合格的

#### 4.2 术语不一致的地方

| 术语问题 | 具体表现 | 影响 |
|---|---|---|
| **"次卡"歧义** | 次卡既是"卡产品族统称"（含通卡/次卡/权益卡三种类型），又是其中一种具体类型（TIMES 型，按次核销）的名字 | AI 写文案时容易混淆，读者也可能困惑。00 号术语表里虽然有说明，但命名本身容易造成理解偏差 |
| **"核销活码" vs "动态核销码"** | 00 号术语表第 139 行写的是"核销活码 / 动态核销码"，两个名字指同一个东西 | 术语不唯一，AI 可能混用。建议确定一个正式名称，另一个标"又称" |
| **文档命名不统一** | 05 号文档标题是"内容弹药库"，AGENTS.md 里叫"营销视角索引"，SKILL §七叫"行业调研与场景策略" | AI 找文档时可能困惑哪个是哪个 |
| **"私密发放"的别名** | 术语表写"不要写成：私发券、定向券"，但实际文档中是否严格执行了？需要确认 | 如果有混用，AI 会困惑哪个是标准说法 |
| **"企微" vs "企业微信"** | 对内文档中大量混用"企微"和"企业微信"，虽然不影响对外内容，但对内文档不统一也可能造成理解偏差 | 影响较小，但建议统一 |

#### 4.3 存在模糊表述

| 模糊表述 | 出现位置 | 问题 |
|---|---|---|
| **"软种草"** | SKILL §2.2、08 号 §2.1 | 08 号尝试解释为"像同行分享经验，不像广告"，但仍偏主观。AI 很难判断自己写的东西算不算"软种草"。 |
| **"信息密度要高，不能水"** | 08 号 §2.4 | 什么叫"水"？什么叫"密度高"？没有量化标准。自检问题"剪掉一半会不会损失重要信息"是个好思路，但仍是主观判断。 |
| **"高密度但不杂乱"** | 09 §五、13 §5.8 | "高密度"和"不杂乱"本身有张力，平衡点在哪？AI 难以把握。 |
| **"不着重强调免费"** | SKILL §2.1、08 §1.3 | 什么叫"着重强调"？出现几次、放在什么位置、用什么字号算强调？AI 难以量化。 |
| **"CTA 自然收尾"** | SKILL §四、12 号步骤 11 | 什么叫"自然"？有多少种"自然"的方式？没有话术库参考。 |
| **"像同行分享经验，不像广告"** | 08 号 §2.1 | 主观判断，不同 AI 的理解可能差异很大。 |

#### 4.4 流程步骤的可执行性问题

| 步骤 | 问题 |
|---|---|
| **12-SOP 步骤 1：行业调研三问** | "搜索行业经营痛点"——用什么工具搜？搜什么关键词？搜到的信息怎么判断可信度？搜到的结果是真是假？AI 可能搜到错误信息然后当真。 |
| **步骤 1.5：场景策略设计** | "AI 自己先过一遍第二层的 4 个自检问题"——过了但不通过怎么办？迭代机制不明确。是 AI 自己改到通过？还是找人讨论？ |
| **SKILL §五步骤 1：风格情报** | "搜索 2-3 个源做参考挖掘"——搜什么关键词？怎么判断哪些是爆款？搜出来的结果怎么提炼成 style brief？ |
| **13 §4.1 本地素材检索** | "AI 不扫描全库列文件名（库小但避免上下文膨胀），而是输出'从XX目录中选取XX色调XX构图的竖版底图'的引导"——AI 不看素材库，怎么知道有什么、没有什么？本质上是靠人找，AI 的主动性不足。 |
| **设计稿的"人确认"环节** | 多处提到"人确认"作为闸门，但人确认的标准是什么？确认哪些点？没有明确的人审 checklist，全凭人的经验和感觉。 |

#### 4.5 文档引用网络复杂，AI 容易迷路

- **权威分层有 9 层**：00（事实）/ 02（流程）/ 05（营销）/ 08（质量）/ 09（经验）/ 12（SOP）/ 13（视频技术）/ SKILL（红线/SOP单一权威）/ MEMORY（记忆）—— AI 需要在 9 个文档之间来回跳转，容易迷失。
- **SOP 有两份**：SKILL §五有生产 SOP，12 号文档也是 SOP。两者的关系是"SKILL 是单一权威，12 号是详细手册"，但内容有大量重叠，AI 可能不知道该看哪份。
- **规则多处重复**：红线规则在 SKILL §二、08 号 §一、09 号踩坑清单、12 号 §四、13 §九.3 都有提及——如果某条规则更新了，需要改 N 个地方，容易遗漏（虽然有"全量对齐"流程，但流程本身就很复杂）。
- **"深挖指针"容易变成"无限递归"**：SKILL §七列了 10 个深挖指针，每个指针指向另一个文档，另一个文档又指向更多文档——AI 可能越挖越深，忘了最初的问题是什么。

### 问题/缺口总结

1. "次卡"术语有歧义，容易混淆
2. 多处模糊表述（软种草、信息密度、自然收尾、不着重强调），AI 难以准确把握
3. 调研类步骤缺少具体指引（搜什么、怎么搜、怎么判断可信度）
4. 文档引用网络复杂，SOP 有两份，AI 容易迷路
5. 人审环节缺少明确的审查标准

### 改进建议

1. **消除"次卡"术语歧义**：
   - 方案 A：产品族改名为"卡券"或"预付卡"，"次卡"专指 TIMES 型
   - 方案 B：保留"次卡"作为产品族名，TIMES 型改名为"次数卡"或"计次卡"
   - 无论选哪个方案，00 号术语表和所有文档统一口径

2. **给模糊表述加量化标准和正反例**：
   - "免费"使用频次：每篇/每条视频最多出现 1 次，不放在标题/首屏/CTA 强调位置
   - "信息密度"：每屏至少 N 个有效信息点（已有 13 §5.8 的 3 个标准，可以再细化）
   - "软种草"：给出 3 段示例文案（✅ 软种草 / ⚠️ 偏硬 / ❌ 硬广），让 AI 通过对比理解

3. **细化调研步骤的操作指引**：
   - 给出搜索关键词模板（如"[行业] + 经营痛点 / 获客难题 / 营销方法"）
   - 给出信息可信度判断标准（优先来源：行业报告 / 连锁品牌官网 / 权威媒体；谨慎来源：个人博客 / 论坛 / 自媒体）
   - 规定：搜到的行业信息需要交叉验证，不能只信一个来源

4. **简化文档导航**：
   - 在 AGENTS.md 或 08 号文档中加一张"文档查找速查表"——"遇到 X 问题，先查 Y 文档的 Z 章节"
   - 明确 SKILL 和 12 号文档的分工：SKILL = 规则与红线（裁决用），12 号 = 操作手册（干活用）
   - 减少规则的重复出现：非红线文档中只引用不复述，用"详见 SKILL §二"代替重复抄写

5. **建立人审 checklist**：
   - 设计稿审查清单（已有雏形，补充完善）
   - 成片审查清单
   - 文章审查清单
   - 让人审也有章可循，不靠感觉

#### P0（高危，建议立即处理）
