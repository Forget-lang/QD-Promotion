## 一、整改目标（唯一北极星）

**让视频发出去后有显著更高的流量**（当前 20~30 播放的瓶颈）。

判据不是"内容充不充实、画面精不精致"这类主观词，而是这条链通没通：

> 让人点开 → 看完 → 恍然大悟 → 信 → 收藏/转发 → 自发搜「券到卡包」

**总原则：吸收 985 篇爆款的成功打法，但守住红线 / 事实 / 真值——爆款只改变"讲法"，不碰"底线"。**

## 二、口径底座（这几轮对话锁死的共识，整改一切从此出发）

1. **行业是主轴**，目标客户 = 实体店老板；按"当下最迫切用券"选行业，一个打透一个，逐步渗透各行各业。
2. **内容不分片**：不碎片化切功能点，改为"一条闭环故事讲透一套行业攻略"（抛悬念 → 讲道理 → 证明 → 落地 → 金句）。
3. **洞察/定律当"讲故事的引擎"，不当主角**；主角始终是"这个行业怎么用电子券把活动做好"。
4. **功能点只讲小程序真实支持的功能**；平台禁用词、文案规范照 `spec/redlines.json`。
5. **母题（视觉语言）保留**：一个行业一套，换行业换整套——它是防"换皮同构"的头号工具，不动。
6. **官网内容照旧可用**：选题素材主源，三层采信、只借鉴不修改（见 `官网资源库落地规划.md`）。

### B 类 · 优化（保留骨架，升级方法）

### C 类 · 纠错（现有错口径 / 矛盾 / 游离）

1. **"行业=皮肤池、洞察=选题主轴"**（v8 旧口径）→ 改回"行业主轴、洞察当引擎"。
2. **爆款技能包"拆零件 RAG 方法"** → 标「已废止」（用户已否，985 篇语料留作查证库）。
3. **技能包"评分器当创作闸门（低于 80 分不终稿）"** → 对齐为"评分器仅做选题/标题筛选，不进逐屏创作"。

5. **爆款数字钩子 vs redlines 无来源数字禁令** → 补一条"爆款→红线翻译规则"（数字锚点三合法来源：① facts 参数可写；② 功能示例假设可写；③ 其余经营效果数字一律改机制化描述）。

### D 类 · 新增

1. `knowledge/洞察库.md`：**道理弹药库**，先种 8 条定律，服务闭环故事"讲道理"层（每条 = 定律 + 心理机制 + 适用行业痛点 + 承载真实功能 + 语料出处）。它是"表达引擎的燃料"，不是选题主轴。
2. **开工「视觉语言隔离声明」**：开工三动作后、选行业前，查 `list-assets` 已产出风格序列，声明本片母题 + 背景风格族 + 转场字幕风格，并逐条写出与上一条片的差异——先锁方向再动笔（把防换皮从"事后拦截"前移到"事前隔离"）。

## 六、元治理：下次再遇大整改，文档如何规划与维护

> 这节是"授人以渔"——把本次的规划方法沉淀成可复用原则，下次不再从头摸索。

1. **一切整改先锚北极星**：动手前先问"这个改动是为了流量/效果，还是为了让文档顺眼"——防"文档自指"（规则套规则、服务自己）。
2. **整改前先跑现状审计四问**：① 哪些是已验证真值（不动）② 哪些是拍脑袋未验证（可大改）③ 哪些是矛盾口径（纠错）④ 哪些缺失（新增）。
3. **落点路由先行**：每个改动先定"属哪类 → 落哪个文件哪个位置 → 理由"，再动手（机器可判进 spec / 人判进 SKILL / 原理进 R 层 / 历史进 docs/changes/）。
4. **强制"先验证再固化"**：新方法先跑一条试点拿数据，验证前不写进 SKILL——治"未验证即固化"这个头号病。
5. **被否做法标「已废止」不物理删**：保留失败记录，防未来回流重蹈。
6. **文档分层 · 改动分级**：真值层（只纠错）/ 方法层（可大改）/ 知识层（补弹药）/ 快照层（只增删）——不同层不同改法。
7. **规划文档 = 一次性快照**：执行后内容落真源、决策进 docs/changes/，本文件转快照冻结，不长期滞留（防多一份口径副本）。
