## 4. 接口说明（当前文档完全缺失，建议新增）

**现状（架构事实）**：`applet/` 下**无集中 API 层**（`apis/`、`services/` 均不存在），全部接口 URL 以 `request.get/post/put/delete` **散落内联**在 `pages_*` 与 `components/m/*`。`hooks/request.js` 统一附加 `Authorization / Merchant-Id / Version / sign / timestamp`，响应 `code===0` 用 `res.data`，`*Label` 后端直出禁前端映射。

**文档缺口**：00/02 几乎不含任何后端 endpoint（仅 00:207-208 泛述、02:59/214 提 `hasIssuePermission` 与状态枚举），导致"小程序调了哪些接口、核销/领券/审核链路参数"完全无据可查。

**建议新增"接口说明"节 / 独立文档，至少覆盖以下关键接口（已枚举验证）**：

| 域 | 关键接口 |
|---|---|
| 核销 | `POST /seller/coupon/verify`、`GET /seller/coupon/verify/{info,detail,list}`、`POST /seller/coupon/verify/export`；次卡 `POST /seller/card/verify` |
| 顾客领券 | `POST /user/coupon/public/receive`、`/user/coupon/private/receive`、`/user/coupon/transfer/receive`；次卡 `/user/card/*`；券包 `/user/bundle/private/receive` |
| 审核/认证 | `POST /seller/merchant/audit`、`GET /seller/merchant`、`POST /user/wecom/corp/bind`、`POST /seller/staff/update-pending`（员工审批） |
| 发放渠道 | `POST /seller/coupon/public/issue/create`（channelType 1~5）、`POST /seller/activity-poster/share` |
| 企微 | `POST /seller/wecom/staff/{create,update,unbind,delete}`、`/seller/wecom/group/*`、`POST /seller/wecom/batch/create` |
| 统计九件套 | `/seller/{coupon,card}/stat/{store-overview,staff-overview,staff-issue-rank,store-issue-rank,store-verify-rank,staff-verify-rank,channel-issue-rank,user-verify-rank,user-transfer-rank}` |
| 素材/对象 | `POST /seller/object/upload`（含审核态 `MEDIA_AUDIT_STATUS`） |

> 注：以上为前端调用面枚举，真实参数与校验以**后端为唯一事实来源**（00 §9 已声明）。
