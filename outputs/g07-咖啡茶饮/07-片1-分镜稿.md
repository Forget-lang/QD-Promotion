# g07 · 咖啡茶饮 · 片1 · 分镜稿（含口播）

> 攻略：一张"能拉新又能复购"的满减券怎么设。故事线三段：痛点（发券不回头）→ 逐个功能点讲透（消费门槛 / 发放方式 / 有效期 / 核销后赠券）→ 各方结果。
> 画面权重：大头给制券（S3 券面、S4 门槛对比、S5 发放与期限）；核销只讲页面重要信息；领取不单开屏（只讲由设置决定的结果）。
> 字段名逐字回 `spec/coupon-fields.json`；金额/张数/天数均为示例值（顶部标注）。母题=点单小票，色板=caramel，详见 `03-母题一页.md`。
> 屏号 ui 前缀 g07-，与教培那条不同构；跨片结构雷同靠一屏标杆人判（已过）。

## S1 · 钩子 hook — `g07-hook`
- 叙事职责：钩子。布局来源：全新做（咖啡母题：小票从顶部吐出 + 大字标题）。
- 这一环商家在想什么：发过券、人来了却不回头，想不通哪出了问题。
- 口播 → 区域：
  1. 「很多咖啡店老板发完券都纳闷：人是来了，怎么不回头？」→ 点亮标题
  2. 「先别怪客人，问题常常出在券的那一栏——门槛。」→ 点亮"门槛"关键词
- 信息全景：标题两行 + 关键词强调 + 一句副点 + 底部小票示意。占用率≥70%。
- 入场：标题 spring 落 + 关键词咖啡渍圈；下方一张小票打印出"无门槛"字样做钩子实物。

## S2 · 痛点 pain — `g07-pain`
- 叙事职责：痛点。布局来源：拆 anchor-pain（实物小票 + 右侧痛点句），咖啡版。
- 商家怕什么：券发出去，来一堆只占便宜的，客单没提上去。
- 口播 → 区域：
  1. 「无门槛的券，谁都想白拿一杯，喝完就走，你一分钱客单没提。」→ 点亮小票"无门槛·免费领一杯"
  2. 「这种券发得越多，越像在请客，不像在做生意。」→ 点亮右侧两句痛点
- 信息全景：小票（券名/无门槛/免费领一杯/领取后长期有效）+ 右侧 2 条痛点批注。
- 本屏判据自查：C-05 场景压在实物上 ✓；C-06 可暂停截图 ✓；无 AI 具象插画 ✓。

## S3 · 制券·券面 make-basic — `g07-make-basic`（★一屏标杆已过）
- 券种：满减券（满 X 减 Y）。⚠ 券种决定面额字段组合——满减券=消费门槛+优惠金额；代金券才=原价+券面额（X 代 Y），不可混用。
- 叙事职责：字段（制券主体）。布局来源：照 create.vue 分组自绘（仿表单，非截图）。
- 口播 → 区域（行→句）：
  1. 「我们重做一张，券名直接写清场景，比如到店咖啡券。」→ 优惠券名称
  2. 「关键在门槛这一栏，别填 0。」→ 消费门槛（点亮 hero）
  3. 「填 0 是白送，招来只占便宜的；设到店里的客单价，比如满 35 才能用，来了就得消费一次。」→ 消费门槛（分水岭）
  4. 「优惠金额减 8 块，数量先做 200 张。」→ 优惠金额 + 制作数量
- 字段真值：优惠券名称 / 消费门槛（0 为无门槛）/ 优惠金额 / 制作数量（库存 1~10000）。组标题「① 券面」为分步自述。
- 合规：顶部面包屑「数值为示例」+ 右上「示例」（C-11）。

## S4 · 机制·门槛对比 mech — `g07-mech`
- 叙事职责：机制（把分水岭讲透）。布局来源：拆 anchor-mech（两列 muted vs 高亮），咖啡版。
- 口播 → 区域：
  1. 「同样发券，门槛填法不一样，来的人完全不一样。」→ 标题
  2. 「左边无门槛：人人来白拿，你贴钱。」→ 左列（灰）
  3. 「右边满 35：来的都是要消费的，减 8 块换一单生意。」→ 右列（高亮）
  4. 「这一栏，就是拉新还是提客单的分水岭。」→ 底部结论条
- 信息全景：左列（无门槛·白送一杯·招羊毛）+ 右列（满35·减8·来就消费）+ 结论。
- 本屏判据：C-09 结论条本片最多 2 次之一（换咖啡红底）。

## S5 · 制券·发放与期限 fields — `g07-make-rules`
- 叙事职责：字段（发放方式 + 有效期）。布局来源：同制券表单自绘，本屏为 select/input 混合，与 S3 不同构。
- 口播 → 区域：
  1. 「券设好了，怎么发？这张要拉新，发放方式选公开领取——谁看到都能领，存成海报贴门口就行。」→ 发放方式（公开领取）
  2. 「有效期别选固定档期，选自领取日起 7 天内有效：客人领了就得尽快来，不然过期作废，不会压在包里睡觉。」→ 有效期类型 + 有效期
- 字段真值：发放方式（公开领取/私密发放/券包，创建后不可改）；有效期类型（自领取日起N天内有效）；有效期（最少1天最多365天）。组标题「③ 发放与期限」分步自述。
- 边界：私密发放只一句"要只发给指定人是另一套"带过，不展开（留给系列后集）。

## S6 · 进阶·核销后赠券 chain — `g07-chain`
- 叙事职责：进阶（复购主开关）。布局来源：拆 ref-11 纵向编号步骤条，咖啡版（编号圆 + 小票节点）。
- 口播 → 区域（节点→句）：
  1. 「最后开一个开关，把一次客变成回头客——核销后赠券。」→ 节点1（开启核销后赠券）
  2. 「打开它，客人这次把券用掉，系统马上再给他一张一样的，直接到账。」→ 节点2（核销后自动再得一张）
  3. 「他为了用掉第二张，多半就会再来一趟。」→ 节点3（回头再消费）
- 字段真值：开启核销后赠券（核销后立奖本券一张，直接到账）；顾客侧文案「核销奖励 · 到店核销后可再得本券一张」。
- 本屏判据：C-12 节拍=口播句 3 句 3 节点。

## S7 · 结果·顾客与核销 steps — `g07-steps`
- 叙事职责：收尾前的结果（顾客侧 + 核销那一下）。布局来源：拆 ref-16 步骤结果对照，咖啡版。
- 口播 → 区域：
  1. 「发出去之后，客人看到的是：一张满 35 才能用的券，用完又自动多一张。」→ 行1（顾客领到/再用）
  2. 「你核销时扫他的码一验，这张能不能用、是不是别人转来的，页面上写得清清楚楚。」→ 行2（核销重要信息）
- 真值：核销页重要信息——「转赠获得」标签（这张是不是别人转来的）；能不能用由有效期/状态决定。领取结果由设置决定（满35才能用、领后7天）。
- 边界：不演示怎么扫码（一次就会的动作一句带过）。

## S8 · 结果·商家后台 ledger — `g07-ledger`
- 叙事职责：结果（商家后台数据）。布局来源：拆 ref-10 多栏清单，咖啡版（两栏：发券业绩 / 核销业绩）。
- 口播 → 区域：
  1. 「在后台不用猜——发出去多少张、有人真来核销没有，两个数就摆在那。」→ 两栏抬头
  2. 「有效发放张数配着核销率，看发出去有没有人来；本店核销张数，看这一阵到底来了多少单。」→ 各栏条目
- 真值（statPageKeyInfo 原词）：有效发放张数、核销率、有效发放且核销张数、本店核销张数。⚠ 页面上没有"已领取/已核销"这两个词（那是券包/次卡页），不得用。
- 本屏判据：数字只列真词标签，不编具体业绩数值（冷启动无案例）。

## S9 · 收尾 cta — `g07-cta`
- 叙事职责：收尾（攻略收束 + 品牌署名）。布局来源：全新做（咖啡母题收束）。
- 口播 → 区域：
  1. 「门槛设对、公开发出去、限期领了就来、用完再送一张——拉新和复购，一张券一次办齐。」→ 四条收束条
  2. 「券到卡包，实体店的电子券工具。」→ 品牌署名（CTA 只在账号资料位，画面不写导流话术）
- 信息全景：四条攻略要点 + 品牌名 + 一句价值主张。
