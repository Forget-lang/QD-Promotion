# 历史片 Legacy 隔离声明

> 定位：**历史片清单与隔离标记登记表**——只登记"哪些片是历史交付、标记长什么样、谁来核对"。
> 隔离**规则本体**的 Owner 是 `AGENTS.md` §九（新会话视觉隔离）＋ `SKILL.md` 第 4 步 C-15；本文件只引用，不另立规则。
> 建立：`CHANGE-20260924-056`（AI-A 复核结论：历史 outputs 保留不删除，增加 Legacy 隔离声明，避免未来作为模板读取）。

## 一、背景（为什么需要它）

g06 至 g11 六片是 039 多风格架构**之前**的交付物。它们的文档里保留着旧流程术语（旧流程名、旧片类二分、旧视觉判据编号），且在 039 之后**零改动保留**——这是当时的明确裁定（历史交付不回改）。

问题在于它们是**活的可见文件**：位于 `outputs/` 活跃区（不是 `outputs/archive/`），新会话按开工三动作读"当前产物"时会撞见。旧口径扫描（`deprecatedTerms`）的扫描面只覆盖文档层，**不覆盖片目录**，因此没有任何机器防线阻止"把 g06–g11 的写法当模板抄到新片"。

本声明把这道防线从"靠自觉记着 C-15"升级为**声明 ＋ 机器核对**。

## 二、登记内容

- **历史片清单**：`g06`、`g07`、`g08`、`g09`、`g10`、`g11`（机器声明源＝`scripts/ref-registry.json` 的 `legacyPieces.pieces`；本文件与之一致）。
- **隔离标记（机检 token）**：`Legacy 隔离声明` —— 每片的内容输入包首部必须带这一行（模板见 §三）。
- **核对方式**：`node scripts/check-style-rotation.mjs` 会逐片核对"登记表里的每一片是否真带标记"——**登记与实物不一致即硬失败**（防标记被后续清理悄悄删掉）；`ref-registry.legacyPieces` 未登记的片不受此检查影响。

## 三、标记模板（每片内容输入包首部一行）

```text
> ⚠️ **Legacy 隔离声明**：本片属 g06–g11 旧架构历史交付，**禁止作为新片模板或参照**（`AGENTS.md` §九／`SKILL.md` 第 4 步 C-15）；清单与核对方式见 `outputs/LEGACY-ISOLATION.md`。
```

## 四、边界（本声明不做什么）

- **不改历史片内容**：g06–g11 的正文、数据、成片、帧图一律零改动；本声明只增加上面那一行标记。
- **不构成新入口**：本文件不是生产入口、不是规则 Owner，只有"片清单 ＋ 标记 token ＋ 核对方式"三件事。
- **不放宽既有闸门**：g06–g11 的豁免（`bgExemptions`／`motionWaivers`／`safeAreaWaivers`）仍按其原登记逐条生效，与本声明无关。
- **新片不得登记**：本表只出不进——新的历史片应进 `outputs/archive/`，不得用本表把活跃片洗成"历史"。
