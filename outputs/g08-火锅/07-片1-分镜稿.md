# g08 · 火锅 · 片1 · 分镜稿（设计准绳 · 逐屏规格）

> 第 4 步产出。**本文件是画面执行的设计准绳**：每屏的字段/为什么/信息清单/布局来源以本文为准，真图按此校验，对不上以本文为准回炉那一屏。
> 字段名逐字取自 `spec/coupon-fields.json`；值均为示例；口播句见 `02-口播文案.md`。
> 屏序跟功能点选择逻辑走（固定有效期→到期提醒→发出去→次日起接力），不跟点击顺序走。

## S1 · 钩子屏（type hook）
- **叙事职责**：首屏即钩子，痛点直接压在"正在被填的档期券"界面上（C-05，不另开铺垫屏）。
- **本屏要观众看到**：`有效期类型`=固定有效期 · 到期日=10 月 7 日 · "过期自动作废=紧迫感"。
- **商家在想什么**：怕假期一过店里就空——所以钩子就是"带到期日的券"。
- **布局来源**：桌号牌语言（与 S3 一屏标杆同源，非沿用 g07）。
- **口播句→区域**：「假期一过，店里就空」→痛点牌匾；「带到期日的券」→号牌卡 hero 行。
- **信息全景（≥3）**：痛点牌匾 / 券名 / 固定有效期 / 到期日 / 过期作废标注 = 5。
- **入场语法**：牌匾落章 + 号牌卡落章。
- **本屏判据自查**：C-05 ✓（钩子长在界面上）｜C-10 ✓（无返回键/状态栏）｜C-11 ✓（"示例"挂右上角标，屏底只字幕）｜C-06 ✓（暂停可读）｜占用率 ⚠️（见文末反查）。

## S2 · 痛点屏（type pain）
- **叙事职责**：把"现在这么做"的失效摊开，为攻略立动机。
- **本屏要观众看到**：临时打折→节一过没人记得；印海报→看一眼划走、留不下凭证；当天才做券→来不及领。
- **商家在想什么**：明知要促销，但老办法节后归零。
- **布局来源**：痛点锚（anchor-pain）语法 + 号牌卡承载。
- **口播句→区域**：三句分别点亮三条做法→失效。
- **信息全景（≥3）**：3 做法 + 3 失效结果 = 6。
- **入场语法**：牌匾落章 + 三条逐条落定。
- **本屏判据自查**：C-05 ✓（动机长在每一项上，非独立铺垫段）｜C-06 ✓｜C-11 ✓｜占用率 ⚠️（见反查）。

## S3 · 制券屏·中秋家宴券（type fields，couponType 满减券）
- **叙事职责**：讲透功能点①固定有效期（+领取上限）。制券环节大头。
- **字段→值→为什么→不这么填会怎样**：
  - `优惠券名称`=中秋家宴券（场景写进名字）；`消费门槛`=满 150 元可用；`优惠金额`=减 30 元；`制作数量`=200 张。
  - `有效期类型`=**固定有效期**（hero，节日专属）→ `有效开始时间`=9 月 25 日、`有效结束时间`=10 月 7 日。**为什么**：过了假期券自动作废=紧迫感；**不这么填**：日常券用固定有效期=过期浪费。
  - `每人限领总量`=1 张。**为什么**：防一人囤多张、更多客人能领到。
- **商家在想什么**：要的是"假期前来吃"，不是"随便哪天"。
- **布局来源**：一屏标杆（已过，桌号牌语言）。
- **信息全景**：券面 4 行 + 期限 3 行 + 领取上限 1 行 = 8（≥3 ✓）。
- **入场语法**：牌匾落章 + 号牌卡落章 + 行逐条擦入（每行入场前不占位，C-07①）。
- **本屏判据自查**：字段回源码 ✓（check-ui-truth ①）｜⑥ 满减券↔优惠金额配对 ✓｜组归属：券面/期限/领取上限为我方分步自述、非原生组 ✓｜C-07 骨架容量：8 行在牌内 ✓｜C-11 ✓。

## S4 · 到期提醒屏（type fields，无面额→不声明 couponType）
- **叙事职责**：讲透功能点②到期提醒（独立成屏，催到店）。
- **字段→值→为什么→不这么填会怎样**：`到期提醒`=开（hero）→ `提前提醒`=提前 3 天。**为什么**：吃火锅要订位，到期当天才说要安排来不及；**不这么填**：顾客错过、券白作废。送达是产品支持能力，直说"会提醒"、措辞不带平台名。
- **商家在想什么**：怕客人忘了用、也怕当天扎堆订不到位。
- **布局来源**：复用制券屏组件（同片内多屏喂不同数据）。
- **信息全景**：券名(标题) + 到期提醒=开 + 提前 3 天 = 3（钩子级下限）。
- **入场语法**：牌匾落章 + 卡落章 + 行擦入。
- **本屏判据自查**：组归属：`到期提醒`为页面原生组、行(到期提醒/提前提醒)对得上 ✓（check-ui-truth ③）｜无面额字段故不声明 couponType ✓｜占用率 ⚠️（低行数，见反查）。

## S5 · 发出去屏（type fields，无面额→不声明 couponType）
- **叙事职责**：发放环节——只讲要设数据的（公开领取 + 领取时间），活动海报作载体。
- **字段→值→为什么**：`发放方式`=公开领取（hero）；`领取开始时间`=9 月 18 日（节前开抢）；`领取结束时间`=10 月 7 日。**为什么**：节前就能领、进卡包；载体=生成活动海报贴门口，客人扫码即领。
- **商家在想什么**：节前把入口铺开，别等当天。
- **布局来源**：复用制券屏组件。
- **信息全景**：发放方式 + 领取开始 + 领取结束 + 活动海报(sub) = 4。
- **本屏判据自查**：无面额→不声明 couponType ✓｜活动海报是产品功能、不上作字段、只在 sub 说明 ✓｜占用率 ⚠️（见反查）。

## S6 · 接力券屏（type fields，couponType 满减券）
- **叙事职责**：讲透功能点③次日起有效期（节后回店券，匀客流）。
- **字段→值→为什么→不这么填会怎样**：`优惠券名称`=节后回店券；`消费门槛`=满 100 元可用；`优惠金额`=减 20 元；`有效期类型`=**自领取次日起N天内有效**（hero，隔天生效）→ `有效期`=7 天。**为什么**：当天用不了、隔天才能用，把节末高峰客人匀到平时；**不这么填**：选"当日起"就挤在假期当天、节后照旧空。
- **商家在想什么**：节后别断档。
- **布局来源**：复用制券屏组件。
- **信息全景**：券面 3 行 + 期限 2 行 = 5。
- **本屏判据自查**：⑥ 满减券↔优惠金额配对 ✓｜字段回源码 ✓｜C-07 容量 ✓｜占用率 ✓（居中后）。

## S7 · 结果屏（type advance）
- **叙事职责**：尾——做完各方看到什么（顾客侧 + 商家侧 + 核销那一下）。
- **本屏要观众看到**：顾客那边=券在卡包里/到期前收到提醒/节后又多一张/到店出示就能用；你这边=后台核销数·核销率/两个数看清/领取核销明细可导出。
- **商家在想什么**：想知道"这节日到底做没做对"。
- **布局来源**：全新做（两栏对照台账，桌号牌语言）。
- **信息全景**：两栏各 3 条 = 6。
- **本屏判据自查**：数字口径：核销数/核销率是 facts 统计口径、非编效果数据 ✓｜无趋势图表（facts 只有指标卡+排行，此处不画折线）✓｜C-11 屏底只字幕 ✓｜占用率 ⚠️（见反查）。

## S8 · 收尾屏（type cta）
- **叙事职责**：一句主张收束 + 品牌署名。
- **本屏要观众看到**：主张"节日的客人，就留住了" + 品牌"券到卡包" + 定位"实体店的电子券工具"。
- **布局来源**：品牌收尾（落章式）。
- **信息全景**：主张 / 品牌 / 定位 = 3。
- **本屏判据自查**：品牌署名允许上屏（结尾位）✓｜CTA 不写导流话术、导流只在账号资料位 ✓｜无极限词 ✓｜C-11 ✓。
