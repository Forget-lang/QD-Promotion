# 教培托管 · 系列规划（一片 = 一个痛点的一套完整攻略）

> 2026-08-30 定稿口径（同日敲定三次后的最终版）：**一个行业 = 一个系列**；**一条视频 = 一个痛点 + 解决它的一套完整攻略**，叙述线**有头有尾**；攻略里**只选 2~4 个功能点，但每个都讲透**——怎么设 → 为什么这么设 → 设完之后哪一方看到什么。用不上的不提；想讲的多了就拆成下一条痛点的视频。画面重心给"怎么做这张券"，一次就会的动作不啰嗦（难理解的讲透，简单的不细说）。
> 功能真值全部取自 **`spec/coupon-fields.json`**（逐项带源码行号）；**功能上不猜**，表里没有的先取证回写再上屏。

## 一、我前两版各错在哪（钉住，防止再走形）

| 版本 | 我做成了什么 | 你的纠正 |
|---|---|---|
| 第三轮 | 把制券页→券详情→领取页→核销页逐屏走一遍，11 屏 195 秒 | 没必要把所有流程页都做出来；那是页面顺序 |
| 第五轮 | 改成"一片 = 一张券的一组设置项"，切得太碎，一片只剩一个开关的后果 | 一片还是**痛点 + 攻略 + 功能点**的完整故事；只是**别贪多**，选中哪几个功能点就把它讲透 |

现在的判定单位是**攻略**：一条攻略天然会用到两三张券、两三个机制，它们服务同一个痛点，所以必须在同一片里；反之服务不同痛点的两件事，绝不缝在一条片尾。**"讲透"指深度，不指覆盖面。**

## 二、每个功能点在画面里怎么陈列（系列内统一语法）

片 1 立住这套语法，后续片复用：

1. **一屏 = 一张"券的设置卡"**：真实字段名逐字取真值表，一屏摆 4~7 行，没念到的行保持可见安静。
2. **每一项三件信息**：字段名 ｜ 按托管场景真填进去的值 ｜ 为什么这么填（这句归口播，画面不重复）。
3. **本篇必须这么设的项给强标记**（描边 / 底色 / 序号章），其余是背景信息。
4. **联动当场演**：选「私密发放」→「公开领取设置」整组与「允许分享」那行当场消失；「每人限领总量」填 2 → 「每次领取数量」「领取周期」当场长出来；开「指定手机号可领取」→「填写手机号」自动打开并锁死。这是"真懂功能"最直观的证明，也是和同行教程拉开差距的地方。
5. **上限就是话术**：兑换内容十个字、使用须知五百字、名单五百个、可用时段两段——数字决定"什么必须写在哪一行"。
6. **后果要讲到人身上**：每讲完一个功能点，补一句"设完之后——家长那边／你后台／核销那一下会看到什么"。攻略的尾就靠这些结果句收。
7. 产品原话带禁词的几行按真值表 `onScreen:false` 跳过，不留空位。**消息提醒按真值表说**：六类通知逐条列在 `spec/coupon-fields.json` 的 `messageReminders.types`（2026-08-30 用户服务端口径 + `applet/config.js:10-16`），**表里没写的一类都不提**；送达同日已确认是支持的能力 → 可以直接说"到期前会提醒""到账会收到通知"，不再挂"顾客订阅过才收得到"那层保留说法。仍守两条边界：措辞不带平台名（站外生态词硬禁）、订阅授权发生在顾客点领取时而不是商家能代开（所以制券页那格只讲开不开、提前几天）。

## 三、教培托管 × 开学季：四条痛点攻略

### 片 1 · 观望型家长（母片，就是你举的例子）

- **痛点**：开学季家长到处比价，嘴上说"回去想想"，你既留不住人，也不知道到底谁会来。
- **攻略三招（三个功能点，逐个讲透）**：
  1. **兑换券做体验引流**——券种选兑换券；优惠券名称「开学季下午托管体验」（十八个字内）；兑换内容「下午托管一次」（**十个字装不下服务明细，明细写「使用须知」五百字**：放学去校门口接 · 回来看着写作业 · 晚饭在店里吃）；消费门槛 **填 0**（引流不设槛，填了就把想试的人挡掉）；有效期类型选 **「自领取日起 N 天内有效」**，不选固定日期（家长今天领，未必这周送来）；可用时段选「定制」，只开周中下午两段（避开高峰、填闲时）；发放方式 **公开领取**；限领总量开、每人限领总量 **1 张**（防一人囤多张，也因此「每次领取数量」「领取周期」这两行不会出现）；「允许分享」本片**不占行**——制券屏容量上限六行，这行只在 S7/S8 的公开对私密里作为"私密发放根本不显示"的对照出现，不作为设置项教。→ 结果：海报存下来贴到门口，家长领了券就在卡包里，到期还有提醒。
  2. **满减券 + 仅指定手机号可领取（只给谈过的几家）**——券种满减券；消费门槛按学期费填（例：满一千）、优惠金额填一百（门槛不到客单价附近，券就没分量）；发放方式 **私密发放**（**创建后不可修改，新建时就得定死**；选它之后「公开领取设置」整组消失、「允许分享」这行根本不出现）；打开 **「指定手机号可领取」**，把谈过的家长号码导进去（**每行一个、最多五百个、重复自动跳过**）；联动后果必须讲：**这颗开关一开，「填写手机号」会被自动打开并锁死**，因为要靠号码校验。→ 结果：名单外的家长在领取页根本领不到，只有你点过头的那几家能领。
  3. **转赠奖励（家长带家长，整条链走完）**——先另做一张私密发放的券当奖品（原话限制：**仅可选择「私密发放」类型的有效优惠券**，所以这条玩法天生要两张券）；回到体验券开「允许转赠」→「开启转赠奖励」→ 选那张奖品券。完整链路：**家长A 把券转赠给家长B → B 领取（弹窗原话「仅首位领取好友可获得本券」；可取消转赠按真值表 offScript 不上屏、不念）→ B 到店核销 → A 自动获得那张奖品券**。核销侧的重要信息一并讲：券卡上的 **「转赠获得」** 标签让你知道这家长是谁带来的；B 的券如果还在转赠中，核销页会挡下来（原话「优惠券转赠中，暂不可核销」）；核销成功页直接显示 **核销奖励 / 转赠奖励** 的发放状态（奖励成功 / 待补偿 / 失败带原因）。若关掉「允许转赠」，转赠奖励会被自动关掉、已选奖品清空。
- **尾（结果，引流收口）**：这周有几个孩子来体验、名单里谈过的几家报了名、还有家长开始带家长；后台只看统计页有的真词：**有效发放张数 + 核销率、有效发放且核销张数、本店核销张数**，账对不通用「导出领券记录 / 导出核销记录」（`spec/coupon-fields.json` 的 `statPageKeyInfo.rule`——优惠券统计页上没有"已领取/已核销"这两个标签，别拿次卡页的字说事）。
- **实测（已落地）**：12 屏 / 5748 帧 = 191.6 秒，数据在 `video/src/data/g06.ts`，分镜见 `07-片1-分镜稿.md`。当初按三个功能点讲透估的是 12~14 屏；真做下来第一招的制券占了两屏（S4 券面 5 行 + S5 期限与发放 6 行——骨架容量上限，七行会超屏）。

### 片 2 · 家长怕一次交一学期，你怕他这个月来下月不来

- **痛点**：托管按月收，家长不想一次掏一学期；你也不想靠催。
- **功能点三个**：① **券包**做报名礼包（**2~10 种券、每种 1~5 张**，一次给齐体验 + 满减 + 转赠各一张）——**券包只支持私密发放**，选它之后限领总量、领取口令、指定手机号、发券员工会**整套自动关掉**，这个"选了一种另一种整套没了"必须演出来；② **开启核销后赠券**（原话「核销后立奖本券一张，直接到账」）——一张券自己续自己，家长不用每次找你要新券；③ **每人每天限核销 1 张**（先开「开启每天核销限制」这行才出现）——把"一次囤着砸完"变成"每天都得来一次"。
- **尾**：核销成功页显示「核销奖励：奖励成功」；家长券上写着"到店核销后可再得本券一张"。

### 片 3 · 券发出去了，两分钟被熟人和羊毛党领完

- **痛点**：群里、门口发的券要么没人领，要么被同一批人囤走，真正想来的家长反而领不到。
- **功能点三个**：① **自定义领取时间**（领取开始 / 结束时间）——准点开放，家长那边在点之前按钮就是「活动未开始」；② **制作数量 = 名额**（一到一万张）+ 抢完显示「已抢光」，稀缺是设出来的不是喊出来的；③ **线下收款口令**——固定口令自己设五位数字，或随机口令每三分钟变化一次，写在收银台，等于给券加一道"到场才拿得到"的门。顺带把「每人限领总量填 2 之后才会出现的『每次领取数量』『领取周期』」讲清（**每周可领一张**这种回头节奏就是这么来的）。
- **尾**：准点那一下的领取曲线、以及哪些号是重复的（自动跳过）。

### 片 4 · 两个校区、三个老师各发各的，账最后算不清

- **痛点**：券发出去了不知道是谁发的、哪个校区领的、哪个老师带来的家长。
- **功能点三个**：① **适用门店**（多选，默认自动选中）；② **发券员工**（多选；**券包类型不显示这一行**，公开领取与私密发放才有）；③ **核销页的「领取信息 / 核销信息」**——领取渠道、领取时间、发放门店、发放员工、发放备注 · 核销店铺、核销员工、核销备注、核销时间。加上私密发放那栏 **发放备注（选填、仅商家可见）** 怎么用来标"这是哪一波"。
- **尾**：一张券从谁手里发出、谁核的，页面上都有；导出领券记录对账。
