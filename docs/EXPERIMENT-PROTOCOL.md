# QD-Promotion · 方法实验与晋级协议

> 定位：规范“新想法如何进入系统”，避免一次整改就把临时方案写成永久规则。
> 本文件面向 AI，用户不需要学习这套分类；AI 负责执行。

## 1. 什么进入实验

以下情况默认进入实验，不直接修改稳定生产方法：

- 用户提出“能不能这样做”的新想法；
- AI 提出的新技术/内容方案；
- 某次真实产物中的新视觉尝试；
- 某次局部整改可能具有普适价值，但尚未验证；
- 对现有方法的明显怀疑或替代方案。

## 2. 实验最小记录

每个实验只需要回答：

```text
问题：为什么要尝试？
想法：是谁观察到什么、提出什么？
方案：AI 建议怎么做？
选择：双方为什么采用这个方案？
实验：实际做了什么？
证据：真实产物在哪里？
判断：用户认可、否决、还是暂不确定？
边界：什么条件下有效？
下一步：继续、晋级、放弃？
```

不要把实验过程改写成大段“教程”。实验首先服务于决策。

## 3. 什么时候晋级为稳定能力

同时满足以下条件，AI 才可以建议升级为稳定生产方法：

1. 解决了原始问题，而不是只让某一个案例看起来更好；
2. 有真实产物证据，而不是理论判断；
3. 得到用户明确认可；
4. 具有跨项目/跨场景的可复用性；
5. 不会与产品事实、平台红线或更高层规则冲突；
6. 晋级后能减少未来决策成本，而不是增加维护负担。

一旦晋级，稳定层只记录“当前怎么做”和必要的边界；“为什么走到这里”的完整过程留在实验/历史中。

## 4. 什么时候只修当前项目

以下情况不要晋级：

- 当前行业特例；
- 当前镜头/屏幕排版问题；
- 一次性的文案偏好；
- 当前素材不合适；
- 仅针对 G06 的故事线或功能取舍；
- 用户只说“这一版不好”，但尚未形成可复用原则。

处理方式：修当前项目，必要时在项目内留下简短决策，不改全局规范。

## 5. 什么时候修改产品真源

只有当“产品实际能力/字段/限制/UI 行为”发生变化或现有事实被证明错误时，才进入 `spec/` / 产品源码真源。

不要因为宣传表达不好，就修改产品事实。

## 6. 什么时候废弃方法

出现以下情况之一，可以建议降级/废弃：

- 真实成品持续证明它降低质量；
- 新方法在相同场景中稳定优于旧方法；
- 方法带来的维护成本大于价值；
- 方法只为某个历史项目存在，已不再适用；
- 用户明确否决其作为生产方式。

废弃不等于删除历史。保留原因，但明确“不可作为当前生产依据”。

## 7. AI 的默认动作

用户只说人话，例如：

> “这张图太粗糙了。”
>
> “这个内容太流水账。”
>
> “能不能像这个参考图一样？”

AI 应自行完成：

```text
理解反馈
→ 判断问题类型
→ 判断影响范围
→ 当前项目直接修复？
→ 值得实验？
→ 是否可能成为稳定能力？
→ 给出最小必要变更
→ 验证真实产物
→ 决定是否晋级/废弃
```

用户不需要负责判断“改哪个文档”。
