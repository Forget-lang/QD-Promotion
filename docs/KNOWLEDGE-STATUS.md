# QD-Promotion · 当前知识状态

> 定位：告诉新会话“现在什么可以当默认方法、什么还在实验、什么已经废弃”。
> 本文件不是产品事实真源，也不是详细生产手册。它的价值是降低 AI 对历史资料的猜测。
> 维护原则：只记录“状态”，不重复详细规则；详细执行方法仍在 `SKILL.md`，产品事实仍在 `spec/`。

## 一、知识状态

### Stable · 已验证、可作为默认生产方法

以下方法已经通过真实产物和用户反馈证明有价值，但仍允许未来被更好的方法替代：

- 内容以“实体店商家真实痛点 → 一套完整攻略”为基本叙事单位，而不是功能流水账。
- 功能少而透：只讲真正参与攻略的功能，每个关键功能讲清“怎么设 → 为什么 → 设置后谁看到什么结果”。
- 产品展示优先使用真实产品 UI / 产品源码证据，不凭空画假产品界面。
- 优秀视觉参考优先抽取“做法/视觉语法”，不直接复刻载体与外观。
- 新视觉方向先做“一屏标杆”并用真实图确认，再铺完整片子。
- 能机器验证的事实、红线、工程状态、素材状态尽量交给脚本，而不是要求 AI 靠记忆。
- 真实画面与用户最终判断优先于“文档看起来全绿”。

## 二、Experimental · 实验中

这里记录的是仍需要通过更多真实产物验证的方法。实验状态不应被新会话自动当成硬规则。

当前重点由近期真实生产继续确认，包括：

- 非产品信息屏如何持续做到“高信息密度 + 高质感 + 行业自然”，而不是重新退化成廉价几何图。
- 哪些视觉语法可以跨行业复用，哪些必须每个行业重新设计。
- 如何把当前的视觉样本、UI 真值和 Remotion 能力进一步组合成稳定的自动设计能力。
- 如何减少人工逐屏审核，逐步让 AI 在出片前自己发现明显的内容与视觉问题。
- 如何逐步从“无声成片 → 审核 → TTS → 合成”过渡到一次生成完整可发布视频。

## 三、Deprecated · 已废弃

已被真实产物或后续实验否决的做法，不作为当前生产依据。历史原因保留在 Git / changelog / 旧文档中，但新会话默认不要回流。

典型类别：

- 为满足指标而硬凑装饰或静止/运动元素。
- 把页面点击顺序直接当成行业教程结构。
- 为了铺功能而把很多功能各讲一句，形成流水账。
- 把内部策划词、工程取证词、负面限制说明直接带进成片。
- 仅靠换颜色、换图标、换纹理冒充“换了一套视觉语言”。
- 用 `check-similarity` 的绿灯代替真实视觉相似性判断。
- 把历史测试片当成当前高质量视觉参考。

## 四、状态升级规则

```text
想法 / 用户反馈
    ↓
候选实验
    ↓
真实产物
    ↓
用户认可/否决
    ↓
继续验证可复用性
    ↓
Stable / Deprecated
```

“用户认可一次”只能证明“这一版有效”，不能自动证明“这是全局默认方法”。

## 五、给新会话的读取原则

1. 先用本文件判断知识成熟度。
2. 再读 `SKILL.md` 获取当前生产方法。
3. 需要事实时回 `spec/` 或产品源码。
4. 需要理解为什么形成某方法，再查实验记录或 changelog。
5. 不得因为历史文档写得很详细，就把它当成当前规范。
