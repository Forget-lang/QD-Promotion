# QD-Promotion · 文档架构迁移状态

> 版本：2026-08-31 v1
> 目的：防止新旧文档体系在迁移期重新混成一个“谁都可能是真源”的系统。

## 当前已生效

- `AGENTS.md`：新会话入口与知识读取顺序。
- `docs/PROJECT-UNDERSTANDING.md`：长期项目认知基线。
- `docs/KNOWLEDGE-STATUS.md`：当前能力成熟度。
- `docs/KNOWLEDGE-LIFECYCLE.md`：反馈影响范围与知识生命周期。
- `docs/EXPERIMENT-PROTOCOL.md`：实验、验证、晋级、废弃。
- `SKILL.md`：当前稳定生产方法，不再承担历史实验日志。
- `docs/AI使用手册.md`：用户只负责目标/反馈/拍板，不负责文档同步。
- `docs/DOCUMENT-ARCHITECTURE.md`：全局架构规则。

## 当前暂不迁移

现有 `outputs/gXX-行业/`、`outputs/archive/`、`docs/internal/`、`video/` 和 `spec/` 的物理目录暂不大规模搬迁。

原因：目录迁移不是当前痛点的核心，先验证“反馈分流 + 稳定能力 + 实验生命周期”是否真正降低维护成本。

## 对旧文档的解释

旧文档不是自动失效，也不是自动继续有效。AI 必须先依据 `KNOWLEDGE-STATUS.md` 和当前 `SKILL.md` 判断，再在需要时引用旧资料获取证据或历史原因。

如果旧资料与当前稳定方法冲突，以当前稳定方法为准；如果涉及产品事实，以产品真源为准。

## 下一阶段的迁移触发条件

只有当连续实际生产证明以下结构有效，才继续物理拆分：

1. 项目级内容与视觉可以独立于全局规则迭代；
2. 新方法可以在不修改大量历史文档的情况下进入实验；
3. 稳定方法更新时不会产生大量复制粘贴同步；
4. 新会话可以从当前状态快速恢复，而不需要阅读大量 changelog；
5. 用户只需提供目标和真实反馈，AI 可以自行完成知识分流。

否则应先修模型，不要继续增加目录。
