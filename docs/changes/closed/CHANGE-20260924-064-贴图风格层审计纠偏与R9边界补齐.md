## 二、Goal

修正静态贴图风格层接入后的文档边界，使：
1. R9 的通用导演原则不再把视频风格包写成唯一风格包实现；
2. `poster/styles/` 与 `video/styles/` 的职责边界在 R9 层也一致；
3. 贴图方法文档的章节顺序恢复为“既有抖音图文判线 → 方法/风格边界”，避免阅读顺序误导；
4. 明确 `posterStyles` 当前仅为独立贴图风格声明源，未接入视频闸门/轮换，也**不宣称已经存在独立贴图机器闸门**。

## 三、新口径 New Policy

1. 视频风格包的实现 Owner 是 `video/styles/`，服务既有视频内容线；独立静态贴图风格包的实现 Owner 是 `poster/styles/`，服务不依附 `gXX` 视频的静态贴图。
2. R9 继续只拥有通用视觉导演/审美判据，不拥有任一具体风格包的实现细节；视频与贴图风格包都必须满足“换包不改内容”的边界，但贴图暂不继承视频的风格轮换机检。
3. `scripts/ref-registry.json.posterStyles` 是贴图风格的当前登记/导航声明源；当前没有专门的贴图风格硬闸门消费者，因此“styleId 必须在 posterStyles 中”的执行以方法层人工核对为准，不把未存在的机器检查宣称为已接线。
4. 贴图方法层不再长期保存某个具体视觉包的色彩、字体或构图规则。
5. 063 为已关闭历史事务，不回写；本次只新增纠偏事务。
