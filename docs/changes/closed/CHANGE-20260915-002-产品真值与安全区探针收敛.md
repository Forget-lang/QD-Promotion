## 二、Goal
消除产品源码增长造成的历史 `src` 行号漂移假失败，同时保留“目标源码中不存在的产品字段”硬失败；把安全区检查收敛到真正影响抖音发布可见性的“信息内容不贴左右边缘、不被侧边 UI 吃掉”；固定 g11 生产验证口径。

## 三、新口径 New Policy
1. Product Truth 的字段真实性以目标源码文件中的逐字存在为硬真值；历史 `src` 行号只作为定位证据，发生插行漂移时记录 advisory，不将机械行号漂移当作产品事实错误。
2. `onScreen: false` 的字段在真值表自证与分组归属中均视为明确 retired / 不上屏条目；历史命名 `开启核销活码` 不作为当前上屏字段，当前产品命名统一为 **动态核销码**，源码已存在该最新原话。
3. 安全区硬闸门聚焦左右 120px 信息边界：重要文字、数字、实色信息不得侵入左右边带；字幕另查字形是否越左右线。顶部只做诊断，不机械定罪；底部字幕带不量。合法 full-bleed 背景/氛围层不属于信息安全区违规。
4. g11 生产 `sceneScale` 保持 `0.76`；不得以继续缩小 scale 代替定位真实越界来源。
5. 安全区探针不是“所有像素离边缘 120px”的审美尺子，而是捕捉明确会影响信息完整显示的危险侵入；机器结果必须与真图复核。

## 四、Replace
- `scripts/check-ui-truth.mjs`：历史固定行窗 → 目标源码全局硬真值 + 行号漂移 advisory；retired 条目不再误报硬失败。
- `scripts/probe-safe-area.mjs`：全幅像素污染式判定 → content-only 取证 + 左右信息安全硬判定，顶部仅诊断。
- `video/src/VTemplate.tsx` / `video/src/index.tsx`：增加确定性的 g11 安全区取证 Composition；生产 Composition 不改变背景与 `0.76` scale。
- `.github/workflows/visual-shot-contract.yml`：安全区只读取新鲜、隔离的 content-only frames；Gate all 通过后再生成独立生产静帧证据。
