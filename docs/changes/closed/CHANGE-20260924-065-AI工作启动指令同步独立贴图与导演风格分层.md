## 二、Goal

将用户侧工作控制台 `AI工作启动指令.md` 与当前 `AGENTS.md` 已生效的三类生产职责、R9 导演层、视频/贴图双风格命名空间同步，避免新会话在执行生产或复杂侦察时仍按旧的“两条视频内容线 + 单一 video/styles”模型路由。

## 三、新口径 New Policy

1. `AI工作启动指令.md` 只负责工作模式、路由与执行纪律，不复制 Owner 的具体业务规则。
2. 生产/制作类任务的一级路由不再默认等同于 `contentLines`；应先判断当前**内容职责**：
   - 行业场景视频 → `SKILL.md`
   - 产品功能教程 → `docs/internal/产品功能教程作业规范.md`
   - 独立静态宣传贴图 → `docs/internal/贴图宣传作业规范.md`
3. 视频风格层为 `video/styles/`，声明源为 `scripts/ref-registry.json.styles`；独立静态贴图风格层为 `poster/styles/`，声明源为 `scripts/ref-registry.json.posterStyles`。二者保持物理、登记、闸门隔离。
4. R9 在启动指令中应被描述为通用“导演决策 Owner”，负责“为什么这样讲、为什么这样看”的导演层，不把具体风格技法或生产流程收归 R9。
5. 场景 B、G、M 等涉及选题/生产/侦察的入口提示必须能正确识别独立静态贴图，但不在启动指令中复制贴图 Owner 的具体流程。
6. 不新增场景编号，不建立第二套贴图工作模式；独立贴图接入既有场景骨架。
