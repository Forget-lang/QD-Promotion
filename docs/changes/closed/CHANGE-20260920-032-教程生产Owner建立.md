#### 3.5.1 模型缺口与最小修法（初稿"N/A 默认态"被复核拦下后的修正）

**缺口陈述**：031 冻结的五态（`APPLY`／`OBSERVE`／`N/A`／`OWNER_PENDING` ＋ 运行时失败态"判不了线"）描述的是**闸门×线的结果**；解析链为"`gateOverrides[闸门][线]` → 无则落 `defaultApplicability`"。这套模型**无法表达**"Owner 已建立、但某个闸门尚未对该线做适用性声明"——初稿把默认态写成 `N/A`，会让未来新增闸门在漏登记时**静默得到 N/A**，正是 031 消灭的"未声明 ≠ 不适用"。

**回答复核提出的问题**（"怎样区分'真正声明的 N/A'与'根本没做决策'？"）：**靠位置与值**——
- 真正声明的 `N/A`：一定来自 `gateOverrides[闸门][线]`（逐闸决策）或整线 `defaultApplicability`（如行业线的 `APPLY` 是同型整线声明）；
- "没做决策"：用默认位置专用策略值 `EXPLICIT_REQUIRED` 表示——解析器遇到它**抛硬错误，不返回任何状态**。故闸门**只可能**收到 APPLY／OBSERVE／N/A／OWNER_PENDING 四种结果；"未声明"永远到不了 N/A。

**最小修法（本事务实施）**：
1. `scripts/content-lines.mjs`：`values` 新增 `EXPLICIT_REQUIRED`（描述="仅作内容线 defaultApplicability：该线不设默认适用性，每个闸门必须显式登记；未登记即硬失败，不得当作 N/A"）；`gateAppliesFor` 在默认位解析出 `EXPLICIT_REQUIRED` 时抛可读硬错误（**错误信息自带修法**："闸门「X」未对内容线「Y」声明适用性——请在 `gateOverrides['X']['Y']` 登记 APPLY／OBSERVE／N/A 后重跑（该线不设默认，见 CHANGE-20260920-032 §3.5.1）"）；统一入口预检拒绝把 `EXPLICIT_REQUIRED` 写进任何 `gateOverrides`（作用域校验）。
2. **4 处调用点补 try/catch**（`check-similarity`×2、`check-bg`、`check-motif-card`）：未声明错误＝可读报错＋`exit=1`，不抛裸堆栈——与 031"统一诊断边界"一致。`check-layout-diversity`／`check-voice-brand`／`gate-all` 已有包裹，仅把 catch 前缀由"内容线声明非法"放宽为"内容线适用性声明问题"（覆盖"声明缺失"与"取值非法"两种）。
3. **`OWNER_PENDING` 语义不动**：仍＝"该线权威 Owner 未建立"，保留给未来新内容线的建立前阶段。内容线生命周期＝`OWNER_PENDING`（建线未立 Owner）→ Owner 建立时改为 `EXPLICIT_REQUIRED`（逐闸必须声明）→ 未来如有整线策略可改整线声明值。本事务不改 `OWNER_PENDING` 的定义与消费者文案。
4. 与五态的关系：**不是替换**。五态仍是闸门×线的结果枚举；`EXPLICIT_REQUIRED` 是**默认位置的策略值**、不参与 `gateOverrides`——模型从"两级回退"升级为"两级回退 ＋ 默认位可声明'必须显式'"。

**三处保证**（对"未来新增闸门不会因默认值静默 N/A"）：
- **保证一（拦截点）**：新闸门若未登记 tutorial 适用性，命中即抛硬错误，绝不返回 N/A；无教程数据时闸门天然不与该线交互（无目标即无判定，非静默放行）。
- **保证二（作用域）**：`EXPLICIT_REQUIRED` 写进 `gateOverrides` 被统一预检拒绝，杜绝被误用为"闸门结果态"。
- **保证三（对称性）**：与 031 既有的"判不了线→硬失败"同构——**未知一律响亮**。

6. **硬顺序（机器强制，本事务后生效）**：本事务 `CLOSED` → f01 事务方可启动；f01 事务启动前，`video/src/data/` 不得出现真实 `f*.ts`、`outputs/` 不得出现 `fXX-功能/`。
