# Change Contract

## 一、基本信息

- changeId：`CHANGE-20260924-057`
- 标题：豁免收窄——只裁「判据红」，不裁「探针不可用」（探针自报状态）
- 负责人：项目 AI（执行）／用户（方向）
- 范围：`global`
- 状态：`CLOSED`
- 来源：2026-09-24 复盘审计发现 T 类问题：`gate-all` 的豁免是**一把梭**（`if (!row.ok && waiver)`），任何非零退出都被转成"已裁放行"；同日实测发生——本机 `video/node_modules` 缺失致探针报"找不到 ffmpeg"，该行仍显示为已裁放行。

## 二、Goal

让豁免只覆盖它当初被批准覆盖的东西：**判据给出的红**。探针因环境/输入问题没跑起来时，红灯必须**照原样红**，不得被豁免通道吞掉。否则"已裁放行"会同时掩盖两类完全不同的东西——"这条片的历史红我们认了"与"我们的尺子今天根本没量"。

## 三、新口径 New Policy

1. **探针自报状态**：`check-motion.mjs` 与 `probe-safe-area.mjs` 在退出前打印一行 `PROBE_STATUS=<状态>`：
   - `VERDICT`：真的量过并给出判据（**达标或未达标都算**）；
   - `UNAVAILABLE`：环境/输入问题没量成（缺 ffmpeg、解码失败、采样帧过少、参数不合法）。
2. **豁免资格**：`gate-all` 只在 `PROBE_STATUS=VERDICT` 时允许套用 `motionWaivers`／`safeAreaWaivers`；`UNAVAILABLE` 或**缺状态行**（探针崩溃/被替换）一律**不可裁**，红照原样显示并附注原因。
3. **fail-safe 方向**：未知状态按"不可裁"处理——宁可多亮一盏红灯，也不许把不可用伪装成已裁。
4. **`--json` 模式不受影响**：`check-motion --json` 不打印状态行，stdout 保持纯 JSON（本仓库当前无 `--json` 消费者，属预防性边界）。
5. **既存豁免不动**：6 条 `motionWaivers` 与 1 条 `safeAreaWaivers` 的判词、依据、生效范围零改动——它们的红都是判据红，仍照旧被裁。"过期证据"（本闸自算的判据红）同样保持可裁。
