## 三、新口径 New Policy

1. **审核类一律不进内容**。券 / 券包 / 次卡的审核状态（`auditStatus`）属**平台安全合规机制**，与"功能怎么用"无关 → 不上屏、不进口播、不写进发布稿；**不出现**「审核 / 待审核 / 审核通过 / 审核失败 / 已认证 / 违规锁定」及任何同义改写（如"平台会先过一遍"）。**也不讲审核是否阻断发放**（该点本身在 `facts.unverified` 里未定，更不该进内容）。
2. **版本档位类一律不进内容**。系统内存在商家版本档位（次卡「每张包含次数」上限随档位变化、积分兑换受版本开关约束），但对外**不提版本、不提档位、不说"升级/解锁可提升上限"**。
3. **次卡「每张包含次数」的正常讲法**：**按本片设计的行业活动正常给具体次数**——该说 7 次卡就说 7 次、该说 30 次卡就说 30 次，**该怎么讲就怎么讲**；**上限以 `facts.constraints` 的 1000 次为准**，只要不超过 1000 即可。
   - **禁止**改成"在可选的最大次数范围内"这类**抽象说法**（用户 13:12 明确否决）；
   - **禁止**引用档位值（7/30/100/365），也禁止说"档位不同上限不同/升级可提高上限"。
4. **总原则**：内容只讲功能本身；审核与版本档位都**不构成讲解难点**。
5. **不动既有数值**：`facts.constraints` 的「次卡每张次数（TIMES 型）1~1000 次」**是正确口径，保留原值不动**——本次只在内容侧堵住"档位"这个说法，不改真值。
