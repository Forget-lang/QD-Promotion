# CHANGE-20260916-003 · 全局治理阵型收口

- 状态：MIGRATING
- Issue：#3
- 目标：把“先统筹全局、后局部执行”的原则升级为仓库最高治理戒律，彻底降低文档维护成本，杜绝 Owner/入口/规则/历史边界反复漂移。

## 1. 最高原则

> **先察全局，后定阵型；先立中军，后分兵执行；先清旧阵，后布新阵；任何局部修改，不得破坏全局唯一性、边界、Owner、入口和历史/当前分层。**

## 2. 六条不可破戒

1. 任何规则必须有明确落点。
2. 任何落点只能有一个 Owner。
3. 任何引用只能指向 Owner；非 Owner 只能解释、引用、导航，不得重新定义同一规则。
4. 任何替代必须清理旧阵：新口径进入 Owner 后，旧口径必须删除或进入明确的 deprecated registry，不能长期并存。
5. 任何历史必须退出当前指挥链：archive/changelog 只能提供证据与回顾，不得成为当前入口、当前规则或当前状态源。
6. 任何全局改动必须先完成战场侦察与影响面布阵：资源、Owner、规则、入口、依赖、重复、冲突、断档、当前/历史边界、P0/P1/P2，再进入 Migration。

## 3. 文档角色侦察结论

本事务补充确认了一个此前未被正确建模的角色：

| 角色 | 当前落点 | Owner 性质 | 是否进入 AI 自动读取链 |
|---|---|---|---|
| AI 自动入口 / 项目宪法 | `AGENTS.md` | 全局治理 Owner | **是，唯一自动入口** |
| 用户指挥接口 / Prompt 模板 | `AI启动提示词.md` | **用户操作接口，不是规则 Owner** | **否；由用户复制/粘贴触发** |
| 视频生产作业流程 | `SKILL.md` | 生产 Owner | 按任务读取 |
| 产品/红线/字段事实 | `spec/*` | 各真源 Owner | 按任务读取 |
| 领域方法/技术/视觉/治理 | R2–R10 | 各领域 Owner | 按任务读取 |
| 当前状态总账 | `PROJECT-CONSISTENCY-MAP.md` | 状态索引 | 按需读取 |
| 历史证据 | `outputs/archive/` / `changelog` | 历史记录 | 不进入当前指挥链 |

关键结论：

> `AI启动提示词.md` 与 `AGENTS.md` **不是两个“AI 入口”**。前者属于用户侧操作接口，后者属于 AI 进入仓库后的自动入口；二者是上下游关系。

本事务已将当前用户提示模板恢复到根目录；`outputs/archive/AI启动提示词.md` 降级为历史快照，并同步归档 README 的角色说明。
