## 二、Goal

修掉一个**已经形成的死结**：

`visual-shot-contract` 工作流的最后一步是 `gate-all`，且它是**硬步骤**（无 `continue-on-error`）；而 `gate-all` 里含 g11 线的 2 道**既存红**（文档引用 5 处断链＋母题卡 g10 缺口）。因此——

1. **该工作流只要 g11 线那 2 道红不除，就恒红**；"全绿 fresh CI"在结构上**不可得**；
2. `005`、`010`、`011` 三笔未关闭事务，全部把"final candidate 上的 fresh CI"写成唯一剩余前置 → **它们被一个不可得的东西卡住**；
3. 而 CI 运行记录由 GitHub 侧产生，本地取不到（无 `gh`；仓库 `Forget-lang/QD-Promotion` 私有，匿名 API 返回 404）→ 连"确认它是否跑过"都做不到。

**结论：把"证据从哪来"与"判据是什么"解耦。** 前者换成可本地取得、可复算、可审计的路径；后者一个字不放松。

## 三、新口径 New Policy

1. **关闭证据以「最终候选状态上的重跑」为准**，不再要求 GitHub CI 运行记录。取证方式二选一：
   - ① **CI 可用且能取到运行记录**时：用 fresh CI（原路径保留）；
   - ② **CI 不可得、或该工作流会因与本次改动无关的既存红恒红**时：在**干净检出**上按工作流原样步骤重跑 —— `git worktree add --detach <候选 commit>`，**工作树零改动**，并逐条记录退出码。
2. **等价重现必须对齐 CI 的前置步骤**，不得拿本机现成环境顶上：至少包括 `npm ci --prefix video`（或等价的依赖就位）与 APPLET 快照 materialize（`spec/product-truth/applet/source.tar.xz` → `../applet`，文件数须为 **298**）。**前置未对齐会引入假红**（本事务实测到过，见 §九 负向观察）。
3. **既存红必须点名归因**：报告中须逐条列出红项、并说明为何与本次改动无关；**不得**把既存红表述为"通过"，也不得因为"反正会红"就跳过任何步骤。
4. **不降低任何判据**：本口径只换"证据从哪里来"——不改任何闸门语义、不删任何检查项、不把任何硬步骤改成 `continue-on-error`、不宽免任何红。`R8` §九 的全部关闭条件与「必须有一个自己构造的反例测试」维持原样。
5. **报告须写明候选 commit 短 SHA**，否则"最终候选状态"不可核对。
6. **对既有未关闭事务普遍生效**（`005` / `010` / `011`），**不逐笔回填历史正文**；需要时以本事务为订正落点。
