### 3.2 闸门模型：namespace + applicability 两层

不是把 `g` 正则替换成 `[gf]`，而是先确定内容线、再确定该线目标：

- `check-similarity.mjs`：统一读 `video/src/data/index.ts`；行业线只比 g↔g，教程线只比 f↔f，跨线默认不比较；"最新一条"必须先按线筛选再按数字编号定序。
- `check-bg.mjs`：按线选择目标；行业线背景底要求不变；教程线是否要背景底由教程 Owner 定义，本事务不为其新增或继承任何内容要求。
- `check-layout-diversity.mjs`：行业线 g↔g；教程线纳入扫描入口，专属 layout 判据由后继事务定标；**禁止字符串排序模拟"上一条"**（`'f01' > 'g11'` 会判错），必须按 `(contentLine, numericId)` 排序。
- `check-voice-brand.mjs`：g/f 均进入扫描，删除"非 `g\d{2}` 即 `continue`"的静默漏检语义；不适用对象必须显式输出。
- `check-motif-card.mjs`：行业母题卡不套教程线；教程线必须获得**显式 N/A ＋ reason**，不得静默忽略；教程视觉规范卡及其机检归后继事务。
- `check-voice-discipline.mjs`、`check-redlines.mjs`：g/f 一体适用，零改动。
- `gate-all.mjs`：`newestVideo()` / `newestFrames()` 禁止再用全局 mtime 猜当前片，改为显式按线取目标（如 `--line g` / `--line f`）；`check-motion.mjs` 是参数驱动的算法，其计算与合格线**本身不动**——教程线观察态只落在 `gate-all` 汇总层，与 `safeAreaWaiver` 既有的"豁免在汇总层、probe 本体不动"同构（CHANGE-20260918-029 先例）。
- `list-assets.mjs`：开工视野脚本按 `spec/assets.json` 的 `D` 求和展示（实测 `:189-190` 输出"D 级截图…配图先查分类表"）。D 的语义扩展后，本脚本必须同步：既不漏计 `screenshotLedger`，也不与 `D.categories.files` 重复计数，且旧"配图"文案不再代表 D 的全部职责。
- `ref-registry.json`：豁免类登记（背景/布局/相似度/尺子/探针）增加内容线维度；g 系既有豁免逐条原样保留，**不得因改造而扩大命中面**。适用性（APPLY / OBSERVE / N/A）的**声明源是注册表或 Owner 文档，脚本只读取声明**；禁止脚本用 `g`/`f` 前缀自行推导不适用（`if (!/^g/.test(f)) return 'N/A'` 属隐式 applicability，本事务明确禁止）。

### 3.2.1 内容线状态机（五态）与硬顺序（阶段 B 执行中补入）

每个闸门对每条内容线只能处于五态之一，且**必须由声明源给出**（`ref-registry.contentLines` ＋ `gateApplicability`），脚本不得用 `filter`／前缀判断／默认值把任何一种状态"算出来"：

| 态 | 行为 | 退出码 |
|---|---|---|
| `APPLY` | 按现行判据执行 | 正常 |
| `OBSERVE` | 照测照出读数，但不判红（仅用于教程线 motion） | 正常 |
| `N/A` | 显式输出 `N/A ＋ 声明源位置`，不静默跳过 | 正常 |
| `OWNER_PENDING` | 该线权威 Owner 未建立 → **显式硬失败**，指名"先立 Owner 再产出" | 1 |
| 判不了线 | 目标命名不在声明内 → **显式硬失败**，要求补声明或改名 | 1 |

**被 AI-A 认定为阻断点的一条**：本状态机不允许"把不属于本闸门的文件从集合里 filter 掉"这种写法——它等价于本事务正在消灭的静默跳过，只是换了实现。`check-layout-diversity` 首轮改造曾犯此错（教程数据文件被过滤而非报 `OWNER_PENDING`），已修正并纳入负向测试。

**枚举注册与校验（防"代码在用、声明没登记"）**：`OBSERVE` 属合法声明态，必须登记在 `ref-registry.gateApplicability.values`；`判不了线` 是**运行时失败态**，不进枚举（它表示"没有任何合法声明匹配到该目标"）。共享模块对 `contentLines[].defaultApplicability` 与 `gateOverrides[gate][line]` 的取值做枚举校验，写入 `OBSERVE2 / PENDING / OPTIONAL / 小写 apply` 等未注册值一律**可读报错 ＋ exit=1**（不抛未捕获堆栈，便于 `gate-all` 显示与后人诊断），也不静默退化成某种合法态。

**统一诊断边界（阶段 B 执行中补入）**：配置类失败有四条路径——① `contentLines[].defaultApplicability` 非法；② `gateOverrides[gate][line]` 非法；③ `ref-registry.json` 不可读或 JSON 损坏；④ `contentLines` 整体缺失。四条必须由**同一个入口**（`content-lines.initContentLines`）给出同一种"可读诊断 ＋ exit=1"，且**消费者不得再自行 `readFileSync + JSON.parse` 声明源**（否则损坏时会从消费者抛出未捕获堆栈，形成第二种失败形态）。

② 的检出口径为**统一入口全量预检**：`initContentLines` 一次性遍历 `gateOverrides` 全部取值校验，**不采用"用到那条线才检查"的惰性口径**——惰性会让只有别的闸门消费的坏账安静躺着，直到某次无关运行才炸。因此任一 `gateOverrides` 取值非法，所有已迁移消费者一起以可读诊断失败（registry 是共享配置，全局失败是有意决定；代价见 §十 反例 7）。`gateAppliesFor()` 内的校验保留为防御式第二道。

实测四条路径在 `check-layout-diversity` 与 `check-voice-brand` 上均为 `exit=1`、首行可读、无堆栈；并把"非法值出现在**本消费者并不使用**的 gate 覆盖项上"单独验一次，仍须炸（证明是全量预检而非用到才查）。已知表现差异（不影响语义）：`check-voice-brand` 把其自身循环内的 `gateAppliesFor` 异常归入硬失败清单打印，`check-layout-diversity` 归入声明非法行——两者都响亮、都 exit 1，不追求逐字同形。

**门状态即执行边界（阶段 B 执行中补入，适用所有已迁移闸门）**：`OWNER_PENDING` / `N/A` / 判不了线 / 未注册目标一旦判定成立，必须**立即停止、不再执行该闸门的任何判据**；"照常把判据跑完、最后才 exit 1"不成立——那等于一边宣布不适用、一边用行业尺子裁了该线内容，仍属机械继承。分组比较类逻辑必须**只对 `APPLY` 的线构建分组**（从结构上排除误执行），而不是先全量比较再补一句失败。诊断性数据转储（如指纹清单）可以保留，但它不得参与判定或产生"通过/不通过"语义。

**硬顺序（后继事务必须遵守）**：
`先立教程 Owner（方法文档 ＋ 该线在 gateApplicability 中的 APPLY/OBSERVE/N/A 判定）→ 才允许出现第一条真实 f 数据文件`。
在 Owner 建立前放入 `video/src/data/f*.ts`，会被 `check-voice-brand`、`check-layout-diversity`、`check-similarity` 显式判红——这是设计意图，不是缺陷，不得通过把闸门改成"跳过"来消除。

### 3.3 教程线效果尺状态（新增线级判定态）



行业线：`check-motion` 三项合格线继续按硬闸执行，数值不动。

教程线：本事务**不重定** `45% / 0.35 / 70%` 任何数值；教程片的效果尺结果作为**观察/诊断证据**输出，不作为内容长度或教学完整性的否决依据。该状态必须在实现上**区别于 `motionWaivers` 的"已裁放行"**——不复用 `skipped + ok:true` 豁免通道、不需要豁免登记、输出标签可辨识（"已测·观察（不判红）"）。理由：`check-motion.mjs` 对整段成片求**全片统计量**（静止占比＝帧间差 ≤`DEAD_T` 的帧对数 ÷ 全部帧对数；另有中位帧间差、画面占用率），**代码中不存在"100 秒窗口"这一判定**——"全片 100 秒内有无持续变化"是 `SKILL.md` 第 6 步**叙事 8 问第 ⑤ 问**的人判条目，不是机检定义，本契约不得把两者混为一谈。真实风险在于全片比值统计的分母随时长增长：长片可能结构性偏离短片，该偏离已有 g11 实测同型证据（无声 96.66s→有声 106.27s，静止 49%→54%、帧差 0.32→0.23）。因此本事务只把教程线结果降为观察，不据此调任何封版基线。是否建立教程专属判据，由后继事务按 `SKILL` 第 6 步定标纪律（先向好/坏样本入库 `outputs/archive/calibration/` 再重定标）决定。

### 3.4 红线适用范围拆分

`spec/redlines.json` 仍是唯一红线 Owner，只做 applicability 拆分，不新建第二红线源：

- `rules.video_visual`：行业线继续现有 Remotion 代码 UI 路线；教程线允许真实产品截图作为教学证据，条件是来源可追溯、有当前产品真值对应、有 D-1 登记，且**不因此解除微信/导流/平台任何红线**，发布前逐屏人工确认。
- `rules.content_ratio`：行业线 8:2 与产品界面 ≤1/3 原样保留；不再机械套用于"产品本身即教学对象"的教程线；教程线内容比例与商业浓度口径由教程 Owner 单独定义。
- `rules.brand_display`：行业线画面/封面零品牌名原样保留；教程线允许标题、封面出现「券到卡包」，以及真实教学画面中的产品识别信息；该允许项不自动解除 `account_profile`、平台规则、导流禁令与其他红线。
- 依据等级校正：**`rules.content_ratio`** 中的"产品界面占比 ≤1/3"一类数值，其外部出处经实测为抖音《小程序推广计划任务审核标准》"示例视频"条款（该文档自我限定为"面向开发者发布的特别约定"，页面更新时间 2026-01-13）。因此该 1/3 条款**不能直接作为自然分发内容的适用依据**；但本事务**不**据此得出"自然分发不受任何同类要求约束"——自然分发侧同类条款的取证尚未完成，列为后继事务发布前的前置取证项（本事务不把它写成已成立事实）。据此，该数值的分线适用性属我方内部分发策略，不得表述为平台强制上限；行业线继续使用该值。同理，该文档中"商品/品牌/App 界面主体展示""无法核实真伪的优惠券等招揽信息"等条款，对本场景只具有**审核经验性参考**价值，不是判据来源。
  > 勘误（阶段 C 补）：本段初稿误写为 `rules.video_visual` 中 ≤1/3——该数值实际位于 `rules.content_ratio`；`rules.video_visual` 管的是"视频主视觉不用截图"（另一条，已在 §3.4 第一项处理）。已按实际位置更正。

### 3.5 截图证据 D-1

扩展进既有素材唯一真源 `spec/assets.json`，不新建台账：`D` 的职责由"文章配图速查"扩为"产品截图素材唯一真源"（同时服务文章配图与教程教学截图），新增 `D.screenshotLedger`，字段：`screenshotId`、`localFileName`、`sha256`、`capturedAt`、`appletSnapshot`、`truthRef`、`sourceLocation`、`verificationStatus`（取值 `reference-only` / `current-verified`；该状态是**素材属性**，不构成第二状态源）。

- PNG 本体继续留在 `截图素材/`，不进入 Git（`.gitignore:31` 保持）。
- 校验边界：Git/CI 校验登记结构、`truthRef`、`sourceLocation`、字段格式；本地生产负责确认文件存在、重算 SHA-256 与登记一致、人工逐屏确认图文相符。**机器不得声称能判断截图像素与真实 UI 是否相符。**
- 书写禁令：截图本体一律以 `screenshotId` 指代，**禁止在文档中以反引号路径书写**（`check-doc-references.mjs:130` 的 `RES_ROOTS` 含 `截图素材/`，会对本地文件做磁盘存在性硬失败，而 CI 上不存在本体）；字段名用 `localFileName` 不带目录前缀。
- **存量 88 张截图的资格重定义（本事务新增，属 D-1 语义迁移本体，不后移）**：现有截图属**历史素材库**，经用户确认其中部分可能已与当前前端源码不一致，因此其状态比"缺版本锚点"更严——**默认 `reference-only`**：可用于找页面、找字段、找操作路径、当 UI 参考，**不自动视为当前产品真值**，且**不得因"已登记在 `assets.json`"就直接进入教程成片**。不采用"已废弃"作为默认状态，旧图仍具历史参考价值。
- **不启动全量重拍**：纠正路径是**按使用逐张核验**——某条教程确实需要某界面时，回 `APPLET` 当前 live / snapshot 比对 `truthRef` 与 `sourceLocation`；不一致则重截，一致则重确认并登记，`verificationStatus` 由 `reference-only` 升为 `current-verified`。一次性把 88 张全部重做属"以大而全重写替代增量迁移"，本事务禁止。
- **证据链主锚**：`screenshotId → sha256 → appletSnapshot(或 commit SHA) → truthRef → sourceLocation`。`capturedAt` 只是采集时间元数据，**不能单独证明截图对应的源码状态**，不得当主锚使用。
- 只有 `verificationStatus = current-verified` 的截图可进入教程教学素材链；`reference-only` 被教程素材引用时必须判失败（见 §十 负向测试 7）。
- 与既有事实守门的关系（实测确认，避免新造机制）：`check-facts.mjs:53-67` 已把 D 级整体登记为**外部项**（`reason: 'external screenshot library'`，不计为仓库磁盘资产缺失），这是该脚本头注释"不把 Agent 本机相对路径伪装成仓库内资产"规则的既有实现。`screenshotLedger` **沿用同一"外部项"归类**，并把它的登记名 ↔ 本地文件存在性对账、`verificationStatus` 取值受控一并纳入这条已经存在的双向核对逻辑。如此既复用现成机制，也不让机检假装能验证仓库里并不存在的图片本体。

### 3.6 时长与结构边界（不设数值口径）

教程线不设项目级时长档、不设硬时长上限；时长按"一个完整使用任务是否讲透并形成闭环"决定；拆片依据是内容是否自然分叉为两个独立使用任务，不以秒数为条件。本事务**不新增教程时长数字**，因此不登记数值口径属主，也**不修改** `ref-registry.json` 的 `caliberOwners`（`60-90 / 90-120 / 120-150 / 硬上限 200s` 继续只服务行业线）。教程 Owner 表述时须正面书写，**禁止出现"不受 200s 上限约束""不适用 120-150s"这类否定式复述**（会命中 `caliberOwners` 的属主外复述判定）。

结构边界：一条教程只承担一个完整使用任务；字段多、步骤多、联动复杂均可继续讲，不因时长压缩。

### 3.7 教程内容前提与账号身份

教程内容只讲功能本身，不以版本/档位/升级为话题（依据 `spec/facts.json` `forbidden_claims` #11，2026-09-17 裁定）；"不提版本"不得被解释为可虚构能力或覆盖 Product Truth。功能、数字、字段、限制一律回 `APPLET / spec/`。

教程线仍发布在现有账号。本事务不把账号整体改造为官方产品账号，`rules.account_profile` 不因教程线自动改写；内容级产品身份与账号级身份分开治理。

### 3.8 注册链

1. 假 `fXX` 不得改变任何 g 条目的既有判定结果（阶段 A/D diff）。
2. 假 `fXX` 不得成为 g 线的 latest video / latest frames。

4. 任意非 g 前缀数据文件不得因片号格式不符而静默绕过 `check-voice-brand`。
5. 教程线观察态不得使任何 g 线条目变绿，也不得写入 `motionWaivers`。
6. 缺 `sha256` 或缺 `truthRef` 的 `screenshotLedger` 条目必须被 `check-facts` 判失败。
7. `verificationStatus = reference-only` 的截图被教程素材链（fixture）引用时必须判失败；只有 `current-verified` 可进入教学素材链。

   > 实测（阶段 C 补做后）：账本独立成行计数；重复登记被显式标注为"❌ 与分类表重复登记 N 条（双登记，check-facts 判失败）"而非静默去重，同时 `check-facts` 判红（`exit=1`）——两处同时显形。
10. 教程线观察态若被实现为写入 `motionWaivers`／`safeAreaWaivers`，视为不通过（观察 ≠ 豁免，前者无需批准人与理由）。

12. 往 `gateApplicability.gateOverrides` 写入枚举外取值（如 `OPTIONAL`／`PENDING`）时，**消费该闸门的脚本必须可读报错并 exit=1**，且 `gate-all` 对应行显示这条错误而非堆栈尾行；还原合法值后判定须与基线一致。
13. 配置类失败四条路径（`defaultApplicability` 非法／`gateOverrides` 非法／`ref-registry` JSON 损坏／`contentLines` 缺失）逐一注入后，每个已迁移消费者都必须 `exit=1` 且**输出首行可读、不含 Node 未捕获堆栈**；其中"JSON 损坏"这一条若从消费者自己的 `JSON.parse` 抛出，即判为统一诊断边界未收住（消费者不得自行解析声明源）。
14. 把非法值写在**本消费者并不使用**的覆盖项上（例：只改 `gateOverrides['check-bg']['tutorial']`，然后跑 `check-layout-diversity`），仍必须 `exit=1` 并指出该具体路径。若这一情形静默通过，说明 ② 退化成"用到才查"的惰性校验，统一入口预检不成立。
15. 向 `video/src/data/` 放入**未注册进 `data/index.ts`** 的 `.ts`（含 `f*.ts`）时，以 index 为数据源的闸门（`check-similarity`、`check-bg`）必须显式报"未注册/静默不可见"并 exit=1；两种调用形态（默认与 `--all`）都要抓到。只扫 `data/` 目录的闸门（`check-voice-discipline`、`check-voice-brand`）不适用本条，但须由负向 11 覆盖。
16. 相似度闸门的 `--all`（基线取证模式）：教程数据文件存在时**不得返回 0**（跨线泄漏）；且在门状态已判为不可适用时，**不得产生任何两两比较/判定输出**（只允许诊断性清单）——"跑完判据再 exit 1"按不通过处理。
17. `N/A` 必须是"不执行"，不是"必然通过的执行"，**且须有正向对照同时成立**：
    - 正向对照（证明判据真的会执行）：给**行业线**数据文件配一个不存在的 `bgImage`，闸门必须 `exit=1` 并指出文件不存在；
    - 反向（证明 N/A 不是"执行一次必绿"）：给**教程线**数据文件配同样的非法取值，在 `N/A` 下应 `exit=0` 且打印带声明源的 `📤 N/A`。
    ⚠️ 取证口径：若 APPLY 分支被"拒绝机械继承"保护条款先行拦下（该闸门尚未实现该线判据），则**只算证明了保护条款生效，不算完成本条**——必须补跑行业线对照，否则不得登记为 PASS。
    另须验：`data/index.ts` 无导出但 `data/` 有文件时，必须报"注册链断裂"而非"基线为空"。
18. **`industry` 声明缺失不得退化为假绿**：删除 `contentLines` 中的 `industry` 项而保留 `data/*.ts` 时，每只已迁移闸门必须 `exit=1` 并指向"未声明 industry 内容线"。此情形下 `classifyLine` 对 g 文件返回 null（前缀匹配依赖声明存在），因此**只加后置守卫不够**——守卫必须前置在任何"该线无目标 → 视为基线为空"的分支之前。

19. **兜底：判得了线但该线未被本闸门遍历**（如 `contentLines` 被改成不含 industry 的多线组合）→ 必须硬失败，不得静默放过。实现时须**显式排除 industry 本身**，否则会把全部 g 数据误判为异常（此错在阶段 B 实际发生过一次，被"与基线逐字节一致"的回归当场抓住）。

### 语义反例（改了关键词但本质仍违规）

1. **字符串排序伪 namespace**：把文件名字典序当"上一条"（`f01` 排在 `g11` 之后）。本质仍是全局顺序，不是内容线顺序。由 `check-layout-diversity` 的 `(contentLine, numericId)` 实现与负向测试 1/2 拦。

3. **截图已登记即真实**：`screenshotLedger` 字段齐全但图是旧版界面（用户已确认存量截图部分可能与当前前端不一致）。机器判绿、语义为红。拦截层：`verificationStatus` 资格门槛（负向测试 7）＋ 以 `sha256`/`appletSnapshot`/`truthRef`/`sourceLocation` 为证据链主锚（`capturedAt` 不作主锚）＋ 图文相符由人工逐屏确认（R8 §十 人机边界）。

5. **为过尺压缩教程内容**：用观察态作借口，反向把长片砍短以迎合旧阈值。观察态的语义是"不判红"，不是"内容向尺子靠拢"。拦截层：§3.6 结构边界（一条教程＝一个使用任务）＋ 后继事务定标。
6. **观察态伪装成豁免**：为让教程线"不判红"，直接给它写一条 `motionWaivers` 登记（或反过来把 g 系豁免的匹配放宽）。前者把"未判"说成"人已裁"，后者会扩大 g 系豁免命中面。机器两边都可能显示绿灯，语义均已错位。拦截层：负向测试 5/10 与 §3.3 实现约束（观察态落在汇总层、独立标签、不进豁免表）。
7. **全局预检伪装成本地校验**：为了让"配置错必须响亮"，把 `gateOverrides` 全量校验放进统一入口，却不同时约束爆炸半径——一处与本闸门无关的坏值会让所有闸门一起红。本事务接受这个代价（registry 是共享配置，一起红有助于立刻发现），但必须显式登记：判定逻辑本身不受影响，**不得**为了让某个闸门单独变绿而回退成惰性检查，也不得把这种红写成"教程线有问题"。归因口径：这类红的正确修法是改 registry，不是改闸门。
