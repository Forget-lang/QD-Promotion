## 三、新口径 New Policy

### 3.1 Owner 与入口

唯一 AI 自动入口不变：`AGENTS.md`。Owner 地图拆为两条生产职责：行业场景视频 → `SKILL.md`；产品功能教程 → 教程生产 Owner（由后继事务建立）。教程 Owner 不占 R 编号，因其属生产流程层，与 R2–R10 的协议/参考层不同；同型先例为 `整改作战总纲.md`、`内容资源调用协议.md`。

### 3.2 闸门模型：namespace + applicability 两层

不是把 `g` 正则替换成 `[gf]`，而是先确定内容线、再确定该线目标：

- `check-similarity.mjs`：统一读 `video/src/data/index.ts`；行业线只比 g↔g，教程线只比 f↔f，跨线默认不比较；"最新一条"必须先按线筛选再按数字编号定序。
- `check-bg.mjs`：按线选择目标；行业线背景底要求不变；教程线是否要背景底由教程 Owner 定义，本事务不为其新增或继承任何内容要求。
- `check-layout-diversity.mjs`：行业线 g↔g；教程线纳入扫描入口，专属 layout 判据由后继事务定标；**禁止字符串排序模拟"上一条"**（`'f01' > 'g11'` 会判错），必须按 `(contentLine, numericId)` 排序。
- `check-voice-brand.mjs`：g/f 均进入扫描，删除"非 `g\d{2}` 即 `continue`"的静默漏检语义；不适用对象必须显式输出。
- `check-motif-card.mjs`：行业母题卡不套教程线；教程线必须获得**显式 N/A ＋ reason**，不得静默忽略；教程视觉规范卡及其机检归后继事务。
- `check-voice-discipline.mjs`、`check-redlines.mjs`：g/f 一体适用，零改动。
- `gate-all.mjs`：`newestVideo()` / `newestFrames()` 禁止再用全局 mtime 猜当前片，改为显式按线取目标（如 `--line g` / `--line f`）；`check-motion.mjs` 是参数驱动的算法，其计算与合格线**本身不动**——教程线观察态只落在 `gate-all` 汇总层，与 `safeAreaWaiver` 既有的"豁免在汇总层、probe 本体不动"同构（CHANGE-20260918-029 先例）。
- `list-assets.mjs`：开工视野脚本按 `spec/assets.json` 的 `D` 求和展示（实测 `:189-190` 输出"D 级截图…配图先查分类表"）。D 的语义扩展后，本脚本必须同步：既不漏计 `screenshotLedger`，也不与 `D.categories.files` 重复计数，且旧"配图"文案不再代表 D 的全部职责。
- `ref-registry.json`：豁免类登记（背景/布局/相似度/尺子/探针）增加内容线维度；g 系既有豁免逐条原样保留，**不得因改造而扩大命中面**。适用性（APPLY / OBSERVE / N/A）的**声明源是注册表或 Owner 文档，脚本只读取声明**；禁止脚本用 `g`/`f` 前缀自行推导不适用（`if (!/^g/.test(f)) return 'N/A'` 属隐式 applicability，本事务明确禁止）。

### 3.3 教程线效果尺状态（新增线级判定态）

行业线：`check-motion` 三项合格线继续按硬闸执行，数值不动。

教程线：本事务**不重定** `45% / 0.35 / 70%` 任何数值；教程片的效果尺结果作为**观察/诊断证据**输出，不作为内容长度或教学完整性的否决依据。该状态必须在实现上**区别于 `motionWaivers` 的"已裁放行"**——不复用 `skipped + ok:true` 豁免通道、不需要豁免登记、输出标签可辨识（"已测·观察（不判红）"）。理由：`check-motion.mjs` 对整段成片求**全片统计量**（静止占比＝帧间差 ≤`DEAD_T` 的帧对数 ÷ 全部帧对数；另有中位帧间差、画面占用率），**代码中不存在"100 秒窗口"这一判定**——"全片 100 秒内有无持续变化"是 `SKILL.md` 第 6 步**叙事 8 问第 ⑤ 问**的人判条目，不是机检定义，本契约不得把两者混为一谈。真实风险在于全片比值统计的分母随时长增长：长片可能结构性偏离短片，该偏离已有 g11 实测同型证据（无声 96.66s→有声 106.27s，静止 49%→54%、帧差 0.32→0.23）。因此本事务只把教程线结果降为观察，不据此调任何封版基线。是否建立教程专属判据，由后继事务按 `SKILL` 第 6 步定标纪律（先向好/坏样本入库 `outputs/archive/calibration/` 再重定标）决定。

### 3.4 红线适用范围拆分

`spec/redlines.json` 仍是唯一红线 Owner，只做 applicability 拆分，不新建第二红线源：

- `rules.video_visual`：行业线继续现有 Remotion 代码 UI 路线；教程线允许真实产品截图作为教学证据，条件是来源可追溯、有当前产品真值对应、有 D-1 登记，且**不因此解除微信/导流/平台任何红线**，发布前逐屏人工确认。
- `rules.content_ratio`：行业线 8:2 与产品界面 ≤1/3 原样保留；不再机械套用于"产品本身即教学对象"的教程线；教程线内容比例与商业浓度口径由教程 Owner 单独定义。
- `rules.brand_display`：行业线画面/封面零品牌名原样保留；教程线允许标题、封面出现「券到卡包」，以及真实教学画面中的产品识别信息；该允许项不自动解除 `account_profile`、平台规则、导流禁令与其他红线。
- 依据等级校正：`rules.video_visual` 中 ≤1/3 一类数值，其外部出处经实测为抖音《小程序推广计划任务审核标准》"示例视频"条款（该文档自我限定为"面向开发者发布的特别约定"，页面更新时间 2026-01-13）。因此该 1/3 条款**不能直接作为自然分发内容的适用依据**；但本事务**不**据此得出"自然分发不受任何同类要求约束"——自然分发侧同类条款的取证尚未完成，列为后继事务发布前的前置取证项（本事务不把它写成已成立事实）。据此，该数值的分线适用性属我方内部分发策略，不得表述为平台强制上限；行业线继续使用该值。同理，该文档中"商品/品牌/App 界面主体展示""无法核实真伪的优惠券等招揽信息"等条款，对本场景只具有**审核经验性参考**价值，不是判据来源。

### 3.5 截图证据 D-1

扩展进既有素材唯一真源 `spec/assets.json`，不新建台账：`D` 的职责由"文章配图速查"扩为"产品截图素材唯一真源"（同时服务文章配图与教程教学截图），新增 `D.screenshotLedger`，字段：`screenshotId`、`localFileName`、`sha256`、`capturedAt`、`appletSnapshot`、`truthRef`、`sourceLocation`、`verificationStatus`（取值 `reference-only` / `current-verified`；该状态是**素材属性**，不构成第二状态源）。

- PNG 本体继续留在 `截图素材/`，不进入 Git（`.gitignore:31` 保持）。
- 校验边界：Git/CI 校验登记结构、`truthRef`、`sourceLocation`、字段格式；本地生产负责确认文件存在、重算 SHA-256 与登记一致、人工逐屏确认图文相符。**机器不得声称能判断截图像素与真实 UI 是否相符。**
- 书写禁令：截图本体一律以 `screenshotId` 指代，**禁止在文档中以反引号路径书写**（`check-doc-references.mjs:130` 的 `RES_ROOTS` 含 `截图素材/`，会对本地文件做磁盘存在性硬失败，而 CI 上不存在本体）；字段名用 `localFileName` 不带目录前缀。
- **存量 88 张截图的资格重定义（本事务新增，属 D-1 语义迁移本体，不后移）**：现有截图属**历史素材库**，经用户确认其中部分可能已与当前前端源码不一致，因此其状态比"缺版本锚点"更严——**默认 `reference-only`**：可用于找页面、找字段、找操作路径、当 UI 参考，**不自动视为当前产品真值**，且**不得因"已登记在 `assets.json`"就直接进入教程成片**。不采用"已废弃"作为默认状态，旧图仍具历史参考价值。
- **不启动全量重拍**：纠正路径是**按使用逐张核验**——某条教程确实需要某界面时，回 `APPLET` 当前 live / snapshot 比对 `truthRef` 与 `sourceLocation`；不一致则重截，一致则重确认并登记，`verificationStatus` 由 `reference-only` 升为 `current-verified`。一次性把 88 张全部重做属"以大而全重写替代增量迁移"，本事务禁止。
- **证据链主锚**：`screenshotId → sha256 → appletSnapshot(或 commit SHA) → truthRef → sourceLocation`。`capturedAt` 只是采集时间元数据，**不能单独证明截图对应的源码状态**，不得当主锚使用。
- 只有 `verificationStatus = current-verified` 的截图可进入教程教学素材链；`reference-only` 被教程素材引用时必须判失败（见 §十 负向测试 7）。
- 与既有事实守门的关系（实测确认，避免新造机制）：`check-facts.mjs:53-67` 已把 D 级整体登记为**外部项**（`reason: 'external screenshot library'`，不计为仓库磁盘资产缺失），这是该脚本头注释"不把 Agent 本机相对路径伪装成仓库内资产"规则的既有实现。`screenshotLedger` **沿用同一"外部项"归类**，并把它的登记名 ↔ 本地文件存在性对账、`verificationStatus` 取值受控一并纳入这条已经存在的双向核对逻辑。如此既复用现成机制，也不让机检假装能验证仓库里并不存在的图片本体。

### 3.6 时长与结构边界（不设数值口径）

教程线不设项目级时长档、不设硬时长上限；时长按"一个完整使用任务是否讲透并形成闭环"决定；拆片依据是内容是否自然分叉为两个独立使用任务，不以秒数为条件。本事务**不新增教程时长数字**，因此不登记数值口径属主，也**不修改** `ref-registry.json` 的 `caliberOwners`（`60-90 / 90-120 / 120-150 / 硬上限 200s` 继续只服务行业线）。教程 Owner 表述时须正面书写，**禁止出现"不受 200s 上限约束""不适用 120-150s"这类否定式复述**（会命中 `caliberOwners` 的属主外复述判定）。

结构边界：一条教程只承担一个完整使用任务；字段多、步骤多、联动复杂均可继续讲，不因时长压缩。

### 3.7 教程内容前提与账号身份

教程内容只讲功能本身，不以版本/档位/升级为话题（依据 `spec/facts.json` `forbidden_claims` #11，2026-09-17 裁定）；"不提版本"不得被解释为可虚构能力或覆盖 Product Truth。功能、数字、字段、限制一律回 `APPLET / spec/`。

教程线仍发布在现有账号。本事务不把账号整体改造为官方产品账号，`rules.account_profile` 不因教程线自动改写；内容级产品身份与账号级身份分开治理。

### 3.8 注册链
