# R9 · 视觉导演与审美决策

> 定位：**导演决策 Owner（视觉导演 ＋ 叙事导演）**——2026-09-23 `CHANGE-20260923-039` 起由"视觉决策层"演进；**是「通用导演原则」的 Owner，不拥有所有具体导演方法**（具体风格中的表达能力方法属风格包，须满足本文判据）。
> R3 负责“怎么实现”，R7 负责“有什么积木”，**风格包**负责“用什么视觉语言表达”，R9 负责“**为什么这样讲、以及为什么这样看起来更好**”。
> 本文件不替代 SKILL 的作业流程；**SKILL（内容层）决定讲什么，R9（导演层）决定怎么讲与如何形成视觉表达**。本文只写**判据与原则**，不写具体技法或套路清单。

## 一、核心目标

把“高级感 / 不像 PPT / 有质感 / 有节奏”转换成可复述、可执行、可审片的视觉决策。

## 二、六维视觉决策

每个关键镜头必须回答六件事：

1. **Visual Subject**：这一镜的视觉主语是什么。
2. **Visual Metaphor**：口播的抽象关系用什么视觉隐喻表达。
3. **Spatial Composition**：主体、留白、前中后层级如何组织。
4. **Motion Meaning**：为什么动、动向哪里、速度为什么这样设。
5. **Attention Curve**：这一镜的关注峰值在哪一帧，峰值前后如何留白。
6. **Exit Logic**：这一镜如何退出，以及如何把注意力自然交给下一镜。

## 三、视觉主语

“一个镜头一个主语”指的是一个视觉主导关系，不是一个镜头只能有一个元素。

允许：手机 A → 手机 B → 奖励券，只要主导关系始终是“券发生转移”。

禁止：标题、数字、三张卡、流程线、图标、字幕同时争夺第一注意力。

优先级：产品状态变化 > 结果数字 > 核心关键词 > 装饰。

## 四、视觉隐喻

当现实素材不可用时，不模拟廉价场景；提取叙事关系，再用程序化视觉表达。

| 叙事意图 | 优先视觉语言 |
|---|---|
| 规模/增长 | 大数字、滚动、密度变化 |
| 稀缺/即将失去 | 倒计时、余量、逐渐熄灭 |
| 记住/惦记 | 未读、未使用、持续存在的对象 |
| 核销/消耗 | 对象消失、状态切换 |
| 赠送/生成 | 新对象复制、生成、出现 |
| 转赠/传播 | 对象位移、连线传递 |
| 奖励回流 | 光线回流、第二状态生成 |
| 认知反转 | 快切、尺度反转、视觉留白 |

## 五、构图

每镜先定“主区域”，再决定次级元素。

默认遵循：
- 主体有明确空间锚点。
- 至少保留一块呼吸区。
- 装饰不得侵入主视觉层级。
- 竖屏先考虑上下纵深，再考虑左右分栏。
- UI 不是默认全屏。

信息越复杂，越应减少同屏对象，而不是缩小字号硬塞。

## 六、动效语义

动画必须对应一个语义动作：

- 出现 = 被注意/生成/进入视野
- 消失 = 使用/离开/被消耗
- 复制 = 奖励/新增/再得一张
- 位移 = 转赠/传递/关系改变
- 聚拢 = 注意力集中/结果形成
- 扩散 = 传播/裂变
- 锐化 = 认知明确/关键句落地
- 变暗 = 失去/退出/过渡

禁止无语义的“为了好看而动”。

## 七、Attention Curve

每个关键镜头只设置一个 peak frame。

推荐节奏：

`建立状态 → 累积 → peak → 停留/确认 → 退出`

peak 前避免堆叠新的高权重元素；peak 后主动减法，为下一镜留注意力空间。

## 八、动效性格

动效不统一为一个速度。

- **Snappy**：问题、结论、关键数字。
- **Heavy**：产品实体、手机、券、重要结果。
- **Soft**：背景、烟雾、光晕、氛围。
- **Elastic**：奖励、生成、轻惊喜。
- **Linear/Drift**：只有需要持续匀速移动的环境元素才使用。

具体参数回 R3；本层只决定语义与选型。

## 九、排版决策

优先顺序：

`关键词 > 数字 > 解释文字 > 装饰`

普通口播不自动变成字幕海报。

一个镜头只有在文案本身构成视觉事件时，才使用大字主视觉。

## 十、产品 UI 决策

UI 的任务是提供“产品证据”，不是负责制造氛围。

适合 UI：设置、核销、状态、领取、转赠、奖励。

不适合 UI：老板痛点、行业规模、情绪、抽象洞察。

当一个 UI 镜头无法通过状态变化完成叙事，应优先重构镜头，而不是继续添加 UI 元素。

## 十一、场景转换（2026-09-23 CHANGE-039 修订）

默认无外部**实拍**素材。遇到“排队、空店、顾客、老板、夜市”等现实场景要求时，**转换目标由所选风格包定义**：

- **Remotion 类风格**：先抽取信息关系，再转换成 `数字 / 大字 / 产品状态 / 连线 / 密度 / 光影 / 粒子 / 空间`（原口径保留为该类风格的表达法之一）。
- **生成式风格**：场景／人物／环境为合法生成对象（边界见 `SKILL.md` 第 2 步《AI 创作边界协议》L2）；产品界面仍只认 L1 三来源。

禁止使用低质占位图假装真实场景。

## 十二、质量诊断词典

用户说“廉价”时，优先检查：
- 同层级对象是否过多
- 卡片是否成为主视觉
- 动效是否机械同频
- 阴影/渐变是否过度
- 是否缺少空间层级
- 是否缺少停顿

用户说“乱”时，优先检查：
- 是否有多个视觉主语
- 是否所有元素都在动
- 是否文字过多
- 是否没有主次

用户说“空”时，优先检查：
- 主体尺寸是否不足
- 是否缺少纵深
- 是否缺少环境层
- 是否应该增加视觉隐喻，而不是增加装饰

## 十三、审片顺序

先看：
1. 第一眼主语
2. 注意力峰值
3. 信息层级
4. 空间层级
5. 动效语义
6. 转场逻辑
7. 细节质感

不得反过来先修阴影、圆角、字号等细节，再发现整镜构图错误。

## 十四、与其他文档的边界

- `SKILL.md`：内容层——工作流、产出步骤、五拍骨架、硬判据。
- `R3`：Remotion 原理、API、动画参数与工程实现。
- `R7`：组件目录、复用、组件状态。
- **风格包**（每个风格一个独立能力包目录，落在 video/styles 下，声明源见 `scripts/ref-registry.json` 的 `styles`）：表达能力——用什么视觉语言表达；**不得拥有独立导演方法／故事结构／观看路径**（判据＝换包不换导演稿）。
- `R9`：**导演层**——通用导演判据（叙事结构／观看动力／悬念／转折／情绪曲线／信息释放顺序）＋ 视觉决策、审美判断、镜头语言与文案→视觉的转换；**不拥有所有具体导演方法，不写套路库**。
- `spec/`：产品事实、红线、素材等机器真源。

## 十五、叙事导演（判据 · 2026-09-23 CHANGE-039 新增）

> **形态规定（先于内容）**：本节**只写判断标准，不写套路库**。任何"第一幕必须怎样""固定三幕结构""固定剧情模板"一律不得进入本文——那是逐片设计或风格包表达层的事，写进本文即越界（R9 是通用导演原则 Owner，不是所有导演方法的 Owner）。

导演层只回答一个问题：**为什么观众会继续看下去。** 六个必答项（每片《导演稿》逐项作答；答不出即未完成）：

1. **叙事结构**：这一段为什么在这个位置？——判据：任意相邻两段之间存在可复述的"因为…所以…"关系；若某段可随意调换位置而观众无感 ⇒ 结构未成立。
2. **观看动力**：观众此刻为什么继续看？——判据：每个关键节点能答出"这里给观众留下的问题／期待是什么"；答不出 ⇒ 该节点只是信息搬运。
3. **悬念**：信息缺口是否被制造并兑现？——判据：全片至少有一次"提出问题 → 延后回答"的完整对答；全程无缺口 ⇒ 清单式陈述。
4. **转折**：观众认知是否发生过变化？——判据：能指出"观众原本以为 X，之后改为 Y"的那一处；指不出 ⇒ 平铺。
5. **情绪曲线**：情绪是否有起伏而非单值？——判据：能指出至少一次"紧—松"或"低—高"的变化点；恒定 ⇒ 无曲线。
6. **信息释放顺序**：为什么先讲这个、后讲那个？——判据：改变顺序会损害理解或期待（顺序有理由）；可任意打乱而效果不变 ⇒ 释放顺序未被设计。

**《导演稿》机制**：逐片产出，落在该片既有的 R9 视觉决策卡文件（文件名规则与机检定义见 `scripts/check-visual-shot-contract.mjs`）的「导演稿」一节（**不新增文件、不新增第二状态源**）；内容 ＝ 上述六项逐项作答 ＋ 本片所选风格包 `styleId`。**验收判据（换包不换导演稿）**：同一份《导演稿》换任一风格包后仍应能落地；若某风格包要求改写叙事顺序／信息释放／观看路径 ⇒ 该包越界。

**导演稿替换测试（长期判据，2026-09-23 冻结于 CHANGE-039）**：取同一份《导演稿》，分别用不同风格包表达——**任一风格包都不得要求修改叙事结构／信息释放顺序／观看路径／情绪曲线**；若某包要求修改，判该包越界（回收给 R9）。本判据**不随 039 关闭而失效**。

**与五拍的关系**：五拍＝内容传播骨架（内容层，`SKILL.md` 第 1 步），本节判据只在骨架之上检验"讲法"；**叙事不得漏讲骨架里必讲的信息，也不得替代五拍**。
