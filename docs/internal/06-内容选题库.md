**痛点搜集（内部调研，灵活使用）**：每篇攻略产出前，AI 搜集该行业痛点（行业知识 + 网络搜索深化），写入 05「行业痛点表」（痛点 → 功能映射 +「不写」清单）。痛点表是文章的**吸引力引擎**，不是必须展示的交付物：写文章时自由运用痛点制造共鸣与诱惑，灵活使用、不逐条陈列；痛点的表达手法 AI 自由发挥。

**痛点融法（吸引力结构，自由发挥）**：

1. 戳痛：第二人称具体场景（打烊时刻/闲时/流失瞬间），利用损失厌恶——把「正在失去」写疼；
2. 放大痛点代价：定性表达（闲着的桌子=房租白交），不编数据；
3. 重构反转：把痛点翻译成可解的设计问题，制造「还能这样玩」的顿悟（如「别降价，降次数」）；
4. 解法绑定功能：每个反转落在一个真实功能上，讲价值、不写操作手册；
5. 降低行动门槛：零门槛 + 「进入券到卡包」小第一步，收统一 CTA。

诱惑力来自重构的「顿悟」与零门槛，不来自夸大承诺。

**唯一硬约束**：文章里每个「怎么解」都指向 00 真实功能；无对应功能的痛点（「不写」清单）不得写成能解。

**交付固定四件套**（格式样例见《行业用券攻略·火锅店新店开业》）：

1. 活动设计总览：目标拆解 → 券组合表（类型/承担目标/发放方式/核心设计）；
2. 卡券制作单：逐字段填值 + 边界说明 + 须知全文，人操作制作；
3. 发放组合与执行顺序：海报/活动海报/定时开抢/自动发券分支等；
4. 攻略文章（痛点吸引开头 → 券组合解法 → 场景示例[行业泛称] → CTA）+ 封面文案包。

**铁律**：每个字段值落在 00 §6 约束内并附边界说明；能力边界外功能不进制作单；明确写「什么不用」（如券包仅私密、不做公域引流）；文末边界自检清单必备。

**产出顺序**：与种子商户名单行业耦合，逐行业产出；交付物兼作 M4 陪跑包内容。

**写作风格原则（灵活多元 · 不套模板）**：攻略文章表达风格必须多元、随内容调性自由发挥，不锁固定格式、避免读者产生「套模板」的雷同感——与视频「画面开放发散」同源（见 11 §3 画面元素规范）。结构骨架（痛点共鸣 → 真实功能解法 → CTA）是吸引力引擎、不是格式模板，每篇可在该逻辑上自由变化；配图（代码驱动 UI 组件 + 项目商用字体 + 关键字等元素，见 10/11，不 AI 生图主视觉）按内容需要嵌入、且克制不用太多，不强制「一段一图」或固定密度。
