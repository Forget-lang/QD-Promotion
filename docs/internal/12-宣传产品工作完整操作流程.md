# 12 · 宣传产品工作完整操作流程（SOP）

> 本文件是「券到卡包」**宣传与运营主流程**的总操作手册，整合 00、02、04~07、10、11、13 的执行步骤。
> 当前阶段：宣传推广线冷启动（获新商户），无真实案例，正文用行业泛称。
> 任何一步拿不准，先回 `00-产品事实表.md` 核对能力边界，或标注「待确认」交人核实。

---

## 一、目标与范围

- **目标**：通过内容（文章/视频）让实体店老板知道、心动、注册「券到卡包」，完成首次制券。
- **范围**：宣传推广线（获客）+ 素材生产（代码 UI 组件绘制 / 可选插画 / 关键字提取 / 封面）。
- **暂不做**：付费投流。

## 二、角色分工

| 角色 | 负责 |
|---|---|
| AI | 选题建议、文案、券组合设计、设计稿（含本地素材检索与源路径标注）、代码执行（data/gXX.ts）、豆包 TTS 调用、Remotion 渲染、封面素材索取与引导输出（不 AI 生成封面）、合规自查、归档 |
| 人 | 确认设计稿、从本地素材库选取或按规格找图并复制到 `video/public/`、提供 TTS Key/音色、确认语速样片、按引导制作封面并回传、确认单帧画面、最终发布、纠偏 |

### 二.5 AI 协作准则（贯穿全流程）

> AI 是策划者+设计者，不是执行者。以下准则适用于全流程所有环节。

**1. 主动策划，不被动执行**
- 用户给方向/感觉/建议时，先拆解成具体可落地的改进方案，再跟用户确认
- 不要等用户说"加 X""改 Y"才动手，要主动想"还能怎么更好"
- 每个环节结束时主动想：下一个环节需要我提前准备什么？

**2. 两步确认法（关键节点必走）**
- 理解确认：先复述用户的意思，确认理解对了再动手
- 规划确认：给出具体规划（做什么/怎么做/影响范围/顺序），确认了再执行
- 两个确认节点：设计稿确认（步骤 4）、成片确认（步骤 9）

**3. 全局一致性**
- 改动前自查 3 问：影响事实层吗？影响流程层吗？影响经验层吗？
- 改一处，全量对齐。不能只改一份文档，相关文档都要同步
- 红线类改动必须跑闸门（`node scripts/check-redlines.mjs`），零命中才算完

**4. 决策必回写**
- 用户拍板的任何决策、口径、规则，必须同步写进权威文档
- 不能只停留在聊天记录里，要让下一个 AI 也能读到
- 生产回顾是强制动作（步骤 12），缺了不算完成

## 三、完整操作流程

### 步骤 1 · 行业调研三问（替换静态选题库）

> 不再依赖预先写死的选题库/行业场景文档。AI 选定行业后，按以下框架调研，确保每一条内容从行业真实痛点出发。

**行业调研三问：**
1. **这个行业的老板最头疼什么？** → 搜索行业经营痛点（如"咖啡店 经营难题""美业 获客痛点"）
2. **这个行业现在怎么做营销？** → 搜索行业营销方式（如"咖啡店 锁客方式""美业 办卡模式"）
3. **这个行业的券到卡包场景是什么？** → 结合前两步结果，匹配电子券/次卡/券包的能力，设计具体的卡券策略

**产出**：一段 100-200 字的行业画像，包含：行业典型经营模式、核心痛点、关键词。用行业泛称，不编具体商户名。

### 步骤 1.5 · 行业场景策略设计（内容深度闸门）

> **内容质量标准权威在 `08-内容质量三层标准.md`**，本步骤是 08 号文档的落地闸门。
>
> **核心**：在画任何一帧之前，先想清楚"这个视频到底要讲一个什么场景"。不泛泛罗列功能，而是设计一个具体的、让老板看完想说"这招我也能用"的场景。
>
> **三层对照**：
> - 硬边界（第一层）：功能不能说错、不能编数据 → 对照 00 号事实表检查
> - 方向锚（第二层）：要达到"老板觉得我能用"的效果 → 对照 08 号 4 个自检问题
> - 创作自由（第三层）：切入点、结构、句式 → 自由发挥

**怎么做：**
1. 基于步骤 1 的调研结果，设计一个**具体的卡券运营场景**——不是"次卡可以锁客"这种泛泛之谈，而是一个有细节、有逻辑的场景，含以下要素：
   - 行业具体场景（如"咖啡店早上 10 点前的空档期"）
   - 卡券类型和规则（如"早鸟次卡，核销间隔每天一次，有效期 30 天，10 点前核销额外送一杯"）
   - 预期效果和逻辑链条（如"客人领了卡，每天早上 10 点前就来，自然填满空档期"）
2. **对照 08 号文档自检**：AI 自己先过一遍第二层的 4 个自检问题
3. **人确认这个场景策略**：人觉得"这个场景确实能打动老板，有真实感"→ 再进设计稿。人觉得"太浅/太假/不痛"→ 回炉。
4. 确认后，场景策略作为设计稿的"核心理念"写入设计稿元信息。

### 步骤 2 · 券组合设计 + 边界校验
- 基于步骤 1.5 确认的场景策略，设计卡券组合（优惠券/券包/次卡）。
- **边界校验**：逐字段对照 00§6（数值上限）与 00§8（能力边界）。次卡走私密发放、随机金额 1~99 整数、套餐券只写文字预约说明（不暗示在线预约）。

### 步骤 3 · 四件套文案（G 类）
- 活动设计总览 + 卡券制作单（逐字段 + 边界 + 使用须知）+ 发放组合与执行顺序 + 攻略文章 + 封面文案包。
- 数值以 00§6 为准，状态文案以后端 Label 为准。

### 步骤 4 · 视频设计稿（AI 核心产出，闸门）
- 按 **13 §5 模板**产出完整设计稿：视频元信息 / 风格配置五维 / 相似度检查（≥3 维不同 + 叙事结构差异 ≥3 位置不同）/ 逐屏分镜表（帧级动画时序，遵守内容深度铁律）/ 图片素材清单 / 口播稿 / 合规自查。
- 口播稿、关键字、每屏 UI 布局 brief 全部在设计稿中定稿，不再单独产出「脚本」。
- 动画时序写到帧级（组件名、delay、easing），禁止模糊描述（13 §1.1）。
- **内容深度**：以 `08-内容质量三层标准.md` 为准。方向锚是"让老板觉得这个我能用"，达到这个结果就行，具体怎么组织内容 AI 自由发挥。禁止"功能罗列"——每屏换一个功能、每个只提一嘴。场景序列必须与已有行业视频至少 3 个位置不同（查看 13 §7.1 已注册场景序列），不可"换行业词照搬结构"。
- **图片素材清单**：先按 13 §4.1 检索本地素材库，本地有合适的标注源路径；不足才输出外部找图规格（13 §4.3）。
- **行业背景图（B 方案）**：设计稿必须包含视频背景图的找图引导——关键词、选图标准、放置路径（`video/public/backgrounds/gXX/bg.jpg`）。每个行业一张专属背景图，全片共用作为氛围底层（模糊 30px + 30% 透明度 + 主色渐变蒙版，详见 13 §3.3）。
- **文章配图**：小红书图文和搜狐长文的截图配图从 `截图素材/` 速查表选取（见 11 §1），在文案对应位置标注截图文件名。
- **闸门**：人确认内容方向/风格/素材来源/内容深度/叙事结构差异后，才进步骤 5。

### 步骤 5 · 视觉素材准备与代码执行
- **素材（人执行 + AI 核对）**：本地素材从根目录复制到 `video/public/` 对应子目录（13 §4.1 路径引入机制）；外部找图放入同一目录结构。AI 核对尺寸/风格/版权。
- **代码（AI 执行）**：新建 `data/gXX.ts` 填入 scenes + style；复用 `components/` + `scenes/`；如需新积木按 13 §7.2 扩展；新图标用 Icon MCP Server 检索/生成后转内联组件（13 §8.3）；图片用 `staticFile()` 引用。
- **技术硬规则**：全部动画用 useCurrentFrame + interpolate/spring、禁止 CSS animation、motion 透传 style.motion、非 spring 插值用 EASE_OUT、场景间 TransitionSeries 转场（13 §2）。
- **验证**：`npx tsc --noEmit` 零错误 → 每屏单帧 still 验证。
- **渲染命令必带** `NODE_OPTIONS=""` 前缀（skill §七硬执行约束）。

### 步骤 6 · 文章配图
- 小红书图文、搜狐长文**使用截图素材作为功能示例图**（来源：`截图素材/` 目录），讲哪个功能配哪张图，让读者直观看到产品界面。
- 截图作为功能示例图使用，不做文章头图（头图仍用封面图/设计图风格）。
- AI 负责选图、放到文章对应位置；**截图中的微信元素（导航栏、分享面板等）由人发布前裁剪处理**。
- 配图素材清单标注来源（截图素材路径）。

### 步骤 7 · 封面（素材索取/引导 + 文案包）
- **AI 先从 `背景素材/` 索取**合适模板/素材；库内无合适时输出「详细引导」（检索词/尺寸/风格/版权要求），指引人到创客贴等设计网站制作。**AI 不生成封面。**
- 随稿附封面文案包（系列条/主副标题/用图方向/排版留白）。
- 封面 = 未播放态缩略图（≠ 第一帧，可独立构图、更海报化）；首帧复用封面 hero 视觉（共用同一视觉语言，13 §5.2/07 §3）。
- 尺寸：抖音 9:16（1080×1920）、小红书 3:4（图文笔记封面）、搜狐 16:9（1920×1080）。
- 三平台封面不得含小程序码；设计原则见 07 §3。

### 步骤 8 · 视频生产（9:16 + 设计稿驱动）

**核心原则**：设计稿是最终权威。设计稿定义每屏 dur 和口播稿文字量，口播稿按 4-5 字/秒校准，TTS 自然语速生成后自动匹配，无需任何一方驱动另一方。

- **代码执行**：新建 `data/gXX.ts`，dur 从设计稿取值。视觉：代码 UI + 字体 + 图标，关键字层从设计稿口播稿提取；首帧复用封面 hero 视觉。
- **TTS 语音（验证环节）**：豆包 `seed-tts-2.0`，`speech_rate=0` 常速。先出 5-10s 样片（信息密度最高的一屏，含数字验证）确认语速，再逐屏合成全片。输出 `public/audio/s1.wav` ~ `s7.wav`。**数字统一写中文**（如"三天"非"3 天"）。**禁止 atempo 调速**。
- **精确时长验证**：用 `getAudioDurationInSeconds` 获取每段语音精确时长，偏差 ±5% 内正常，超出则微调 dur（语音时长决定帧数，设计稿内容结构不变）。
- **单屏音画预览**：每屏 TTS 音频 + still 帧拼 1-2s 预览，人耳确认节奏。
- **成片渲染**：`npx tsc --noEmit` → `npx remotion still` 关键帧验证 → `npx remotion render`（含音频+字幕）。整片时长 = 设计稿总时长，声画帧级同步，字幕与口播逐句对齐。
- **闸门**：成片经人确认画面质量 + 语音同步 + 整体节奏后，才进入发布。**盲听校验**：渲染后盲听全片一遍（不看画面），确认无断句异常、无卡顿。

### 步骤 9 · 测试—纠正循环
- 每轮只做 1 个单元，人审 → 列问题 → AI 改 → 沉淀踩坑点。过审再扩量。

### 步骤 10 · 确认素材入库 + 归档
- 人确认过的插画（若有）/纹理归档进对应库（11 §2）。视频引用的本地素材已在步骤 5 复制到 `video/public/`，无需重复操作。
- 成品归档 `outputs/gXX-行业/`（目录规范见 AGENTS.md）。

### 步骤 11 · 发布（按渠道）
- 抖音发 9:16 视频，CTA 见 07 §5（自然收尾，不硬推关注/收藏，可轻署「券到卡包」，副标题可用「再小的门店也可以制作电子券」）。
- 小红书发图文笔记（不发视频），封面与抖音视频共用同一 hero 视觉语言，3:4 裁切中间区。
- 搜狐发长文攻略，导流仅限账号资料位。
- 社群/地推辅助。

### 步骤 12 · 生产回顾（固定动作 · 自进化核心）

> 这是系统"越做越好"的关键一步。做完不等于完成，沉淀了才算完成。

**触发时机**：每条视频/每篇文章人审通过、最终交付后，AI 主动发起，不等人催。

**回顾模板（5 项必答）**：

1. **做得好的**：哪些地方效果超预期？为什么好？能不能提炼成可复用的模式？
2. **踩坑的**：哪些地方走了弯路、出了问题？根本原因是什么？下次怎么避免？
3. **用户反馈**：用户说了什么（夸的、骂的、改的）？背后的偏好/规律是什么？
4. **待验证假设**：这次有什么想法没来得及试？下次可以怎么验证？
5. **可沉淀的资产**：有没有新的金句、新的结构、新的组件，可以加到最佳实践库里？

**三个沉淀去向（按内容分类回写）**：

| 沉淀内容 | 回写到哪里 |
|---|---|
| 高转化句式 / 验证过的结构 / 踩坑记录 / 风格偏好 / 效率技巧 | `docs/internal/09-最佳实践库.md` |
| 新功能事实 / 产品能力边界调整 / 术语变更 | `docs/internal/00-产品事实表.md` |
| 新红线 / 新 CTA 口径 / SOP 变更 / 新的生产规范 | `quandao-content` SKILL + 对应 docs |

**过程归档**：完整回顾笔记存 `outputs/archive/{日期}-gXX-生产回顾.md`，作为过程留档。

> 原则：**做完一个行业，系统就强一分**。不沉淀 = 白做。
