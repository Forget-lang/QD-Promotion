# M2 · 视频制作手册（怎么出片）

> 最后校验：2026-08-21（从原 12-SOP 步骤 4/5/8/9 + 13 号文档操作部分融合）
> 读者是"零上下文的 AI"：完成内容策划（M1 输出设计稿输入）后，只读本手册即可独立完成视频制作：设计稿 → 代码 → 无声版确认 → TTS → 成片。
> 技术"为什么"与组件 API 查 `R3-Remotion技术参考.md`（本手册不重复原理）；画风审美查 `R4-最佳实践库.md`。

## 一、制作流程总览（顺序不可乱）

```
M1 策划完成（行业/玩法/文案已定）
  ↓
① 设计稿（帧级分镜 + 口播全文 + 素材清单）→ 人确认内容方向/风格/深度
  ↓
② 阶段一 · 无声版：代码执行（dur 用预估）→ tsc + still 验证 → 渲染无声版（字幕占位）→ 人确认画面
  ↓
③ 阶段二 · 有声版：TTS 逐屏生成 → loudnorm → ffprobe 量时长 → 算 dur 回填 → 字幕精确同步 → 渲染成片 → 盲听校验
  ↓
④ 交付：视频文件 + 生产回顾（沉淀进 R4）
```

**核心原则**：先确认画面再加语音，避免画面返工浪费 TTS 额度。禁止 atempo 调速；TTS 一次生成、零调试。

## 二、设计稿（AI 核心产出，人确认闸门）

> 设计稿是**可执行规格**，不是灵感参考。目标读者是执行 AI：每一条必须能被无歧义地翻译成代码。模糊写法禁止（例：「标题柔和淡入」→ 必须写「FadeInUp，delay=6，motion=style.motion，dist=50px」）。

**设计工具使用规则（2026-08-21 定）**：
- **主标准（优先）**：本手册设计语言系统（§2.9 视觉参数 / §2.10 焦点规则 / §2.11 拆解模板 / §2.12 四维评分）+ R4 审美标准（V-R/V-S / §5.9 布局模式库 / §5 参照库）——项目定制规则，**始终优先**
- **辅助工具（按需）**：`ui-ux-pro-max` 技能（通用设计知识库：67 种风格 / 96 套配色 / UX 指南）——**仅当项目规则覆盖不了时调用**：需要新风格方向、配色灵感、通用排版/色彩理论时，可查它做参考
- **冲突裁决**：ui-ux-pro-max 的建议与项目定制规则冲突时，**以项目规则为准**（通用知识不带行业语境，可能不符合券到卡包调性）
- **禁止**：用通用知识覆盖项目定制规则；为用技能而用技能（常规场景直接按项目规则设计，不额外调用）

设计稿必须包含以下章节：

### 2.1 视频元信息

```yaml
视频编号: GXX
行业: （如：美业/洗车/餐饮）
标题: （视频主题，≤14字）
预估总时长: XXs（设计稿阶段预估值，最终由 TTS 实测确定，硬上限 ≤200s）
画幅: 1080×1920 @30fps
目标平台: 抖音（视频只发抖音）
```

### 2.2 风格配置五维

```yaml
style:
  palette: ink-green      # 7 套选 1（mint-cool/warm-orange/berry-purple/deep-blue/caramel/ink-green/neon）
  motion: snappy          # 4 种选 1（bouncy/snappy/buttery/heavy）
  typography: friendly    # 3 种选 1（impact/clean/friendly）
  transition: slide       # 5 种选 1（slide/wipe/dissolve/zoom/pop）
  hookStyle: number       # 已实现 4 种选 1（contrast/number/question/clock）
```

### 2.3 相似度检查（与上一条视频对比，≥3 维不同才放行）

| 维度 | 上一条（基线，以 data 代码实际值为准） | 本条 | 是否不同 |
|---|---|---|---|
| palette | ink-green | ? | ✅/❌ |
| motion | snappy | ? | ✅/❌ |
| transition | slide | ? | ✅/❌ |
| typography | friendly | ? | ✅/❌ |
| hookStyle | number | ? | ✅/❌ |
| 行业背景图 | 冰蓝柔光（ink-green） | ? | ✅/❌ |
| 场景序列 | hook→pain→solution→flow→grid→transfer→panel→cta（8 屏） | ? | 新增+消失+重排 ≥3 |
| 布局模式组合 | 上一条各屏 L-XX 选型 | ? | 至少 4 种模式不同（R4 §5.9） |

**场景序列比对规则**：列出两条视频的场景类型清单（去重），统计「新增类型数 + 消失类型数 + 位置重排数」之和 ≥ 3 即为通过。简单判断：开场类型不同 + 中段结构不同 + 收束方式不同，基本就满足。
**布局模式组合比对**：两条视频的布局模式选型（L-01~L-12）对比，相同模式数 ≤ 屏数 - 4 才算通过（即至少 4 种模式不同）。
> 基线值以 `video/src/data/` 最新一条视频代码实际值为准，不用本文档静态值。做完新视频后回写基线。

### 2.4 分镜表（逐屏填写）

```yaml
屏号: S1
场景类型: hook       # hook/pain/solution/flow/grid/panel/cta/timeline/transfer；不够写 new:xxx（按 R3 §五流程）
时长: 5s（150帧）    # 预估 dur；最终由 TTS 实测 + dur 公式确定
标题: （≤14字）
副标题: （≤30字）
布局模式: L-01 大字中心型     # 必填：从 R4 §布局模式库 12 种中选，禁止自由排列
画面布局: （区域坐标 + 焦点元素，遵守 §3.3 核心内容集中 + §2.9 视觉参数）
排版参照: 参照 #X（XXX 型），借鉴了 Y 手法    # 从 R4 §5 排版参照库 选
参考拆解: （§2.11，用户提供了参考图才填；拆解 7 项：焦点/分区/色彩/字号/留白/质感/转化）
资源标注: BG-ABS-002（背景素材/抽象模板/冷色系/）  # 从 R1 素材登记附录选
动画时序:
  - 帧 0-2: 背景渐入
  - 帧 2-20: 标题 WipeIn（clip-path left，EASE_OUT）
  - 帧 8-30: 数字 ScaleIn（motion=style.motion，startScale=0.3）
  - 帧 20-50: 副标题 FadeInUp（motion=style.motion）
  - 帧 28: 数字 Pulse（intensity=0.08，duration=24）
图片素材: 无 / IMG-GXX-01（本地-背景素材）/ IMG-GXX-02（外部找图）
图标: cup（从图标库选）
备注: （特殊说明）
```

**动画时序要求**：每个元素标注起止帧、组件名、参数；帧序号从该屏起始帧（0）开始；转场由 TransitionSeries 自动处理，不在分镜表中描述；避免嵌套时序冲突（见 R3 §2.4）。

**内容深度自检**（硬性闸门，4 条全过才合格，依据 M1 §质量标准）：
- ☐ 钩子够不够狠（前 3 秒能否让目标老板停下来）
- ☐ 痛点够不够深（说了为什么+后果，不是只说"有这个问题"）
- ☐ 方案够不够具体（能直接抄作业的步骤，不是概念）
- ☐ 有没有"哦，还能这样"的意外点
- ☐ 覆盖 ≥6 个信息单元、≥2 层递进（对照 M1 的信息单元表）

### 2.5 图片素材清单（含本地检索结果）

按 §6.1 流程**先检索本地素材库**，再填表。每屏"图片素材"三选一：
1. **无图片需求**：纯 UI 组件可表达，写"无"
2. **本地已有素材**：素材编号 + 来源库 + 源库路径 + 复制目标路径
3. **需外部找图**（仅 A 类背景+封面）：按 §6.3 规格表填全部字段，标注"外部找图"

### 2.6 口播稿与声画同步

- 口播按 M1 产出定稿；文字量按 4.5-5 字/秒校准（用于预估 dur，非硬约束）
- **数字统一写中文**（"三天"非"3 天"，"百分之九十九"非"99%"），防 TTS 读法不一致
- 关键字大字弹入、核心数据展示、对比画面切换三类动画可绑定口播重音（口播稿中重音词加粗标注）

### 2.7 合规自查（7 项必查，依据 R5）

- ☐ 无极限词（最/第一/顶级/独家/唯一）
- ☐ 无微信/小程序/搜索提及
- ☐ 无虚构功能/案例/数据
- ☐ 数字以 R1 关键数值为准
- ☐ 「核销活码」不在宣传中使用
- ☐ CTA 自然收尾，无「关注/收藏/进主页」
- ☐ 「免费」未在封面/开头/结尾作为卖点强调（正文自然提及没问题）

### 2.8 美感自查（逐屏对照 R4 §视觉审美标准）

- ☐ V-R01 标题醒目：字号 ≥56px，颜色与背景强对比
- ☐ V-R02 内容填满上 2/3：标题+主体集中，上下不空
- ☐ V-R03 一屏一焦点：有且只有一个主视觉焦点
- ☐ V-R04 文字对比度 ≥4.5:1
- ☐ V-R05 相邻屏不重复：连续两屏布局模式不同
- ☐ V-R06 安全区：top ≥120px / bottom ≥160px / left&right ≥60px
- ☐ V-R07 无全屏遮罩：背景图毛玻璃后直接透出
- ☐ V-R08 信息点 ≥3：每屏至少 3 个有效信息点

红线全过后，建议项（V-S01~V-S14）由 AI 自主判断。

### 2.9 视觉层级参数表（设计生成配方，解决"只会放大字体"）

> 字号、间距、留白、色彩**按阶梯取值，禁止凭感觉给数字**。参考图里的设计，也要按本表换算成参数，而不是照抄尺寸。

**字号阶梯**（焦点数字 > 主标题 > 副标题 > 正文 > 标注）：

| 层级 | 字号 | 用途 | 约束 |
|---|---|---|---|
| 焦点数字 | 160-200px | 大数字（百分比/金额/数据） | 全屏最大，唯一可超 150px |
| 主标题 | 96-120px | 每屏标题（≤14 字） | ≥ 副标题 1.5 倍 |
| 副标题 | 56-72px | 辅助说明（≤30 字） | ≥ 正文 1.4 倍 |
| 正文 | 36-44px | 卡片内描述 | ≥ 标注 1.3 倍 |
| 标注 | 26-30px | 脚注/提示 | 最小可读，不低于 26px |

**层级比例铁律**：焦点元素 ≥ 相邻元素 **2 倍**（大小）+ 至少一项额外对比（颜色/明暗/位置居中）。达不到 2 倍，就**缩小相邻元素**，不是放大焦点。

**间距网格**（8px 基准）：
- 卡片内 padding ≥ 43px ｜ 卡片间距 ≥ 卡片高度 20%（保持）
- 标题与内容间距 40-60px（保持）
- 列表行间距 ≥ 24px ｜ 图标与文字间距 16px

**留白规则**：
- 标题区顶部 y:200 起；内容区 y:200-1100 集中（保持）
- **每屏至少保留 1 个"呼吸区"**（≥画面 15% 的连续空白）——高级感的主要来源
- 底部 y:1600-1760 为留白缓冲（字幕上方）

**色彩比例（60/30/10 法则）**：
- 主色（背景/大面积）≈60% ｜ 辅色（卡片/次要）≈30% ｜ 强调色（焦点/数字/箭头）≈10%
- **强调色只用在焦点元素上**；次要元素一律降饱和/降明度
- 全屏色彩 ≤3 个色系（主/辅/强调 + 黑白灰）

### 2.10 一屏一焦点规则（V-R03 的可执行版）

每屏必须回答"观众第一眼看哪"，按以下规则设计：

1. **焦点选择**：该屏最重要的信息（大数字 / 主标题 / 对比中心 / 核心券面）
2. **焦点实现**：三选二——大小对比（≥2 倍）/ 颜色对比（强调色）/ 位置居中或视觉中心
3. **降级处理**：非焦点元素必须主动弱化——字号缩小、饱和度降低、透明 0.6-0.8、移出视觉中心
4. **反例**：全屏所有元素同字号同明度 = 无焦点 = 必返工

### 2.11 参考图拆解模板（用户给参考图时必走）

> 用户提供优秀参考（视频页面/创可贴设计）时，AI **必须按 7 项拆解并写进设计稿**，禁止"看一眼就放大字体"。

```yaml
参考图: （用户提供，可多张）
拆解结果:
  ① 视觉焦点: 第一眼看什么？怎么突出的？（大小/颜色/位置）
  ② 区域划分: 画面分几个区？各占多少比例？
  ③ 色彩分配: 主色/辅色/强调色各是什么？各占多少？
  ④ 字号层级: 最大的字 vs 最小的字差几倍？层级几档？
  ⑤ 留白位置: 哪里是空的？空多少？为什么空？
  ⑥ 质感细节: 圆角/阴影/纹理/光效？什么让画面"不廉价"？
  ⑦ 转化到本屏: 布局模式（L-XX）+ 焦点元素 + 借鉴的具体手法（只借鉴手法，不照搬）
```

**纪律**：拆解不出 7 项 = 该参考图没被真正理解 = 设计稿不达标。每屏至少 1 张参考图（或 1 条已提炼的布局模式）。

### 2.12 设计质量四维评分（迭代有基线，不靠感觉）

设计稿完成后 AI 自评四维（分数写进设计稿）；无声版渲染后用户按四维打分（可说感受，AI 按 R4 §4.4 用户反馈翻译表翻译）。**任一维 ≤3 分 → 定位到对应规则返工，不做"整体重做"式模糊返工**。

| 维度 | 评分项（0-5 分） | 5 分标准 |
|---|---|---|
| 层次 | 字号阶梯符合 §2.9？焦点 ≥2 倍？ | 层级分明，一眼看出主次 |
| 焦点 | 一屏一焦点？非焦点已降级？ | 观众第一眼知道看哪 |
| 节奏 | 相邻屏布局模式不同？动效有错峰？ | 每屏有变化，不重样 |
| 质感 | 氛围层挂载？阴影/圆角统一？留白呼吸感？ | 画面"高级"，不是"会动的 PPT" |

## 三、技术硬规则（操作版；原理见 R3）

### 3.1 动画规则

| 规则 | 说明 | 反例（禁止） |
|---|---|---|
| 禁止 CSS animation/transition | Remotion 逐帧渲染，CSS 时间轴与帧不同步 | `style={{animation: 'fadeIn 0.5s'}}` |
| 全部用 useCurrentFrame + interpolate/spring | 唯一合法动画驱动方式 | — |
| 非 spring 插值必须指定 easing | 统一用 `EASE_OUT = Easing.bezier(0.16, 1, 0.3, 1)`（expo-out） | `interpolate(f, [0,30], [0,1])` 缺 easing |
| spring 必须透传 motion | motion 参数从 `style.motion` 读取，禁止硬编码覆盖 | `<FadeInUp motion='bouncy'>` 写死 |
| 禁止嵌套动画时序冲突 | 父动画期间子元素 delay 超父时长 = 空跑 | `<SlideInRight delay={14}><ScaleIn delay={40}>` |
| 颜色过渡用 interpolateColors | 禁止 boolean 瞬切 | `color={lit ? '#fff' : '#333'}` |

### 3.2 转场规则

- **必须用 TransitionSeries**，场景间禁止 `<Sequence>` 硬切（用 `@remotion/transitions` 的 TransitionSeries + Transition）
- 转场时长 12 帧（0.4s）；特殊风格 8-16 帧，设计稿显式标注
- timing 用 springTiming，config 对齐 `style.motion`
- presentation 由 `style.transition` 决定（VTemplate 的 getPresentation 映射），禁止硬编码单一转场型

### 3.3 布局规则

| 规则 | 值 |
|---|---|
| 画幅 | 1080×1920 @30fps，9:16 竖版 |
| 字号/间距 | 绝对像素（固定画幅下不用 vmin） |
| 中文字体 | 本地 @font-face 加载 `public/fonts/`，禁止依赖系统字体 |
| 文字安全区 | 标题左右 padding ≥60px、顶部 ≥120px、底部 ≥160px |
| 字幕安全区 | 底部距底 60px，白字黑描边 34px，位于 y:1760-1920，不侵入内容区 |
| 活动区硬底线 | y:120-1760，出界 = 不合格 |
| **核心内容集中** | 核心内容（标题+卡片/图标/流程）集中在 **y:200-1100**；标题距顶 ≥200px；标题与内容间距 40-60px；多卡片间距 ≥ 卡片高度 20%；卡片内 padding ≥43px。只约束垂直分布，不限制风格 |

### 3.4 代码结构规则

- 场景内容全部从 scene 数据读取（禁止硬编码文案/颜色/图标名，语义色 ACCENT_RED/GREEN 除外）
- 风格值全部从 style/palette 读取（禁止硬编码色值）
- 图标用内联 SVG 组件 `<Ico name={color} />`（禁止外部图标文件/CDN）
- 图片用 `<Img src={staticFile(...)} />`（禁止 `<img>`）
- 字幕用 `<Subtitle>` 组件，接收 `lines: {text, startFrame, endFrame}[]`（数据在 data/gXX.ts 的 subtitles 字段）

## 四、场景积木（9 种已注册）

| type | 组件 | 数据字段 | 视觉特征 |
|---|---|---|---|
| `hook` | HookScene | title, sub, hookStyle, leftTitle, rightTitle | 深色背景+GlowOrb，大字标题；支持 number（数字弹入+Pulse）/contrast（左右红绿VS）/question（大问号）/clock（时钟SVG+Pulse） |
| `pain` | PainScene | title, leftTitle, leftItems, rightTitle, rightSub | 浅底+DotGrid，左红卡痛点+右绿卡解法+VS |
| `solution` | SolutionScene | title, items[], layout | 浅底+DotGrid；vertical（默认纵向通栏）/horizontal（三卡横排） |
| `flow` | FlowScene | title, nodes[], footnote | 深色背景+GlowOrb，横向流程节点+箭头，节点依次平滑点亮 |
| `grid` | GridScene | title, cards[] | 浅底+DotGrid，2×2 卡片网格 |
| `panel` | PanelScene | title, metrics[] | 深色背景+GlowOrb，数据指标卡（图标+箭头脉冲+数值+描述） |
| `cta` | CtaScene | title, sub | 全屏 accent 色+GlowOrb，品牌收尾；title=品牌名，sub=价值主张 |
| `timeline` | TimelineScene | title, sub, timelineMode, timelinePoints[], timelineHighlight, timelineCoupons[] | 深色背景+SVG 客流曲线（Catmull-Rom 平滑+stroke-dasharray 绘制） |
| `transfer` | TransferScene | title, sub, transferFrom, transferTo | 深色背景+GlowOrb；左侧人物→spring 飞卡→右侧人物淡入，表达券转赠裂变 |

- 版式变体：同一 type 通过 `scene.layout` 字段切换布局（如 solution 的 vertical/horizontal），不新建类型
- 需要新积木：设计稿写 `new:xxx`，按 R3 §五 完整流程（人审确认→代码→验证→回写）

## 五、两阶段生产流程

### 阶段一 · 无声版（画面确认）

1. 新建 `data/gXX.ts`：dur 用设计稿预估值（按 4.5-5 字/秒估算）；视觉 = 代码 UI + 字体 + 图标；首帧复用封面 hero 视觉
2. **字幕占位**：字幕内容按口播全文拆分（语义断句，每行 10-20 字），时间轴按预估 dur 均匀分布（仅作位置参考）

   **断句示例**：
   ```
   口播原文：开咖啡店的老板，别再让顾客充卡了。充一次几百块，顾客怕跑路不敢办；就算办了，充完就不见人，卡睡死半年用不完。换个思路——十杯次卡，锁客反而更牢。
   拆为 4 行（每行 10-20 字）：
   行1：开咖啡店的老板，别再让顾客充卡了。
   行2：充一次几百块，顾客怕跑路不敢办
   行3：就算办了，充完就不见人，卡睡死半年用不完
   行4：换个思路——十杯次卡，锁客反而更牢
   ```
3. 渲染无声版：`npx tsc --noEmit` → `npx remotion still` 关键帧验证（每屏 ≥1 帧）→ `npx remotion render`（无音频、有字幕占位）
4. **still 评审环**：① 首帧单独审（抖音首帧即门面）② 逐屏峰值帧出九宫格一起审 ③ 新风格方向 S1-S2 先出 2 版 still 供选择
5. **闸门**：人确认画面质量。不合格 → 走「指屏反馈闭环」→ 再渲染；合格 → 进入阶段二

#### 指屏反馈闭环（画面修改标准流程，2026-08-21 定）

> 用户的表达方式：不干预 AI 自主设计、不要求懂术语，**不满意的表达 = "第 X 屏不好" + 参考图（可选）**。AI 承担全部理解、重设计、渲染工作。

**默认态（零干预）**：设计稿阶段 AI 用布局模式库（R4 §5.9）+ 视觉参数（M2 §2.9）自主设计，**不需要用户提供参考图、不需要用户干预**。参考图是用户的"表达工具"（替代专业术语），用户主动给才算，不是流程强制环节。

**闭环步骤**（用户指出不满后 AI 执行）：

1. **定位**：用户指出的那一屏（只改这一屏，不动其他屏；除非用户明确要求整体重做）
2. **理解**：
   - 用户说了感受（如"这屏很乱""太空了"）→ 按 R4 §4.4 反馈翻译表翻译成专业指令
   - 用户给了参考图 → 按 §2.11 参考图拆解模板拆解 7 项
   - 两者都有 → 翻译 + 拆解交叉印证
3. **重设计**（该屏）：换布局模式（R4 §5.9，与相邻屏不重复）/ 重排视觉参数（§2.9 字号阶梯/间距/留白/色彩）/ 重设焦点（§2.10）
4. **验证**：渲染该屏 still → 用户确认 → 通过才继续；不通过重复 1-3（每轮只改该屏）
5. **沉淀**：修改中发现的规律回写 R4——新感受 → §4.4 反馈翻译表；新手法 → §5 参照库 / §5.9 布局模式库；新坑 → §3 踩坑库（E-xxx）

**纪律**：
- 用户没说"整体重做"前，禁止推倒重来——只改指定屏，保证其他已确认屏不受影响
- AI 必须把"用户感受"翻译成可执行指令后动手，禁止直接"把字体放大/卡片放大"式表面修改
- 每轮修改渲染 1-2 帧 still 即可，不必全片重渲（除非改的是全片氛围层等全局项）

### 阶段二 · 有声版（最终成片）

1. **TTS 语音（J-cut 一次到位）**：豆包 `seed-tts-2.0`，`speech_rate=0` 常速；逐屏合成 `public/audio/{视频ID}/s1.wav`~`sN.wav`（N=屏数，按视频 ID 分子目录）；**数字统一写中文；禁止 atempo 调速**；如有问题整体重录，不做片段微调
2. **响度归一化**：`scripts/process-audio.sh`（仅 loudnorm，零裁剪零淡入）
3. **精确时长**：ffprobe / `getAudioDurationInSeconds` 测每段语音时长
4. **算 dur（确定性公式，零经验值）**：
   ```
   dur = ceilTo01(audioDuration) + extraHold
   voiceOffset = 0（画面一出来就说话；CTA 屏可 0.5s 品牌先出）
   extraHold：信息屏（hook/pain/solution/flow/grid）= 0s；数据屏（panel）= 0.8s；CTA 屏 = 1.5s
   voiceDur = audioDuration 实测值回填（音频淡出起点 = 语音实际结束帧，尾字零削波；未回填时退回到最后 12 帧淡出）
   ```
5. **字幕精确同步**：字幕内容 = 口播全文；每行起止帧按 TTS 实测时长精确分配
6. **成片渲染**：`npx tsc --noEmit` → `npx remotion render`（含音频+字幕）
7. **盲听校验**：渲染后盲听全片一遍（不看画面）——检查每屏首字清晰完整、转场无爆音/尾字被切、整体节奏自然。**以渲染结果为准，不信预览器**

## 六、素材取用规则

### 6.1 本地素材优先检索（设计稿前置步骤）

素材库清单（`promotion/` 下，与 docs/ 同级；数量与登记以 R1 素材登记附录为准）：

| 库 | 根路径 | 内容 | 适用场景 | 引入 video/public 路径 |
|---|---|---|---|---|
| 背景素材 | `背景素材/` | 抽象模板（暖/冷色系）+ 小红书风格 | 全屏氛围背景 | `video/public/backgrounds/gXX/` |
| 图鱼纹理 | `图标素材/图鱼素材/` | 771 个纹理图案（数字命名） | UI 卡片底纹、装饰层 | `video/public/textures/gXX/` |
| 插图库 | `插图库/` | 挂件贴纸/物体插画（按类型/行业分子目录） | 情境插画 | `video/public/illustrations/gXX/` |
| 商用字体 | `商用字体/` | 普惠体/得意黑/方圆体（已 bundle 6 个） | 全片排版 | 已在 `video/public/fonts/` |

**检索流程**：
1. 判断该屏是否纯 UI 组件可表达（当前 9 种积木多数场景不需要外部图）
2. 需要背景图：AI 输出需求引导（风格/色调/构图），人从 `背景素材/` 子目录选；本地无合适 → 输出找图需求单（仅 A 类）
3. 需要纹理：先用代码 `DotGrid`/`GlowOrb` 零素材方案；需图片纹理时人从图鱼素材选
4. 需要情境插画：先查 `插图库/`；为空或不匹配 → AI 用代码图标/几何/文字排版替代（B 类，不卡流程不等人）
5. **A/B 分类铁律**：A 类（背景图+封面图）本地没有 → 输出完整规格表人找图；B 类（插画/挂件/装饰）本地没有 → AI 用代码替代，**不输出找图需求**

**路径引入机制**：素材从根目录**复制**（非符号链接）到 `video/public/` 对应子目录：
```
背景素材/抽象模板/冷色系/BG-ABS-002.png → video/public/backgrounds/gXX/bg.jpg
```
命名规则：`gXX-s{屏号}-{角色}.{ext}`（如 g03-s1-bg.jpg）。音频按视频 ID 分子目录 `public/audio/{视频ID}/`，raw/ 放 TTS 原始输出。

### 6.2 图片使用规范（Remotion 中）

- 图片必须有入场动画（FadeInUp/ScaleIn/WipeIn 等），禁止裸放
- 背景图必须有叠加层保证文字可读（对比度 ≥4.5:1）
- 路径用 `staticFile()` 引用，禁止硬编码绝对路径
- 三类素材对应三个 public 子目录：backgrounds/ / textures/ / illustrations/
- data 文件通过 `image?: string` 字段指定图片路径

**背景图显示策略（2026-08-21 定调）**：
- **默认直接显示原图（blur=0）**——背景图按找图需求单选回后，本身就是"氛围好、内容区留白"的图，直接透出，不做毛玻璃模糊
- 仅当背景图过亮/过花、与前景对比度不足时，才用 `AccentOverlay` 主色调和（palette 主色 soft-light 18%，已有组件）做统一
- 毛玻璃模糊（blur 2-6px）降为**可选**，不作为默认（用户实测：纯色差、毛玻璃差，直接显示 + 约束前置才稳）
- 禁止全屏半透明遮罩（V-R07）

**背景图兼容验证（图到位后必做，防全量渲染后才发现撞色）**：
1. 背景图放入 `video/public/backgrounds/gXX/` 后，先渲染 1-2 帧 still（含前景元素的内容区帧）
2. 逐帧检查前景对比度：标题/正文/卡片与背景图同区域是否清晰（对比度 ≥4.5:1）、有无颜色重叠
3. 不达标 → 二选一：① 代码层局部处理（内容区局部暗化 / 文字加描边 / 卡片加白底）② 让用户换图或按「前景兼容约束」重新生成
4. 验证通过后才进入全量无声版渲染

### 6.3 外部找图规格表（仅 A 类背景+封面）

```yaml
素材编号: IMG-GXX-01
来源: 外部找图
使用场景: S1 钩子屏全屏背景
画面位置: 全屏背景（文字在上层）
尺寸规格: 1080×1920 px，72dpi，JPG/PNG
风格方向: 抽象光斑/渐变色块/纹理（8 种风格方向见 R1 素材附录）
色调要求: 与 palette 协调（写出主色 hex + 禁用色）
前景兼容约束: 内容区（y:200-1100）必须留白或低饱和；前景主色清单（如标题白字/卡片白底/强调色 #2E7D32），背景图同区域不得与之撞色；内容区禁高饱和色块/复杂纹理/人脸/文字
内容描述: 具体到元素+构图+留白（文字放哪里）
情绪氛围: 温暖/专业/科技…

版权要求: 可商用（站酷/创客贴/Envato/Unsplash License）
文件命名: g03-s1-bg.jpg
存放路径: video/public/backgrounds/g03/g03-s1-bg.jpg
```

> **背景图 AI 描述铁律**：只描述"质感+光色+氛围"，不描述具体物体（背景图是底色不是内容，画了咖啡杯会跟前景 UI 抢戏）。
> **前景兼容约束必填**：找图/生图需求必须包含「前景兼容约束」字段（§6.2），否则图回来可能撞色返工。AI 生图提示词里同步写入：内容区留白、避开前景主色、无文字无 logo。

## 七、质量检查清单

### 7.1 无声版检查（阶段一，AI 渲染后逐项自检）

| 检查项 | 检查方法 | 通过标准 |
|---|---|---|
| 画面安全区 | 渲染关键帧，检查顶部 120px/底部 160px 是否有内容溢出 | 无溢出 |
| 核心内容集中 | 每屏核心内容是否在 y:200-1100 | 无内容分散到全屏 |
| 排版节奏 | 逐屏看 padding/间距/标题与内容关系 | 呼吸感好，不挤不散 |
| 整体节奏 | 按预估语速默读一遍 | 不拖沓不仓促 |
| 字幕位置 | 字幕在 y:1760-1920，底部距底 ≥60px | 不侵入内容区 |
| 转场流畅 | 屏间转场无黑帧/闪白/卡顿 | 无缝衔接 |
| 氛围层 | Vignette/Grain/AccentOverlay 已挂载 | 画面不"平"不"黑" |

### 7.2 有声版追加检查（阶段二）

| 检查项 | 检查方法 | 通过标准 |
|---|---|---|
| 字幕对齐 | 播放全片逐屏检查 | 字幕与口播首字同步 |
| 首字完整性 | 逐屏检查口播第一个字 | 每屏首字完整可听 |
| 尾音不爆 | 逐屏检查尾音 | 尾音自然衰减无截断 |
| 整体节奏 | 盲听全片一遍 | 节奏自然语速舒适 |
