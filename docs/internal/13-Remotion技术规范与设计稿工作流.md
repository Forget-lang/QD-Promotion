# 13 · Remotion 技术规范与设计稿工作流

> 本文档是「券到卡包」Remotion 视频的**技术规范 + 设计稿工作流单一权威**，与 10（视频制作方案）配套。
> 10 定义「做什么内容」，本文档定义「怎么用代码精确实现、设计稿写到什么程度才算可执行」。
> 冲突分层：红线/合规以 14 号文档为准，产品事实以 `00` 为准，视频技术实现以本文档为准。
> 源于 G02 茶饮咖啡视频专业级评审的经验沉淀。

## 一、核心原则

### 1.1 设计稿是「可执行规格」，不是「灵感参考」

设计稿的目标读者是**执行 AI**，不是人。每一条描述必须能被无歧义地翻译成代码：

| 模糊写法（禁止） | 精确写法（要求） |
|---|---|
| 「标题柔和淡入」 | 「FadeInUp，delay=6 帧，motion=buttery，dist=50px」 |
| 「节点依次亮起」 | 「节点 i 在 frame 18+i×22 开始，15 帧内 interpolateColors 从 rgba(255,255,255,0.08) 到 #ffffff」 |
| 「转场自然」 | 「wipe({direction:'from-bottom'})，12 帧，springTiming damping=50 stiffness=50」 |
| 「配一张咖啡店图」 | 先按 §4.1 检索本地素材库，再按 §4.3 规格表逐字段填写 |

**AI 在设计稿环节的核心职责**：把内容创意、视觉风格、动画时序、素材需求全部规划到参数级，让人只需要「找图 + 确认」，不需要做创意决策。

### 1.2 架构分层：引擎锁定，内容替换

```
┌─────────────────────────────────────────────┐
│  data/gXX.ts          内容数据 + 风格配置     │  ← 每条视频新建
│  （文案/卡片/节点/指标 + style 五维）         │
├─────────────────────────────────────────────┤
│  scenes/              场景渲染器（9 种积木）  │  ← 锁定，按需扩展
│  HookScene / PainScene / SolutionScene ...  │
├─────────────────────────────────────────────┤
│  components/          原子组件库              │  ← 锁定，不轻易改
│  animations / ui / icons                    │
├─────────────────────────────────────────────┤
│  VTemplate.tsx        编排引擎                │  ← 锁定
│  TransitionSeries + 场景分发                 │
└─────────────────────────────────────────────┘
```

**铁律**：新视频 = 新建 `data/gXX.ts` + （按需）找图片素材。引擎和积木保持锁定，只有在需要新叙事型时才扩展 scene renderer，扩展后回写本文档。

### 1.3 图片素材：AI 规划，本地优先，人找图

视觉素材以**代码 UI 组件为主视觉**，AI 生图不用于主视觉（质感不可控、风格不统一）。素材获取优先级：

1. **代码生成**：DotGrid/GlowOrb 等装饰、内联 SVG 图标、纯 UI 组件（当前多数场景够用）
2. **本地素材库**：按 §4.1 先检索 `背景素材/`、`图标素材/图鱼素材/`、`插图库/`，本地有合适的直接引用
3. **AI 生成补充插画**：仅当代码 UI 和本地素材都不足以表达时，AI 可生成草稿，附 11 §4 可用性声明，人确认后入 `插图库/`
4. **人从外部平台找图**：以上均不满足时，AI 在设计稿中输出规格表（§4.3），人从站酷/创客贴/Dribbble/Envato/Unsplash 等平台找到后放入 `public/` 对应子目录

## 二、Remotion 技术硬规则

> 以下规则源于 G02 评审中发现的真实 Bug，全部为强制项，违反即视为技术缺陷。

### 2.1 动画规则

| 规则 | 说明 | 反例（禁止） |
|---|---|---|
| **禁止 CSS animation/transition** | Remotion 逐帧渲染，CSS 动画时间轴与 Remotion 帧不同步，渲染结果不可控 | `style={{animation: 'fadeIn 0.5s'}}` 或 Tailwind `animate-fade-in` |
| **全部用 useCurrentFrame + interpolate/spring** | 唯一合法的动画驱动方式 | — |
| **非 spring 插值必须指定 easing** | 禁止裸 interpolate 不设 easing（默认线性，观感生硬） | `interpolate(f, [0,30], [0,1])` 缺 easing |
| **标准缓动曲线** | 所有非 spring 动画统一用 `EASE_OUT = Easing.bezier(0.16, 1, 0.3, 1)`（expo-out） | 自行发明 bezier 参数 |
| **spring 必须透传 motion** | 所有动画组件的 motion 参数必须从 `style.motion` 读取，禁止硬编码默认值覆盖风格配置 | `<FadeInUp motion='bouncy'>` 写死，应 `<FadeInUp motion={style.motion}>` |
| **禁止嵌套动画时序冲突** | 父容器入场动画期间，子元素不要设独立 delay 超过父动画时长（会导致子元素在不可见期间空跑动画） | `<SlideInRight delay={14}><ScaleIn delay={40}>` 父动画 14-30 帧期间子 opacity=0 |
| **颜色过渡用 interpolateColors** | 涉及颜色变化的动画禁止 boolean 切换 | `const lit = f > threshold; color={lit ? '#fff' : '#333'}` 瞬切 |

### 2.2 转场规则

| 规则 | 说明 |
|---|---|
| **必须用 TransitionSeries** | 场景间禁止 `<Sequence>` 硬切，必须通过 `@remotion/transitions` 的 TransitionSeries + Transition 串联 |
| **转场时长 12 帧（0.4s）** | 专业 MG 标准，不拖沓不突兀。特殊风格可在 8-16 帧范围内调整，设计稿中显式标注 |
| **timing 用 springTiming** | config 对齐当前视频的 motion 风格（buttery→damping50/stiffness50，bouncy→damping14/stiffness100） |
| **presentation 由 style.transition 决定** | 通过 `getPresentation()` 映射，禁止在 VTemplate 里硬编码单一转场型 |

### 2.3 布局规则

| 规则 | 说明 |
|---|---|
| **画幅固定 1080×1920 @30fps** | 9:16 竖版，抖音单画幅输出 |
| **字号/间距用绝对像素** | 当前 1080×1920 固定画幅下直接用 px，不引入 vmin（避免响应式复杂度）；如果未来需要多画幅再引入 |
| **中文字体必须本地加载** | 通过 `@font-face` 注册 `public/fonts/` 下的字体文件，禁止依赖系统字体 |
| **文字安全区** | 标题左右 padding ≥60px，顶部距上边 ≥120px（避开状态栏+平台UI），底部距底边 ≥160px（字幕区） |
| **字幕安全区** | 有字幕的视频，字幕底部距视频底部 60px（白字黑描边，34px），整体位于 y:1760-1920 底部区域内，不侵入内容区 |
| **活动区（安全底线）** | y:120-1760。画面主体内容不能超出这个范围（硬底线，出界 = 不合格） |
| **核心内容集中原则（好看的推荐范围）** | 核心内容（标题 + 卡片/图标/流程等）推荐集中在 **y:200-1100** 区域内。标题距顶部 ≥200px（避开平台 UI + 给呼吸空间）；内容区底部距字幕区（y:1760）留出大量留白让画面不压抑；标题与下方内容间距 40-60px（是一个整体，不能割裂）；多卡片之间间距 ≥ 卡片高度的 20%；卡片内 padding ≥ 画面宽度的 4%（约 43px）。此规则只约束垂直分布，不限制风格/配色/创意。120-1760 是安全底线，200-1100 是让画面好看的推荐集中区 |

### 2.7 字幕同步规范

**核心规则：字幕 = 口播全文，内容完全一致，不做摘要不缩写。**

| 项 | 规范 |
|---|---|
| **内容** | 字幕与口播完全一致（全文同步），按语义断句分行，每行 10-20 字 |
| **样式** | 普惠体 500，34px，白字 + 黑色描边 3px，居中 |
| **位置** | y:1760-1920 底部区域，底部距视频底边 ≥60px |
| **时间轴** | 无声版：字幕按预估 dur 均匀分布（仅作位置参考）；有声版：每行字幕的显示/隐藏时间点由 TTS 实测时长精确分配 |
| **工作流顺序** | 阶段一：写口播 → 拆字幕分行 → 代码实现（dur 预估 + 字幕占位）→ 无声版渲染确认 → 阶段二：生成 TTS → ffprobe 量时长 → 按公式算 dur → 字幕精确时间轴 → 有声版渲染 |

**实现方式**：在 Remotion 中用 `<Subtitle>` 组件，接收 `lines: {text, startFrame, endFrame}[]` 数据，按帧渲染当前应显示的字幕行。字幕数据写在 `data/gXX.ts` 的 `subtitles` 字段中。

### 2.4 代码结构规则

| 规则 | 说明 |
|---|---|
| **场景内容全部从 scene 数据读取** | 场景渲染器内禁止硬编码文案、颜色、图标名 |
| **风格值全部从 style/palette 读取** | 禁止在场景组件内硬编码色值（语义色 ACCENT_RED/GREEN 等除外） |
| **图标用内联 SVG 组件** | 通过 `<Ico name={color} />` 调用，禁止引用外部图标文件/CDN；新图标优先用 Icon MCP Server（`search_icons`/`generate_icon`）检索或生成 SVG，再转为内联组件加入 `icons.tsx`（见 §8.3） |
| **图片用 `<Img src={staticFile(...)} />`** | 禁止用 `<img>`（Remotion 的 Img 组件有渲染优化） |

### 2.5 声画同步技术原理（帧级确定性）

> Remotion 的同步保障和传统编辑器（PR/剪映）有本质区别——它是"代码即时间线"，每一帧都是确定性的纯函数。

**核心原理**：`视频 = f(frame)`，frame 从 0 到 N，每一帧独立渲染、结果唯一。
- 全片固定 FPS（30），`durationInFrames = 秒数 × 30`，无浮点误差
- 动画参数通过 `interpolate(frame, ...)` 由 frame 直接计算，不依赖"播放了多久"
- 第 150 帧渲染 100 次结果完全一样，不存在播放漂移

**三层同步机制**：

1. **`<Audio>` 组件精确时间定位**：`startFrom` / `endAt` 单位是帧，不是秒。多段音频各自对齐到对应分镜的起始帧，音量用 `interpolate(frame, ...)` 做帧级淡入淡出。
2. **`useCurrentFrame()` 驱动动画**：所有动画都是 frame 的函数，`spring({ frame: frame - offset, fps })` 的起始帧精确可控，不会因性能波动延迟。
3. **`Sequence` 嵌套组织时间线**：`<Sequence from={from} durationInFrames={dur}>` 相当于轨道片段，`from` 决定该区块从全局第几帧开始。嵌套 Sequence 可精确控制子动画相对于分镜起点的偏移。

**字体/素材预加载**：中文字体通过 `@font-face` + `delayRender` 确保加载完成后再渲染，避免文字字形偏移。大图用 `<Img>` 的 `onLoad` + `delayRender` 确保资源就绪。

**音频时长精确获取 API**：
```tsx
import { getAudioDurationInSeconds } from '@remotion/media-utils';
const duration = await getAudioDurationInSeconds(staticFile('audio/{视频ID}/s1.wav'));
const frames = Math.round(duration * 30);
```
渲染前用此 API 拿到精确时长（非估算），再决定分镜帧数。

**预览 vs 渲染差异**：Remotion Studio 预览时音频和画面可能因性能有轻微延迟，但最终 `npx remotion render` 渲染结果一定同步——以渲染结果为准，不以预览为准。

**渲染管线（双轨并行 + 最终 mux）**：
Remotion 的视频和音频是两条独立管线，最后通过 FFmpeg mux（封装）合成。
1. **视频轨**：Headless Chrome 逐帧截图 → FFmpeg 编码视频
2. **音频轨**：解析所有 `<Audio>` 组件的 `startFrom`/`endAt`/`volume(f)` → FFmpeg `amix` 混合多轨 → AAC 编码
3. **最终合成**：FFmpeg 将视频帧和音频轨按精确时间戳封装进 MP4 容器，精度微秒级

→ 结论：`<Audio>` 的 `volume` 属性是帧级精确的（Remotion 采样每帧音量值传给 FFmpeg volume 滤镜），`startFrom` 是帧级精确的，不存在"大概"或"漂移"。

### 2.6 J-cut 转场同步法（标准方案）

> **这是声画同步的标准方案。所有新视频默认采用此方案，无需再调试。**

**核心思想**：音频驱动时长，转场 = 上句淡出 + 下句满音量进入（J-cut），首字不丢、尾音不爆、无缝衔接。

**音频预处理**（零裁剪、零淡入，只做响度归一化）：
- TTS 自然语速生成（seed-tts-2.0, speech_rate=0），**禁止 atempo 调速**
- 仅用 ffmpeg `loudnorm=I=-16:TP=-1.5:LRA=11` 做响度归一化
- **不裁剪首尾静音**，不做文件级淡入淡出
- 脚本：`scripts/process-audio.sh`（仅 loudnorm 模式）

**时间轴公式**（确定性计算，零经验值）：
```
dur = ceilTo01(audioDuration) + extraHold
voiceOffset = 0（画面一出来就说话）
voiceDur = audioDuration 实测值原样回填（ffprobe，秒）→ 音频淡出从语音实际结束点开始
```
- `ceilTo01`：向上取到 0.1 秒，确保 `dur ≥ 音频时长`，音频绝不被截断
- `extraHold`（说完后画面额外停留）：
  - 信息屏（hook/pain/solution/flow/grid）：0s → 说完立刻转场
  - 数据屏（panel）：0.8s → 给观众读数字的时间
  - CTA 屏（最后一屏）：1.5s → 品牌记忆停留
- `voiceDur`（2026-08-20 B 方案）：TTS 后 ffprobe 实测时长回填进 data 的每屏 `voiceDur` 字段；音频淡出起点 = 语音实际结束帧，**尾字零削波**（旧方案固定最后 12 帧淡出，实测会压到尾字自然衰减约 0.2s，换 TTS 引悦/音色后风险放大）。未回填时自动退回旧逻辑。

**J-cut 转场同步原理**：
```
时间：     ←──── 转场 0.4s（12帧）────→
           
上屏音频： 正常音量 ─── 1→0 线性淡出 ── 0
           ↖ 尾音完整说完，最后 0.4s 渐弱
           
下屏音频：  满音量 ───── 正常播放 ──────
           ↗ 第一个字 100% 完整清晰（零淡入）
           
画面：     上屏渐出 ←────────→ 下屏渐入
```

**代码实现**（`FadingAudio` 组件，VTemplate.tsx）：
- 每屏音频从第 0 帧开始播放（voiceOffset=0）
- 淡出起点：voiceDur 已回填时 = 语音实际结束帧（B 方案）；未回填时 = 最后 `TRANSITION_FRAMES`（12帧=0.4s）
- 下一屏音频在转场第 0 帧以满音量进入
- 最后一屏（CTA）说完后随 voiceDur 缓淡出到屏尾，自然收尾

**为什么是确定性的（不需要反复试）**：
1. TTS 同一模型同一参数，语速波动 ±2% 以内
2. ffprobe 毫秒级精确测量音频时长
3. Remotion 帧级渲染，音量曲线是精确数学函数
4. 所有 dur 从 audioDuration 直接推导，无经验调参
→ **TTS 只生成一次，渲染一次成片，零调试**

**验证方式**：听最终渲染的 MP4 文件（不信预览器），检查三点：
1. 每屏第一个字是否清晰完整
2. 转场时是否有爆音或尾字被切
3. 整体节奏是否自然（不拖沓也不赶）

### 3.2 相似度检查闸门（强制）

新视频启动前，必须与上一条已产出视频逐维对比，**至少 3 个维度不同**才放行。
> 注意：基线值以 `video/src/data/` 中最新一条视频的代码实际值为准，不以本文档的静态表格为准。每次做完新视频，本表基线值应更新。
>
> **关于 G02**：G02 是 1.0 时代的首条视频（7 屏 52.6s），仅作为相似度对比的起点基线，**不代表 2.0 标准的达标样板**。2.0 的深度/屏数/时长标准见 08 号文档。

| 对比维度 | G02 代码实际值（当前基线） | 新视频必须不同的条件 |
|---|---|---|
| palette | warm-orange | 换一套 |
| motion | snappy | 换一种 |
| transition | slide | 换一种 |
| typography | friendly | 换一种 |
| hookStyle | question | 换一种 |
| 行业背景图 | 咖啡拉花（warm-orange 氛围） | 换行业专属图 |
| 场景序列 | hook → pain → solution → flow → grid → panel → cta（共 7 屏） | 至少 3 个场景类型不同（比对规则见下） |

**场景序列比对规则**：
- 比对的是**场景类型集合的差异**，不是按位置序号一一对应（因为屏数可能不同）。
- 方法：列出两条视频的场景类型清单（去重），统计**新增类型数 + 消失类型数 + 位置重排数**，三者之和 ≥ 3 即为通过。
  - 新增类型：新视频有、基线没有的场景类型
  - 消失类型：基线有、新视频没有的场景类型
  - 位置重排：同一类型在两条视频中的相对顺序发生了变化
- 简单判断：如果两条视频的"开场类型不同 + 中段结构不同 + 收束方式不同"，基本就满足了。

检查结果写入设计稿「相似度检查」小节，列出对比表。

### 3.3 背景模板图（每行业一张专属）

> 每条视频配一张行业专属背景模板图（抽象光斑/渐变色块/纹理），**毛玻璃微虚化处理**（轻微模糊，保留光影层次）。
> 背景模板图从 `背景素材/抽象模板/` 中选取（11 号 §9.1），设计稿阶段先查索引。

#### 三层结构

```
┌─────────────────────────┐
│  第三层：文字 + UI 组件    │  代码绘制，最清晰（卡片自带白底/阴影保证可读）
├─────────────────────────┤
│  第二层：局部对比度处理    │  不是全屏遮罩！仅在文字/卡片直接放背景上看不清时，
│                           │  用局部白底/描边/投影处理，保证可读性（见 V-R07）
├─────────────────────────┤
│  第一层：背景模板图        │  毛玻璃微虚化（blur: 4px），提供质感和行业氛围，
│                           │  直接作为画面基底，不被全屏遮罩覆盖
└─────────────────────────┘
```

> **重要**：第二层不是"铺满全屏的半透明深色/浅色遮罩"。背景图虚化后直接透出作为画面基底，内容（卡片、文字）直接放在上面。
> 只有当某个文字/元素直接放在背景图上对比度不够时，才做局部处理（比如给文字加描边、给卡片加白底+阴影），**禁止**全屏铺满半透明纯色/渐变遮罩把背景图完全盖住。
> 视觉设计的审美红线、建议、创意标准，统一以 09 号最佳实践库 §5.2 为唯一真源。

#### 处理参数（所有行业通用）

| 参数 | 值 | 原因 |
|---|---|---|
| 模糊 | 4px（推荐值 2-6px） | 毛玻璃微虚化：前景内容更突出，背景仍保留光影层次，不是一片糊 |
| 不透明度 | 100%（不降透明） | 虚化后仍保持全透，作为画面质感基底 |
| 主色统调 | 背景图上叠 palette 主色 `soft-light` 混合 18%（`AccentOverlay` 组件） | 模板图与 UI 色系融合 |
| Ken Burns | 背景图全片线性缩放 1.0→1.04（VTemplate 内 interpolate） | 静态模板图极慢推近变「活」，仍只做氛围不承担信息 |
| 叠加层 | **禁止全屏半透明遮罩**。内容（卡片/文字）直接放在虚化背景上，靠卡片白底+阴影、文字描边/投影保证对比度；仅局部需要时加小面积底色处理 | 全屏遮罩会盖住背景图质感，违反 V-R07 |
| 覆盖范围 | 全视频所有屏共用同一张 | 形成系列感，减少素材量 |

> **模糊强度参考**：
> - 2px — 极轻微，几乎看不出，但质感更柔
> - 4px — 毛玻璃感，光影层次仍清晰（默认推荐值）
> - 6-8px — 更明显的虚化，基本只剩色块
>
> 通过 `style.bgBlur` 字段配置（见 §4.1），不配置默认为 0（不模糊，兼容旧项目）。

#### 全片氛围层（VTemplate 统一挂载，场景与设计稿无需处理）

> 全片自动叠加两层质感，参数为视频级常量，**不逐屏调、不写进设计稿**：

| 层 | 组件 | 参数 | 作用 |
|---|---|---|---|
| 暗角 | `Vignette` | 径向渐变，55% 中心透明 → 四角 rgba(0,0,0,0.25) | 聚焦中部视线 |
| 颗粒 | `Grain` | feTurbulence 噪点 240px 平铺，opacity 3.5%，静态不动画 | 杀纯色渐变的色带（banding），全片图层质感统一 |

#### 选图标准

✅ 要：
- 抽象光斑/渐变色块/纹理风格（非照片实拍）
- 与行业色调协调（茶饮咖啡→暖棕/焦糖，美业→粉紫/玫瑰，教育→淡蓝/白）
- 画面简洁，留白多，不抢前景内容
- 竖版 1080×1920 或可裁剪的横版

❌ 不要：
- 文字太多的图
- 人物脸部特写（版权风险）
- 照片实拍类（已弃用，统一用抽象模板图）
- 横版元素强行竖用（构图严重失衡）

#### 文件路径

- 从 `背景素材/抽象模板/` 选取，复制到：`video/public/backgrounds/gXX/bg.jpg`
- 代码通过 `staticFile('backgrounds/gXX/bg.jpg')` 引用
- 每个行业一个独立子目录，互不干扰

### 3.4 品牌记忆锚（固定不变，不参与轮换）

以下元素是品牌「神」，每条视频保持一致：
- 品牌名称「券到卡包」（CTA 屏必须出现品牌名，具体文案由设计稿决定）
- 语义色体系（红=痛点/绿=解法/橙=强调/青=科技）
- 字体家族（得意黑/普惠体/方圆体，字重可轮换但字体不换）
- 底部字幕（白字黑描边，安全区内，所有视频统一）

## 四、图片素材规格表（设计稿核心产出物）

### 4.1 本地素材优先检索（前置步骤）

> **设计稿产出时，AI 必须先检索本地素材库，再决定是否输出外部找图规格。** 本地有合适素材时标注源路径直接引用；本地不足时才按 §4.3 输出外部检索规格表。

**本地素材库清单（`promotion/` 目录下，与 `docs/` 同级）**：

| 库 | 根路径 | 内容 | 适用场景 | 引入 video/public 路径 |
|---|---|---|---|---|
| 背景素材 | `背景素材/` | 古朴风格 15 张 + 小红书风格 20 张（共 35 张） | 全屏氛围背景（钩子屏/CTA 屏等） | `video/public/backgrounds/gXX/` |
| 图鱼纹理 | `图标素材/图鱼素材/` | 771 个纹理图案（PNG/JPG/GIF，数字命名） | UI 卡片底纹、装饰层、边角纹理 | `video/public/textures/gXX/` |
| 插图库 | `插图库/` | 当前为空；AI 生成经人确认后归档 | 情境插画（代码 UI 不足时补充） | `video/public/illustrations/gXX/` |
| 商用字体 | `商用字体/` | 普惠体/得意黑/方圆体等（已 bundle 6 个到 fonts/） | 全片排版 | 已在 `video/public/fonts/`，无需再引 |

**检索流程（AI 在设计稿 §5.5 中执行）**：

1. **判断是否需要图片素材**：按 §4.2 判断该屏是否纯 UI 组件可表达。当前 9 种积木多数场景不需要外部图。
2. **需要背景图时**：AI 列出需求（风格/色调/构图），由人在 `背景素材/` 子目录中浏览选择。AI 不扫描全库列文件名（库小但避免上下文膨胀），而是输出「从背景素材/古朴风格/ 或 小红书风格/ 中选取 XX 色调 XX 构图的竖版底图」的引导。
3. **需要纹理底纹时**：AI 输出纹理需求（图案类型/颜色/平铺方式），由人在 `图标素材/图鱼素材/` 中浏览选择。因文件全数字命名无标签，当前以人浏览选取为主；AI 不逐文件扫描。代码已内置 `DotGrid`（SVG 点阵）和 `GlowOrb`（CSS 柔光）作为零素材装饰方案，多数场景无需纹理图。
4. **需要情境插画时**：先检查 `插图库/` 是否有已入库可复用素材；为空或不匹配时，AI 可生成草稿（附 11 §4 可用性声明），人确认后入库。
5. **本地无合适素材**：按 §4.3 规格表字段填写外部检索需求，人从设计平台找图。

**路径引入机制（根目录 → video/public/）**：

Remotion 的 `staticFile()` 只能引用 `video/public/` 下的文件。根目录素材库是**源库**，使用时需**复制**（非符号链接）到 `video/public/` 对应子目录：

```
背景素材/小红书风格/3.jpg  → 复制到  video/public/backgrounds/g02/g02-s1-bg.jpg
图标素材/图鱼素材/1186.png → 复制到  video/public/textures/g02/g02-s3-texture.png
插图库/xxx.png             → 复制到  video/public/illustrations/g02/g02-s4-illus.png
```

命名规则：`gXX-s{屏号}-{角色}.{ext}`（如 `g02-s1-bg.jpg`、`g03-s3-texture.png`）。首次使用时由人创建对应 `gXX/` 子目录。

**音频文件规则（按视频 ID 分子目录）**：
- 语音文件放在 `video/public/audio/{视频ID}/`（`s1.wav`、`s2.wav`...），按视频 ID 分子目录，避免多视频串音
- 视频 ID 即 `data/gXX.ts` 中的 `id` 字段（如 `G02-TeaCoffee-V2`）
- `raw/` 子目录放 TTS 原始输出，处理后覆盖到上一级
- 历史音频保留在各自子目录，互不干扰

**代码引用示例**：

```tsx

       style={{width:'100%',height:'100%',objectFit:'cover'}} />
  {/* 文字在上层 */}
</AbsoluteFill>

// ② 纹理底纹平铺（来自图鱼素材/，复制到 public/textures/）
<div style={{
  backgroundImage:`url(${staticFile('textures/g02/g02-s3-texture.png')})`,
  backgroundSize:'200px 200px', backgroundRepeat:'repeat', opacity:0.06,

// ③ 情境插画（来自插图库/，复制到 public/illustrations/）
<ScaleIn delay={10} motion={style.motion}>
  <Img src={staticFile('illustrations/g02/g02-s4-illus.png')}
```

> 字体无需复制：已 bundle 的 6 个字体文件在 `video/public/fonts/`，通过 `index.tsx` 的 `@font-face` 全局注册，场景中直接用 `FONT_TITLE`/`FONT_BODY`/`TYPOGRAPHY` 常量引用。

### 4.4 字段填写规范

**素材编号**：`IMG-{视频编号}-{序号}`，如 IMG-G03-01。

**使用场景**：标注在哪个 Scene（S1-S7）和什么角色（背景/配图/装饰）。

**画面位置**：精确描述图片在画面中的位置和尺寸关系：
- 全屏背景：说明叠加层（如「深色渐变 60% 透明度叠加」）
- 局部配图：说明 x/y 坐标和宽高（如「画面中部偏右，400×400px」）
- 装饰元素：说明大小和位置（如「左下角，120×120px」）

**尺寸规格**：
- 全屏背景：1080×1920 px
- 局部配图：按实际显示尺寸 ×2（2x 图保证清晰度）
- 纹理底纹：512×512 px 可平铺
- 格式：照片用 JPG，插画/透明用 PNG

**风格方向**：从以下 8 种中选择（对应归档风格轮换方案 I1-I8）：

| 编号 | 风格 | 代码可实现度 | 素材来源建议 |
|---|---|---|---|
| I1 | 扁平几何 | 高（代码可做） | 通常不需要外部图 |
| I2 | 2.5D 等距 | 低 | 创客贴/Envato 搜 isometric |
| I3 | 手绘涂鸦 | 低 | 站酷搜 doodle/手绘 |
| I4 | 孟菲斯 | 中（代码可做几何） | 几何装饰可用代码，复杂图案需素材 |
| I5 | 国潮水墨 | 极低 | 站酷搜 国潮/水墨 |
| I6 | 极简线条 | 高（当前方案） | 内联 SVG 已覆盖 |
| I7 | 3D 黏土 | 极低 | Envato/Dribbble 搜 3D clay |
| I8 | 像素复古 | 中 | 创客贴搜 pixel |

**色调要求**：必须与当前视频的 palette 协调。写出主色 hex 值和禁用色。

**内容描述**：具体到画面元素（有什么物体、什么动作、什么构图），以及留白区域（文字要放在哪里）。

**检索关键词**：给人在设计平台搜索用的词，3-6 个，包含行业+风格+色调+元素。

**AI 生成描述**（A 类背景图/封面图必填）：当创可贴等平台找不到合适素材时，直接复制这段话到 AI 生图工具（Seedream / Midjourney / 即梦 / 可灵 等）生成。填写必须满足以下精度要求：

| 项 | 要求 | 示例 |
|---|---|---|
| **画幅方向** | 明确竖版/横版 + 具体像素 | 竖版 1080x1920 |
| **主色调** | 写出 2-3 个具体色值（与 palette 对应） | 墨绿 #1a4d3e + 浅绿 #52b788 + 米白 #f8f9fa |
| **核心元素** | 具体到有什么、怎么排布 | 柔和散焦光斑，左上亮右下暗 |
| **风格质感** | 用质感词描述，不用抽象词 | 朦胧柔光、颗粒质感、高级感 |
| **行业氛围暗示** | 通过光色/质感暗示行业，不画具体物体 | 模拟咖啡店暖光氛围 / 美业柔光氛围 |
| **留白/构图** | 说明哪里空、哪里有内容 | 画面中心偏下留白，四周虚化过渡 |
| **排除项** | 明确不能有的东西 | 无文字、无 logo、无人脸、无具体物体 |
| **英文关键词** | 附 3-5 个英文风格词（适配 Midjourney 等海外工具） | bokeh, soft focus, minimal, abstract, high quality |
| **负面提示词** | 列出必须排除的元素 | text, logo, watermark, people, face, sharp edges |

> **背景图 AI 描述的铁律**：只描述"质感+光色+氛围"，不描述具体物体。背景图是底色不是内容，画了咖啡杯/理发椅会跟前景 UI 抢戏。

### 5.6 口播稿与声画同步

按 10 §7 规范产出旁白文本。**采用两阶段生产：先无声版确认画面 → 再生成 TTS 做有声版**。声画同步采用 J-cut 转场同步法（§2.6），音频驱动时长，TTS 只生成一次，零调试。

**文字量参考（用于设计稿阶段估算，非硬约束）：**
- 自然语速约 4.5-5 字/秒，用于设计稿阶段估算大概时长
- 无声版 dur 用预估值（按 4.5-5 字/秒估算）
- 最终 dur 由 TTS 实测时长决定（公式见 §2.6），不是由文字量反推
- 禁止 atempo 调速，文字量不合适就改文案

**两阶段标准流程：**

```
阶段一 · 无声版（画面确认）
1. 设计稿写口播文案（按 4.5-5 字/秒 估算大致节奏）
2. 代码实现 → dur 用预估值 → 字幕占位（均匀分布）
3. 渲染无声版 → 人确认画面
4. 画面不合格 → 改 → 再确认；合格 → 进入阶段二

阶段二 · 有声版（最终成片）
5. TTS 逐屏生成（一次，消耗 1 次额度）
6. ffprobe 测量每段音频时长（毫秒级精确）
7. 按公式算 dur：dur = ceilTo01(audioDur) + extraHold
   信息屏 extraHold=0 / 数据屏 0.8s / CTA 1.5s
8. 更新字幕精确时间轴 → 更新 data 文件 → 渲染最终成片
```

**声画同步规则（全部按 §2.6 J-cut 标准执行）：**

1. **voiceOffset = 0**：画面一出来就说话，不做画面铺垫延迟。钩子屏、信息屏都从第 0 帧开口。CTA 屏品牌名可以先出现 0.5s 再说话（voiceOffset=0.5）。

2. **数字统一写中文**：口播稿中所有数字统一写中文汉字，防止 TTS 对阿拉伯数字读法不一致。示例：写"三天"而非"3 天"，写"百分之九十九"而非"99%"。

3. **音频零裁剪零淡入**：TTS 原始内容完整保留，只做响度归一化。淡入淡出在代码层通过 `<Audio volume={f}>` 帧级控制，不在文件级做。

4. **关键字动画绑定语音重音（可选进阶）**：关键字大字弹入的动画时刻对齐口播中的重音词。口播稿中重音词用 **加粗** 标注，动画 delay 绑定到该词在语音中的时间偏移。仅对**关键字大字弹入**、**核心数据展示**、**对比画面切换**这三类做绑定，普通装饰动画按屏内固定时序执行。

#### 信息单元数（≥ 6 个才算合格）

#### 深度 4 问（全过才算合格）

- [ ] **有没有"哦，还能这样"的感觉**：有没有一个让人意外的点？还是全是意料之中的常识？

#### 同质化检查（与上一条视频对比）

- [ ] **切入点不同**：上一条是"痛点→功能罗列"，这条是"反常识→完整方案"，还是换汤不换药？

- [ ] **行业话术不同**：不是把"咖啡店"换成"美容院"就行，而是每个业态的场景、话术、痛点都有行业专属感

### 5.9 封面图设计规范（独立交付物）

> **封面规范唯一真源见 07 号文档 §3**，本节为设计执行层面的细则补充。
> **封面的战略地位**：封面决定点击率，点击率决定初始流量，初始流量决定平台是否推流。封面做不好，视频内容再好也没人看。
> **设计依据**：07 §3（策略层唯一真源）+ 09 最佳实践库 §6.3「封面设计与 3 秒留存优化」+ 本节版式库
> **AI 职责**：按本规范产出封面设计稿（版式选型 + 文案 + 找图规格 + 检索关键词），由人到设计平台（创可贴/Canva 等）制作，AI 不直接生成封面主图

#### 5.9.1 封面尺寸与基础要求

| 项 | 要求 |
|---|---|
| 尺寸 | 1080×1920（竖屏，与视频画幅一致） |
| 格式 | JPG / PNG |
| 文件大小 | ≤ 5MB |
| 安全区 | 顶部 160px（平台头像/昵称），底部 200px（文案/话题标签），左右各 80px |
| 文字最小字号 | 不小于 80px（手机小屏上能看清） |

#### 5.9.2 高转化封面的 6 个核心要素

> 一个好封面至少具备以下 3 个要素。要素越多，点击率通常越高。

1. **数字冲击**——用具体数字制造反差感（"3 天 200 个新客""一张券省 50 块"）
2. **痛点共鸣**——直接说中目标用户的烦心事（"下午 3 点没人？""发券没效果？"）
3. **行业识别**——一眼看出是做什么行业的（咖啡杯/理发椅/洗车机等）
4. **反差对比**——打破预期，激发好奇心（"不打折也能锁客""越送越赚钱"）
5. **利益承诺**——明确告诉观众能得到什么（"学会这招，回头客翻 3 倍"）
6. **情绪脸谱**——真人表情（惊讶/困惑/开心）比纯文字更抓眼（有条件时用）

#### 5.9.3 封面版式库（7 种标准版式）

> AI 设计封面时从以下版式中选一种，不要凭空发明。每个版式都标注了适用场景和关键设计点。

| 编号 | 版式名称 | 结构 | 适用场景 | 关键设计点 |
|---|---|---|---|---|
| C-01 | **大字标题型** | 上半屏大标题 + 下半屏行业元素 | 钩子是问句/金句的视频 | 标题占画面 40% 以上，粗黑字+描边，下方配 1-2 个行业图标 |
| C-02 | **数字冲击型** | 超大数字 + 右侧/下方说明文字 | 有具体数据/数字的视频（"3 个方法""省 50%"） | 数字用对比色突出，字号至少是文字的 2 倍，数字做描边/投影 |
| C-03 | **左右对比型** | 左 "以前" / 右 "以后"，中间分隔线 | 讲"前后变化"的视频（用了 vs 没用） | 左边暗/冷色（痛点），右边亮/暖色（解法），中间用 VS 或箭头分隔 |
| C-04 | **卡片干货型** | 仿浏览器顶栏 + 白色卡片 + 标题 + 元素 | 知识干货类视频（"咖啡店经营干货"） | 顶部橙色条 + 分类标题 + 三点小图标，吊牌标签增加信任背书 |
| C-05 | **痛点场景型** | 上半屏痛点问句 + 下半屏装饰元素 | 场景化强的行业（餐饮/美业/洗车） | 背景用行业专属模板图（毛玻璃微虚化），前景大字问句，白字黑描边，底部配 1-2 个行业图标/几何装饰 |
| C-06 | **产品展示型** | 中心大图（券/卡/手机）+ 上下文字 | 展示具体产品形态的视频（次卡/优惠券/核销码） | 产品图占画面 50%，有阴影和倾斜角度，标题在上方，利益点在下方 |
| C-07 | **利益清单型** | 标题 + 3-4 个带对勾的好处 | 讲"多个好处"的视频（"这 4 种券都能做"） | 左对齐的好处列表，每个前面有对勾图标，主色统一，信息密度高 |

#### 5.9.4 封面配色规范

| 原则 | 说明 |
|---|---|
| **主色不超过 2 个** | 同色系深浅变化不算。主色 + 背景色 + 黑/白 = 最多 3 个色系 |
| **与视频 palette 呼应** | 封面主色与视频主色调一致或接近，保持品牌统一感 |
| **文字对比度 ≥ 4.5:1** | 标题文字与背景的对比度必须足够，手机小屏上能一眼看清 |
| **行业适配** | 茶饮咖啡→暖橙/咖棕；美业→粉紫/米金；洗车→蓝绿；餐饮→红橙；零售→绿/蓝 |

#### 5.9.5 封面找图方法（三层关键词法）

> 找图不是搜关键词碰运气，而是有方法地筛选。以下是从 100 张图里快速找到 1 张好图的方法。

**第一步：确定主体关键词（必须有）**
- 行业主体：如「咖啡店」「理发店」「洗车店」「餐厅」
- 场景动作：如「空座」「忙碌」「扫码」「顾客排队」

**第二步：加上风格关键词（提升质感）**
- 摄影风格：「写实摄影」「高清摄影」「俯拍」「侧光」「暖色调」
- 排除词：加「-卡通 -插画 -手绘 -图标 -logo -文字」排除非摄影图

**第三步：加上构图关键词（提高命中率）**
- 构图：「竖构图」「留白」「居中」「特写」
- 光线：「自然光」「暖光」「柔和光线」

**示例（咖啡店闲时段场景）**：
```
主体：咖啡店 空座位 下午
风格：写实摄影 高清 -卡通 -插画 -文字
构图：竖构图 留白 自然光 暖色调
```

#### 5.9.6 选图标准（5 个判断维度）

| 维度 | ✅ 好图 | ❌ 坏图 |
|---|---|---|
| **清晰度** | 高清，放大后不糊 | 模糊、像素低、有水印 |
| **构图** | 有留白，文字有地方放 | 画面太满，到处都是东西 |
| **行业感** | 一眼看出是什么行业 | 太抽象，不知道在拍什么 |
| **光线** | 明亮、通透、暖色调 | 昏暗、冷色调、曝光过度 |
| **版权** | 可商用授权（Unsplash/Pexels/创可贴素材库） | 明显有品牌 logo、有人脸无授权 |

#### 5.9.7 封面与首帧的关系

- **首帧 ≠ 封面**（推荐做法）：封面是精心设计的静态海报，首帧是视频的第一个动态画面。两者风格一致但不完全相同——封面可以更"海报感"，首帧可以更"动态感"。
- **一致性要求**：封面与首帧的主色、字体风格、核心元素必须一致，不能封面是暖橙色首帧是冷蓝色。
- **3 秒留存逻辑**：用户因为封面点进来，首屏（前 3 秒）决定要不要继续看。首屏内容必须兑现封面的承诺——封面问"下午 3 点没人怎么办"，首屏就必须接着讲"下午 3 点的咖啡店"，不能跳转到不相关的内容。

#### 5.9.8 封面设计稿交付格式与文件规范

**设计稿中封面部分必须包含**：
```yaml

封面主标题: 一张次卡，把客人留下来
封面副标题: 咖啡店锁客不靠打折

  - 找图关键词: 抽象光斑 暖棕 竖版 无文字 高质感
```

**封面图文件存放规范**：
```

    ├── gXX-cover-A-xxx.jpg         ← A版封面（风格/用途后缀）
```

**命名规则**：`{行业编号}-cover-{版本/用途}-{风格标识}.{格式}`
- 版本：A / B / C（用于 A/B 测试的多个版本）
- 用途：sohu（搜狐横版）/ douyin（抖音专用，一般不用标）

**三平台封面规则**：

## 六、工作流程

### 6.1 新视频启动流程

> **dur 确定规则**：设计稿填预估 dur 作为无声版参考，最终 dur 由 TTS 实测时长 + dur 公式（信息屏 +0s / 数据屏 +0.8s / CTA +1.5s）确定，写入 data 文件。口播稿按 §5.6 规则控制文字量，TTS 自然语速生成。禁止 atempo 硬拉语速。

**完整操作流程（选题→设计稿→素材→代码→无声版→TTS→有声版→发布）见 `12-SOP §三`（步骤1→步骤10）**，本文档不再重复。以下仅列出与 Remotion 技术直接相关的执行要点：

**⑤ 代码执行（无声版）**：`data/gXX.ts` 的 dur 从设计稿取预估值。字幕按口播全文拆分做占位（均匀分布）。若设计稿含 new:xxx 新积木，按 §7.2.3 流程实现（types.ts → scenes/ → index.tsx 注册），扩展后回写本文档 §7.1。

**⑥ 类型检查 + 单帧验证 + 无声版确认**：
- `npx tsc --noEmit` → `npx remotion still` 关键帧（每屏至少 1 帧）
- still 评审环：① 首帧单独审（抖音首帧即门面）；② 逐屏峰值帧出九宫格一起审；③ 新风格方向在 S1-S2 先出 2 版 still 供用户选择，通过后再全量生产
- 渲染无声版完整视频 → 用户确认画面质量 → 合格后才进入阶段二

**⑦ TTS 语音合成 + J-cut 时间轴计算（画面确认后）**：
- 豆包 `seed-tts-2.0`，`speech_rate=0` 常速。**数字统一写中文，禁止 atempo 调速**
- 逐屏生成 → `scripts/process-audio.sh` 做响度归一化（零裁剪零淡入）
- ffprobe 测每段时长 → 按公式算 dur（§2.6）+ **voiceDur 实测值回填** → 更新 `data/gXX.ts`
- 更新字幕精确时间轴（按 TTS 实测时长分配每行起止帧）
- 验证：听最终 MP4，检查首字清晰度、转场爆音、整体节奏（§2.6 验证清单）

**⑧ 成片渲染**：`npx remotion render`（含音频），前置 `NODE_OPTIONS=""`。每屏 dur 由 TTS 实测时长+公式确定（§2.6），声画帧级同步，字幕与口播逐句对齐。

### 6.2 AI 在各步骤的职责边界

| 步骤 | AI 做什么 | AI 不做什么 |
|---|---|---|
| ② 设计稿 | 内容创意、分镜规划、逐屏判断场景积木（用现有/版式变体/新建）、动画参数、**按 §4.1 先检索本地素材库**、标注本地源路径或输出外部找图规格、按 §5.6 规则校准口播稿文字量 | 不生成图片；不未经判断就新建积木；不跳过本地检索直接输出外部找图；不写出文字量与 dur 不匹配的口播稿 |
| ④ 素材 | 核对素材是否符合规格、确认本地素材已正确复制到 public/、给替代建议 | 不替人找图（人从设计平台选或从本地库选）；不扫描全库 771 个纹理文件列路径 |
| ⑤ 代码 | 写 data（dur 从设计稿取值）、按需新建积木（§7.2.3）、扩展组件、渲染 | 不擅自改锁定层（VTemplate/components 已有组件）；不提前写没被设计稿确认的积木 |
| ⑦ TTS | 调用豆包 TTS API 逐屏生成语音、响度归一化、ffprobe 测时长、按 §2.6 公式算 dur、写入 data 文件 | 不在口播稿定稿前合成；不 atempo 调速；不反复调 TTS 试效果（J-cut 一次到位） |

### 6.3 设计稿到代码的映射规则

设计稿中的动画时序描述与代码的映射关系：

| 设计稿写法 | 代码实现 |
|---|---|
| `WipeIn, delay=2, duration=18, direction=left` | `<WipeIn delay={2} duration={18} direction="left">` |
| `FadeInUp, delay=20, motion=style.motion` | `<FadeInUp delay={20} motion={style.motion}>` |
| `ScaleIn, delay=8, startScale=0.3` | `<ScaleIn delay={8} startScale={0.3} motion={style.motion}>` |
| `Pulse, delay=28, intensity=0.08` | `<Pulse delay={28} intensity={0.08} duration={24}>` |
| `节点 i 在 frame 18+i×22 平滑点亮` | `interpolate(f, [18+i*22, 18+i*22+15], [0,1], {easing:EASE_OUT})` + `interpolateColors` |
| `箭头方向脉冲` | `interpolate(f, [d, d+12, d+24], [0, dir==='↑'?-14:14, 0])` |
| `转场 wipe from-bottom 12帧` | VTemplate TransitionSeries 自动处理，不在场景内写 |

### 7.2 场景积木扩展：判断标准与步骤

> 场景积木（scene type）不是自动增加的，由 AI 在设计稿阶段判断、人审确认后新建。以下是判断标准和完整步骤。

#### 7.2.1 什么时候用现有积木，什么时候新建

AI 在规划每屏分镜时，必须先对照 §7.1 表格判断：这一屏的叙事结构能否被现有积木承载？

| 情况 | 处理方式 | 示例 |
|---|---|---|
| 内容结构与现有积木一致，只是文案/图标/颜色不同 | 直接用现有积木 | 茶饮咖啡的「次卡锁客」用 solution，美业的「套餐卡」也用 solution |
| 结构一致但布局想换一种排列 | 用版式变体（§7.3），不新建类型 | solution 从纵排列表改为横排卡片 |
| 现有积木的视觉结构无法表达叙事意图 | 新建积木 | 美业需要「日历选日期」、餐饮需要「地图门店」、洗车需要「前后推拉对比」 |

**判断核心**：区分「内容不同」和「结构不同」。换文案、换图标、换颜色是内容不同，用现有积木；画面的信息组织方式根本不同（比如从「卡片列表」变成「日历格子」），才是结构不同，需要新建。

#### 7.2.2 行业常见需新增积木的场景（参考，非穷举）

| 行业 | 可能需要的新积木 | 原因（现有积木为何不够） |
|---|---|---|
| 美业/预约制 | `calendar`（日历选择型） | 现有积木无「日期格子+选中态」结构 |
| 餐饮/到店 | `map`（地图 LBS 型） | 现有积木无「地图+门店标记」结构 |
| 洗车/家政 | `before-after`（前后对比型） | pain 是红绿文字对比，无法表达「图片推拉对比」 |
| 教育/健身 | `timetable`（课程时间表型） | 现有积木无「时间轴+多列排期」结构 |
| 零售/电商 | `carousel`（商品轮播型） | grid 是固定 2×2，无法表达「横向滑动浏览多个商品」 |
| 任何行业 | `testimonial`（评价型） | 现有积木无「引号+头像+评价文字」结构 |

> 以上仅为预判参考，实际是否新建以设计稿阶段的判断为准。不要为了「可能用到」提前写积木——有真实内容验证才写。

#### 7.2.3 新建积木的完整步骤

当判断需要新建积木时，AI 按以下顺序执行：

**步骤 1 · 设计稿阶段标注（AI 做，人审确认）**

在设计稿分镜表中，该屏的 `场景类型` 字段写 `new:xxx`（如 `new:calendar`），并附：
- 新积木名称与用途（一句话）
- 视觉结构描述（画面怎么组织、有哪些元素、什么布局）
- 数据字段定义（需要哪些内容字段，字段名 + 类型 + 说明）
- 与现有积木的差异说明（为什么不能用现有积木或版式变体）
- 动画时序（按 §5.4 帧级规范写）

**步骤 2 · 人审确认（闸门）**

人在审设计稿时确认：这个新积木是否必要？如果现有积木能替代，回退用现有积木。确认后才进入代码阶段。

**步骤 3 · 代码实现（AI 做）**

1. 在 `types.ts` 的 `SceneType` 联合类型中新增类型名
2. 如果有新数据字段，在 `Scene` interface 中加对应可选字段
3. 在 `scenes/` 新建渲染器组件（如 `CalendarScene.tsx`），严格遵守 §2 全部技术硬规则：
   - 动画用 `useCurrentFrame` + `interpolate`/`spring`，禁止 CSS animation
   - 所有 spring 透传 `style.motion`
   - 非 spring 插值用 `EASE_OUT`
   - 颜色变化用 `interpolateColors`，禁止 boolean 瞬切
   - 文案/颜色从 scene 数据和 palette 读取，不硬编码
4. 在 `scenes/index.tsx` 的 `SceneRenderer` switch 中注册新类型
5. 如果需要新图标，先用 Icon MCP Server（`search_icons`/`generate_icon`）检索或生成 SVG，再转内联组件加入 `components/icons.tsx`（见 §8.3）
6. 如果需要新动画模式（现有 6 个动画组件不够），在 `components/animations.tsx` 加新组件

**步骤 4 · 验证（AI 做）**

1. `npx tsc --noEmit` 零错误
2. 至少渲染 1 帧 still 检查布局和动画起始态
3. 如果该积木有复杂时序（如依次点亮、多阶段动画），渲染多帧验证
4. 跑 `check-redlines` 闸门

**步骤 5 · 文档回写（AI 做）**

1. 在本文档 §7.1 表格中新增一行（type / 组件 / 数据字段 / 视觉特征）
2. 如果加了新动画组件，在 §8.1 表格中补充
3. 如果加了新图标，在 §8.3 补充
4. 在当日记忆 `.workbuddy/memory/YYYY-MM-DD.md` 记录新增了什么积木、为什么需要

#### 7.2.4 新积木的质量标准

新积木必须满足：
- **结构独特**：与已有积木在画面信息组织方式上有肉眼可辨的差异，不是换色/换图标/换排列方向
- **可复用**：积木是通用叙事结构，不绑定某行业的具体内容（如 calendar 任何预约制行业都能用，不是「美业日历」）
- **合规**：不画不存在的产品功能界面、不编虚构 UI
- **动画完整**：有入场动画，元素有时序编排，不是静态画面堆元素

### 7.3 版式变体（待实现）

同一 scene type 支持多种布局变体，通过 scene 数据中的 `layout?` 字段控制。例如 SolutionScene 可支持：
- `vertical`（当前）：纵向卡片列表
- `horizontal`：横向滑动卡片
- `split`：左图右文分屏

实现版式变体时，在场景组件内按 `scene.layout` 条件渲染，不新建 scene type。

## 八、原子组件库规格

### 8.1 动画组件（components/animations.tsx）

| 组件 | 参数 | 用途 |
|---|---|---|
| `FadeInUp` | delay, dist, motion | 向上淡入（标题/正文/卡片通用） |
| `SlideInLeft` | delay, motion | 从左滑入（痛点卡） |
| `SlideInRight` | delay, motion | 从右滑入（解法卡） |
| `ScaleIn` | delay, motion, startScale | 缩放弹入（数字/卡片/图标） |
| `WipeIn` | delay, duration, direction | clip-path 擦入（标题 reveal） |
| `Pulse` | delay, intensity, duration | 单次脉冲强调（数字/箭头） |

所有组件透传 motion，spring config 从 SPRING_CONFIG 读取。EASE_OUT 为标准缓动常量。

### 8.2 UI 组件（components/ui.tsx）

| 组件 | 用途 |
|---|---|
| `SectionTitle` | 段落标题：逐字 mask 入场（内部用 CharReveal）+ 下划线 wipe 擦入，宽度按中文字宽估算 |
| `Subtitle` | 底部多行字幕（帧级精确同步）：白字黑描边，距底 60px，接收 `lines:{text,startFrame,endFrame}[]`，每行独立起止帧，最多同时显示 2 行 |
| `CharReveal` | 逐字 mask 入场（text/delay/stagger/duration/style），大标题专用「贵感」来源（2026-08-20） |
| `AccentWord` | 重音词大字：字号+颜色同时弹入（text/color/delay/peak），对齐口播重音帧使用，位置由各视频设计稿决定（2026-08-20） |
| `IconBadge` | 图标容器：squircle 底 + 主色 tint + 内高光（icon/color/size/pad/radius），图标不裸放（2026-08-20） |
| `PhoneMockup` | 手机样机：bezel+灵动岛+玻璃高光（children/width/height），内嵌产品示意 UI 用，不使用真实小程序截图（2026-08-20） |
| `elevation(level, dark)` | 三级投影常量（浅底/深底两套），卡片统一取用，全片光影方向一致（2026-08-20） |
| `CouponCard` | 券面票券标准件：大字金额 + 虚线分隔 + 条码感装饰 + 可选撕边缺口（holeColor 传场景背景色）。文案必须查 00 号事实表，禁止虚构券规则（2026-08-20） |
| `StatCounter` | 数字滚动 0→value（value/suffix/delay/duration/color/size）。只用于真实可述口径（发了多少张/用了多少张），禁止虚构营销数据（2026-08-20） |
| `StatCard` | 数据卡：图标+标签+滚动数字+说明（label/value/suffix/caption/icon/accent），grid/panel 数据屏通用（2026-08-20） |
| `StepFlow` | 步骤条：连接线擦入 + 步骤逐个弹入（steps[{icon,title,note}]/accent/stagger），flow 屏通用（2026-08-20） |
| `CompareCard` | 左右对比卡：痛点(红) vs 解法(主色默认绿) + 中缝 VS 徽章（left/right{title,items}/accent），痛点-解法对照屏通用（2026-08-20） |

### 8.3 图标库（components/icons.tsx）

内联 SVG 图标，通过 `Ico[name](color)` 调用。当前覆盖：cup, x, check, gift, clock, users, cash, bolt, search, arrow 等。新增图标需保持单色描边风格统一。

**新增图标流程（Icon MCP Server 已接入）**：

项目根目录 `.mcp.json` 已配置 `icon-mcp-server`（npx 全局安装 v1.4.0）。新增图标时：

1. **先查 `icons.tsx`**：确认现有图标是否够用。
2. **`search_icons`**：用英文关键词（逗号分隔可批量）从 Element Plus + Ant Design 图标库模糊检索，返回 SVG 代码。`search_icons` 无需 API Key。
3. **`generate_icon`**：检索不到时用 AI 生成（需 `DASHSCOPE_API_KEY` 环境变量），传入 description + style（element-plus/ant-design/default）。
4. **转内联组件**：将返回的 `rawSvg` 转为 `icons.tsx` 中的 React 组件，统一改为 `width="100%" height="100%"`、`stroke={c}`（单色描边风格）、`fill="none"`，加入 `IconKey` 类型和 `Ico` 映射表。
5. **禁止直接引用外部 SVG 文件/CDN**：所有图标必须是内联 React 组件，确保 Remotion 渲染时无网络依赖。

### 8.5 组件生长机制（2026-08-20 拍板）

> 原则：组件库**靠纪律生长**——不一次性大建（避免过早优化），也不无纪律堆砌（避免重复造轮子）。装饰组件**少而精**：画面主要靠排版层级和内容动效撑，不靠堆装饰件（防「会动的 PPT」感）。

**三条机制**：

| 机制 | 规则 | 触发时机 |
|---|---|---|
| 提炼纪律 | 写场景时出现「第二个行业也会用到」的结构（券面/数值/步骤/对比类），必须写成 ui.tsx 组件，禁止场景内联 | 写代码时 |
| 回顾收编 | 生产回顾固定加一问：「这次哪些场景级 JSX 值得提成通用组件？」提出后收编并更新 §8.2 组件表 | SOP 步骤 12 |
| 高频预建 | 只有「产品核心物件 / 全行业刚需」允许无需求预建（如 CouponCard），其余等需求出现 | 需求确认时 |

**写代码时对照判断**：

| 情况 | 做法 | 例子 |
|---|---|---|
| 跨行业通用结构 | ✅ 写成 ui.tsx 组件 | 券面卡片、数字滚动、步骤条、左右对比 |
| 只此一家的场景结构 | ✅ 留在场景文件内 | TimelineScene 的曲线抬升逻辑 |
| 海报风装饰件（窗口容器/吊牌/波浪线类） | ⚠️ 默认不建代码；设计稿确需时按需实现，**每条视频装饰件 ≤1-2 处** | 创可贴封面拆解的 BrowserHeader/TagLabel 等（见 09 号 §6.2） |

✅ 正确做法：GridScene 数据屏用 StatCard，三个行业都复用同一组件
❌ 错误做法①：FlowScene 里手写第三遍步骤条 JSX（该提成 StepFlow）
❌ 错误做法②：每屏都套浏览器顶栏容器当背景（装饰件滥用，像会动的 PPT）
