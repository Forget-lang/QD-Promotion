# R8 · 变更收敛协议

> 目的：把“全局想法/新口径”从一次普通文档修改，升级为一次可追踪、可验证、可关闭的迁移事务，解决新旧口径并存、遗漏清理、反复确认的问题。
> 这是原理与协议层；具体口令入口仍由 `AGENTS.md` / `docs/AI使用手册.md` 指向本文件。

## 一、基本模型

一次全局变更不是“新增一条规则”，而是：

> **旧状态 → 新状态 → 影响面迁移 → 机械验证 → 反例验证 → 真图/成片验证 → CLOSED**

任何替代型变更必须回答：

- 新口径是什么
- 被替代的旧口径是什么
- 哪些资产受影响
- 哪些旧资产保留但禁止回用
- 什么条件满足后算完成

## 二、变更契约 Change Contract

全局变更开始前，AI 先生成一份变更契约，不先改文档。

最少包含：

- `changeId`
- `goal`
- `newPolicy`
- `replace`
- `remove`
- `preserve`
- `scope`
- `affectedAssets`
- `acceptance`

用户只需要确认契约方向；确认后进入执行阶段。

## 三、影响面 Impact Map

执行前必须扫描：

- 权威规则文档
- 真源 spec
- 检查脚本
- 模板与提示词
- 组件目录
- 当前进行中的片子
- 参考样本
- 旧口径登记

输出四态动作：

- `ADD`：新增
- `REPLACE`：替代
- `REMOVE`：删除/停用
- `PRESERVE`：保留但不可回用于新产出

## 四、迁移而不是叠加

替代型变更不得只新增新规则。

必须同时完成：

1. 新规则进入唯一属主
2. 旧规则进入废止登记
3. 旧规则的代码/模板/示例/提示词被清理或标记为历史保留
4. 新产出路径不得再命中旧口径
5. `check-doc-references` 与对应领域检查通过

## 五、机械收敛

机械验证用于回答：

> “旧口径是否还存在于禁止出现的位置？”

至少覆盖：

- 旧术语
- 旧数字
- 旧路径
- 旧组件名
- 旧布局名
- 旧模板名
- 旧规则片段

机械验证通过不等于语义完成。

## 六、语义反例

每个重要全局变更至少构造一个“故意绕开关键词但仍违反新原则”的反例。

例：

- 旧规则“不做五节点流程图”
- 错误变体：“五个状态框依次连接”
- 语义结论：仍属于旧模式，应被视觉验收拒绝

语义反例用于验证新规则是否真的改变了生成方式，而不是只改变了关键词。

## 七、视觉/成片验证

涉及内容、视觉、动效的变更，机械检查之后必须进入真实产物验证：

- 至少一个真实关键帧或短片
- 一屏标杆先行
- 视觉判据逐项验收

“文档通过”不等于“视觉通过”。

## 八、关闭条件

变更只有在以下条件全部满足后才能标记 `CLOSED`：

- 影响面已处理
- 新口径已落唯一属主
- 旧口径已清理/登记
- 机械检查通过
- 至少一个反例测试通过
- 真实产物通过对应验收
- 本次新增红为 0

## 九、Closure Report

执行完成必须提交极简收敛报告：

```text
Change ID：
目标：

已修改：
已废止：
影响面：已处理 / 总数
旧口径扫描：PASS / FAIL
机械检查：PASS / FAIL
负向测试：PASS / FAIL
语义反例：PASS / FAIL
真图/成片：PASS / PENDING
本次新增红：0 / N

结论：CLOSED / NOT CLOSED
```

## 十、责任边界

- 用户：决定方向、确认视觉与最终发布
- 方法论/视觉负责人：设计变更契约、影响面、质量标准与验收方案
- 项目 AI：执行迁移、改文档/代码、跑检查、提交 Closure Report
- 机器检查：验证可机械判断的约束

目标不是增加用户监督，而是让系统自己证明“已经改干净”。
