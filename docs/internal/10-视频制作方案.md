# 10 · 视频内容方案

> 本文档定义视频「做什么内容」——叙事结构、关键字规则、配音与 TTS 规范、命名归档。
> **代码怎么写、动画怎么实现、设计稿到什么精度**，见 13（Remotion 技术规范与设计稿工作流）。
> **端到端流程顺序与角色分工**，见 12（SOP）。
> **红线/CTA 合规话术**，见 `quandao-content` skill §二/§四。
> 当前工作机 `video/` 已初始化（Remotion 4.0.507），1080×1920@30 渲染链路与豆包 TTS 合成链路均可用。

---

## 0. 核心思路

**视频 = Remotion 代码绘制的 UI 组件 + 项目商用字体排版 + SVG 内联图标 + 精确动画。** 每条视频、每个分镜的画面结构、组件、动画都独立设计，不预设跨视频通用模板。9:16（抖音/小红书）单画幅输出。不用截图、不显产品 UI、不编虚构界面、不靠 AI 生图做主视觉。搜狐只发图文文章（16:9 头图按 07 §3 封面机制制作，非 Remotion 视频）。

Remotion（React 逐帧渲染）擅长 motion graphics 形态，可按每镜需求灵活写动画逻辑——像素级精确控制 UI 布局与动画。

## 1. 三平台宣传类型与画幅

| 平台 | 宣传类型 | 画幅 | 说明 |
|---|---|---|---|
| 抖音 | 短视频 | 竖版 9:16（1080×1920） | 唯一短视频主阵地 |
| 小红书 | 短视频 | 竖版 9:16（1080×1920） | 同一条 9:16 视频，封面可微调 |
| 搜狐 | 图文文章（长文攻略） | 文章 16:9 头图 | 搜狐只发图文；16:9 头图按 07 §3 封面机制制作，文章承接深度玩法（G 类长文） |

同一条视频抖音/小红书各发一次属正常分发（平台间不互通查重）；同一平台内禁止重复发同一条。

## 2. 视频内容创作元素

> 主视觉由 Remotion 代码绘制，元素可增删重组，无强制配方。素材获取优先级与代码引用方式见 13 §1.3/§4。

| 要素 | 呈现方式 | 合规约束 |
|---|---|---|
| **① UI 组件** | 代码绘制（卡片/对比面板/流程图节点/数据指标卡/列表），结构化承载信息 | 颜色有语义（绿=解法/红=痛点/橙=强调/青=科技）；不画不存在的功能界面 |
| **② 项目商用字体** | 得意黑=冲击力标题、阿里巴巴普惠体=正文层级、阿里妈妈方圆体=亲和场景（字体性格映射见 13 §3.1） | 必须本地 `@font-face` 加载，否则渲染缺字 |
| **③ SVG 内联图标** | 单色描边风格统一；新图标用 Icon MCP Server 检索/生成后转内联组件（见 13 §8.3） | 不引用外部图标文件/CDN |
| **④ 关键字/标题** | 从口播稿提取核心词/金句，大字标题 + spring 入场 | 文字不凸显品牌名（禁用表述见 skill §二）；数字以 00§6 为准 |
| **⑤ 纹理/底纹** | 可选，来自 `图标素材/图鱼素材/`；代码内置 DotGrid/GlowOrb 零素材装饰方案 | 商用授权即可 |

每屏只承载 1 个核心信息，靠分区与层级组织不显乱。

## 3. 技术选型

选用 **Remotion**：用 React 代码描述画面、本地渲染成 mp4。

- **画幅**：1080×1920 @30fps，字号/间距用绝对像素（不引入 vmin，见 13 §2.3）
- **中文字体**：必须本地加载，`@font-face` 注册 `public/fonts/` 下字体文件（见 13 §2.3）
- **渲染参数**：`--codec h264 --crf 18 --jpeg-quality 90`
- **架构**：数据驱动——内容在 `src/data/gXX.ts`（scenes + style），组件库在 `src/components/` + `src/scenes/`，VTemplate 编排。新视频 = 新 data 文件 + 复用组件库，每条视频独立设计（见 13 §1.2）
- **渲染必带**：通过 AI Bash 工具执行 Remotion 渲染时必须前置 `NODE_OPTIONS=""`（见 skill §七硬执行约束）

## 4. 叙事结构（控完播率，总 ≤180s）

> 抖音完播率 <15% 十分钟停推；前 3 秒决定划走与否。每场景 ≥4–8s。

| 段 | 时长 | 作用 | 要点 |
|---|---|---|---|
| **Hook（钩子）** | 0–3s（S1 实际约 5s） | 留人 | **静音可懂**：反差/矛盾/情绪/数字/提问型强钩子；禁用开场放 logo、禁用"你是否想过…"等划走触发词。钩子型实现见 13 §7.1 HookScene |
| **痛点** | 3–10s | 共鸣 | 第二人称具体场景，利用损失厌恶把"正在失去"写疼；定性表达不编数据 |
| **解法** | 10–20s | 软种草 | 自然带出产品价值（讲场景讲玩法，不写操作步骤）；每个反转落在一个 00 真实功能上 |
| **价值点** | 穿插 | 记忆 | 关键利益 stagger 逐条弹出，强化"还能这样玩"的顿悟 |
| **CTA** | 末 5s | 行动 | 屏幕停留 ≥5s；自然收尾、不硬推关注/收藏，可轻署「券到卡包」 |

7 种场景积木（hook/pain/solution/flow/grid/panel/cta）的视觉特征、数据字段、版式变体见 13 §7.1。

## 5. 关键字提取规则

从口播稿提取，而非堆砌：
1. 每屏 1 个核心词或 1 句金句（≤14 字效果最佳）；
2. 钩子屏 = 钩子主标题；痛点屏 = 痛点词；解法屏 = 功能价值词；CTA 屏 = 行动词；
3. 禁用极限词（最/第一/顶级）；数字以 00§6 为准；
4. 不凸显品牌名：禁用"微信里搜/微信小程序"点名；「免费使用」可说但不强调。

---

## 6. 配音呈现（不使用字幕）

- **视频不使用配音字幕**。旁白口播照常合成，画面仅以关键字大字标题传递核心信息，不显示逐词字幕条。
- 语音参数：豆包 `zh_female_vv_uranus_bigtts` + `seed-tts-2.0`，`speech_rate=0` 为常速（先出 5–10s 样片由人确认语速再合成全片）。

---

## 7. 语音合成（火山引擎·豆包 TTS）

| 项 | 说明 |
|---|---|
| 定位 | 视频无声 → 用 TTS 补旁白，是视频链路的独立一环，**最后一步执行** |
| 输入 | 定稿的口播稿文本（设计稿阶段定稿，见 12 步骤 4） |
| 输出 | `public/audio/gXX-narration.mp3`，整片时长 = 音频时长（音频为主时钟） |
| 前置（人提供） | 火山引擎账号 + API Key；选定 1 个品牌音色贯穿所有视频 |
| 约束 | 按字符计费；口播稿守红线（不用极限词、不编数据、数字以 00§6 为准） |
| 前置闸门 | **须在无声版经人确认画面质量后**才调用——画面未定稿前调用 TTS 会致旁白返工、浪费额度 |

## 9. 生产流程概览

> 完整端到端流程见 12（SOP 步骤 4–8）；技术实现细节、设计稿模板、单帧验证见 13 §6。

1. **设计稿**：AI 按 13 §5 模板产出完整设计稿（含口播稿/关键字/帧级动画时序/素材清单），人审确认
2. **素材准备**：本地素材复制 + 外部找图（见 13 §4.1），AI 核对
3. **无声版**：AI 新建 `data/gXX.ts` → tsc 检查 → 单帧验证 → 渲染无声版 → 人审画面（**此步前绝不调用 TTS**）
4. **语音合成**：口播稿 → 豆包 TTS → 先出语速样片确认 → 合成全片
5. **成片合成**：无声版 + 音频压合，整片时长 = 音频时长，声画同步，无字幕
6. **人最终确认 → 归档发布**
