## 0. 核心思路

**视频 = Remotion 代码绘制的 UI 组件 + 项目商用字体排版 + SVG 内联图标 + 精确动画。** 每条视频、每个分镜的画面结构、组件、动画都独立设计，不预设跨视频通用模板。9:16 抖音单画幅输出。不用截图、不显产品 UI、不编虚构界面、不靠 AI 生图做主视觉。小红书发图文笔记（封面 3:4 裁切中间区），搜狐发图文文章（16:9 头图按 07 §3 封面机制制作，非 Remotion 视频）。

Remotion（React 逐帧渲染）擅长 motion graphics 形态，可按每镜需求灵活写动画逻辑——像素级精确控制 UI 布局与动画。

## 2. 视频内容创作元素

> 主视觉由 Remotion 代码绘制，元素可增删重组，无强制配方。素材获取优先级与代码引用方式见 13 §1.3/§4。

| 要素 | 呈现方式 | 合规约束 |
|---|---|---|
| **① UI 组件** | 代码绘制（卡片/对比面板/流程图节点/数据指标卡/列表），结构化承载信息 | 颜色有语义（绿=解法/红=痛点/橙=强调/青=科技）；不画不存在的功能界面 |
| **② 项目商用字体** | 得意黑=冲击力标题、阿里巴巴普惠体=正文层级、阿里妈妈方圆体=亲和场景（字体性格映射见 13 §3.1） | 必须本地 `@font-face` 加载，否则渲染缺字 |
| **③ SVG 内联图标** | 单色描边风格统一；新图标用 Icon MCP Server 检索/生成后转内联组件（见 13 §8.3） | 不引用外部图标文件/CDN |
| **④ 关键字/标题** | 从口播稿提取核心词/金句，大字标题 + spring 入场 | 文字不凸显品牌名（禁用表述见 14 号文档）；数字以 00§6 为准 |
| **⑤ 纹理/底纹** | 可选，来自 `图标素材/图鱼素材/`；代码内置 DotGrid/GlowOrb 零素材装饰方案 | 商用授权即可 |

每屏只承载 1 个核心信息，靠分区与层级组织不显乱。

## 3. 为什么选 Remotion

选用 **Remotion**（React 逐帧渲染）做视频，核心原因：
- 像素级精确控制 UI 布局与动画，适合代码驱动的 motion graphics 风格
- 数据驱动架构：新视频 = 新 data 文件 + 复用组件库，每条视频独立设计
- 与项目商用字体/SVG 图标体系无缝衔接

**技术实现细节（动画硬规则/布局/转场/代码结构）见 13 §二**；**渲染命令与 NODE_OPTIONS 约束见 13 号文档 §6**。

## 4. 叙事结构（控完播率，总 ≤200s）

> 抖音完播率 <15% 十分钟停推；前 3 秒决定划走与否。屏数由内容深度决定（推荐 8-10 屏，硬指标是 ≥6 个信息单元 + ≥2 层递进，详见 08 号 §2.5）。

| 段 | 时长 | 作用 | 要点 |
|---|---|---|---|
| **Hook（钩子）** | 0–3s（S1 实际约 5s） | 留人 | **静音可懂**：反差/矛盾/情绪/数字/提问型强钩子；禁用开场放 logo、禁用"你是否想过…"等划走触发词。钩子型实现见 13 §7.1 HookScene |
| **痛点** | 3–10s | 共鸣 | 第二人称具体场景，利用损失厌恶把"正在失去"写疼；定性表达不编数据 |
| **解法** | 10–20s | 软种草 | 自然带出产品价值（讲场景讲玩法，不写操作步骤）；每个反转落在一个 00 真实功能上 |
| **价值点** | 穿插 | 记忆 | 关键利益 stagger 逐条弹出，强化"还能这样玩"的顿悟 |
| **CTA** | 末 5s | 行动 | 屏幕停留 ≥5s；自然收尾、不硬推关注/收藏，必须出现品牌名「券到卡包」，具体文案由设计稿定制 |

9 种场景积木（hook/pain/solution/flow/grid/panel/cta/timeline/transfer）的视觉特征、数据字段、版式变体见 13 §7.1。

## 5. 关键字提取规则

从口播稿提取，而非堆砌：
1. 每屏 1 个核心词或 1 句金句（≤14 字效果最佳）；
2. 钩子屏 = 钩子主标题；痛点屏 = 痛点词；解法屏 = 功能价值词；CTA 屏 = 行动词；
3. 禁用极限词（最/第一/顶级）；数字以 00§6 为准；
4. 不凸显品牌名：禁用"微信里搜/微信小程序"点名；「免费使用」可说但不强调。

---

## 6. 配音与字幕

- **视频配有逐屏字幕**。字幕和口播逐句对齐，方便静音观看（抖音 80%+ 用户静音刷视频）。
- **字幕样式**：底部居中，白字 + 黑色描边，字号适中（不遮挡主视觉），每屏显示完整的一句或两句口播文字。
- **语音参数**：豆包 `zh_female_vv_uranus_bigtts` + `seed-tts-2.0`，`speech_rate=0` 为常速。J-cut 方案一次到位，无需先出样片确认语速（见 13 §2.6）。

## 7. 语音合成（火山引擎·豆包 TTS）

| 项 | 说明 |
|---|---|
| 定位 | 视频无声 → 用 TTS 补旁白，是视频链路的独立一环，**成片渲染前执行** |
| 输入 | 定稿的口播稿文本（设计稿阶段定稿，见 12 步骤 4） |
| 输出 | `public/audio/s1.wav` ~ `sN.wav`（N = 屏数），逐屏语音，整片时长 = 设计稿总时长（设计稿驱动） |
| 前置（人提供） | 火山引擎账号 + API Key；选定 1 个品牌音色贯穿所有视频 |
| 约束 | 按字符计费；口播稿守红线（不用极限词、不编数据、数字以 00§6 为准）；禁止 atempo 调速 |
| 验证 | 用 ffprobe 读取实测语音时长，按 dur 公式（信息屏 +0s / 数据屏 +0.8s / CTA +1.5s）反算实际 dur，写入 data 文件。禁止 atempo 调速。 |
