# 10 · 视频制作方案（Remotion）— 新模型

> 本文档属于执行层，是「券到卡包」宣传视频的**唯一权威方案**，与 06（选题）/07（渠道与执行）/11（素材与图片规范）配套。
> 当前工作机 `video/` 已初始化（Remotion 4.0.507 + node_modules 已装），1080×1920@30 渲染链路与豆包 TTS 合成链路均可用；视频模板按新思路自由创作，不锁固定模板。
> 本方案已融合两份调研结论（已归档于 `outputs/archive/`）：`三平台规则调研-限流与推荐机制-20260813.md`（限流红线与推荐增益）、`Remotion宣传视频制作技巧-20260813.md`（制作技巧）。能力边界见 `quandao-content` skill §七；素材取用见 11 §1.1。

---

## 0. 核心思路（一句话）

**视频 = 用 Remotion 代码绘制的 UI 组件 + 项目商用字体排版 + SVG 内联图标 + 精确动画（参考标杆：程序员鱼皮信息图/视频的「讲解级 PPT Motion Graphics」风格）。每条视频、每个分镜的画面结构、组件、动画都独立设计，不预设跨视频通用模板。9:16（抖音/小红书）单画幅输出。不用截图、不显产品 UI、不编虚构界面、不靠 AI 生图做主视觉（AI ImageGen 质感不可控、与代码 UI 风格不统一）。搜狐只发图文文章（16:9 头图由代码/模板生成，非 Remotion 视频）。**

> **方向变更（2026-08-14 晚间）**：原「背景图 + AI 生成插画 + 关键字大字」三要素方案经用户实测否定（AI 插画质感粗糙、信息量低），改为上列「代码驱动 UI 组件」方案。视觉素材优先用项目本地资源（`商用字体/` `图标素材/图鱼素材/纹理`），并可从优秀设计网站（站酷/创客贴/Dribbble/Envato 等）找模板灵感持续优化。

Remotion（React 逐帧渲染）擅长 motion graphics 形态，可按每镜需求灵活写动画逻辑——这正是它相比 AI 生图的核心优势：像素级精确控制 UI 布局与动画。

## 1. 三平台宣传类型与画幅

| 平台 | 宣传类型 | 画幅 | 说明 |
|---|---|---|---|
| 抖音 | 短视频 | 竖版 9:16（1080×1920） | 唯一短视频主阵地 |
| 小红书 | 短视频 | 竖版 9:16（1080×1920） | 同一条 9:16 视频，封面可微调 |
| 搜狐 | 图文文章（长文攻略） | 文章 16:9 头图（创客贴+素材库生成，非 Remotion 视频） | 搜狐只发图文；16:9 头图由创客贴+素材库生成（非代码、非 AI 生图），文章承接深度玩法（G 类长文） |

**"同一条视频抖音/小红书各发一次"的正确做法**：脚本、口播、配乐完全一致，仅产 9:16 单画幅；这不算违规——平台间不互通查重；但**同一平台内禁止重复发同一条**。

## 2. 视频内容创作元素（代码驱动，非固定组合）

> 主视觉由 Remotion 代码绘制，元素可增删重组，无强制配方。

| 要素 | 来源 | 呈现方式 | 合规约束 |
|---|---|---|---|
| **① UI 组件** | Remotion 代码绘制（卡片/对比面板/流程图节点/数据指标卡/列表/要点） | 结构化承载信息，每屏一个明确信息目标 | 颜色有语义（绿=解法/红=痛点/橙=强调/青=科技）；不画不存在的功能界面 |
| **② 项目商用字体** | `商用字体/`（已复制到 `video/public/fonts/`，index.tsx @font-face 注册） | 得意黑=冲击力标题、阿里巴巴普惠体=正文层级、阿里妈妈方圆体=亲和场景 | 必须本地加载，否则渲染缺字 |
| **③ SVG 内联图标** | 代码内联（自绘业务图标：咖啡杯/券/核销/人群/箭头等） | 辅助 UI 组件传达语义，单色描边风格统一 | 不引用未授权图标库 |
| **④ 关键字/标题** | 从口播稿提取核心词/金句 | 大字标题 + `textShadow`，spring 入场 / stagger / 逐词弹入 | 文字不凸显品牌名（三类禁用表述见 07 §5）；数字以 00§6 为准 |
| **⑤ 纹理/底纹** | `图标素材/图鱼素材/`（771 纹理图案）可选 | UI 卡片底纹/装饰层 | 商用授权即可 |

**关系**：UI 组件定结构 → 字体定层级 → 图标定语义 → 关键字点题。每屏只承载 1 个核心信息，信息密度可高（参考鱼皮一屏多卡），靠分区与层级组织不显乱。AI 生图原则上不用于主视觉（质感不可控）。

## 3. 技术选型与 9:16 单画幅（Remotion）

选用 **Remotion**：用 React 代码描述画面、本地渲染成 mp4。

**9:16 画幅的响应式布局（vmin 单位）**：
- 竖版 9:16 下 **`vmin = width/100 = 10.8px`**。字号、间距、元素尺寸**全部用 `vmin` 倍数**，保证不同分辨率下比例一致（这是布局技巧，不限制画面结构）；
- 中文字体**必须本地加载**：用项目 `商用字体/`（得意黑.ttf / 阿里巴巴普惠体系列 / 阿里妈妈方圆体.ttf，已复制到 `video/public/fonts/`，在 `src/index.tsx` 用 `@font-face` 注册），否则渲染缺字；
- 渲染：`--codec h264 --crf 18`，9:16 用 1080×1920@30。

**理由**：结构骨架（Hook→痛点→解法→价值→CTA）固定于代码，保证"基本合格结构"；配色、字体、视觉风、单屏节奏全部随内容调性自由，不锁死单一风格。参数化批量出行业变体（餐饮版/美业版/洗车版）。

## 4. 场景结构（控完播率，总 ≤180s）

> 抖音完播率 <15% 十分钟停推；前 3 秒决定划走与否。每场景 ≥4–8s，"太 Fast"是头号错误。

| 段 | 时长 | 作用 | 要点 |
|---|---|---|---|
| **Hook（钩子）** | 0–3s（S1 实际 5s，含钩子句+标题展示；前 3s 仍须强钩子） | 留人 | **静音可懂**：反差/矛盾/情绪/数字型强钩子（如"你店里的老客，正被隔壁一张券悄悄撬走"）；禁用开场放 logo（像广告被划走）、禁用"你是否想过…"等划走触发词 |
| **痛点** | 3–10s | 共鸣 | 第二人称具体场景，利用损失厌恶把"正在失去"写疼；定性表达不编数据 |
| **解法** | 10–20s | 软种草 | **自然带出产品价值**（讲场景讲玩法，不写操作步骤）；每个反转落在一个 00 真实功能上 |
| **价值点** | 穿插 | 记忆 | 关键利益 stagger 逐条弹出，强化"还能这样玩"的顿悟 |
| **CTA** | 末 3–5s | 行动 | 屏幕停留 ≥5s；分平台话术（见 §8），结尾引导**关注/收藏**，而非"去领券/去搜" |

**关键字节奏**：旁白每段对应一组关键字卡，逐词/逐句弹入（画面文字效果，非配音字幕）。

---

## 5. 关键字提取规则

从口播稿提取，而非堆砌：
1. 每屏 1 个核心词或 1 句金句（≤14 字效果最佳）；
2. 钩子屏 = 钩子主标题；痛点屏 = 痛点词；解法屏 = 功能价值词（如"次卡锁客""转赠裂变"）；CTA 屏 = 行动词；
3. 禁用极限词（最/第一/顶级）；数字以 00§6 为准；
4. 不凸显品牌名：禁用"免费"等促销词、"微信里搜/微信小程序"点名（见 07 §5 三类禁用表述）。

## 6. 配音呈现（不使用字幕）

- **视频不使用配音字幕**（用户决定：带字幕体验不好）。旁白口播照常合成（见 §7），画面仅以「关键字大字标题」传递核心信息，**不显示逐词字幕条**。
- 语音参数：豆包导出 44.1/48k、16bit，段间留静音；音色 `zh_female_vv_uranus_bigtts` + `seed-tts-2.0`，`speech_rate=0` 为常速（先出 5–10s 样片由人确认语速再合成全片）；语速样片确认见 §9 ④。

## 7. 语音合成（火山引擎·豆包 TTS）

| 项 | 说明 |
|---|---|
| 定位 | 视频无声 → 用 TTS 补旁白/解说，是视频链路的独立一环 |
| 输入 | 定稿的口播稿文本 |
| 输出 | `public/audio/{选题编号}-narration.mp3`，Remotion 整片时长 = 音频时长（**音频为主时钟**，分镜按全程比例分布） |
| 前置（人提供） | 火山引擎账号 + API Key（已存项目 `.env`）；选定 1 个「品牌音色」贯穿所有视频 |
| 实现 | AI 写调用火山引擎 TTS HTTP API 的脚本（Node/Python），Key 写入本地配置不泄露 |
| 约束 | 按字符计费；**视频时长以音频时长为准**（分镜按全程比例/节拍分布，绝不靠调语速去凑时长）；口播稿守红线（不用极限词、不编数据、04§6） |
| 前置闸门 | **须在 ③ 无声版经人确认画面质量后**才调用（见 §9 流程）——画面/动效未定稿前调用 TTS 会致旁白返工、**浪费合成声音（字符）额度** |

## 9. 完整生产流程（口播稿 → 9:16 成片）

```
① 脚本      AI 出参数化视频脚本：hookText / 关键字序列[词+屏] / 每屏 UI 组件布局 brief（卡片/对比/流程/面板选型）/ 旁白口播稿
② 视觉素材   从口播稿提取关键字；用 Remotion 代码绘制各屏 UI 组件 + 项目商用字体 + SVG 内联图标；纹理底纹可选自 `图标素材/图鱼素材/`；原则上不 AI 生图
③ 无声版渲染  Remotion 渲 9:16 无声版（代码 UI 组件层 + 字体层 + 图标层 + 关键字层，不含音频、不含字幕）；交人审画面质量/动效/切换
            （闸门：③ 无声版经人确认质量后，才进 ④；**此步前绝不调用 TTS，避免浪费合成声音（字符）额度**）
④ 语音合成   旁白口播稿 → 火山引擎·豆包 TTS → mp3；先出 5–10s 样片确认语速（`speech_rate=0` 常速），再合成全片
⑤ 成片合成   无声版 + 音频压合成最终 9:16 成片（整片时长 = 音频时长，分镜按全程比例分布；画面切换点落在语音对应叙事节点上，声画同步，无字幕）
⑥ 加角标 → 分平台 CTA → 人最终确认 → 归档
```

| 角色 | 职责 |
|---|---|
| AI | 模板代码维护；脚本/关键字/每屏 UI 组件布局 brief/旁白稿；可选插画生成（仅补充）；调用豆包 TTS；Remotion 9:16 合成与排障；合规自查 |
| 人 | 确认插画可用性并授权入库；确认无声版画面质量；提供/确认 TTS Key 与音色；确认语速样片；最终发布；纠偏 |

## 12. 项目与命令（简表）

项目位置：仓库根目录 `video/`（Remotion 4.0.507 工程，当前工作机已初始化）。**架构（2026-08-15 数据驱动重构）：内容在数据文件、视觉在组件库，两者解耦**——核心环节（文案/脚本）产出 `data/` 数据，组件库负责渲染，见 §13。

```bash
cd video
npm install                # 本地安装依赖（remotion 4.0.507 / react 18）
npm run dev                # Studio 预览，改参数实时看（9:16 Composition）
npm run render             # 无声版（--crf 18 --jpeg-quality 90 高质量）
npm run render:final       # 成片（同高质量参数）
npm run render:4k          # 4K 超采样（--scale 2，文字更锐利，慢）
```

工程结构（数据驱动 + 组件库，原子积木非成品模板）：
- `src/index.tsx`：注册 `G02-TeaCoffee` 单 Composition（9:16），并用 `@font-face` 注入项目商用字体（得意黑/阿里巴巴普惠体/阿里妈妈方圆体）；
- `src/palette.ts`：设计常量（配色/字体/FPS）+ 行业风格配色 `PALETTES`（P1–P7，风格轮换方案落地）；
- `src/types.ts`：`Scene` 内容类型 + `StyleConfig` 风格配置（配色/动画/字体/转场/钩子五维）；
- `src/data/g02.ts`：**G02 内容数据 + 风格配置（核心环节产物，改这里即换内容）**；
- `src/components/`：基础动画（spring 性格化 bouncy/snappy/buttery/heavy）、SVG 图标库、通用 UI（SlideTag/SectionTitle）——仅提效可复用，非模板；
- `src/scenes/`：7 种场景渲染器（hook/pain/solution/flow/grid/panel/cta），读 scene 数据 + 风格配置渲染；
- `src/VTemplate.tsx`：主组件，读 `data/g02.ts` → 按 `scene.type` 分发到场景渲染器；
- `public/fonts/`：项目商用字体；`public/textures/`：可选纹理源；`public/audio/`：旁白 mp3。

> 安装、迁移与验证记录属过程信息，见过程文档《视频技术方案-Remotion》，不入本知识库。

## 13. 数据驱动脚本 + 风格配置 + 相似度检查（2026-08-15 新增）

**核心思路**：视频画面 = 内容数据（`data/`）+ 风格配置（`style`）+ 组件库渲染。内容写得好，画面就跟着好——消除「文案→代码翻译」损耗，质量稳定。

**新视频生产范式**（下一条视频，如 G03 美业）：
1. 核心环节产出 `data/g03.ts`：内容（scenes）+ 风格配置（style），复用 `components/` + `scenes/` 渲染器；
2. 风格配置五维（`StyleConfig`）：`palette`（P1–P7 配色）、`motion`（动画性格）、`typography`（标题字重）、`transition`（转场）、`hookStyle`（钩子型）——与 §六 风格库六大维度对应；
3. **相似度检查（强制闸门）**：新视频与已产出视频逐维度对比（配色/版式/钩子/转场/动画性格），**至少 3 个维度不同**才放行；品牌记忆锚（开场标识/角标）固定不变，其余全可变——「神」统一、「形」轮换，抗审美疲劳 + 抗同质化（平台相似度 >25% 压流量池，见三平台调研）；
4. 每条视频仍须**全新独立设计**（画面结构/素材/动画独立），组件库只是原子积木，不是成品模板（§3 硬禁区不变）。

**渲染质量**：`--crf 18 --jpeg-quality 90`（默认 CRF 23/JPEG 80 画质偏低）；`--scale 2` 4K 超采样提升文字锐度（慢，仅终稿用）。
