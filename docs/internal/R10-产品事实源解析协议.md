# Product Truth / applet 源解析协议

> 状态：生效。用途：统一 ChatGPT、本机 Agent、其他 Agent、CI 对 `APPLET` 的逻辑身份与物理路径认知。

## 1. 唯一逻辑身份

项目文档中只允许使用 **`APPLET`** 表示产品源码事实源；禁止把某个机器上的绝对路径当成唯一事实源。

`APPLET` 的优先级：

1. 当前执行环境明确提供的 applet 源码目录；
2. 已提交且经过完整来源核验的 Product Truth Snapshot；
3. 两者都不存在时，必须报告“无法验证产品事实”，不得猜测或用历史记忆代替。

## 2. 本机路径

默认本机工作区布局仍可使用：

```text
promotion/
../applet/
```

这里的 `../applet` 是**本机 Agent 的解析路径**，不是跨环境永久路径。

## 3. ChatGPT / 上传源码

会话上传的 `applet.zip` 可以作为一次 `APPLET` Product Truth 输入；会话物理位置不写入项目规范作为永久路径。

当前正式 Product Truth Snapshot：`spec/product-truth/applet/source.tar.xz`。

Snapshot 的来源、哈希、文件范围及历史迁移证据统一记录在 `docs/changes/`（历史变更事务）；本协议只保留当前规则，不重复审计轮次叙事。

当前 Snapshot 为干净的 298 个 `.vue/.js/.json` 源文件，并已进入 CI materialize 流程；当前验证状态以最新 CI / `gate-all` 为准。

## 4. CI / 无 applet 工作区

CI **不伪造 applet 源码目录，也不静默跳过 UI Truth**。正式 Product Truth Snapshot 进入仓库后，CI 从归档 materialize 出 `../applet`，再运行现有 UI Truth 检查；如果快照缺失、解包范围不符或文件数不符，应失败。

`check-facts` 不把 `../applet/*` 当作 promotion 仓库内资产存在性问题；这些路径由本协议定义为外部产品事实源，并在结果中显式标记为 external。这样不会把“路径不同”误报成“产品事实不存在”，同时不会把 UI Truth 误判为已验证。

正式 snapshot 必须同时满足：

- 来源 archive 有 SHA-256；**live source 重建时**（§7 的"以最新源码为准"路径）改记源集摘要 `source_tree_sha256`（manifest 的 `files[]` 排序串 SHA-256，`archive_sha256` 留空，并在 `provenance_note` 写明输入为本机 live source）；
- 每个 materialized 文件有源路径与内容哈希；
- `spec/coupon-fields.json` / `spec/card-fields.json` 的 `src` 行段可回溯到 snapshot；
- CI materialization 后，现有 `check-ui-truth.mjs` 无需降低验证等级即可运行。

## 5. 外部截图/素材库

外部截图库与图标素材库属于历史外部素材资源，不要求复制进 promotion Git checkout。`spec/assets.json` 继续保存登记与用途；`check-facts` 对这类外部库只登记为 external，不将其缺失误报成仓库内资产缺失。

## 6. 外部能力说明书源（quandao-mcp-server）

`quandao-mcp-server`（服务端 `quandao-mcp` v1.0.0，Streamable HTTP，配置在用户级 `~/.workbuddy/mcp.json`）是产品侧的**外部能力说明书源**：7 个工具**全部只读**（4 份能力说明书 `coupon/bundle/card/point_capabilities` ＋ `industry_tree` ＋ `position_list`/`recommend_list`）。

**定位：人工校对尺——不是第二份产品真值，也不是数据管道。** 产品能力/字段的唯一 Owner 仍是 `APPLET / spec/`（本协议 §1 与 §7「Agent 协作规则」不变）。

三条硬边界：

1. **不作机检判据。** 能力说明书措辞含「通常/一般」等模糊限定，只供人工校对；任何闸门（`scripts/*.mjs`）不得读取或依赖其返回值。
2. **不进选题判据。** `industry_tree` 只作行业身份校准（名称/层级/id）与相邻行业查重旁证；不得当候选行业清单（`SKILL.md` 第 1 步「现场调研，不预置清单」不受影响）。
3. **上屏仍回源码取证。** `position_list`/`recommend_list` 只作「落点真实性」线索；任何上屏表述仍按上屏真实性闸门回 `APPLET` 源码逐字取证。

**引用义务**：把 MCP 结论写进 `spec/*.json` 时，`src`/来源必须显式标注「外部能力文档：quandao-mcp · <工具名>（非小程序源码）」并记录取用日期；说明书随产品迭代过期，不得把它的数值当永久真值。

## 7. Agent 协作规则

- 讨论产品字段、UI、券种、流程时，先引用 `APPLET`。
- `../applet`、会话上传压缩包、CI 临时目录都只是环境绑定，不得成为新的事实源名称。
- 如果本地 Agent 能看到 live source，应优先用 live source 验证。
- ChatGPT 当前会话可直接使用用户上传的 applet 压缩包进行事实核验。
- snapshot 与 live source 发生差异时，以用户提供的最新产品源码为准，并重新生成 snapshot；不得自行覆盖产品真值。
- 不允许为了让闸门变绿而把无法验证的产品事实改成“已验证”。

## 8. 与现有闸门的关系

- `scripts/check-ui-truth.mjs`：本机有 live `../applet` 时直接验证；CI 从正式 snapshot materialize 后直接验证。
- `scripts/check-facts.mjs`：只负责 promotion 仓库内资产存在性；外部 APPLET 与外部截图/素材库按本协议显式标记 external。
- `spec/coupon-fields.json`、`spec/card-fields.json`：仍是 promotion 内的字段真值登记表，但其产品事实必须可追溯到 `APPLET`。
- `scripts/ref-registry.json`：继续保持唯一文档/事实登记角色，不复制事务状态。

## 9. 当前状态

- Product Truth Snapshot：**已入库 / 当前有效**。
- Snapshot：298 个 `.vue/.js/.json` 源文件。
- CI：已支持从正式 Snapshot materialize `APPLET` 并执行 UI Truth；当前是否通过以最新 CI / `gate-all` 为准。
- 历史“尚未写入 Git / 尚未 CI 验证”描述已退休，不得作为当前状态继续引用。

## 10. 禁止事项

1. 禁止把会话临时文件位置写死为项目永久路径。
2. 禁止要求所有 Agent 必须拥有相同的绝对目录。
3. 禁止 CI 因缺少 live applet 而静默跳过 UI Truth。
4. 禁止用不完整或合成内容冒充 applet source snapshot。
5. 禁止为了让 `check-facts` 变绿，把外部素材库伪装成本仓库文件。
