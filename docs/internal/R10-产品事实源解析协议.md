# R10 · Product Truth / applet 源解析协议

> 状态：生效。用途：统一 ChatGPT、本机 Agent、其他 Agent、CI 对 `applet` 的逻辑身份与物理路径认知。

## 1. 唯一逻辑身份

项目文档中只允许使用 **`APPLET`** 表示产品源码事实源；禁止把某个机器上的绝对路径当成唯一事实源。

`APPLET` 的优先级：

1. 当前执行环境明确提供的 applet 源码目录；
2. 已提交且经过完整来源核验的 Product Truth Snapshot（当前尚未启用）；
3. 两者都不存在时，必须报告“无法验证产品事实”，不得猜测或用历史记忆代替。

## 2. 本机路径

默认本机工作区布局仍可使用：

```text
promotion/
../applet/
```

这里的 `../applet` 是**本机 Agent 的解析路径**，不是跨环境永久路径。

## 3. ChatGPT / 上传源码

本次任务提供的 `applet.zip` 是 `APPLET` 的一次 Product Truth 输入。

archive SHA-256：`afb1b0385cf167392eb78b2031d104b714134d72697a1e735d6d4313e6ca1ad7`

当前会话物理位置由运行环境提供，不写入项目规范作为永久路径。

## 4. CI / 无 applet 工作区

当前 CI **不伪造 applet 源码目录，也不静默跳过 UI Truth**。在完成一个可逐文件、逐行追溯到用户上传源码的 snapshot 之前，CI 中依赖 `../applet` 的检查保持明确失败。

后续正式 snapshot 必须同时满足：

- 来源 archive 有 SHA-256；
- 每个 materialized 文件有源路径与内容哈希；
- `spec/coupon-fields.json` / `spec/card-fields.json` 的 `src` 行段可回溯到 snapshot；
- CI materialization 后，现有 `check-ui-truth.mjs` 无需降低验证等级即可运行。

## 5. Agent 协作规则

- 讨论产品字段、UI、券种、流程时，先引用 `APPLET`。
- `../applet`、`/mnt/data/applet.zip`、CI 临时目录都只是环境绑定，不得成为新的事实源名称。
- 如果本地 Agent 能看到 live source，应优先用 live source 验证。
- ChatGPT 当前会话可直接使用用户上传的 applet 压缩包进行事实核验。
- snapshot 与 live source 发生差异时，以用户提供的最新产品源码为准，并重新生成 snapshot；不得自行覆盖产品真值。
- 不允许为了让闸门变绿而把无法验证的产品事实改成“已验证”。

## 6. 与现有闸门的关系

- `scripts/check-ui-truth.mjs`：本机有 live `../applet` 时直接验证；CI 在正式 snapshot 完成前保留缺源失败。
- `scripts/check-facts.mjs`：R6/产品事实路径同样不能用占位文件冒充源码。
- `spec/coupon-fields.json`、`spec/card-fields.json`：仍是 promotion 内的字段真值登记表，但其产品事实必须可追溯到 `APPLET`。
- `scripts/ref-registry.json`：继续保持唯一文档/事实登记角色，不复制事务状态。

## 7. 禁止事项

1. 禁止写死 `/mnt/data/applet.zip` 作为项目永久路径。
2. 禁止要求所有 Agent 必须拥有相同的绝对目录。
3. 禁止 CI 因缺少 live applet 而静默跳过 UI Truth。
4. 禁止用不完整或合成内容冒充 applet source snapshot。
