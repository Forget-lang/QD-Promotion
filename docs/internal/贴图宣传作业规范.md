# 券到卡包 · 贴图宣传策划与制作

> 本文是**独立静态宣传贴图的策划与视觉设计方法 Owner**。  
> 适用对象：不依附于某条行业视频、由用户单独发布的产品介绍图、经营攻略图、功能/玩法系列图。  
> 不适用：随 `gXX` 行业视频伴生的抖音图文生产线（该线仍由 `SKILL.md` 负责）、行业短视频、产品功能教程、官网原生页面设计。  
> 用户负责最终发布；本技能负责**选题、内容、文案、视觉、制图、交付**。

## 〇、最高原则

### 1. 先理解，再设计；先设计，再制图

禁止：

> 官网找一段文案 → 改几个字 → 配一张漂亮图。

必须：

> 产品真值 → 官网场景理解 → 经营痛点 → 功能组合 → 独立攻略 → 图片表达。

### 2. 官网是“研究材料”，不是“文案库”

官网可以帮助 AI 理解：

- 产品正在解决什么经营问题；
- 某个功能在什么场景里出现；
- 多个能力如何组合；
- 商家为什么会使用这种玩法；
- 产品官方如何解释某个业务过程。

但官网**不能直接变成贴图文案**。

以下内容禁止直接复制：

- 官网标题；
- 官网副标题；
- 官网整句宣传语；
- 官网段落顺序；
- 官网场景案例的完整叙述；
- 官网金句或 CTA。

允许借鉴的是：

- 场景事实；
- 玩法机制；
- 业务链路；
- 功能关系；
- 用户问题。

然后必须由 AI **重新提炼、重新组织、重新表达**。

一句判据：

> **看完官网后，如果只换了几个词，图片仍然能和官网原页面逐段对照，就说明没有真正完成原创设计。**

### 3. Product Truth 最高优先级

任何会被用户理解为“券到卡包具有的功能、字段、数字、规则、限制”的信息：

- 回 `spec/facts.json`；
- 券类回 `spec/coupon-fields.json`；
- 次卡回 `spec/card-fields.json`；
- 新能力回对应真值表；
- 与 APPLET 源码冲突时，以 APPLET 为准。

官网中的能力描述、数字、套餐、版本、效果承诺都不能跳过真值层。

### 4. 不把功能做成功能清单

贴图宣传的核心不是“告诉用户我们有 20 个功能”，而是：

> **让商家看懂某个真实经营问题，理解为什么这样设计，并看到一套可以落地的解决办法。**

一个作品优先讲：

- 一个经营时刻；
- 一个核心痛点；
- 一条核心机制；
- 一组必要功能。

功能少而透，胜过功能多而浅。

## 〇-A、与既有抖音图文线的边界

项目已经存在一条正式的「抖音图文线」，由 `SKILL.md` 作为生产 Owner：它默认与 `gXX` 行业视频伴生，使用 `outputs/gXX-行业/graphic/`、图文数据文件、图文发布稿与既有工程/后验体系。

本技能不替代、不复制那条生产流程。

### 路由判据

- **随某个 `gXX` 行业视频伴生**，同题复用行业片的选题/真值/字段取证 → 走 `SKILL.md` 的抖音图文线。
- **独立做一组产品介绍/经营攻略贴图**，不依附某条行业视频 → 走本技能。
- 两者都涉及静态 PNG 时，**先按是否伴生判线，再按对应 Owner 执行**；不得因为都叫“图文/贴图”而形成第二套同任务流程。

### 独立贴图的典型任务

- 产品总览置顶作品；
- 功能介绍系列；
- 某个经营玩法的独立攻略系列；
- 为抖音/小红书准备的单张或多张独立静态宣传图。

本技能可以借鉴既有图文线的真实制作经验，但不得把其工程、发布、后验规则复制成第二套规则；平台红线、Product Truth 与资源调用边界仍回各自 Owner。

# 一、任务类型

贴图任务分两类：

## A. 产品总览作品

目的：

> 让第一次接触产品的人快速认识产品。

典型内容：

- 产品是什么；
- 核心产品族；
- 顾客端 / 商家端；
- 核销、数据、经营闭环。

适合做：

- 置顶作品；
- 产品介绍系列；
- 官方能力总览。

## B. 经营攻略作品

目的：

> 教老板解决一个具体经营问题。

典型内容：

- 顾客为什么不再来；
- 新客只来一次；
- 结账之后怎么衔接下一次；
- 闲时怎么安排活动；
- 老客如何重新触达；
- 一次消费如何变成多次到店。

这是后续内容生产的主力。

# 二、标准工作流

## 第 1 步 · 定义这一组作品到底要解决什么

先明确：

1. 目标行业或门店类型；
2. 一个具体经营时刻；
3. 老板当下怎么处理；
4. 当前做法哪里断掉；
5. 券到卡包哪个真实能力组合能解决；
6. 最终这一组贴图要让用户学会什么。

禁止：

> “今天介绍优惠券。”

必须改成：

> “今天解决餐饮店顾客结账后不再来的问题。”

或者：

> “今天解决美容门店第一次到店后没有下一次预约理由的问题。”

### 一个作品组 = 一个核心问题

不要把两个互不相关的问题塞进同一组。

---

## 第 2 步 · 研究官网，但不抄官网

按需要读取：

1. 官网首页：建立整体产品认知；
2. 相关功能介绍页：了解能力组合；
3. 相关营销玩法页：学习完整业务链路；
4. 行业解决方案页：寻找真实经营场景；
5. 教程页：只有在需要理解操作语气时再读。

阅读时只提取四类研究结果：

### 场景

这个功能发生在什么时候？

### 痛点

老板为什么需要它？

### 机制

几个功能是怎么一起工作的？

### 结果路径

顾客 / 商家完成这个动作后，下一步发生什么？

不要抄原文。

---

## 第 3 步 · 进入“自己设计攻略”阶段

官网读完后必须离开官网原始叙事，重新设计：

### ① 核心命题

用一句自己的话定义：

> “这一组图究竟要教老板什么？”

### ② 机制

说明：

> 为什么这个做法成立？

### ③ 功能组合

只保留真正必要的 2～4 个功能。

### ④ 配置示例

如需数字：

- 产品确定参数 → 可以直接使用；
- 假设配置 → 明确写“示例配置”；
- 无来源经营结果 → 不写。

### ⑤ 视觉故事

决定：

- 用真实场景；
- 用人物；
- 用流程；
- 用卡券；
- 用抽象关系；
- 用少量产品 UI。

---

# 三、攻略设计标准

## 1. 一组作品建议 3～5 张

不要为了“丰富”机械做 9 张。

建议一组完整攻略包含：

### 01｜提出问题

让老板认出自己的经营时刻。

### 02｜解释为什么

把问题背后的经营机制讲明白。

### 03｜给出设置方式

展示真正有价值的配置。

### 04｜讲清执行流程

说明这套玩法如何跑起来。

### 05｜场景收口

说明哪些门店适合，以及如何迁移。

具体张数由内容决定，不是固定配额。

## 2. 一张图只讲一个主信息

一张图必须存在一个明确视觉中心。

不能同时承担：

> 产品总览 + 三个玩法 + 六个功能 + 联系方式 + CTA。

## 3. 不靠堆文字制造“知识感”

一张图信息多，不等于有价值。

优先：

> 场景 → 判断 → 机制 → 例子 → 动作

而不是：

> 标题 → 六个卡片 → 十二个图标 → 一堆小字。

# 四、平台安全设计

> 具体平台规则以项目 `spec/redlines.json` 为当前项目红线；涉及平台规则变化时，在制作前重新核对对应平台官方规则，不把历史经验当成永久规则。

## 1. 默认公开发布安全口径

画面中不主动放：

- 微信；
- 企业微信 / 企微；
- 小程序；
- 小程序码；
- 二维码；
- 电话；
- 微信号；
- 邮箱；
- 网址；
- 第三方社交平台 Logo；
- 搜索导流提示；
- 加好友 / 加群 / 私信等引导。

也不要用谐音、字母变体、符号替代来绕审核。

## 2. 不做诱导点击视觉

禁止把图片设计成：

- “点击领取”；
- “立即领取”；
- “马上下载”；
- 假按钮；
- 假下载入口；
- 假客服入口；
- 假扫码入口。

图片可以展示“券面”和“操作结果”，但不要把平台用户当成正在点击广告的人。

## 3. 不做无来源效果承诺

禁止：

- 客流 +300%；
- 复购 ×3；
- 营业额翻倍；
- 7 天回本；
- 爆单；
- 行业第一；
- 最佳 / 最强 / 最划算等绝对化表达。

允许：

- 产品真实参数；
- 功能真实限制；
- 明确标为“示例配置”的示例值。

## 4. 强监管行业

涉及：

- 教育培训；
- 美业 / 养生 / 医美；
- 健身 / 减重；
- 母婴；
- 食品；
- 储值 / 预付；

必须额外检查行业特有红线。没有证据时，不自行补充效果、健康、资质、升学、收益等承诺。

# 五、图片真实性

## L1 · 不可凭空生成

以下内容不能让 AI 自己“猜”：

- 真实产品 UI；
- 真实功能字段；
- 真实金额；
- 真实规则；
- 真实统计结果；
- 真实后台读数；
- 真实产品流程。

需要展示时：

- 使用真实产品截图；
- 或根据真实 UI 证据重新绘制；
- 或采用非产品化、抽象化的视觉表达。

## L2 · 可以自由创作

AI 可以自由设计：

- 门店环境；
- 人物；
- 商业场景；
- 氛围；
- 情绪；
- 隐喻；
- 光影；
- 空间；
- 抽象动线；
- 卡券的艺术化表现。

## L3 · 装饰文字

招牌、海报、包装、年份、手写标语等装饰文字可以创作，但：

- 不承担产品事实；
- 不放第三方导流信息；
- 不放极限词；
- 不伪装成真实系统字段。

# 六、尺寸与交付形式

## 默认母版

**1080 × 1440 px，3:4**

作为抖音图文 / 小红书图文的默认贴图尺寸。

## 需要 9:16

使用：

**1080 × 1920 px，9:16**

必须独立重新构图。

禁止把 3:4 成品强行拉伸、裁掉关键内容后当 9:16 成品。

## 单图原则

必须：

> **一张图 = 一个独立文件 = 一个独立主题。**

禁止：

- 九宫格；
- 五宫格；
- 多张拼图；
- 一张长图里放多个页面；
- 先生成合集再裁切成独立图。

# 七、视觉设计

## 1. 统一品牌气质，不固定一个模板

可以保持统一：

- 清爽；
- 现代；
- 有产品感；
- 有空间层次；
- 轻 3D / 插画 / UI 混合；
- 蓝白与产品色点缀。

但不要让每一张都变成：

> 大标题 + 手机 + 五个圆角卡片。

每组作品需要自己的视觉母题。

## 2. 视觉中心优先

一张图优先保证：

- 远看知道讲什么；
- 近看能学到什么；
- 中间视觉主体明确；
- 文案有层级；
- 背景不抢主信息。

## 3. 真实场景优先于装饰堆砌

经营攻略优先考虑：

- 收银台；
- 餐桌；
- 美业服务区；
- 洗车工位；
- 门店前台；
- 顾客使用场景；

而不是用大量无意义的小图标填空间。

# 八、制图执行

## 每次必须单独生成

用户要求“继续下一张”时：

1. 明确这一张的单一主题；
2. 明确完整文案；
3. 明确构图；
4. 检查平台安全；
5. 单独生成这一张；
6. 交付这一张；
7. 用户通过后再进入下一张。

不得把下一张一起生成。

## 文字检查

生成后人工检查：

- 标题是否正确；
- 功能名称是否准确；
- 数字是否真实；
- 示例值是否标注；
- 是否出现第三方平台；
- 是否出现二维码 / 联系方式；
- 是否出现诱导词；
- 是否出现极限词；
- 是否出现不存在的功能。

AI 生成出的中文字不能默认视为正确。

# 九、作品验收

一张图至少回答：

### 内容

- 我一眼知道这张在讲什么吗？
- 它真的解决一个经营问题吗？
- 有没有把官网原文搬过来？
- 有没有讲一个功能，却没有解释为什么？
- 有没有把两个不相关的问题混在一起？

### 产品

- 所有产品能力是否都有真值依据？
- 有没有虚构功能？
- 有没有把示例值写成固定规则？
- 有没有虚构案例 / 数据？

### 平台

- 有没有第三方平台元素？
- 有没有联系方式？
- 有没有二维码？
- 有没有站外导流？
- 有没有诱导点击？
- 有没有夸大效果？
- 有没有绝对化表达？

### 视觉

- 是否是一张独立成品？
- 是否为正确尺寸？
- 缩小到手机信息流后是否仍看得懂？
- 是否有明确视觉中心？
- 是否像产品宣传作品，而不是 PPT 字段堆叠？
- 是否与同系列保持统一，又没有简单复制上一张构图？

### 最终标准

> **用户看完应该学会一个东西，而不是只知道“券到卡包有这个功能”。**

# 十、每组作品的研究记录

每次设计新作品组，内部至少留下：

- 本次经营问题；
- 官网读过哪些相关页面；
- 官网提供了什么场景启发；
- Product Truth 核验了哪些能力；
- 最终自己设计出的玩法；
- 哪些官网表达刻意没有采用；
- 哪些平台风险主动规避；
- 本组每张图分别承担什么信息。

这些记录用于保证下一张、下一组不会重新从零猜。

# 十一、一个完整示例：结账送券

不要直接复制官网的“结账送券”页面。

正确过程：

### 官网研究得到

“结账”是一个重要经营节点。

### 重新提炼经营问题

> 顾客今天消费完成后，门店怎样给下一次到店留下理由？

### 重新设计攻略

**01 顾客结账就走？**  
提出问题。

**02 结账不是终点**  
解释消费与下一次到店的连接机制。

**03 复购券怎么设？**  
用餐饮示例配置展示：

> 满100减20  
> 次日起可用  
> 7天有效

并明确这是示例配置。

**04 5 步把这次消费接到下一次**  
结账发券 → 次日起可用 → 有效期 → 到期提醒 → 到店核销。

**05 哪些门店适合？**  
餐饮 / 美业 / 洗车 / 宠物。

注意：

- 不复制官网原句；
- 不虚构经营结果；
- 不添加第三方平台；
- 不添加二维码；
- 不做“点击领取”等按钮；
- 每张独立制作。

这才叫“从官网理解玩法，再自己设计攻略”。

# 十二、与其他项目 Owner 的边界

本技能：

- 不定义 Product Truth；
- 不修改平台红线；
- 不替代 `knowledge/玩法版图.md`；
- 不替代视频 `SKILL.md`；
- 不负责最终平台发布；
- 不把官网变成第二真值源。

调用关系：

```
AGENTS
  ↓
贴图宣传作业规范
  ↓
Product Truth
  ↓
官网场景 / 玩法研究
  ↓
玩法版图组合
  ↓
原创攻略
  ↓
平台安全策划
  ↓
视觉设计
  ↓
单张独立制图
  ↓
人工验收
  ↓
交付用户发布
```

一句话：

> **官网负责让我“看懂产品和场景”，不负责替我“写好这张图”；真正的攻略必须由 AI 基于真实产品能力重新设计。**
