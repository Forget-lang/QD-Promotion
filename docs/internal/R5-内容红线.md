# R5 · 内容红线（唯一真源）

> **本文档是全部对外内容（视频/文案/封面/文章）的红线唯一真源。**
> 任何对外内容的合规判断，以本文档为准。
>
> **与 R1 的分工**：R1 管「产品有什么功能」（事实），R5 管「对外怎么说」（口径）。R1 说"产品有核销活码功能"，R5 说"宣传中不提活码"——互不矛盾，各司其职。
>
> **机器执行子集**：`scripts/redlines.json` 是本文档的机器可执行版本（闸门脚本读它），只收录能精确匹配的关键词。文档比 JSON 更完整（包含判断逻辑），JSON 比文档更严格（机器兜底）。
>
> **改红线固定三步**：① 改 R5 本文档 → ② 同步 `redlines.json`（如果涉及机器可检测词）→ ③ 跑 `node scripts/check-redlines.mjs` 验证 code 层零命中

## 1. 平台导流红线（三平台通用）

### 1.1 绝对不能说的（违者 = 限流/封号）

| 类别 | 禁止内容 | 为什么 |
|---|---|---|
| 微信相关 | 微信、小程序、公众号、微信搜、小程序码、加微信、扫码关注 | 抖音/小红书/搜狐都禁止导流到微信生态 |
| 搜索导流 | 搜一下、去搜、搜索框、搜我、搜名字 | 平台禁止站外搜索导流 |
| 诱导互动 | 关注我、点关注、私信我、进主页、评论区扣 1 | 平台打击诱导互动行为 |
| 硬广导流 | 立即领取、马上领取、点击下载、扫码加微信 | 硬广感强，限流严重 |

**正例**：（只出现品牌名 + 价值主张，不说导流方式）
- 「券到卡包」+ 一句价值主张（由设计稿根据内容定制）

**拿不准怎么办**：宁可不提，也不要碰。导流只有一个合法位置——账号资料位。

## 2. 虚假宣传红线

### 2.1 不虚构功能

产品没有的功能绝对不能说。完整功能边界见 `R1-产品事实表.md §8 能力边界`。核心几条：

- 无在线支付/收款、无短信验证码领券
- 统计无趋势图表（只有指标卡 + 排行榜）
- 券包/次卡仅私密发放（无私开领取）
- 无在线预约系统、无会员等级/积分体系
- 无第三方系统对接（收银/POS/外卖平台）
- 核销方向固定：商家扫顾客的码，不存在顾客扫商家码
- 企微群发不是全自动（需员工在群发助手中确认）
- **次卡没有转赠奖励**（次卡仅支持转赠；转赠奖励是优惠券独有功能，不能把两者混在一条链路里）

### 2.2 不编案例/数据

- 不虚构商户名、不编"某店增长 30%"类案例
- 所有数字从 `R1-产品事实表.md §6 关键数值约束` 取（上限内自由设）
- 无真实案例阶段，正文一律用**行业泛称**（咖啡店/火锅店/美容院等）

### 2.3 示例 vs 案例的判别

| 类型 | 能不能用 | 判定标准 |
|---|---|---|
| **功能示例** | ✅ 可以 | "比如你可以设置满 30 减 5 元"——这是在说明功能怎么用，不是在说"某某店用了效果很好" |
| **效果案例** | ❌ 不行 | "XX 咖啡店用了之后营业额翻了三倍"——有具体店名/数据/效果，属于虚构案例 |

**拿不准怎么办**：去掉具体名字和数字，改成泛化说明。

## 3. 极限词红线（广告法 + 平台违禁）

### 3.1 绝对不能用的

| 类别 | 示例（非完整清单） |
|---|---|
| 最字类 | 最佳、最优、最好、最强、最大、最高、最低、最快、最新、最先进、最划算、最便宜、最低价 |
| 顶级类 | 独一无二、绝无仅有、顶级、顶尖、极品 |
| 第一类 | 全球第一、全国第一、行业第一、国家级、世界级 |
| 绝对类 | 百分之百、百分百、100%、秒杀一切、秒杀全网 |
| 稀缺恐吓类 | 不看后悔、错过就没了、最后机会、爆单、卖疯了、抢疯了 |
| 医疗类 | 治病、疗效、包治、根治、痊愈、瘦身、丰胸、增高 |

**完整机器可检测清单见 `scripts/redlines.json`。**

### 3.2 怎么绕开

| 不要说 | 可以说 |
|---|---|
| "最好用的电子券工具" | "很实用的电子券工具" |
| "最快 30 秒做一张券" | "几十秒就能做好一张券" |
| "全国第一" | "很多门店都在用" |

**拿不准怎么办**：换成模糊描述，不用绝对化的词。

## 4. 功能表述红线（特定功能的口径规范）

### 4.1 企微泛称

- ❌ 不说「企业微信」「企微」
- ✅ 说「加好友自动发券」「进群自动发券」「社群发券」
- 原因：企微是核心功能，但平台对"企业微信"导流敏感，用功能泛称更安全

### 4.2 核销活码

- ❌ 不提「核销活码」「5 分钟刷新」「防截屏」
- ✅ 只说「扫码核销 + 手动输码兜底」
- 原因：活码是技术细节，不是商家核心价值；避免被截图滥用的安全风险

### 4.3 免费卖点边界

- ✅ 可以说（自然提及）：「免费使用」「免费创建」
- ❌ 不强调、不堆促销词：不要说"永久免费""完全免费""免费送"
- ❌ 不承诺未来：不要说"永远免费""一直免费"（后续商业模式未定）
- 原因：免费是事实，但不是核心卖点；过度强调会拉低品牌调性 + 未来不好转向

#### 4.3.1 封面图 / 开头 / 结尾不刻意提免费

- ❌ **封面图**不能把"免费"当主卖点大字展示（如封面写"免费电子券工具""免费领"）
- ❌ **视频开头（钩子）**不能用"免费"做噱头（如"这个免费工具老板们都在用""免费帮你管券"）
- ❌ **视频结尾（CTA）**不能以"免费"作为行动号召（如"免费使用，赶紧试试""免费的，快来"）
- ✅ 正文中间自然提到"免费使用"仍然可以
- 原因：封面/开头/结尾是用户注意力最集中的三个位置，在这些位置刻意打"免费"等于把免费当核心卖点推，与品牌调性冲突

### 4.4 审核机制

- ❌ 宣传中不提及「审核/待审核/认证审核/已认证」
- 原因：次卡审核是平台安全合规机制，与获客宣传无关；说了反而让商家觉得麻烦

## 6. 平台特有红线

### 6.1 抖音

- 不用"下期讲 XX"硬切下个视频（一次讲透一个点）
- 不诱导点赞/评论/关注

### 6.2 小红书

- 用经验分享口吻，不用硬广感
- 结尾不硬导流，品牌署名自然收尾

### 6.3 搜狐

- 品牌署名收尾，不硬推扫码
- 长文可以写得深入，不追求短平快

## 7. 改红线的标准流程

每次红线相关的修改，必须走完三步：

1. **改 R5 本文档** —— 先更新本文档（人能读懂的完整规则）
2. **同步 redlines.json** —— 如果涉及机器可检测的关键词，同步更新
3. **跑闸门验证** —— `node scripts/check-redlines.mjs`，确认 `video/src` 层零命中

三步都走完才算完成。只改文档不改 JSON = 机器兜不住；只改 JSON 不改文档 = 人看不懂为什么有这条规则。
