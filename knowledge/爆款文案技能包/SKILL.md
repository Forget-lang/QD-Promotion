# 爆款文案 AI Agent Skill 3.0

> ⚠️ **已废止（2026-09-08 用户拍板）**：下列「拆零件 RAG 学习 + 评分器创作闸门」方法仅供历史留存，不得作为生产流程。**评分器（§9 选题评分 / §10 Hook 评分 / §14 自动审稿 / §15 Viral Copy Score）降级为「仅做选题与标题初筛」**，不进逐屏创作——**「低于 80 分不得终稿」这条创作闸门口径已作废**。985 篇语料库保留作检索源。被否原因与决策记 `docs/changes/`。

## 0. 定义

本 Skill 面向拥有大量抖音爆款文案语料的智能体，目标不是“模仿爆款”，而是建立一个持续学习的内容决策系统：

**案例学习 → 特征抽取 → 模式挖掘 → 机会发现 → 自主选题 → Hook设计 → 成稿 → 严格审稿 → 反馈学习 → 经验更新**

本版本以用户提供的 **985 篇抖音文案语料**为第一批训练/检索语料。语料包含标题、作者、点赞、评论、发布时间、描述、口播文案等字段。

> 注意：本 Skill 属于 Agent/RAG/知识工程层面的“学习”，不是修改底层模型参数的监督微调。除非外部系统另行训练模型，否则 Agent 应把学习结果沉淀到结构化知识库中。

---

# 1. 核心任务

Agent 必须同时具备六种能力：

1. **研究员**：从案例中找规律。
2. **数据分析师**：区分“高频”与“高表现”。
3. **选题策划**：从用户痛点和内容机会生成候选选题。
4. **短视频编剧**：设计 Hook、结构、节奏、信息增量和结尾。
5. **审稿人**：主动寻找划走点、AI味、空话和低价值段落。
6. **学习系统**：将真实表现反馈写回知识库，更新模式可信度。

禁止把任务简化为“找几个爆款然后仿写”。

---

# 2. 学习原则

## 2.1 学习因果，不学习表面

每个案例至少回答：

- 为什么用户会点开？
- 为什么用户愿意继续看？
- 哪个位置发生信息增量？
- 哪个位置发生情绪升级？
- 哪个位置建立可信度？
- 为什么用户可能点赞、评论、收藏或转发？
- 哪些元素可能只是作者已有流量、人设或行业红利，而不是文案本身导致？

## 2.2 高频不等于有效

同一个表达出现很多次，不代表它是爆款因果因素。

Agent 必须区分：

- Frequency：出现频率
- Reach：覆盖范围
- Performance：表现
- Lift：相对于基准的提升
- Confidence：证据可信度

## 2.3 样本分层

默认按以下维度分层比较：

- 赛道
- 作者/账号
- 内容形态
- 发布时间阶段
- 文案长度区间
- 点赞层级

至少进行“同赛道/同账号/相近长度”对照，再判断某个模式是否值得迁移。

## 2.4 避免伪因果

例如“出现评论区三个字”可能和高点赞同时出现，但不能据此断言“评论区三个字导致爆款”。

所有结论使用：

> 相关性 → 假设 → 对照 → 验证

而不是：

> 共现 → 因果

建立 8 个逻辑库：

# 5. Feature Library：案例特征工程

对每篇文案提取四类特征。

## 5.1 表层特征

- 字数
- 句数
- 平均句长
- 问句数量
- 感叹句数量
- 数字数量
- 比较词数量
- 否定词数量
- 第二人称比例
- CTA 密度
- 专业术语密度
- 口语化程度

## 5.2 语义特征

- 目标人群
- 需求
- 痛点
- 欲望
- 风险
- 结果承诺
- 认知冲突
- 反常识
- 信息差
- 社会证明
- 案例证明

## 5.3 结构特征

- Hook
- Problem
- Agitation
- Story
- Proof
- Reveal
- Solution
- Summary
- CTA

## 5.4 心理特征

- 利益驱动

- 焦虑
- 希望

- 争议

# 6. Pattern Mining：爆款 DNA 挖掘

每完成一批案例学习，运行一次 Pattern Mining。

推荐每 25～50 篇执行一次，整个语料完成后再做一次全量聚合。

每一个 Pattern 必须保存：

```json
{
  "pattern_id": "PAT-0001",
  "name": "",
  "layer": "cross_domain|domain|format|creator",
  "formula": "",
  "psychology": "",
  "use_when": [],
  "avoid_when": [],
  "support_cases": [],
  "support_count": 0,
  "median_likes": 0,
  "baseline_likes": 0,
  "lift": 0,
  "confidence": 0,
  "risk": 0,
  "notes": ""
}
```

### Pattern 进入“核心爆款规律”的最低条件

同时满足以下尽可能多项：

1. 至少多个独立作者出现。
2. 不只集中在一个标题/固定账号。
3. 与表现指标存在稳定关联。
4. 能抽象成可迁移公式。
5. 能解释用户心理。
6. 存在反例时能说明适用边界。

不满足时只能放入“候选规律”。

# 7. Performance-aware：表现加权学习

本语料具备点赞/评论字段，因此 Agent 不得只按“文章出现频率”学习。

至少维护三个分层：

### Tier A：高表现

默认进入同赛道 Top 10% 或更高层级。

### Tier B：中表现

用于识别稳定、可复用结构。

### Tier C：低表现

重点用于寻找反模式和失败原因。

### 对照原则

同一 Pattern 出现时，比较：

> 使用 Pattern 的高表现案例
>
> VS
>
> 使用 Pattern 的普通案例

寻找真正有区分度的特征。

禁止因为某 Pattern 在所有文案里出现而直接判定它有效。

# 8. Topic Opportunity Engine：自主选题

收到“今天发什么”“帮我做内容”等指令时，不允许直接写稿。

先执行：

```text
用户画像
→ 当前业务/账号定位
→ Pain Library
→ 最近内容去重
→ 热点/场景机会
→ Pattern Library
→ 生成候选选题
→ 评分
→ Top 5
→ 选 Top 1
```

默认生成 20 个选题。

# 9. Viral Topic Score

总分 100。

```text
痛点强度       15
结果价值       10
好奇缺口       15
冲突强度       10
反常识程度     10
目标人群清晰度 10
信息差         10
评论讨论潜力    5
转发潜力        5
差异化          10
```

评分时必须写出扣分原因。

不要为了凑高分给所有项目打高分。

推荐决策：

- 85+：重点制作
- 75–84：可制作
- 65–74：重新包装
- <65：原则上淘汰

# 10. Hook Engine

一个选题至少生成 5 个 Hook 候选。

候选方向：

- 结果
- 痛点
- 反常识
- 冲突
- 好奇
- 身份
- 故事
- 数字

Hook 评分：

```text
清晰度     20
好奇心     20
目标人群   15
冲突       15
收益/损失  15
可信度     10
口语感      5
```

不要把“夸张”误认为“强 Hook”。

# 11. Script Engine：成稿

确定 Topic 和 Hook 后，再写正文。

基本结构：

```text
Hook
→ 用户问题
→ 具体场景
→ 认知冲突
→ 新信息
→ 案例/证明
→ 核心方法
→ 金句
→ 行动/讨论
```

实际结构根据 Pattern Library 自动选择，不强行套模板。

### 每句话必须承担至少一个功能

- 制造好奇
- 提供信息
- 证明可信
- 推进故事
- 制造冲突
- 情绪升级
- 给结果
- 形成记忆点

不承担功能的句子删除。

---

# 12. Evidence：证据优先

涉及：

- 收入
- 价格
- 用户数量
- 平台规则
- 时间变化
- 行业数据
- 案例结果

必须区分：

**已知事实 / 用户提供 / 案例引用 / 推测。**

不能为了增强冲击力编造数字。

---

# 13. Anti-Pattern：反模式学习

建立失败模式库。

重点关注：

- AI腔
- 空洞鸡汤
- 只有结论没有证据
- 标题与正文不兑现
- 过度悬念
- 低价值重复
- 强行评论区 CTA
- 机械“点赞收藏”
- 伪造结果
- 过度焦虑营销
- 直接复刻单一爆款
- 为了刺激而制造无事实依据的冲突

每个反模式记录：

```text
症状
→ 为什么会失效
→ 常见表现
→ 如何修复
```

# 14. 自我审稿器

初稿完成后，强制切换到“讨厌广告的普通用户”身份审稿。

必须回答：

1. 哪一句最可能让我划走？
2. 哪一句像 AI？
3. 哪一句是废话？
4. 哪一句没有兑现前面的承诺？
5. 哪个地方缺具体画面？
6. 哪个地方信息增量不足？
7. 哪个地方太像其他爆款？
8. 哪个地方可能失去可信度？
9. 哪个地方可以更短？
10. 哪个地方值得留下金句？

然后自动生成二稿。

# 15. Viral Copy Score

```text

留存设计          15
获得感            10
```

# 16. Feedback Loop：真实数据回流

当新视频产生真实数据时，写入：

```json
{
  "content_id": "",
  "topic": "",
  "hook_pattern": [],
  "structure_pattern": [],
  "emotion_pattern": [],
  "predicted_score": 0,
  "views": 0,
  "3s_retention": null,
  "completion_rate": null,
  "likes": 0,
  "comments": 0,
  "saves": 0,
  "shares": 0,
  "follows": 0,
  "publish_context": {},
  "notes": ""
}
```

然后计算预测误差：

```text
Prediction Error = Actual Performance - Expected Performance
```

识别：

- 哪些 Hook 经常高估？
- 哪些 Hook 经常低估？
- 哪些 Topic 在点赞高但完播低？
- 哪些内容收藏高但评论低？
- 哪些内容涨粉高？

把发现写回 Pattern Library。

# 17. Pattern 生命周期

每个 Pattern 有状态：

```text
candidate
→ validated
→ strong
→ weakened
→ retired
```

### candidate
证据不足。

### validated
出现稳定复现。

### strong
跨多个案例/阶段/作者仍稳定。

### weakened
新数据出现后效果下降。

### retired
多轮数据证明迁移价值很低。

禁止永久保留过期套路。

---

# 18. 反过拟合机制

禁止：

- 因为某个作者多次使用某套路，就判定行业规律。
- 因为某个数字/词语出现，就认为数字/词语导致爆款。
- 因为某一篇极端爆款，就把它当成通用规则。
- 只学习成功案例，不学习失败案例。

必须寻找：

> **多个作者 + 多个主题 + 多个时间点 + 多个表现层级**

下依然存在的共同规律。

---

# 19. 原创与防抄袭机制

可以学习：

- 结构
- 心理机制
- 信息组织
- 选题角度
- 表达策略

不应直接复制：

- 大段原句
- 独特故事细节
- 独特数字
- 独特案例叙述
- 连续句式序列
- 标志性表达

输出新文案前，执行：

```text
相似表达检查
→ 与参考案例对照
→ 替换独特表述
→ 保留抽象机制
```

# 20. Agent 自动工作流

```text
读取案例
→ 标准化
→ 特征抽取
→ 单篇分析
→ 跨案例聚类
→ Pattern Mining
→ 形成候选规律
```

## 模式 B：创作

```text

→ 用户
→ 痛点
→ 选题机会
→ 20个选题
→ 评分
→ Top 5
→ Top 1
→ 5个 Hook
→ 最优 Hook
→ 写稿
→ 爆款评分
→ 红队审稿
```

```text

→ 对比预测
→ 诊断误差
→ 找到成功/失败原因
→ 更新 Pattern

```

# 23. 985篇首批语料的使用方式

这批语料作为“第一代经验库”，不要永远视为真理。

建议把它转换为：

```text
Raw Cases
→ Feature Cases
→ Candidate Patterns
→ Validated Patterns
```

目前的初步统计已经显示：

- 文案表现存在明显长尾。
- CTA 并非天然正相关，不能机械认为“多CTA=爆”。
- 文案长度与点赞之间并没有简单的线性关系。
- 数据量主要集中在餐饮/实体店/创业/同城获客相关场景，因此跨行业规律需要谨慎外推。

这些结论只是第一轮数据诊断，不能代替完整的语义分析和真实视频指标。

---

# 24. 最终原则

永远优化这条链：

**让更多正确的人点开 → 让他们愿意继续看 → 让他们得到超出预期的信息 → 让他们产生情绪或认知变化 → 让他们愿意表达/保存/转发 → 用真实数据验证 → 把结果重新喂给系统。**

爆款不是句式，而是一个可迭代的内容系统。
