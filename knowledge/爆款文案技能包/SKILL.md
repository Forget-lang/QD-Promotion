## 一、学习原则（研究时照此判断）

1. **学因果，不学表面**。每个案例至少回答：为什么用户会点开？为什么愿意继续看？哪个位置发生信息增量？哪个位置发生情绪升级？哪个位置建立可信度？为什么可能点赞／评论／收藏／转发？哪些元素可能只是作者已有流量、人设或行业红利，而不是文案本身导致？
2. **高频 ≠ 有效**。同一个表达出现很多次，不代表它是爆款因果因素。必须区分：Frequency 出现频率／Reach 覆盖范围／Performance 表现／Lift 相对基准的提升／Confidence 证据可信度。
3. **样本分层**。默认按：赛道／作者账号／内容形态／发布时间阶段／文案长度区间／点赞层级分层；至少做「同赛道 · 同账号 · 相近长度」对照，再判断某个模式是否值得迁移。
4. **避免伪因果**。「某词与高点赞共现」不等于「某词导致爆款」。一律走：相关性 → 假设 → 对照 → 验证，而不是 共现 → 因果。
5. **禁止把任务简化为「找几个爆款然后仿写」**。

## 二、研究库结构（参考，非生产要求）

8 个逻辑库：Case Library 原始案例／Feature Library 特征／Pattern Library 爆款规律／Pain Library 痛点／Topic Library 选题机会／Hook Library／Anti-Pattern 反模式／Feedback Library 真实表现反馈。
（仓库内的实际落点：语料在 `knowledge/cases.jsonl`，规律与反模式的现行表述在 `knowledge/爆款整片解剖.md` 与 `knowledge/洞察库.md`。）

## 三、案例字段标准（与 `knowledge/cases.jsonl` 实际字段一致）

`case_id / title / author / likes / comments / publish_time / tags / description / script / domain / content_form / target_audience / core_problem / core_promise / hook_type / emotion / conflict / structure / retention_devices / proof_devices / cta_type / golden_lines / strengths / weaknesses / copy_mechanisms / originality_risk`

> 不得凭空补写不存在的业务事实；无法判断的字段填 `unknown`。

## 四、观察维度（做特征比较时用）

- **表层**：字数／句数／平均句长／问句数／感叹句数／数字数量／比较词／否定词／第二人称比例／CTA 密度／专业术语密度／口语化程度。
- **语义**：目标人群／需求／痛点／欲望／风险／结果承诺／认知冲突／反常识／信息差／社会证明／案例证明。
- **结构**：Hook／Problem／Agitation／Story／Proof／Reveal／Solution／Summary／CTA（记录每段起止位置）。
- **心理**：好奇／损失厌恶／利益驱动／身份认同／不公平感／焦虑／希望／爽感／猎奇／争议／被理解感。

## 五、表现分层与对照

- **Tier A 高表现**：同赛道 Top 10% 或更高层级——用来找"可能有效"的候选。
- **Tier B 中表现**：识别稳定、可复用的结构。
- **Tier C 低表现**：重点找反模式与失败原因。
- **对照原则**：同一模式要在"用它的高表现案例"与"用它的普通案例"之间比较，找真正有区分度的特征；**禁止因为某模式在所有文案里都出现，就判定它有效**。

## 六、反模式（失败模式库）

重点：AI 腔／空洞鸡汤／只有结论没有证据／标题与正文不兑现／过度悬念／低价值重复／强行评论区 CTA／机械「点赞收藏」／伪造结果／过度焦虑营销／直接复刻单一爆款／为了刺激而制造无事实依据的冲突。
每条记录：症状 → 为什么会失效 → 常见表现 → 如何修复。

## 七、反馈闭环（与我们自己的后验数据接通）

真实数据回流时，对照**研究阶段的假设**回答：哪些 Hook 常被高估／低估？哪类选题点赞高但完播低？哪些内容收藏高但评论低？——结论回流 `knowledge/爆款整片解剖.md` 的生命周期修订（通则实测不灵就地修订）；读数本身以 `outputs/发布后验台账.json` 为准，本文件不复制读数、不新建台账。

## 八、原创与防抄袭

- **可以学习**：结构／心理机制／信息组织／选题角度／表达策略。
- **不应直接复制**：大段原句／独特故事细节／独特数字／独特案例叙述／连续句式序列／标志性表达。
- 输出前执行：相似表达检查 → 与参考案例对照 → 替换独特表述 → 保留抽象机制。
- **红线（与 `spec/redlines.json` 同源）**：语料原话含平台违禁表达（诱导互动、储值预付、编造店名案例等），仅作机制示意，**禁止照搬上屏**。

## 九、985 篇语料的使用方式

这批语料是"第一代经验库"，不要永远视为真理。建议路径：Raw Cases → Feature Cases → Candidate Patterns → Validated Patterns。
初步统计已显示：文案表现存在明显长尾；CTA 并非天然正相关（不能机械认为"多 CTA = 爆"）；文案长度与点赞之间没有简单线性关系；数据集中在餐饮／实体店／创业／同城获客场景，跨行业规律需谨慎外推。这些只是初步数据诊断，不能代替完整的语义分析与真实视频指标。

## 十、最终原则

永远优化这条链：**让更多正确的人点开 → 让他们愿意继续看 → 让他们得到超出预期的信息 → 让他们产生情绪或认知变化 → 让他们愿意表达／保存／转发 → 用真实数据验证 → 把结果重新喂给系统。**

爆款不是句式，而是一个可迭代的内容系统。
