# 爆款文案资源 · AI 研究入口

> **当前定位**：传播研究资源，不是视频生产流程 Owner。行业线（行业场景视频）唯一作业流程仍是 `SKILL.md`（教程线见其方法 Owner：`docs/internal/产品功能教程作业规范.md`）。
>
> `knowledge/cases.jsonl` 保留为检索源，用于研究与当前选题/经营问题相近的内容：别人为什么能让人点开、继续看、理解方法，以及哪些表达方式可能失效。不得把单篇爆款当模板，不得搬运话术、数字、案例或产品能力。
>
> `knowledge/爆款整片解剖.md`：整片叙事与表达方法研究。
>
> `knowledge/洞察库.md`：内容中的“讲道理”弹药库；进入生产时仍由 `SKILL.md` 决定是否调用。
>
> `knowledge/爆款文案技能包/SKILL.md`：历史 Agent/RAG 知识工程文档。其旧的评分器创作闸门、拆零件 RAG 生产方法已经废止；不要把它当当前视频生产流程。当前生产规则只认 `SKILL.md`。

## 正确调用方式

1. 先在 `SKILL.md` 当前步骤中明确“这一条到底教什么”。
2. 再按行业/经营问题检索 `knowledge/cases.jsonl` 的 3–5 个相近案例（检索不到时明确记录“语料稀疏”，不得硬凑）。
3. 只研究 Hook、结构、信息增量、教学节奏、证明方式、反模式等传播规律。
4. 把研究结果回填到当前内容输入包/研究 trace，并由 `SKILL.md` 继续推进。
5. 产品功能、字段、数字、限制、截图对应关系一律回 `spec/` / APPLET / Product Truth 验证。

## 明确禁止

- 不把爆款案例当产品真值源。
- 不因看到一个爆款就先决定本片玩法。
- 不直接改写单篇爆款的句子、结构细节或数字。
- 不用旧版评分器把“分数”当终稿创作闸门。
- 不在本资源入口重新定义视频生产流程。
