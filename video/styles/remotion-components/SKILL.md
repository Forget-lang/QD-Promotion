# 风格包 · remotion-components（信息卡·组件驱动）

> **本文件是风格包（styleId=remotion-components），不是行业线作业流程；作业流程唯一 Owner 是仓库根 `SKILL.md`。**
> 本包只定义"**用什么视觉语言表达**"。**不含**：故事结构、信息释放顺序、悬念/转折设计、观看路径、情绪曲线、镜头决策意图——这些属导演层（`docs/internal/R9-视觉导演与审美决策.md` ＋ 逐片《导演稿》）。
> 验收判据：**换包不换导演稿**——同一份《导演稿》换用本包或其它风格包都应能落地；若本包要求改写叙事顺序／信息释放／观看路径，即本包越界。

## ① 身份

- **styleId**：`remotion-components`｜**名称**：信息卡·组件驱动（Remotion 实现）
- **来源**：**旧链归位**（2026-09-23 用户裁定）——即 g06–g11 使用的既有行业线风格，**唯一有正式片战绩**的风格。登记后与 `whiteboard` 并存，**并存是合法的**（这正是风格架构的目的：消除"两个默认入口"）。
- **适合**：功能密集的字段精讲、机制对比、多列对照、流程关系、需要高信息密度与产品界面证据的段落。
- **不适合**：需要实景、人物、情绪叙事与"过程感"的段落（那是其它风格的场域）。
- **状态**：`active`

## ② 表达能力（**不是叙事法**）

- **用什么表达**：信息卡／大数字／大字／手机 Mockup／券面／图标／连线／密度／光影／粒子／空间层次。
- **能表达**：字段与数值、阈值与条件、机制对比、多列对照、前后差异、状态变化。
- **明确不承担**（属导演层，写进本包即越界）：故事结构、信息释放顺序、观看路径、情绪曲线；也不决定"这里必须出现什么内容"。

## ③A 母题设计法（自 `SKILL.md` 第 2 步迁入 · 2026-09-23 批 5b 第一波）

> 迁入说明：原文逐字搬移，未改写。`SKILL.md` 原位置已改为指针。**跨风格协议（AI 创作边界协议）不在本栏**——它留在 `SKILL.md` 第 2 步（跨风格单源）。

- **开工视觉语言隔离声明（2026-09-08 用户拍板，把防换皮从「事后拦截」前移到「事前隔离」）**：做母题前先跑 `node scripts/list-assets.mjs` 看已产出片的风格序列（palette / motion / transition / hookStyle / 屏幕序列），再声明本片三件事——本片行业母题 + 背景风格族 + 转场字幕风格——并逐条写出与上一条片（最新一条 g0X）≥3 处**非颜色**的结构差异。先锁这份声明再动笔找载体；它和下文「换语言五轴证据门」一前一后：声明是动手前锁方向，五轴门是标杆渲出后拿真图对证据。

- **视觉定位卡（情绪先行，2026-09-14 用户拍板，先于物理载体）**：定载体前先答一张卡——**核心痛点一句话 / 情绪关键词 ≤5（如 热·真实·烟火气·克制）/ 视觉关键词（如 夜宵电影感·深色·暖橙·浅景深·少UI）/ 禁止出现（如 SaaS PPT·蓝紫科技风·全屏毛玻璃·密集icon）**。判据 = 母题一页须含这四栏；「禁止出现」任一项命中画面 = 拒收。作用：把"高级感/舒服"这类模糊要求变成动手前就定死的情绪与禁令——AI 不再边画边猜气质，也不再默认滑回信息卡。

先回答一个问题：**这个行业的信息，最自然的物理载体是什么？** 由它长出母题，再由母题决定每屏怎么排、元素怎么动。

- **背景底必选（硬判据，2026-09-04 用户拍板）**：每条视频必须从 `背景素材/` 资源库选一张背景图打底，写进 `data/gXX.ts` 的 `style.bgImage`（指向 `video/public/` 下真实存在的图片）；**不得用手写程序化纯色/渐变 Ambient 顶替整张底**（母题装饰层可叠在背景图之上，但不能当底）。缺 `bgImage` = `check-bg` 闸门硬失败。库里没有合适色系时走 `SKILL.md` §五：AI 出规格与检索词、用户找图回传、三关验收入库——不是 AI 直接生成。

- **素材最小化 + 程序化质感（2026-09-14 用户拍板，实景素材匮乏时的默认纪律）**：实景素材（夜市/门店/场景照）只承担**环境底色 + 情绪氛围**——重度虚化、比重压到最低、每片 1 张底起步；真正的"高级信息密度"靠**程序化五刀**撑——①空间层次（前/中/后景）②光影（明确主光源）③摄影机运动（push/pull / 视差 / 手持感）④氛围层（粒子·烟雾·光斑·明暗呼吸）⑤真实UI重量（环境光·阴影·轻微透视）。**同一张底用 crop/scale/pan/depth/light 多重构图撑满全片各屏（g11 S1 近炭火→S6 回投，先例在案），不许每屏讨新素材**。判据 = 缺实景素材时**禁止退回"一张卡片堆字段"凑密度**（那正是"像 PPT"的真根因）；背景上残余实景成分需重度虚化退居氛围（不直给清晰实景当内容——属产品证据位仍守《AI 创作边界协议》L1：真实页面复刻 / 真实截图 / 真实录屏）。**本行只定素材策略；纯 Remotion 片"能画什么 / 不能画什么"的资产白名单与设计禁令，落在第 4.5 步（视觉转换）——不在两处重复写。**

## ③B 画面骨架与硬约束（自 `SKILL.md` 第 4.5 步迁入 · 2026-09-23 批 5b 第二波）

> 迁入说明：原文逐字搬移。Shot 表字段仍属导演层（R9），不在本栏。

- **三层视觉结构（任一片通用的画面骨架，2026-09-15 拍板）**：
  - **Layer 1 · Atmosphere 氛围层**：炭火 / 深底 / 烟雾 / 火星 / 光晕 / 颗粒 / 暗角——**永远动、但很慢**，只做情绪（slow zoom / pan / parallax / embers / glow breathing），**动态不得影响文字阅读**。
  - **Layer 2 · Typography 排版层**：超大数字 / 超大关键词 / 细线 / 小标签 / 强弱层级 / 大留白——没有实拍后**最重要的画面力量**。
  - **Layer 3 · Product 产品层**：手机 / 券 / QR / 核销 / 设置 / 转赠 / 奖励——**产品永远是"证据"，不是整个画面的背景**。
  - 一句记法：**少"卡片/图标/流程框"、多"空间/排版/运动关系"**。三层实现配方（KenBurns 缓推、blur→focus、scale punch、inertia、particle attraction、line tracing 怎么搭）见 R3 §7.x——本步只讲"该画什么"，"怎么搭"回 R3。
- **纯 Remotion 片硬约束清单（2026-09-15 拍板，堵"没素材→拿矩形假装→PPT"）**：
  - **禁用依赖**（不生成、不假设这些素材）：烧烤店街景、排队人群、老板/顾客人物、餐厅照片、烤串实拍、夜市场景照。**需要真实照片才能成立的画面，一律改成 文字/数字/UI/图形/动态关系 完成——禁止拿廉价占位图顶替。**
  - **可用资产（画面只能从这 12 类出）**：① 炭火背景（一张底起，程序化质感撑全片）② 手机 Mockup ③ 电子券 UI ④ 兑换券 UI ⑤ QR Code ⑥ 文本 ⑦ 数字 ⑧ 线条 ⑨ 几何图形 ⑩ 火星粒子 ⑪ 烟雾/Glow ⑫ 简单 SVG/CSS 图形。
  - **设计禁令**：不画成 PPT；不用默认毛玻璃卡当主视觉结构；不堆 icon；不做左右两栏信息对比；不做传统五节点流程图；不让整屏长期挂多张卡片；不大量用 translateY+opacity 入场；不让每个元素都动。
  - **一镜一主语**：**每个镜头只能有一个视觉主语**；优先级 = 手机/券 > 大数字 > 核心关键词 > 状态变化 > 装饰。
  - **语义动效**：所有运动必须有语义（核销→券消失；奖励→新券生成；转赠→券横移到另一台手机；朋友核销→奖励光回流；到期→数字递减）——**不做无语义的装饰动画**。
  - **排版**：优先超大数字/超大关键词/大留白；重要信息不全塞卡片；信息出现后及时退出保画面干净。
  - **色彩基准（纯片默认，行业专属以第 2 步母题为准）**：深底 #120B08/#24130C/#42180D，强调 #F06A24/#FF8B38/#FFC05A，字 #F7F1EA/#C6BDB5；**避免蓝/紫/荧光绿**。
- **产出《视觉导演稿》——Shot 表（逐镜头一行，替代旧"主视觉/装饰元素/字幕/画面节奏"的模糊写法）**：

  | 字段 | 含义 |
  |---|---|
  | Shot | 镜头编号（S1-01 式） |
  | Duration | 时长（秒） |
  | VO | 口播（对应第 3 步哪句） |

## 三、工程约定

- **一行业一套专属屏**：`video/src/videos/gXX/`（屏组件 + 本片零件 + payload 类型）。屏组件**不得跨行业 import**；共享层已冻结——只含原子件与 `VTemplate`。旧共享层已废止：12 个共享场景 + "不写 ui 按 type 回退"旁路 → **ui 必填，缺了直接抛错**；9 个"统一外观"业务组件（CouponCard/PhoneMockup/StepFlow/CompareCard/StatCounter / StatCard/IconBadge/SectionTitle/HighLightText）→ 禁止预建/复用外观件，每片照锚稿手写。**共享件现行消费者状态**以 `node scripts/list-assets.mjs` + grep 实时为准（文档宪法铁律三，本文不复述快照；提醒一句：**零引用 ≠ 已删除**，能调用没人用的原子件仍在）。规则恒定：共享层只有原子件与 `VTemplate`，**没有任何现成的券面/手机壳/步骤条外观**——要上屏照锚稿手写，别以为 import 一下就有。
- 数据文件每屏写 `ui: 'gXX-名字'`，业务数据进 `payload`（形状由本片 `videos/gXX/types.ts` 定义，通用 `Scene` 只留分发/时长/字幕/语音偏移字段）；在 `scenes/index.tsx` 的 `VIDEO_RENDERERS[视频id]` 注册；`ui` 名拼错运行即抛错，不会静默回退旧组件；数据文件的**导出名必须与视频 id 一致**（check-similarity 防伪按该名找 `videos/<key>/index.tsx`）。
- 结构指纹 = `type + ui`，由 `check-similarity` 比对。**⚠️ 这道机检只防「把上一片的 ui 名照抄」**：ui 按约定必须带 `gXX-` 前缀，所以换掉前缀重做一副一模一样的骨架，指纹永远不碰撞（2026-08-30 负向测试证实）。**结构雷同的真判据是「一屏标杆」——你逐张看真图**，别拿这道绿当"结构没重复"。确需复用旧结构 → 在 `ref-registry.json` 的 `similarityExemptions` 登记理由与批准人。
- **布局指纹 = `layoutKind`（粗粒度，2026-09-07 加）**：每屏数据带 `layoutKind`（呈现架构类别，如 `card-list`/`form`/`two-column`/`flow`/`hero-object`/`compare-list`/`cta-statement`），由 `check-layout-diversity` 拦"新片与上一条**同 type 屏用了同 layoutKind**"——补 `type+ui` 拦不住的"换皮同构"。命中要么真换架构，要么在 `ref-registry.json` 的 `layoutWaivers` 登记非空 `structuralDiff` 证据（= 换语言五轴证据门的闸门工件）。它仍是人判的兜底、不替代一屏标杆，但让"悄悄复用上一条画面"从纯靠自觉升级成会撞红灯。
- `dur = ceil01(口播字数÷6) + extraHold`（÷6 取自语速上限口径，**属主见 `SKILL.md` 第 3 步，此处不复述**）；**绝对起始帧 = Σ前各屏帧数 − 12×前屏数**（`TransitionSeries` 每屏重叠 12 帧），峰值帧 = 起始帧 + floor(本屏帧数×0.3)。
- 字数口径：剔除空白与标点后逐屏机器计数（别手估，同一稿会数出两个结果）。
- 卡片宽度按 `border-box` 理解（Remotion 注入全局 CSS）；安全区达标与否**量渲染像素**，不靠读 CSS 推断。
- 交付落 `outputs/gXX-行业/`：内容输入包、分镜稿、逐屏关键帧、成片、封面、三份发布稿；过程文件进 `outputs/archive/`。
