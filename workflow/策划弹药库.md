## 1. 玩法库 P-01~P-13（核心资产，完整收录）

每个玩法 = 一个完整的经营方案 = 1 个核心思路 + 2-3 个功能组合 + 具体操作步骤 + 为什么有用。

**使用原则**：先选业态 → 从 §1.15 矩阵里挑 1 个主打玩法 + 1 个辅助玩法 → 产出内容。每个业态至少做 2 条视频（主打玩法一条 + 辅助玩法一条），避免同质化。

### 1.2 P-01 · 疗程后送卡锁客

**核心思路**：顾客不是讨厌卡，是讨厌被推销。把卡从"商品"变成"福利"，送出去的卡顾客没有负担，自然愿意来。

**适用业态**：美容院（疗程后送养护卡）、头疗馆（头疗后送养护卡）、养生馆（调理后送保养卡）

**功能组合**：
- 次卡（TIMES 按次核销型）—— 核心载体
- 核销间隔 —— 锁节奏的关键（设 3 天 = 每三天来一次）
- 转赠 —— 用不完送朋友 = 老带新

**操作步骤**：
1. 做完项目后，把"送卡"当福利话术说出口（"今天护理做得不错，送您一张养护卡"）
2. 用次卡功能做一张六次养护卡（TIMES 按次核销）
3. 核销间隔设为三天 → 顾客每三天来一次
4. 私密发放，一对一发到顾客手机（次卡不支持公开领取）
5. 顾客用不完可转赠闺蜜 → 闺蜜到店 = 新客

**视频内容结构（视频 8-10 屏，时长按内容深度自然落位，推荐 100-150s，硬上限 200s）**：
1. 钩子：美容院还在推销办卡？很多顾客一听"办卡"就警惕
2. 痛点深挖：推卡顾客跑、不推没收入；顾客不是讨厌卡，是讨厌被推销
3. 反转思路：别卖卡了，送
4. 具体怎么做：做完项目送一张六次养护卡，一对一发
5. 为什么有用：核销间隔三天 → 到店成节奏 → 卡不睡死
6. 进阶玩法：卡用不完转赠闺蜜 → 闺蜜到店 = 新客
7. 真实感细节：店员怎么说、顾客怎么领、怎么核销
8. CTA：品牌署名

**差异化要点**：
- 切入点是"反推销"情绪共鸣，不是"次卡功能介绍"
- 核心是"送"这个动作带来的心理变化，不是"卡"本身
- 每个业态的话术不一样（美容说"养护"、头疗说"保养"、养生说"调理"）

### 1.3 P-02 · 闺蜜同行裂变

**核心思路**：美业/服务业的顾客有强社交属性，闺蜜之间互相推荐是常态。设计一张"两人用"的券，让老客顺手带朋友来。

**适用业态**：美甲美睫（闺蜜一起做指甲）、美容（闺蜜护肤局）、养生（双人按摩）

**功能组合**：
- 券包 —— 内含 2 份相同项目
- 转赠 + 分享 —— 老客转给闺蜜
- 核销奖励（可选） —— 核销后再送一张，裂变循环

**操作步骤**：
1. 用券包功能做一张"双人券包"，内含 2 份相同项目
2. 老客领取后，通过转赠/分享把其中一份发给闺蜜
3. （可选）开启核销奖励：闺蜜核销后再送一张单次券，裂变循环

**视频内容结构**：
1. 钩子：做美甲还在单打独斗？叫上闺蜜呀
2. 痛点：一个人做指甲太无聊、想叫朋友又怕人家嫌贵
3. 思路：闺蜜同行卡，两人一起更划算
4. 具体怎么做：做一张双人券包，老客领了转一份给闺蜜
5. 为什么有用：降低社交门槛 + 老客带新客质量高
6. 进阶：核销后每人再得一张单次券，下次还来
7. CTA

### 1.4 P-03 · 闲时填空档

**核心思路**：门店有高峰有空档，空档期的座位/人工都是成本。用闲时特惠把空位填上，赚一笔是一笔。

**适用业态**：茶饮咖啡（上午空档）、美发（工作日空档）、棋牌室（白天空档）

**功能组合**：
- 折扣券 —— 闲时打折
- 时段设置（可用时段） —— 只在闲时生效

**操作步骤**：
1. 找出门店空档时段（如咖啡店上午 10 点前、棋牌室白天）
2. 做一张折扣券，在"可用时段"里限定只在空档时段生效
3. 发放给周边顾客，让顾客知道"这个时段来更便宜"

**视频内容结构**：
1. 钩子：上午空着也是空着？其实都是钱
2. 痛点：座位空着、员工闲着，全是成本
3. 思路：闲时特惠，把空位变成钱
4. 具体怎么做：发一张仅限上午使用的折扣券
5. 为什么有用：闲时拉客流 + 不影响正价生意
6. 进阶：搭配核销奖励，闲时来了下次高峰还来
7. CTA

### 1.5 P-04 · 储值替代方案

**核心思路**：储值卡是传统锁客手段，但顾客越来越抵触（怕跑路、怕被套路、怕被套住）。用次卡替代储值——效果一样（锁住多次消费），但顾客心理负担小很多。

**适用业态**：美业、健身、洗车、干洗等传统靠储值锁客的行业

**功能组合**：
- 次卡（通卡/次卡/权益卡三类型按业态选） —— 替代储值的载体
- 私密发放 —— 一对一发，有专属感
- 到期提醒 —— 卡不作废、不浪费

**操作步骤**：
1. 按业态选次卡类型：通卡（健身/景区）、次卡（洗车/美甲/理发）、权益卡（美业/VIP）
2. 设次数和有效期
3. 私密发放，一对一发给老客
4. 开启到期提醒，卡不作废、不浪费

**视频内容结构**：
1. 钩子：还在让顾客充卡？小心越充客越少
2. 痛点：储值卡顾客心理负担重，怕套路、怕跑路
3. 思路：用次卡替代储值，一样锁客，顾客没压力
4. 具体怎么做：选次卡类型 → 设次数和有效期 → 一对一发给老客
5. 为什么有用：次卡=预付服务，不是预付钱，心理门槛低
6. 进阶：搭配权益卡，给老客尊贵感
7. CTA

### 1.6 P-05 · 老带新转赠奖励（通用玩法）

**核心思路**：老客转赠一张券给朋友，朋友核销后，老客得到一张答谢券。有来有回，老带新自然发生。

**适用业态**：全业态通用，作为任意主玩法的辅助加成

**功能组合**：
- 转赠奖励 —— 核心机制
- 优惠券（折扣/代金/兑换） —— 作为奖励券

**操作步骤**：
1. 配置转赠奖励：老客把券转赠给朋友
2. 朋友核销后，系统自动给老客发一张答谢券（优惠券）
3. 答谢券可继续转赠或自用，形成循环

**视频内容结构**（通常不作为单独视频，而是嵌入其他玩法）：
- 在主玩法视频中作为"进阶玩法"出现（1 屏）
- 小红书图文可以单独做一篇"老带新怎么玩"

### 1.7 P-06 · 新客首单体验（通用玩法）

**核心思路**：用一张低门槛体验券，让新客第一次进店变得容易。到店后再用主玩法（次卡/送卡）承接。

**适用业态**：全业态通用，作为引流层标配

**功能组合**：
- 兑换券（体验项目） —— 低门槛引流
- 公开领取 —— 门口/镜台放码，自然客流扫

**操作步骤**：
1. 做一张低门槛兑换券（如"免费领一杯柠檬水""首次体验优惠"）
2. 选择公开领取，把码放在门口/镜台等自然客流位置
3. 新客到店后，用主玩法（次卡/送卡）承接转化

**视频内容结构**（通常不单独做视频，作为攻略文章/图文的一部分）：
- 搭配主玩法出现："先用体验券引流进店，到店后送次卡承接"

### 1.8 P-07 · 满减提客单价（通用玩法）

**核心思路**：满减刺激顾客多买一点，单笔消费直接上去。

**适用业态**：茶饮、餐饮、零售等有明确客单价的行业

**功能组合**：
- 满减券 —— 核心工具

**操作步骤**：
1. 按客单价设定满减门槛（如"满 100 减 20"）
2. 公开领取或定向发放
3. 收银台/海报同步提示满减信息，引导顾客凑单

**视频内容结构**（通常作为辅助内容）：
- 在主玩法视频中作为"补充玩法"简短提及
- 可单独做图文笔记

> **P-08~P-13 来源说明**：借鉴官网玩法逻辑补充的扩展玩法，功能机制均以 `spec/facts.json`（applet 代码快照）为准；凡 facts 没写或存疑的口径，先回 `../applet/` 代码核实再写进内容。

### 1.9 P-08 · 结账送券促复购

**核心思路**：顾客结完账就走，容易变成一次性客户。结账时私密送一张"下次能用"的券，给顾客一个再来的具体理由——比口头说"下次再来"实在。

**适用业态**：餐饮、火锅、零售、茶饮等有明确结账动作的行业

**功能组合**：
- 私密发放（代金/满减券）—— 一对一发到顾客手机，有专属感
- 有效期设"领取次日起 N 天"—— 当天用不了，隔几天正好回来（参数见 `spec/facts.json` constraints）
- 到期提醒 —— 快到期自动提醒顾客，减少过期浪费

**操作步骤**：
1. 做一张"下次到店可用"的代金券或满减券，有效期设领取次日起生效
2. 开启到期提醒
3. 结账时店员一句话送出（如"今天消费送您一张下次用的券"），私密发放给顾客
4. 顾客到期前收到提醒 → 带着券回来二次消费

**视频内容结构**：
1. 钩子：顾客结完账就再也没来过？
2. 痛点深挖：一次性客多、回头率上不去；口头说"下次再来"等于没说
3. 反转思路：别让顾客"想着来"，给他一张"有理由来"的券
4. 具体怎么做：结账时私密送券，隔几天生效、到期前自动提醒
5. 为什么有用：具体理由 + 到期提醒，把"想起来"变成"被提醒"
6. 进阶：券开转赠，顾客带朋友来又是新客
7. CTA

**差异化要点**：切入点是"结账时刻"这个具体场景，不是泛泛讲复购；话术重点在"店员怎么说出口"。

### 1.10 P-09 · 沉睡老客唤醒

**核心思路**：老客久未到店往往不是流失了，是忘了你。与其花大钱拉新，不如低成本把睡着的熟客喊醒——名单就在你自己的核销记录里。

**适用业态**：美业、健身、亲子、餐饮等靠老客复购的行业

**功能组合**：
- 核销记录/领取记录筛选 —— 找出 N 天没来的人（筛选维度见 `spec/facts.json` features.verify/stats）
- 私密发放限时代金券或小额券包 —— "专属回归福利"的仪式感
- 到期提醒 —— 配合限时，给顾客一个"再不用就没了"的行动理由

**操作步骤**：
1. 在核销/领取记录里按时间筛，找出超过 N 天没核销的老客
2. 做一张限时代金券或小额券包（面额克制，唤醒为主不打底价）
3. 私密一对一发给这批人，话术点明"专属回馈"
4. 到期提醒兜底，没来的再触达一轮

**视频内容结构**：
1. 钩子：你店里睡着多少老客，你数过吗？
2. 痛点深挖：老客不来的原因往往是忘了 + 没理由，不是不满意
3. 反转思路：拉新贵，唤醒便宜——名单后台就有
4. 具体怎么做：筛记录 → 做限时券 → 私密发 → 到期提醒
5. 为什么有用：老客有信任基础，一张小券就能撬动，成本远低于拉新
6. 进阶：回来的老客顺势推 P-01 送卡锁客，唤醒接锁客
7. CTA

### 1.11 P-10 · 会员日专属券

**核心思路**：平日没理由联系老客，硬发广告招人烦。固定一个"会员日"，让发券变成有节奏的固定福利——老客养成"那天去看看"的习惯，商家也省得天天想联系的理由。

**适用业态**：零售、美业、餐饮、健身等有老客池、想养回访节奏的商家

**功能组合**：
- 满减券或小型券包（多种券组合）—— 会员日专属福利
- 私密发放 / 客户群发 —— 定向发给老客（群发范围与确认机制见 `spec/facts.json` features.wecom）
- 限领规则 —— 控成本（参数见 facts constraints）

**操作步骤**：
1. 固定档期（如每周三）定为"会员日"，坚持成节奏
2. 提前做好专属满减券或小券包，设限领
3. 会员日当天私密发放给老客；用客户群发批量触达时注意：群发任务需员工在群发助手中确认后才发出，且当前从优惠券发起（机制见 facts）
4. 到店核销时顺势升单，"会员日专属"提升身份感

**视频内容结构**：
1. 钩子：为什么有的店每周都有一天生意特别好？
2. 痛点：平时联系老客显得像骚扰；不打扰又容易被忘掉
3. 思路：把发券变成固定档期的"会员日"，福利有节奏
4. 具体怎么做：定档期 → 备好专属券 → 定向发给老客
5. 为什么有用：固定节奏养成回访习惯，专属感让老客觉得被区别对待
6. 进阶：大客户单独发小型券包，不走大群硬广
7. CTA

**差异化要点**：讲"节奏感"和"档期运营"，不是讲某个券功能；把群发机制（需确认、有范围）讲清楚反而显专业。

### 1.12 P-11 · 券包自选降门槛（新客引流）

**核心思路**：不少新客不进店不是不想占便宜，是怕被绑定。把几种券打进一个券包、让新客**自选一种**——选择权给顾客，成本你可控，体验是"有得挑"而不是"被塞券"。

**适用业态**：全业态新客引流（尤其多品类：餐饮+饮品、洗护+护理、零售多品类）

**功能组合**：
- 券包（自选一种领取）—— 引流兑换 + 满减 + 折扣 打包（打包规则见 `spec/facts.json` constraints 券包）
- 领取规则/限领 —— 控新客成本

**操作步骤**：
1. 选 3 种左右互补的券：一款引流兑换（低门槛钩子）+ 一款满减 + 一款折扣
2. 打包成券包，领取方式设"自选一种"
3. 走公开渠道，新客扫码即领、一人一种
4. 新客到店核销后，用主玩法（送卡/会员日）承接

**视频内容结构**：
1. 钩子：新客宁可不要优惠，也不想被"绑"进店？
2. 痛点：单张体验券千篇一律；一口气塞几张券，顾客反而不领
3. 思路：让新客自己挑——自选一种，门槛更低
4. 具体怎么做：三种券打包 → 自选一种 → 公开扫码领
5. 为什么有用：选择权降低决策压力；你只承担"一种"的成本，数据按券种统计照样清楚
6. 进阶：开核销奖励，新客核销后再得一张，回头有理由
7. CTA

### 1.13 P-12 · 一券多店连锁

**核心思路**：多门店最大的痛是"各家发各的、口径乱、对账难"。一张券配好多家适用门店——总部定规则，分店只执行，谁发的、哪家核的，系统分开记。

**适用业态**：连锁品牌、多门店、加盟体系（门店数量额度见 `spec/facts.json`）

**功能组合**：
- 适用门店 —— 一张券勾选多家店，名单外无法核销（机制见 facts features.create_manage/merchant）
- 发券员工 —— 指定谁能发，分店不越权
- 门店/员工发券核销统计排行 —— 分店对账、绩效有据（统计维度见 facts features.stats）

**操作步骤**：
1. 总部制券，勾选参与活动的适用门店
2. 指定发券员工，店长/店员按权限操作
3. 顾客领券后在名单内任一门店核销；核销时选定当前门店、可填备注，记录自动归属该店该员工
4. 后台按门店/员工分开查发放与核销数据，对账复盘

**视频内容结构**：
1. 钩子：三家分店三套优惠，月底对账对到头疼？
2. 痛点深挖：总部统一不了口径；顾客不知道券能在哪家用；发没发、核没核说不清
3. 思路：总部做一次券，多店通用、规则统一
4. 具体怎么做：勾适用门店 → 指定发券员工 → 核销自动归属门店
5. 为什么有用：口径一致不扯皮，分店员工数据分开查，对账有依据
6. 进阶：员工发券排行，连锁内部也能搞激励
7. CTA

**差异化要点**：打"连锁/多店"客群（客群优先级 3），讲管控与对账，不讲单店引流话术。

### 1.14 P-13 · 异业互导

**核心思路**：隔壁店的顾客就是你最精准的新客。把周边互补业态的店员邀请成你的"发券员工"，让TA把你的体验券当福利发给自己的顾客——新客拿着券到你店核销，发了多少张后台按员工分得清清楚楚，对账不扯皮。

**适用业态**：周边互补业态组合（洗车×美容健身、火锅×奶茶、母婴×儿童摄影、理发×美甲、足浴×茶馆……）

**功能组合**：
- 员工邀请 + 发券员工 —— 合作店店员成为本商家发券员工（机制见 `spec/facts.json` features.merchant_ops）
- 体验兑换券/体验次卡 + 私密发放 —— 对方店员一对一发给自己的顾客
- 员工发券/核销统计 —— 每位合作店员发了多少、带来多少核销，分开可查

**操作步骤**：
1. 谈好互补商家：你出券（体验兑换券或体验次卡），对方出流量
2. 邀请对方店员为本商家员工，授予发券权限
3. 对方店员在自家顾客结账后，私密发你的体验券
4. 顾客拿券到你店核销，成为你的新客；发放/核销数据按员工统计，按约定对账

**⚠️ 口径提醒**：合作店只是**代发你的券**，核销仍在你自己的适用门店——对外别说成"两家店通用一张券"；也别承诺对方店的经营效果（`spec/redlines.json` `rules.false_claims`）。

**视频内容结构**：
1. 钩子：隔壁洗车店的顾客，凭什么不能变成你的新客？
2. 痛点：拉新贵、地推累，精准客流就在旁边店手里
3. 思路：让合作店店员帮你发体验券，客流互导
4. 具体怎么做：谈互补店 → 对方店员加成发券员工 → 私密发体验券
5. 为什么有用：客群互补不竞争；发了多少、来了多少按员工统计，对账清楚
6. 进阶：多家联盟把体验券打包成券包，一次谈妥多家
7. CTA

## 2. 11 大卖点 + 4 形态营销差异

### 2.1 4 种产品形态的营销差异

做内容时选对形态，事半功倍。本小节帮你在策划时判断"这期用券、用包、用卡还是做海报"。

#### 2.1.1 优惠券（6 种类型）—— 引流拉新主力

| 类型 | 营销调性 | 适用场景 | 视频切入点建议 |
|---|---|---|---|
| 代金券 | 直接、简单、好理解 | 新店开业、节日促销 | "30 块钱代金券，扫码就领" |
| 套餐券 | 性价比感强，有原价对比 | 餐饮、美容等套餐类 | "原价 198，券后只要 98" |
| 满减券 | 提升客单价 | 零售、餐饮 | "满 100 减 20，多买多省" |
| 折扣券 | 直观，打几折一目了然 | 品类促销、清库存 | "全场 8 折，扫码领券" |
| 兑换券 | 赠品感、零元购心理 | 关注礼、到店礼 | "免费领一杯柠檬水" |
| 随机金额券 | 趣味性、赌徒心理 | 活动裂变、朋友圈传播 | "手气券，试试你能领多少" |

#### 2.1.2 券包（3 种领取方式）—— 提升单客价值

| 领取方式 | 营销调性 | 适用场景 |
|---|---|---|
| 一键全部领取 | 实惠、大礼包感 | 节日礼包、新店福袋 |
| 随机领取一种 | 盲盒、抽奖、刺激感 | 周年庆、互动活动 |
| 自选一种 | 尊重用户选择、精准 | 会员权益、多品类商家 |

**核心卖点**：一张券的钱，体验多种产品 → 带动多品类消费。

#### 2.1.3 次卡（3 种类型）—— 锁客复购神器

| 类型 | 核心价值 | 适用行业 | 营销金句方向 |
|---|---|---|---|
| 通卡 | 不限次，超值感 | 健身、景区、游乐场 | "一天不到一块钱，随便来" |
| 次卡 | 按次扣，看得见用得完 | 洗车、美甲、理发 | "10 次卡，平均每次省 20" |
| 权益卡 | 多项权益，尊贵感 | 美业、VIP、高端服务 | "一张卡享受 10 项专属权益" |

**核心卖点**：预付锁客 → 顾客 N 次必到店 → 每次到店都是追加销售机会。

#### 2.1.4 活动海报 —— 聚合展示，活动化包装

- 把多张券打包成一个"活动"，仪式感更强
- 海报图片可直接发朋友圈、印传单
- 商家主页展示，增加曝光入口

**适用场景**：节日大促、店庆、换季活动、会员日。

### 2.2 11 大特色卖点（内容生产弹药库）

每个卖点都附：**一句话价值主张** + **适用行业** + **内容方向建议**。策划时从里面选 1-2 个支撑当前玩法；所有卖点的底层事实均来自 `spec/facts.json`，写具体文案时务必回查确认数字、术语和边界。

**卖点选用规则**：主卖点绑在玩法上（如 P-01 送卡 → 卖点 8 私密发放），辅卖点放进阶（如 P-01 转赠闺蜜 → 卖点 4/10 转赠）；卖点必须嵌进场景里讲，禁止在视频里逐个罗列卖点。

#### 卖点 1：8 种发券渠道，线上线下全覆盖

**一句话**：想怎么发就怎么发，顾客在哪你就能把券发到哪。
**适用行业**：全行业通用
**内容方向**：
- 对比型："还在印纸质券？out 了，现在 8 种方式发电子券"
- 场景型："店里没人？试试这 3 种线上发券方法"
- 清单型："实体店引流的 8 个渠道，你用过几个？"

#### 卖点 2：数据清清楚楚，每一分钱都有迹可循

**一句话**：谁领了、谁用了、哪个渠道效果好，全部看得到。
**适用行业**：全行业，尤其适合多门店/多员工的连锁店
**内容方向**：
- 痛点型："发了那么多券，到底有没有用？"
- 对比型："纸质券 vs 电子券，差的不只是一张纸"
- 干货型："3 个数据判断你的券发得值不值"

#### 卖点 3：核销奖励 —— 核销一张再送一张，回头客翻倍

**一句话**：顾客用券的时候，自动再塞一张到他包里，下次还来。
**适用行业**：餐饮、茶饮、零售（高频消费）
**内容方向**：
- 揭秘型："为什么这家店的回头客是你的 3 倍？"
- 玩法型："核销后再送一张，顾客想不回头都难"
- 算账型："一张券成本 5 块，换来一个回头客，值不值？"

#### 卖点 4：转赠奖励 —— 老带新裂变，顾客帮你拉客

**一句话**：顾客把券转给朋友，朋友用了，顾客自己也得一张——裂变就是这么简单。
**适用行业**：全行业，尤其适合社交属性强的（美业、健身、餐饮）
**内容方向**：
- 案例型："一杯咖啡带来 3 个新顾客，这个玩法绝了"
- 拆解型："转赠奖励怎么玩？一张图说清楚"
- 对比型："发传单 vs 转赠裂变，哪个获客成本更低？"

#### 卖点 5：多员工 + 多门店 + 权限分级 —— 连锁店也能用

**一句话**：品牌级管全局，门店级管本店，员工级只管发券——权责分明，不越权。
**适用行业**：连锁品牌、多门店商家、规模型企业
**内容方向**：
- 痛点型："店多了管不过来？一套系统全搞定"
- 功能型："3 级权限体系，连锁店的标配"
- 安全感："员工只能发券看不到客户数据，老板放心"

#### 卖点 6：次卡 3 种类型 —— 高频行业锁客神器

**一句话**：通卡/次卡/权益卡，三种模式覆盖所有预付费场景。
**适用行业**：美业、健身、洗车、亲子、教育培训
**内容方向**：
- 选品型："开美容院，应该做次卡还是权益卡？"
- 对比型："3 种次卡怎么选？一张表说清楚"
- 锁客逻辑："为什么 90% 的健身房都卖年卡？"

#### 卖点 7：企微深度整合 —— 私域运营的基础设施

**一句话**：加好友发券、入群发券、群发券、群关键字自助领券——私域里的发券全能手。
**适用行业**：有私域运营意识的中大型商家
**内容方向**：
- 玩法型："加好友自动发券，私域转化效率翻倍"
- 对比型："手动发券 vs 自动发券，差了多少效率？"
- 进阶型："进群就送券，社群活跃度直接拉满"

**对外口径**：写文案时一律用功能泛称"加好友/进群自动发券"，不直说平台名（见 `spec/redlines.json` `rules.wording.wecom`）。

#### 卖点 8：私密发放 —— VIP 专属感 + 精准客诉补偿

**一句话**：一对一发券，只有指定的人能领，做 VIP 福利、客诉补偿特别好用。
**适用行业**：有 VIP 体系、重视客户关系的商家
**内容方向**：
- 场景型："顾客投诉怎么办？一张私密券搞定"
- 运营型："VIP 专属福利怎么发？私密发放了解一下"
- 细节控："为什么大公司都用一对一发券，而不是群里乱发？"

#### 卖点 9：1 分钟做券 —— 零门槛，不用设计不用技术

**一句话**：手机上填几个空，一张专业电子券就做好了——比发朋友圈还简单。
**适用行业**：全行业，尤其是小店老板、个体户
**内容方向**：
- 痛点型："做个券还要找设计？不用，手机上 1 分钟搞定"
- 演示型："看看做一张券需要几步——你绝对想不到这么简单"
- 对比型："印刷券 vs 电子券：省钱 90%，效率翻 10 倍"

#### 卖点 10：转赠功能 —— 社交裂变的底层引擎

**一句话**：顾客可以把券转给好友，相当于免费帮你传播。配合转赠奖励，裂变动力更强。
**适用行业**：全行业
**内容方向**：
- 玩法型："你的顾客为什么不帮你转介绍？因为没有券"
- 心理学："人都喜欢送好处——利用转赠做裂变的底层逻辑"
- 组合拳："转赠 + 转赠奖励 = 裂变飞轮"

#### 卖点 11：活动可控 —— 放心发，薅不动

**一句话**：限领、库存、时段、白名单、口令、核销限制全都可控——活动放开手发，也收得回来。
**适用行业**：全行业，尤其怕被薅羊毛、怕活动失控的零售/餐饮/美业
**功能依据**：领取规则（限领总量/领取周期/自定义时间）、指定手机号白名单、领取口令（固定/随机）、每天核销限制、库存调整、暂停/恢复/作废——参数与规则一律见 `spec/facts.json`，不在文案里硬背数字。
**内容方向**：
- 痛点型："优惠券一发出去就怕被薅？这几道锁了解一下"
- 场景型："只在周末用的券、只发老客的券，怎么设"
- 安心型："活动不想做了随时暂停作废，已领未核的按规则处理"
**口径提醒**：口令的定位是"防外泄、控领取"（固定贴收银台、随机防转发），**不说"收款验证"**（产品不碰钱，见 facts forbidden_claims）；动态核销码不在宣传中使用（见 `spec/redlines.json` `rules.wording.liveCode`）。

## 3. 目标客群与定位

### 3.1 宣传定位

**一句话定位**（与产品分享文案一致，所有物料围绕它展开）：

> 免费实体店电子券制作工具，快速创建优惠券、券包、次卡，支持加好友/进群自动发券。

**定位拆解**（对外话术可围绕这四个词展开）：

| 词 | 含义 | 对外话术方向 |
|---|---|---|
| 免费 | 小微商家零成本上手，没有"先掏钱再试"的门槛 | 突出"免费""零门槛"（注意：封面/开头/结尾不刻意提免费，见 `spec/redlines.json` `rules.wording.free`） |
| 实体店专属 | 不是泛营销工具，解决到店生意：引流到店、到店核销、老客回头 | 突出"到店生意""实体店老板" |
| 券 + 包 + 卡三件套 | 优惠券做引流，券包做组合让利，次卡锁住高频回头客，一个工具全覆盖 | 突出"一个工具全覆盖" |
| 自动发券 | 顾客加你好友、进群自动发券，私域沉淀不用员工手动发 | 突出"加好友/进群自动发券"（用功能泛称） |

### 3.2 目标客群（按优先级）

| 优先级 | 客群 | 痛点 | 主打卖点 |
|---|---|---|---|
| 1 | 单店小微商家（餐饮、奶茶咖啡、美容美发、洗车、便利店等） | 想做活动但不会搞、怕花钱买系统 | 免费 + 简单 + 现成玩法模板 |
| 2 | 正在做私域沉淀的商家 | 已有顾客好友/客户群，缺一个自动发券抓手 | 自动发券能力（加好友/进群/群发） |
| 3 | 小型连锁（2~10 店） | 需要门店间分发与业绩对比 | 多门店 + 权限 + 排行统计 |
| 4 | 地推/异业合作场景 | 台卡、传单、海报物料需求大 | 海报生成 + 员工专属二维码打印 |

策划时先判断"这条内容打给哪类客群"，再决定卖点主次：打第 1 类 → 卖点 1/9/10/11；打第 2 类 → 卖点 7；打第 3 类 → 卖点 5/2；打第 4 类 → 卖点 1 + 活动海报。

### 3.3 冷启动写作约束（无真实案例）

**原则：没有案例就卖「场景 + 方法」，不卖「结果」。**

- 需要案例支撑的文章，用「场景示例」+ 行业泛称替代（例："假设你在大学城开了一家奶茶店……"），行文保持示例口吻，不绑定任何具体虚构店名
- 禁止编造真实数据、真实案例、真实营收（`spec/redlines.json` `rules.false_claims`）
- 种子商户产生真实数据后，经商家书面确认授权，按案例素材模板整理入库，选题才能从「待案例」转为「可执行」
